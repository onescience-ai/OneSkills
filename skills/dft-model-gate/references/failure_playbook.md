# 失败 → 通用修法

按门限编号组织。每条给出：**门限会怎么报** → **根因** → **通用修法** → **不要这么做**。
这里写的是这一类问题的解法，与具体是哪种金属/哪种分子无关。

---

## U4 非键合接触失败

**门限会怎么报**
```
[FAIL] U4 非键合接触  33 对低于门限 | 含H非键合最小 1.0099 Å (H86-H94, 下限 1.920) | ...
```

### 情形 1：分子间 H···H 对撞（最常见，也最隐蔽）

**根因**：按"每个分子把 H 指向最近的受体"逐个摆放。当两个分子**互为最近邻**时，
双方的 H 都投向对方，形成 O–H···O 的正常氢键距离（约 1.9 Å），
但两个 H 在中间迎面对撞：`d(H···H) ≈ d(O···O) − 2 × d(O–H) ≈ 2.9 − 1.92 ≈ 1.0 Å`。

**识别特征**：失败对数很多，且 `d(H···H)` 集中在 1.0–1.6 Å；同时这些分子的
`d(O···O)` 都在 2.9 Å 附近、看起来"很正常"。

**通用修法**：把供体分配做成**全局匹配**，而不是逐分子贪心：

1. 枚举所有 `(供体分子 i, 受体分子 j)` 对，按 `d(O_i···O_j)` 升序。
2. 依次分配 `i → j`，满足三个约束才接受：
   - `i` 的供体槽位未满（每个 XHₙ 分子 n 个）；
   - `j` 的接受数未达上限（水/醇取 2）；
   - **`i` 尚未被 `j` 投氢**（禁止互相双投，这一条就是本症状的解药）。
3. 再按分配结果逐个分子定取向（见 `scripts/hbond_pack.py`）。
4. 取向选择用"硬约束优先"：先把违反非键合下限的候选全部排除，再在合法候选里挑
   最能满足指定氢键的。**不要**用一个大权重把所有项揉进一个软打分里 ——
   软打分会在"少一个氢键"和"多一次 H···H 接触"之间做交易，而后者不可交易。

**不要这么做**：把 H 方向取"最近邻方向 + 固定旋转角"。它假设最近邻一定是氢键受体，
而"互为最近邻"这一情形会让假设失效。

### 情形 2：吸附物嵌进金属表面

**门限会怎么报**：`C2-<吸附物>(吸附物) 最近骨架接触 C65-Cu53 = 2.500 Å | mode=physisorbed 要求 ≥ 3.294 Å`

**根因**：吸附高度是手填常量（如 `Z_CO2 = 2.50`），没有和"吸附模式"核对。
2.5 Å 既远短于 vdW 接触距离（约 3.1 Å），又远长于化学吸附键长（约 2.0 Å），
落在排斥壁里，是一个既非物理吸附也非化学吸附的构型。

**通用修法**：先定 `mode`，再让高度由 `mode` 决定：
- `physisorbed`：最小接触 ≥ `0.90 × (r_vdw(金属) + r_vdw(近端原子))`。CO₂/Cu 约 3.3 Å。
- `chemisorbed`：显式给 `min_contact`（该体系的已知键长 ±0.1 Å）。
- 顺带核对**分子轴向**：用分子轴与表面法线的夹角验证"平行/垂直"这类声明，别只写在说明里。

### 情形 3：溶剂穿入金属

**门限会怎么报**：`C2-H2O(不穿金属) 7 个溶剂原子低于金属顶层 6.261 Å: [...]`

**通用修法**：把金属骨架顶层坐标作为下限，重建溶剂层时对每个分子做该检查；
分子取向搜索时把骨架原子当作硬约束对象（`hbond_pack` 的 `existing` 参数就是干这个的）。

## U2 / C1 物种识别与计数失败

**门限会怎么报**
```
[FAIL] C1 物种计数   H2O: 声明 18, 实测 0; CO2: 声明 1, 实测 0 | 实测全部: {'C5HO3': 1, 'H2O': 14, 'H8': 1}
```

### 情形 1：分子互相"粘连"

**根因**：原子间距离异常（例如 1.3 Å 的 O···H）落在共价键判据内，
把两个分子连成了一个片段。这通常不是"识别错误"，而是**结构本身有病**
（H 太靠近另一个分子的 O，会直接引发质子转移）。

**通用修法**：先看 U4/U5 是不是也失败了。若 U4 的 `H···电负性原子` 距离 < 1.3 Å，
先修取向（情形 1），片段自然分开。

### 情形 2：金属离子被并进载体骨架

**门限会怎么报**：实测物种里根本没有 `K`，但 `U2 片段识别` 显示只有 1 个金属片段。

**根因**：金属–金属按半径自动成键，吸附的碱金属/离子与载体近邻距离也在阈值内，
于是被并进同一片段。

**通用修法**：在契约里声明 `framework.elements`。声明后，只有载体元素之间才自动生成
金属键，离子成为独立物种。（金属键判据本身不宜收紧：K–Cu 在 3.5 Å 也确实有相互作用，
靠收紧阈值来分离会把真实的金属格点也拆散。）

## U5 / C2 氢键网络失败

**门限会怎么报**
```
[FAIL] C2-H2O(氢键网络)  平均 2.11 条氢键/分子, 受体配位数 [4, 3, 2, 2, ...] | 受体过配位(>2): [(69, 4)]
[FAIL] C2-H2O(氢键网络)  平均 0.00 条氢键/分子, 受体配位数 [] | 平均氢键数 0.00 越界 1.0-4.5
```

### 受体过配位（某个 O 接受 3–5 个 H）

**根因**：只保证"每个分子给出 2 个 H"，没保证"每个受体只收 2 个"。

**通用修法**：匹配时给受体加容量（水/醇 2，氨 3，按分子定），并在取向搜索里**按门限同样的
定义**（H···受体距离 ≤ 阈值 **且** D–H···A 角 ≥ 120°）统计受体已接受数，超容量即视为硬违反。
注意：**只用距离统计会误伤** —— 稠密膜里很多 H 只是"路过"受体 2.5 Å 内，
角度根本不构成氢键，按距离计数会得出"受体已满"的错误结论，反而一个氢键都建不起来。

### 平均氢键数过低（< 1 条/分子）

**根因**：供体目标太远够不到，或取向搜索被其他硬约束压死。

**通用修法**：
1. 供体截断取 `d(O···O) ≤ 3.3 Å`。目标距离 d 时 H 到受体最近约 `d − d(X–H)`，
   要让氢键落进 2.4 Å 内需要 `d ≤ 2.4 + d(X–H) ≈ 3.36 Å`。
2. 取向候选里必须有**解析对准项**（把 H 直接对到指定受体），只靠随机采样在稠密体系里命中率太低。
   双受体情形要按"平分线 + 平面"做最优匹配（H–X–H 角固定，只可能做到折中几何）。
3. 多跑几轮（Gauss-Seidel 式扫描）：每个分子的最优取向依赖邻居当前取向，
   一轮不够。经验上 3–4 轮收敛。

## C2 溶剂密度失败

**门限会怎么报**
```
[FAIL] C2-H2O(溶剂)  18 个 H2O / 面积 90.54 Å² × 膜厚 8.70 Å (...) -> 数密度 0.02285 Å⁻³ (0.684 × 体相)
```

**根因**：分子数与膜厚的搭配不对。**膜厚定义必须先说清**：
只用重原子 z 跨度会低估（漏掉分子自身尺寸），只用含 H 全跨度会高估。
门限采用"重原子跨度 + 一个最近邻间距"（相当于两侧各加半个分子直径），
并且同时报告全跨度口径供核对。

**通用修法**：由体相数密度反算目标膜厚，再定层数与层间距：

```
目标膜厚 t = N / (A × ρ_bulk)
```

- 水 `ρ_bulk = 0.0334 Å⁻³`（1 g/cm³），其余常见溶剂见 `scripts/elements.py`。
- 层间距取该液体的近邻间距（水约 2.8–3.0 Å）。
- `层数 ≈ t / 层间距 + 1`，每层分子数 = `N / 层数`。

**不要这么做**：把"层间距"设成等于面内 O–O 目标距离。这样层间与层内是同一尺度，
两层会互相穿插，密度和氢键网络同时坏掉。层间距是**层与层之间**的距离，
不是分子间最近邻距离的别称。

## U6 / C3 维度与真空失败

**门限会怎么报**：`[FAIL] U6 维度与真空  判定为 2D slab，真空 9.3 Å < 硬门限 12.0 Å`

**通用修法**：真空由**最外层原子的 z 最大值**算起（不是金属顶层），
`cell_c = z_max + 目标真空`。含偶极修正时 15–20 Å 更稳。
注意别把"分子自身伸出的 H"漏算 —— 真空不足会让周期镜像之间发生假相互作用。

## C4 固定层失败

**门限会怎么报**
```
[FAIL] C4 固定原子  POSCAR 缺少 Selective dynamics：slab 计算会整体漂移
[FAIL] C4 固定原子  固定的不是最底部连续金属层: 固定 [0.0, 4.174] vs 金属层 [0.0, 2.087, 4.174, 6.261]
```

**通用修法**：
- 写 POSCAR 时必须带 `Selective dynamics`，固定原子写 `F F F`，其余 `T T T`。
- 固定的必须是**最底部连续若干层**，且只固定金属（非金属固定会人为冻结分子构型）。
- **只有 0D 分子/团簇**才应该全部自由；bulk 或 slab 固定层缺失要先问清意图再改。

## I0–I9 VASP 输入失败

### I0 KPOINTS 行序（会让作业直接读失败）

```
[FAIL] I0 KPOINTS 格式  第 2 行不是整数 Nk: 'For tighter convergence use a 2 2 1 mesh instead.'
```

**根因**：VASP 约定 KPOINTS **第 1 行自由注释，第 2 行必须是 Nk**（0 = 自动网格）。
多写一行说明，VASP 会把文字当整数读，**作业在启动阶段就失败**。

**通用修法**：说明合并进第 1 行，或删掉。

### I3 ENCUT

**通用修法**：`ENCUT ≥ 1.3 × max(ENMAX)`，**ENMAX 从 POTCAR 现算**。
不要相信 INCAR 注释或记忆里的数值 —— 同一元素的 `_pv` / `_sv` / `_d` 变体 ENMAX 差别很大
（例如 K_pv 是 117 eV，而不是常被写成 250 eV）。

### I4 金属 smearing / I9 K 点密度

**通用修法**：
- 含金属：`ISMEAR=1` 或 `2`，`SIGMA=0.1–0.2`；`ISMEAR=0` 仅适合绝缘体/分子。
- 金属 slab 的面内 k 点线密度（`|a| × N_k`）建议 ≥ 25 Å；10 Å 面内胞用 Γ 点通常不足，
  至少 2×2×1，常见 3×3×1。

### I5/I6 色散与偶极

**通用修法**：含分子/物理吸附必须开色散（`IVDW=11` 等）；slab 沿 z 有净偶极时开
`LDIPOL=.TRUE. / IDIPOL=3`。这两项漏掉不会让作业失败，但会让**结果系统性错误**。

## 流程性失效（比几何错误更值得警惕）

### 校验数字与交付文件脱钩

**症状**：交付说明写"最近非键距离 ≥ 2.36 Å"，而文件实测 1.01 Å；
或者说明里的原子数/晶胞与文件不一致。

**根因**：先跑了校验、之后又改了结构但没重跑；或者直接把脚本内部变量当作交付值。

**通用修法**：
1. 校验必须传入**最终文件路径**，不能传内存对象或中间产物。
2. 报告里嵌入文件 `sha256` 与完整命令行（门限脚本已自动输出）。
3. 结构一变就重跑；把"最后一次校验的 sha256"和"交付文件的 sha256"对比一致才算数。

### 把注释/记忆当数据源

**症状**：INCAR 注释里的 ENMAX、README 里的层数/覆盖度/吸附高度与文件不符。

**通用修法**：所有数字从文件现算。门限脚本刻意重新解析 POTCAR 的 ENMAX、
重新数金属层、重新算密度，就是为了不信任二手数字。

### 用形容词代替可核对的声明

**症状**："非晶态"、"接近液态"、"物理吸附"、"约 0.4–0.8 ML"。

**通用修法**：把每个形容词换成契约里的一个可判定字段，并让门限去判：
`solvent_model`、`mode`、`count`、`target_coverage`、`density_ratio_range`。
写不出可判定字段的形容词，就不要写进交付说明。
