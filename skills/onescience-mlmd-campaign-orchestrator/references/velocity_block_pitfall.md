# 速度块陷阱：AIMD 从 0 K 起步（T=0）

## 症状
- `OSZICAR` 的 MD 行温度一直为 0：`1 T= 0. E=… EK= 8.4e-06`，`EK` 近似线性缓慢增长。
- 实测估算 1000 步后 `EK` 仅 ~0.07 eV → 温度 ~4 K（远达不到 300 K）。
- 电子步正常收敛、没有 `I REFUSE TO CONTINUE`——**极易误判为“在正常跑”**。

## 根因
VASP 的 POSCAR 允许在坐标块后附加**速度块**（每原子 3 个数，Å/fs）。
MD 启动时若检测到速度块就**直接采用**，不再按 `TEBEG` 生成 Maxwell–Boltzmann 速度。
从一次结构优化得到的 `CONTCAR`、或由 ASE/OneScience 写出的帧，末尾常带一段**全零速度块**。

## 识别
```bash
# 期望坐标末行 = 9(头) + N(原子)。看其后是否有“每行 3 个数、无 flags”的块：
awk 'NR>=195 && NR<=202 {printf "%d: %s\n", NR, $0}' POSCAR
```
若整块为 `0.00000000E+00  0.00000000E+00  0.00000000E+00` → 判定为全零速度块。

## 修法（二选一，报告里说明）
- **A. 重新采样（首次预平衡推荐）**：截断到坐标块末行：
  ```bash
  head -n <坐标末行号> POSCAR > POSCAR.nov && mv POSCAR.nov POSCAR
  ```
- **B. 续跑**：明确保留速度块，并确认其非零且与目标温度自洽。

## 验证
重投后第一步 `T=` 就应接近 `TEBEG`（如 250–350 K）；若仍为 0，检查 POSCAR 是否真被替换。

## 教训
凡是拿 `CONTCAR`/ASE 导出的帧当 MD 起点，**先数行、先看速度块**。
