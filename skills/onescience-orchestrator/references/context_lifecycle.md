# 步骤上下文与释放

本契约用于多技能交接、同技能长步骤和失败修复；独立单步任务沿用当前输入，不为格式新增无用文件。
目标是减少重复输入和输出，同时保留用户约束、精确公共契约、科学证据及未决项。

## 存储与请求分开

- 文件保留完整元信息、论文、源码、日志和历史；任务状态保留有效决策、产物索引及观察。
- 模型请求只携带基础执行规则、用户目标与持续约束、当前步骤及其契约、当前技能和必要参考内容、尚需处理的工具反馈。
- 完整接收元信息之后可复用已核验快照；不要把所有技能元信息反复注入 executor。正式资源结果足够且任务、版本、检索范围一致时复用其 `content`；不足时只补召缺项，资源路径不授权直读 assets。
- 尚未读取或核验的来源不能通过摘要假装已核验。明确的符号、签名、默认值、路径、shape、来源和禁止事项保持原值；未决项保持未决。

## 调用前组装

以现有 `step_handoff` 为主体，附加所需需求条目和产物引用；不传完整 Task State、历史技能正文、已解决错误或完整执行转录。
按当前步骤依赖、需求 ID 和文件选择输入，不另开模型调用生成一份重复总结。

| 接收者 | 决定性输入 |
|---|---|
| paper-repro | 论文身份、目标实验、原始数据路径、用户接口要求、来源和交付限制 |
| coder | 当前实现条目、唯一规格/源码引用、公共接口、数据与配置语义、验证范围 |
| trainer / infer | 当前阶段契约、模型/数据/checkpoint、已核验决策、执行权限 |
| runtime / installer | 当前入口/命令、运行配置/环境缺口、获准检查、日志位置及相关错误 |
| resource / expert | 当前检索范围或待决策方面、足够的任务约束和相关正式资源内容 |
| 修复调用 | 失败条目、当前源码版本、必要错误片段、受影响依赖；保留原契约 |

可使用安装目录内的脚本做确定性投影，不必把完整状态读入模型：

```bash
python "<orchestrator_dir>/scripts/prepare_step_context.py" --task-state ".onescience/task_state.json" --handoff ".onescience/handoff/step_3.yaml" --output ".onescience/handoff/step_3_context.json"
```

原子写出完整 JSON 交接；stdout 只返回文件引用、SHA-256 和大小，目标技能读取该 JSON。
输出位置必须在当前任务允许写入范围内；用户限制交付文件集合时，中间交接使用已授权工作目录。
脚本不读资源资产、源码或日志，不创建需求，不执行验证，也不修改宿主消息历史。

可选 `context_selection` 用于从状态选取条目：

```yaml
context_selection:
  requirement_ids: [api_model, cli_boolean]
  artifact_ids: [reproduction_spec]
  resource_result_ids: [model_usage]
```

状态中的 `requirement_ledger` 每项有唯一 `id`，原样保留 `requirement / implementation_target / verification / status`；`scope: global` 条目总是继承。`artifacts` 按 `artifact_id` 选择。
可复用的 `resource_results` 按 `resource_result_id` 选择，保存正式 result 的完整内容及 task/version/scope 来源；这些条目需要调用方先核对适用性。
handoff 中的 `inputs` 和已选步骤字段完整保留；全局约束合并，禁止训练不可被子步骤解除。不存在的选择 ID、冲突条目和任务不匹配均返回具体错误，先修正交接，不丢项继续执行。

## 完成与实际释放

1. 当前技能完成本步骤所需操作、验证和恢复；结果及必要证据落盘。
2. caller 接收正式 result，将有效状态和产物引用写回 Task State。
3. 宿主结束独立执行上下文，或在下一次模型请求中移除该次技能正文、references 和内部工具历史。父步骤有未完工作时只恢复父步骤的相关上下文。
4. 后续再次需要同一技能时，从有效状态、契约和文件引用重新调用，不回放整个旧会话。

释放的是后续请求中的内容及本调用独占且已无消费者的临时缓存；持久产物、证据、共享环境及仍运行的任务继续保留。
脚本返回或文件交接本身不证明历史已被裁剪。只有宿主确认独立上下文已结束/请求视图已更新，才可记录 `host_release_verified=true`；能力未知时保持 false，并按调用闭环选择实际可用通道，不声称 token 已降低。
不手工删掉未配对的工具消息；实际裁剪需由宿主维护工具调用/结果协议。宿主既不能独立调用也不能动态裁剪时，按既有调用能力缺失规则报告具体限制。

## 步骤内部与输出

- 按模块或阶段落盘有效决定、证据定位和未决项；处理完的原始输出退出后续请求，必要时再按位置读回。调用仍在执行的验证、重试和下游操作不提前释放。
- 相关文件成批实现，避免整套源码、全部测试和最终报告挤入单轮，也不把微小编辑拆成独立模型调用。
- 进度只报当前目标、文件、关键风险和结果变化；正式回执只返回状态、产物、验证、缺失和恢复位置。长日志、源码、规格不重复内嵌在结果和总结里。
- 首次运行即保存 stdout、stderr、退出码、命令和配置/源码版本。后续引用已有证据；仅相关文件、配置或环境变化、上次未覆盖或执行失败时重验，不为补日志重跑成功的完整检查。
- `reason=length` 等中断恢复时，以最后有效状态和磁盘产物核对实际完成项，继续未完成部分；未收到正式 result 的步骤保持未完成，不能由输出长度推断成功。

## 验收

技能规则与辅助脚本可检查契约保真、交接大小、已选/排除条目和重复读取；宿主侧另需检查实际模型请求不含已结束调用的无关正文与转录。
比较同 case 的规则得分、累计 input/output、逐请求上下文规模、重复验证和耗时；性能改进以实测为准，不以“写了释放标记”自判生效。
