# 用户、论文与官方实现的冲突裁决

## 目标

本参考用于同一复现字段在用户要求、论文正文/附录、官方仓库或不同版本之间不一致时，确定最终
采用值，同时保留事实归属和论文忠实度。裁决结果直接写入唯一 `reproduction_spec.md`，不生成
独立冲突报告。

## 1. 区分任务决定与事实判断

两类问题必须分开回答：

1. **本次代码按什么实现**：由执行决策优先级决定。
2. **目标论文原本如何定义**：由事实可信度和适用范围决定。

执行决策优先级：

```text
用户明确要求
> 目标论文的目标实验设置
> 与论文版本和目标实验匹配的官方实现补充
> 可逆且不改变科学语义的工程选择
```

事实可信度优先级：

```text
目标版本论文的明确陈述
> 与目标版本、实验、阶段匹配的官方实现
> 其它官方版本或实验
> 有证据链的机械推导
> 未经来源支持的常识或模型记忆（不得作为确定事实）
```

用户要求具有最高执行优先级，但不是论文事实来源。用户要求改变目标变量、模型变体、loss、split
或评测协议时，代码按用户要求实现，规格同时保留论文基线，并将结果标为用户实验变体。

## 2. 比较前先统一作用域

表面相同的字段可能属于不同作用域。比较前为每个值写明：

- 论文版本、仓库 commit/tag；
- 目标实验、数据集和模型变体；
- 训练、微调、推理、内循环或评测阶段；
- 更新对象、输入变量、target 和指标对象；
- 正式配置、消融配置或 smoke 配置；
- 单位、缩放、坐标系和统计口径。

作用域不同的值不是可以互换的候选。不得把某个消融的学习率、另一个数据集的层数、预训练阶段
的 optimizer 或仓库最新分支的默认值传播到目标实验。

## 3. 裁决流程

对每个冲突字段执行：

1. 建立冲突 ID，列出各值及各自 source ID。
2. 回到集中来源索引核对详细定位和证据摘要，不在正文重复章节、页码或图表编号。
3. 核对论文版本、仓库 commit、实验、阶段、变量语义和单位。
4. 判断属于真冲突、不同作用域、版本演化、命名差异还是可机械换算。
5. 按执行优先级选定本次实现值；按事实可信度保留论文基线。
6. 写明偏离对可构建性、运行、指标可比性和 `paper_fidelity` 的影响。
7. 若无法唯一裁决，转为 `UNRESOLVED` 或 `PROPOSED_CHOICE`，并给出继续实现方式。

## 4. 常见冲突处理

| 冲突类型 | 最终实现 | 规格必须保留 |
|---|---|---|
| 用户文件名、类名、签名与仓库不同 | 用户要求 | 仓库名称仅作为映射，不要求 coder 复制 |
| 用户科学设置与论文不同 | 用户要求 | 论文基线、偏离项、不可直接比较的结果 |
| 论文明确，仓库目标版本不同 | 论文定义 | 仓库版本差异及未采用理由 |
| 论文未说明，匹配 commit 的仓库明确 | 仓库补充 | `OFFICIAL_REPO_DETAIL` 标签和准确适用范围 |
| 论文正文与附录含义不同 | 结合上下文、版本和目标实验裁决 | 两个 source ID、作用域和裁决理由 |
| 仓库多个配置不同 | 与论文版本和目标实验最匹配者 | commit、配置适用范围和未采用变体 |
| 数据实测与论文描述不同 | 不静默改数据 | 论文事实、数据观察、可能的版本/文件错误 |
| 名称不同但公式和变量语义等价 | 可建立别名映射 | 机械等价推导，不描述为来源冲突 |

## 5. 论文与官方仓库的关系

官方仓库用于补齐实现需要而论文未写明的内容，例如版本匹配的配置键、模块调用顺序、数值稳定
常数、数据字段映射和 checkpoint 包装格式。使用仓库证据必须满足：

- 从论文、作者页或项目官网确认官方身份；
- 固定 commit/tag，不以会变化的 branch 名作为唯一版本；
- 定点读取与目标信息需求直接相关的文件和符号；
- 确认目标实验、模型变体和训练阶段匹配；
- 不复制源码，不把仓库实现改写为论文明确陈述。

论文明确给出的科学定义原则上高于仓库默认实现。若仓库看似不同，先检查是否为错误版本、修复后
实现、工程近似、其它实验或不同变量命名。证据不足时保留差异，不能用“官方代码更可信”直接
覆盖论文。

## 6. 证据不足时继续交付

冲突或缺失不自动中断任务：

- 有可逆候选时写 `PROPOSED_CHOICE`，暴露配置键、策略接口或多变体分支；
- 不影响科学语义的选择写 `IMPLEMENTATION_FREEDOM`；
- 影响精确数值但不影响构建时继续交给 coder，并降低 `paper_fidelity`；
- 只有目标无法唯一识别、且任何候选都会误导用户时，才设
  `implementation_readiness=insufficient`。

候选的默认顺序为：版本和实验匹配的官方实现 > 由已确认公式/shape 机械约束的候选 > 不改变
科学语义的工程选择。候选不得用于伪造论文报告值、指标公式或数据划分。

## 7. 统一规格中的记录格式

冲突表至少包含：

```text
conflict_id
field_and_scope
user_value + requirement_id
paper_value + source_id
repo_value + source_id
conflict_kind
adopted_value
decision_reason
implementation_action
paper_fidelity_impact
metric_comparability_impact
```

正文只引用 requirement ID 和 source ID。详细章节、页码、图表、公式、仓库文件及符号位置集中在
来源索引中，不把论文导航文字夹入模型、数据或训练描述。

## 8. 完成检查

- 每个冲突值都有来源和作用域；
- 最终采用值与用户要求一致，或明确说明用户未约束；
- 用户变体没有被写成论文事实；
- 仓库补充没有覆盖论文明确科学定义；
- 不同版本、实验和训练阶段的值没有串用；
- 每个未裁决项都有继续方式和忠实度影响；
- 同一字段没有同时出现在“已采用”和“未决”状态。
