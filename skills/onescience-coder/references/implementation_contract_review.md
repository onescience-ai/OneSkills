# 实现契约审查

本参考用于模型实现、推理入口、数据管线、状态恢复和接口兼容等需要专项审查的编码任务。
它是 coder 内部参考，不是独立技能或前置调度阶段。普通编码以用户要求和原语返回内容为依据，
可以直接进入 coder；仅因使用本参考，不得要求额外调用 paper-repro 或生成 reproduction_spec.md。

## 适用范围

先按本次要求选择适用小节。普通任务只核对实际文件、接口和行为；简单任务可用简短需求清单，
不强制展开完整模型审查。下列条件逐项判断，不因某一项适用就启用其它全部检查：

- 唯一论文规格、规格 ID 与 SHA-256：仅论文复现编码且上游按流程交接该规格时适用。
- 模块结构、tensor layout、forward/loss：本次实现或修改涉及相应模型/数值行为时适用。
- 真实数据链：本次交付包含该数据链或与之集成时适用；独立工具/模块不因缺少数据集而阻断。
- 梯度：本次功能涉及可导性、冻结或参数/latent 更新时适用；运行仍受用户授权限制。
- checkpoint/resume/RNG：本次要求涉及保存、加载、恢复或随机性时，按实际承诺分别核验，
  不把单纯权重加载扩展为完整 resume，也不为确定性工具新增 RNG 要求。

不适用类别不纳入必需验收，必要时在摘要注明原因，不记成 not_run、未决或缺失输入。
not_run 只用于本任务适用但未执行的检查。上游已有完成标准若与任务范围不符，回交调用方修正；
不能自行删掉真实必需项、将失败项改为不适用或以此取得 success。

## 编码前：建立需求台账

从用户原始请求和 `step_handoff` 逐项提取 `requirement_ledger`；独立调用没有 handoff 时直接依据用户要求与原语内容。一个可独立失败的要求对应一项，仅纳入下列实际涉及的类别，不为未涉及类别补需求：

- 必须存在、必须保持不变、禁止新增的文件；
- 类、函数、方法、属性、配置键的精确名称；
- 参数名、默认值、可选值、位置/关键字调用和返回结构；
- 模块层次、子模块顺序、数量、类型和关键维度；
- 数据文件、split、样本数、dtype、shape、归一化、缓存和防泄漏要求；
- forward、loss、metric、随机种子、梯度和状态不变性；
- checkpoint 文件/目录、原始或包装 state dict、`strict` 语义；
- CLI 参数、默认值、布尔语义、输出路径、文件名和 schema；
- 合法边界输入与必须拒绝的非法输入；
- 禁止训练、禁止依赖、只改指定文件等限制。

台账每项记录 `id / requirement / implementation_target / verification / status`。不要把长需求压成一个笼统条目，也不要仅凭实现计划把条目标为通过。

论文任务从已校验 SHA-256 的同一份 `reproduction_spec.md` 逐条引用既有 requirement、field、
module 和 acceptance ID；台账仅是实现进度与证据索引，不成为另一份权威规格。哈希只保证文件版本
一致，不能证明提取正确。实现前核算规格中的字段维度和、轴索引、类职责与必要梯度路径；发现矛盾
回交 paper-repro 修订同一文件，再更新散列和受影响实现。不得自行补科学默认值消解冲突。

## 实现要求

- 公开 API 按字符级契约实现。`forward(self, x)` 中的 `x` 也是契约，调用方可能使用关键字调用。
- 同时验证任务要求的位置调用与关键字调用，不用近义别名替代指定符号。
- 默认构造和合法自定义构造都必须可用；可选映射参数未覆盖的项与默认值合并，除非任务明确要求完整映射。
- 用户指定的属性名和模块结构会被 checkpoint、hook 或结构检查使用，不能只实现数学上相似的网络。
- 输入校验只拒绝明确非法的输入。先做无损规范化，再验证语义，避免误拒绝大小写、等价容器或最小合法长度。
- 承诺的超参数在配置中用清晰、稳定的键显式声明，不藏在私有嵌套键、推导常量或注释中。
- 缺少可选审计元数据时不得让最小合法 CLI 提前退出；只有契约必需且无安全默认值的数据缺失才阻断。

## 文件闭包

- 交付前比较实际文件集合与 `required / unchanged / forbidden` 集合。
- “不修改 `dataset.py`”表示内容不得改变，不等于运行闭包可以缺失该依赖。若隔离交付目录需要它，优先从已核验基线原样物化并校验未改；若任务同时明确禁止新增，则报告缺口。
- “仅生成 X”必须严格只生成 X，不为计划、审计或示例增加其他文件。
- 不得用延迟 import 掩盖缺失的必需依赖后声称完整交付。

## 公共边界验证

仅对本次要求涉及的下列项目执行检查，不以自定义 happy-path smoke 代替适用验收；本列表不是每个任务必须全部执行的固定流程：

1. 文件集合：必须文件存在非空，不变文件与基线一致，禁止文件不存在。
2. 导入与签名：导入目标模块，用 `inspect.signature` 核对参数名和默认值。
3. 构造器：默认、合法自定义、非法配置各至少一例。
4. 模块结构：核对指定属性、类型、顺序、数量和维度。
5. 方法/forward：位置与关键字调用；shape、键、dtype、有限性、梯度和状态语义。
6. 边界输入：合法边界不得误拒绝，非法输入必须明确失败。
7. checkpoint：原始/包装 state dict、单文件/目录入口及 `strict=True`。
8. CLI：`--help` 后执行最小合法命令，核对 exit code、stderr 和约定产物。
9. 输出 schema：重新读取产物，核对文件名、字段、shape、dtype、值域和有限性。
10. 配置：逐个核对需求中的默认值、路径、训练/推理参数和结果目录。
11. 实际数据链：从用户数据绑定经真实 loader、字段选择、特征构造/拼接与 target 构造到 model/loss，
    用其中最小合法样本核对维度等式、producer-consumer、layout 和单位。不以人工匹配模型维数的随机
    tensor 替代这条路径；真实数据不可访问时标 not_run，合成输入只证明明确标注的组件工程检查。
12. 数值失败条件：获准执行的 forward/loss/metric 中，差分或 mask 后有效元素非空、分母有效、
    输出/损失/指标有限；遇到空张量、NaN/inf 必须失败并保留日志，不能继续打印总体通过或跳过该项。
13. 梯度与恢复：按规格核对冻结对象、输入/latent 可导与 detach/no_grad 边界；仅在获准时运行梯度
    检查和 resume/RNG 运行对照。禁止训练/反传时只做对应静态审查，动态标准记 not_run。
    被要求的 optimizer/scheduler/step/RNG 等字段应真实保存与恢复，不把 load_state_dict 当完整 resume。

禁止训练时不运行训练循环、backward 或 optimizer update；仅执行本任务涉及且获准的非训练检查。适用但无法执行的项标 `not_run` 并写明原因，不能由其他检查推断为通过；未涉及类别按前述不适用规则处理。

## 完成门禁

返回 `success` 前，台账不得有 `pending`、`failed` 或未解释的 `unresolved`；实际文件集合必须闭合；
本步必需验收项不得 not_run。用户未授权的训练/反传不作为代码交付的必需项；其未执行状态如实保留，
不扩大权限。未满足的必需项返回 partial/failed，已完成的独立文件仍可交付。未运行的训练、推理或
科研指标不得描述为已验证。代码改动后重做受影响的检查，旧版本证据不能直接用于新版本。

检查必须有能失败的条件，来源是用户要求、原规格或已说明的数学不变量，不能由当前实现自行设定
通过阈值。程序退出 0、无异常或“Full pipeline OK”不是充分证据；异常数值和已失败子项优先于总结。
每项保留原要求引用、实现位置、预期、实测值、命令/检查标识、代码版本与证据文件定位。
静态一致性、获准动态验证和科学结果三个范围分别汇总。

在 `execution_result.observation.verification_results` 中报告实际需求台账总数及适用检查的
`passed / not_run / failed / pending`，并提供逐项要求、实现位置、预期、实测和证据定位，不能只返回
计数。有上游规格或验收 ID 时沿用；普通编码引用原要求或本次台账 ID，不要求论文规格 ID。
not_run 附原因；不适用类别无需生成检查或失败记录。
详细台账可放到获准的现有检查报告中；若用户限定交付文件则不新增审计文件，在正式回执中保留
必要记录。仅独立调用且上游未给 ID 时使用本次台账稳定 ID，不伪造已执行的上游检查。
