# 实现契约审查

本参考用于接口密集的模型实现、推理入口和科研代码二次开发。它补充普通代码风格检查，重点验证用户可观察的专业契约。

## 编码前：建立需求台账

从用户原始请求和 `step_handoff` 逐项提取 `requirement_ledger`。一个可独立失败的要求对应一项，至少覆盖：

- 必须存在、必须保持不变、禁止新增的文件；
- 类、函数、方法、属性、配置键的精确名称；
- 参数名、默认值、可选值、位置/关键字调用和返回结构；
- 模块层次、子模块顺序、数量、类型和关键维度；
- 数据文件、split、样本数、dtype、shape、归一化、缓存和防泄漏要求；
- forward、loss、metric、随机种子、梯度和状态不变性；
- checkpoint 文件/目录、原始或包装 state dict、`strict` 语义；
- CLI 参数、默认值、布尔语义、输出路径、文件名和 schema；
- 合法边界输入与必须拒绝的非法输入；
- 禁止训练、禁止依赖、只改指定文件等限制。

台账每项记录 `id / requirement / implementation_target / verification / status`。不要把长需求压成一个笼统条目，也不要仅凭实现计划把条目标为通过。

## 实现要求

- 公开 API 按字符级契约实现。`forward(self, x)` 中的 `x` 也是契约，调用方可能使用关键字调用。
- 同时验证任务要求的位置调用与关键字调用，不用近义别名替代指定符号。
- 默认构造和合法自定义构造都必须可用；可选映射参数未覆盖的项与默认值合并，除非任务明确要求完整映射。
- 用户指定的属性名和模块结构会被 checkpoint、hook 或结构检查使用，不能只实现数学上相似的网络。
- 输入校验只拒绝明确非法的输入。先做无损规范化，再验证语义，避免误拒绝大小写、等价容器或最小合法长度。
- 承诺的超参数在配置中用清晰、稳定的键显式声明，不藏在私有嵌套键、推导常量或注释中。
- 缺少可选审计元数据时不得让最小合法 CLI 提前退出；只有契约必需且无安全默认值的数据缺失才阻断。

## 文件闭包

- 交付前比较实际文件集合与 `required / unchanged / forbidden` 集合。
- “不修改 `dataset.py`”表示内容不得改变，不等于运行闭包可以缺失该依赖。若隔离交付目录需要它，优先从已核验基线原样物化并校验未改；若任务同时明确禁止新增，则报告缺口。
- “仅生成 X”必须严格只生成 X，不为计划、审计或示例增加其他文件。
- 不得用延迟 import 掩盖缺失的必需依赖后声称完整交付。

## 公共边界验证

根据任务适用范围逐项执行，不以自定义 happy-path smoke 代替：

1. 文件集合：必须文件存在非空，不变文件与基线一致，禁止文件不存在。
2. 导入与签名：导入目标模块，用 `inspect.signature` 核对参数名和默认值。
3. 构造器：默认、合法自定义、非法配置各至少一例。
4. 模块结构：核对指定属性、类型、顺序、数量和维度。
5. 方法/forward：位置与关键字调用；shape、键、dtype、有限性、梯度和状态语义。
6. 边界输入：合法边界不得误拒绝，非法输入必须明确失败。
7. checkpoint：原始/包装 state dict、单文件/目录入口及 `strict=True`。
8. CLI：`--help` 后执行最小合法命令，核对 exit code、stderr 和约定产物。
9. 输出 schema：重新读取产物，核对文件名、字段、shape、dtype、值域和有限性。
10. 配置：逐个核对需求中的默认值、路径、训练/推理参数和结果目录。

禁止训练时不运行训练循环、backward 或 optimizer update，但仍执行不触发训练的签名、构造、forward、CLI 和 schema 检查。无法执行的项标 `not_run` 并写明原因，不能由其他检查推断为通过。

## 完成门禁

返回 `success` 前，台账不得有 `pending`、`failed` 或未解释的 `unresolved`；实际文件集合必须闭合；所有已运行检查必须有真实结果。未运行的训练、推理或科研指标不得描述为已验证。

在 `execution_result.observation.verification_results` 中报告台账总数及 `passed / not_run / failed / pending`，并分别报告 files、signatures、constructors、structure、forward、checkpoint、CLI 和 output schema 的状态。
