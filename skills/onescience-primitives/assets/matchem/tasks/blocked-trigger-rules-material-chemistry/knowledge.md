# 材料化学任务中BLOCKED触发规则

## 适用范围
适用于材料化学计算任务中输入参数验证和任务状态管理。当任务需要用户提供特定输入数据（如材料结构、电池工况参数、电解液/对电极信息）时，系统必须检查这些输入是否完整提供。

## 输入
- 任务工作流定义（包含必填输入参数列表）
- 用户提供的输入数据（可能为空或不完整）
- 公开数据库访问权限（Materials Project、ICSD等）

## 输出
- 任务状态：BLOCKED（输入缺失）或CONTINUE（输入完整）
- 缺失项清单（当状态为BLOCKED时）
- 后续步骤执行状态

## 流程节点
1. 读取任务工作流定义，识别所有必填输入参数
2. 检查用户是否明确提供了每个必填参数
3. 对于未提供的参数，检查是否可以从公开数据库自动获取
4. 如果参数缺失且无法自动获取，标记任务为BLOCKED状态
5. 生成缺失项清单并写入task_state.json
6. 停止执行后续步骤，直到用户提供缺失参数

## 关键参数
| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 必填输入类型 | 材料结构CIF/POSCAR、电池工况参数、电解液/对电极信息 | workflow定义 | 不同任务可能有不同必填参数 |
| 自动获取数据库 | Materials Project、ICSD | 公开数据库 | 当用户未提供时可尝试自动获取 |
| BLOCKED状态标记 | task_state.json | 系统生成 | 必须明确记录BLOCKED状态和缺失项 |
| 缺失项清单格式 | JSON数组 | 系统生成 | 包含参数名称、描述、获取建议 |

## 边界与分流
- 当用户明确提供所有必填参数时，任务继续执行
- 当参数缺失但可从公开数据库自动获取时，系统可自动获取并继续
- 当参数缺失且无法自动获取时，必须标记BLOCKED并请求用户补充
- 不得自行假设参数值或使用典型值替代真实数据
- BLOCKED状态必须阻断所有后续步骤的执行

## 质量检查
- 检查task_state.json中是否包含BLOCKED状态记录
- 验证缺失项清单是否完整列出所有缺失参数
- 确认后续步骤是否因BLOCKED状态而未执行
- 验证系统未生成基于假设数据的产物

## 回退策略
- 如果系统错误地标记了BLOCKED状态，可重新检查用户输入
- 如果用户后续提供了缺失参数，可解除BLOCKED状态并继续执行
- 如果公开数据库获取失败，可请求用户提供参数

## 资源召回建议
- 当需要验证材料结构数据来源时，召回Materials Project或ICSD相关知识
- 当需要检查电池工况参数完整性时，召回电池建模相关知识
- 当需要验证数据可追溯性时，召回数据溯源相关知识
