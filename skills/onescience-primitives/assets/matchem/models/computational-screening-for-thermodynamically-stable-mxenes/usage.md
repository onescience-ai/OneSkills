# launch
该工作流不是单个命令，而是通过脚本驱动的批量DFT投递。典型启动方法是：用Python脚本根据29金属×11终止的组合为每个候选生成工作目录，并写入POSCAR、INCAR、POTCAR、KPOINTS；随后通过SLURM/PBS批量投递命令（如sbatch job.sh）把每个任务提交给集群；待所有驰豫结束后，再运行凸包分析脚本读取能量并输出排序结果。源论文未提供可直接执行的脚本，因此需要使用者按本机调度器编写队列模板；建议先做规模5~10个候选的试运行以验证流程，再扩大到完整筛选。

# input_schema
运行时输入由两类组成：一类是每个候选MXene自洽计算所需的结构/参数文件，包括POSCAR、POTCAR、INCAR、KPOINTS；另一类是批量任务清单CSV/JSON，每行至少记录化学式、目录路径和表面终止类型。对于凸包步骤，输入还包括所涉及元素的参考相能量，可由Materials Project接口自动下载，或使用本地计算出的能量文件。若直接承接论文的998个稳定名单，输入可缩小到该名单中的组成ID，无需重新枚举全空间。

# runtime_interfaces
运行期主要接口是文件系统和命令行。DFT代码从POSCAR读取原子结构，从INCAR读取控制参数，从KPOINTS读取k网格，运行后输出OUTCAR、CONTCAR、OSZICAR等文件；脚本可以定期检查OUTCAR是否出现收敛标记。Python侧使用pymatgen的Vasprun或OUTCAR解析器提取最后一步能量，并把结构与能量对象存为Python字典或JSON供后续凸包计算。与调度系统的接口通过job array完成：每个作业索引对应一个候选目录，避免几百个任务长期占用交互终端。

# main_functions
核心功能包括：结构生成函数（从M、X、T组合构建原子模型并添加真空层）、DFT优化/能量函数（调用外部VASP/QE完成结构弛豫并返回总能量）、凸包构建函数（读取所有产物和参考相能量，构建能量凸包）、稳定性评价函数（调用PhaseDiagram.abs_hull_distance求每个候选到凸包的垂直距离）。论文自述采用DFT计算能量凸包距离作为描述符，因此上述流程函数的最终返回值就是hull distance和稳定/亚稳定的二元标签。在实际代码中，可封装一个process_mxene_entry(entry)函数将这几步连接起来。

# execution_resources
执行环境需要一台可并行运行DFT的计算集群。单个结构优化节点建议分配32~64个CPU核（依体系大小和DFT软件而定），内存每节点16~64 GB；整个筛选的作业数目为数百到数千个，完成全部扫描需要在数百核以上的集群运行数周，或在千核集群上以数十小时量级完成。磁盘方面每个任务通常需要几个GB的临时文件；不建议保存大体积WAVECAR，以节约存储。软件环境包括DFT代码、Python、pymatgen/ASE、Materials Project数据库访问库；论文并未公开其具体机时和设备，因此基础设施由使用者自己估算。

# operation_limits
方法的操作边界集中在新结构可行性阶段：它只能回答热力学是否倾向分解，不能回答盐酸刻蚀或路易斯酸熔盐刻蚀是否真的能把该MXene剥离出来。由于论文覆盖11种表面终止但未见系统覆盖混合终止，实际要研究真实混合基团时，计算需额外枚举覆盖率，可能会让任务量倍增。批处理任务需要设定自动重试、能量突变检查（如原子跑飞）和结构合理性复核，防止单一失败拖慢全流程。若只做粗筛，可将任务限制在29金属×11终止的代表性子集，并固定用论文总结出的稳定终止规则来缩小搜索。
