# OneScience任务完成标准定义

## 适用范围

**触发条件**：
- 需要定义OneScience任务的完成标准
- 需要判定任务执行状态
- 需要检查任务交付物

**适用场景**：
- DFT计算任务的完成标准定义
- 数据分析任务的完成标准定义
- 工作流执行任务的完成标准定义
- 多步骤科研任务的完成标准定义

**不适用场景**：
- 实时监控任务（需要实时更新）
- 实验任务（需要不同标准）
- 非OneScience框架任务（需要自定义标准）

## 输入

**必要输入**：
- 任务定义和目标
- 质量门禁标准
- 交付物清单

**可选输入**：
- 任务执行日志
- 中间产物验证结果
- 资源使用情况

**数据要求**：
- 任务定义明确，目标清晰
- 质量门禁标准具体，可验证
- 交付物清单完整，无遗漏

## 输出

**主要输出**：
- 任务执行状态（completed/partial/failed）
- 质量门禁状态（PASS/PARTIAL/BLOCKED/FAILED）
- 交付物验证结果
- 状态判定依据

**验证标准**：
- 执行状态正确，无遗漏
- 质量门禁状态正确，无误导
- 交付物验证基于实际数据

## 流程节点

### Step 1：任务定义验证
- **操作**：验证任务定义和目标的完整性
- **参数**：任务目标、约束条件、交付物要求
- **工具**：任务定义检查脚本
- **质量门禁**：任务定义明确，目标清晰
- **验证点**：
  1. 任务目标明确，可量化
  2. 约束条件具体，可执行
  3. 交付物要求完整，无遗漏
  4. 质量门禁标准明确，可验证

### Step 2：必需交付物检查
- **操作**：检查所有必需交付物是否存在
- **参数**：交付物清单、交付物状态
- **工具**：交付物检查脚本
- **质量门禁**：所有必需交付物存在且有效
- **必需交付物**：
  1. 计算结果数据（如吸附能、自由能等）
  2. 分析报告（如选择性排序、自由能图等）
  3. 质量门禁状态报告
  4. 执行状态报告

### Step 3：质量门禁通过检查
- **操作**：检查所有质量门禁是否通过
- **参数**：质量门禁标准、验证结果
- **工具**：质量门禁检查脚本
- **质量门禁**：所有质量门禁通过或用户确认接受PARTIAL
- **检查点**：
  1. 数据完整性门禁
  2. 数据一致性门禁
  3. 计算收敛门禁
  4. 结果有效性门禁

### Step 4：执行状态判定
- **操作**：根据交付物和质量门禁状态判定执行状态
- **参数**：交付物状态、质量门禁状态、任务目标
- **工具**：状态判定脚本
- **质量门禁**：执行状态判定正确，无遗漏
- **状态定义**：
  1. completed：所有必需步骤执行完毕，质量门禁全部PASS
  2. partial：部分步骤执行完毕，质量门禁部分PASS（用户确认接受）
  3. failed：任务失败，质量门禁FAIL或BLOCKED

### Step 5：状态一致性检查
- **操作**：检查执行状态与质量门禁状态的一致性
- **参数**：执行状态、质量门禁状态、一致性规则
- **工具**：一致性检查脚本
- **质量门禁**：执行状态与质量门禁状态一致，无矛盾
- **一致性规则**：
  1. 如果execution_status为completed，则所有quality_gates必须为PASS
  2. 如果execution_status为partial，则至少有一个quality_gates为PARTIAL，且用户确认接受
  3. 如果execution_status为failed，则至少有一个quality_gates为BLOCKED或FAILED

### Step 6：状态报告生成
- **操作**：生成任务完成状态报告
- **参数**：状态详情、验证结果、改进建议
- **工具**：报告生成脚本
- **质量门禁**：报告完整，状态明确
- **报告要素**：
  1. 任务摘要
  2. 交付物状态
  3. 质量门禁状态
  4. 执行状态
  5. 状态一致性验证
  6. 改进建议

## 关键参数

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 交付物完整性 | 100%存在 | [1] | 所有必需交付物必须存在 |
| 质量门禁通过率 | 100%或用户确认 | [1] | 所有门禁必须通过或用户接受PARTIAL |
| 状态一致性 | 100%一致 | [2] | 执行状态与门禁状态必须一致 |
| 报告完整性 | 100%完整 | [2] | 所有必需部分必须存在 |
| 状态判定准确性 | 100%准确 | [3] | 状态判定必须基于实际数据 |

## 边界与分流

**异常处理**：
- 交付物缺失 → 标记为BLOCKED，不通过完成标准
- 质量门禁失败 → 标记为PARTIAL或BLOCKED，不通过完成标准
- 状态不一致 → 重新判定状态，确保一致性
- 报告不完整 → 补充缺失信息

**降级策略**：
- 部分交付物缺失 → 标记为PARTIAL，不通过完成标准
- 质量门禁部分失败 → 标记为PARTIAL，不通过完成标准
- 状态判定不确定 → 标记为PARTIAL，等待用户确认

## 质量检查

**验证点**：
1. 任务定义验证：任务定义明确，目标清晰
2. 交付物检查：所有必需交付物存在且有效
3. 质量门禁检查：所有质量门禁通过或用户确认接受PARTIAL
4. 执行状态判定：执行状态判定正确，无遗漏
5. 状态一致性：执行状态与质量门禁状态一致，无矛盾

**失败处理**：
- 验证点失败 → 标记为BLOCKED，不通过完成标准
- 状态判定错误 → 重新判定，确保正确
- 报告不完整 → 补充缺失信息

## 回退策略

**替代方案**：
1. 使用文献数据替代计算数据
2. 采用简化验证（仅检查关键交付物）
3. 降级为人工检查
4. 使用保守状态判定（标记为BLOCKED）
