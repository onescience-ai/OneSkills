# 执行阻塞异常处理策略

## 适用范围
本卡片提供执行阻塞后的异常处理策略，适用于材料计算、模拟任务中的阻塞场景。触发条件：任务执行过程中因数据缺失、配置错误或资源不足而阻塞。不适用场景：正常的任务完成状态、用户主动取消的任务。

## 输入
- **阻塞信息**：阻塞步骤、阻塞原因、错误信息。
- **任务上下文**：任务目标、当前进度、已生成产物。
- **可用资源**：用户数据、公开数据库、计算资源。

## 输出
- **处理建议**：针对阻塞原因的具体处理方案。
- **恢复流程**：从阻塞点恢复执行的步骤。
- **用户交互**：需要用户确认或提供的输入。

## 流程节点
1. **阻塞识别**：检测任务阻塞，记录阻塞信息。
2. **原因分类**：分析阻塞原因，分类为数据缺失、配置错误或资源不足。
3. **处理方案生成**：根据阻塞类型生成相应处理方案。
4. **用户交互**：向用户请求必要输入或确认。
5. **恢复执行**：从阻塞点恢复任务执行。

## 关键参数
| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 阻塞类型分类 | 数据缺失、配置错误、资源不足 | [领域通用] | 三种主要阻塞类型 |
| 数据缺失处理 | 请求用户上传、搜索公开数据集 | [领域通用] | 优先尝试公开数据源 |
| 配置错误处理 | 检查参数、调整配置、请求用户确认 | [领域通用] | 验证配置正确性 |
| 资源不足处理 | 申请资源、降低需求、调整方案 | [领域通用] | 优化资源使用 |
| 恢复策略 | 从阻塞点重试、跳过非关键步骤 | [领域通用] | 最小化重复工作 |

## 边界与分流
- **数据缺失**：如果公开数据库中无所需数据，需请求用户上传或自行进行第一性原理计算。
- **配置错误**：检查参数设置，验证配置文件格式，请求用户确认。
- **资源不足**：申请更多计算资源，或调整任务规模以适应现有资源。
- **未知阻塞**：记录详细信息，请求用户协助诊断。

## 质量检查
- 阻塞原因识别准确率。
- 处理方案有效性。
- 恢复执行成功率。
- 用户满意度。

## 回退策略
- 自动恢复失败：请求用户手动干预。
- 公开数据不可用：尝试其他数据源或用户上传。
- 配置调整无效：回退到默认配置或请求用户协助。

## 资源召回建议
- 何时应召回本卡片：当任务执行阻塞需要异常处理时。
- 配套资源：数据获取、配置管理、资源申请相关卡片。
