# matchem域BLOCKED触发规则

## 适用范围
本工作流规划卡适用于所有涉及必填输入验证的科研计算任务。当任务执行过程中检测到必填输入缺失时，必须按照本规则标记BLOCKED状态并执行处置流程。适用于材料科学、化学、生物信息学等所有需要输入验证的领域。

## 输入验证规则

### 必填输入定义
以下输入被定义为必填项，缺失时必须触发BLOCKED：

| 输入类别 | 具体项 | 缺失后果 | 来源 |
|----------|--------|----------|------|
| 结构数据 | CIF/POSCAR文件 | 无法进行结构分析 | [1] |
| 成分信息 | 元素种类、化学计量比 | 无法建立搜索空间 | [1] |
| 工况参数 | 压力、温度、电荷态 | 无法定义计算条件 | [1] |
| 数据来源 | Materials Project API key | 无法下载训练数据 | [1] |
| 计算资源 | GPU/内存配置 | 无法执行计算任务 | - |

### BLOCKED触发条件
1. **必填输入完全缺失**：关键文件或参数不存在
2. **输入格式无效**：文件损坏、格式不兼容
3. **输入值超出范围**：如压力为负值、元素不在模型覆盖范围内
4. **外部依赖不可用**：API服务不可达、许可证过期

## BLOCKED处置流程

### 步骤1：立即标记
```json
{
  "status": "BLOCKED",
  "blocked_reason": "<具体缺失项描述>",
  "missing_items": ["<缺失项1>", "<缺失项2>"],
  "timestamp": "<ISO时间戳>"
}
```

### 步骤2：停止后续依赖
- 立即停止所有依赖缺失输入的后续步骤
- 不得继续执行或生成模拟数据
- 在Task State中记录BLOCKED状态

### 步骤3：请求用户补充
- 向用户明确说明缺失项
- 提供补充方式（如API key获取链接）
- 等待用户响应后再继续

### 步骤4：记录审计信息
- 记录BLOCKED触发时间和原因
- 记录用户响应和补充内容
- 保留完整的输入验证日志

## PARTIAL与BLOCKED适用边界

### 使用PARTIAL的场景
- **部分完成但有效**：输入不完整但核心功能可执行
- **可降级执行**：缺少可选输入，但必填输入完整
- **部分验证通过**：输入部分有效，其余待确认

### 使用BLOCKED的场景
- **必填输入缺失**：核心功能无法执行
- **数据不可用**：训练数据、预训练权重等无法获取
- **外部依赖失败**：API服务不可达、许可证问题

### 禁止事项
- **禁止使用模拟数据替代**：不得因输入缺失而使用随机或模拟数据
- **禁止将BLOCKED降级为PARTIAL**：必填输入缺失时必须标记BLOCKED
- **禁止跳过验证**：不得绕过输入验证直接执行

## 质量检查
- **输入完整性检查**：所有必填项是否提供
- **输入有效性检查**：格式、范围、兼容性
- **依赖可用性检查**：外部服务、API、许可证
- **审计完整性检查**：BLOCKED记录是否完整

## 资源召回建议
- **召回时机**：当任务涉及输入验证、数据完整性检查、BLOCKED状态管理时
- **配套资源**：
  - 任务卡：所有需要输入验证的任务卡
  - 场景卡：所有包含BLOCKED条件的场景卡
  - 工作流卡：所有包含输入验证步骤的工作流卡
