# onescience-research-workflow专家技能触发条件

## 适用范围

**触发条件**：
- orchestrator需要为科研任务生成工作流规划
- 用户任务涉及复杂的多步骤科研流程
- 需要领域专家知识进行工作流设计

**适用场景**：
- 材料发现任务的工作流规划
- 论文复现任务的工作流设计
- 多学科交叉研究的任务编排
- 需要自动化工作流生成的科研项目

**不适用场景**：
- 简单的单步骤任务（直接执行即可）
- 用户已明确指定工作流的场景
- 缺少必要任务上下文的场景

## 输入

**必要输入**：
- task_state：任务状态对象，包含研究目标、约束、资源
- intent_profile：意图配置文件，描述用户意图的各个方面
- available_resource_summaries：可用资源摘要列表

**可选输入**：
- 关联论文信息（DOI、摘要、关键发现）
- 历史任务执行记录
- 用户特定约束或偏好

## 输出

**主要输出**：
- planner_proposal：工作流规划提案
- workflow_nodes：工作流节点列表
- dependencies：节点间依赖关系
- resource_bindings：资源绑定建议

**验证标准**：
- 提案包含完整的工作流节点
- 依赖关系合理（无循环依赖）
- 资源绑定可行（可用资源满足需求）
- 质量门禁明确（每个节点有验收标准）

## 流程节点

### Step 1：触发条件检查

**操作**：检查是否满足专家技能触发条件
- **intent_profile检查**：确认需要工作流规划
- **resource检查**：确认有足够资源执行任务
- **context检查**：确认任务上下文完整

**参数**：
- 触发关键词：规划、工作流、流程、步骤、方案
- 资源阈值：至少有1个执行技能可用
- 上下文完整度：核心字段非空

**质量门禁**：
- 触发条件明确
- 资源可用性确认
- 上下文完整性验证

### Step 2：输入格式验证

**操作**：验证输入参数的格式和内容
- **task_state验证**：检查必需字段
- **intent_profile验证**：检查意图描述
- **resource验证**：检查资源可用性

**参数**：
- 必需字段：user_goal, constraints, relevant_artifacts
- 意图字段：domain, task_type, complexity_level
- 资源字段：available_skills, compute_resources

**质量门禁**：
- 字段完整性
- 数据类型正确性
- 逻辑一致性

### Step 3：领域识别与规划

**操作**：识别任务领域并生成工作流规划
- **领域检测**：根据任务描述识别领域（matchem/bio/climate/cfd）
- **节点设计**：设计工作流节点（数据获取、模型训练、验证等）
- **依赖关系**：确定节点间执行顺序

**参数**：
- 领域关键词：材料、分子、晶体、催化等
- 节点类型：数据处理、模型训练、验证、可视化
- 依赖类型：数据依赖、资源依赖、时间依赖

**质量门禁**：
- 领域识别准确
- 节点设计合理
- 依赖关系正确

### Step 4：planner_proposal生成

**操作**：生成完整的工作流规划提案
- **节点详情**：每个节点的输入、输出、参数
- **资源绑定**：每个节点需要的技能和资源
- **质量门禁**：每个节点的验收标准

**参数**：
- 节点数量：3-10个
- 资源绑定：基于可用资源
- 质量标准：可测量的验收标准

**质量门禁**：
- 提案完整性
- 资源可行性
- 质量门禁明确

### Step 5：异常处理与降级

**操作**：处理规划过程中的异常情况
- **输入不完整**：请求补充信息
- **资源不足**：建议替代方案
- **规划失败**：降级为direct_step模式

**参数**：
- 重试次数：最多3次
- 降级条件：连续失败或资源不足
- 降级策略：直接执行或部分规划

**质量门禁**：
- 异常处理合理
- 降级策略可行
- 用户通知及时

## 边界与分流

**异常处理**：
- 输入不完整 → 请求用户补充缺失信息
- 资源不足 → 建议替代方案或降低任务复杂度
- 领域识别失败 → 使用通用工作流模板
- 规划超时 → 降级为direct_step模式

**降级策略**：
- 完整规划不可用 → 生成部分规划（核心节点）
- 领域专家不可用 → 使用通用工作流模板
- 资源绑定失败 → 使用默认资源配置
- 质量门禁不可用 → 使用基本验收标准

## 质量检查

**验证点**：
1. 触发条件明确：intent_profile正确解析
2. 输入格式正确：所有必需字段存在
3. 领域识别准确：任务领域与规划一致
4. 节点设计合理：工作流逻辑正确
5. 资源绑定可行：可用资源满足需求
6. 质量门禁明确：验收标准可测量

**失败处理**：
- 触发条件不满足 → 不调用专家技能，使用direct_step
- 输入验证失败 → 请求用户修正输入
- 领域识别错误 → 使用通用工作流或请求用户确认
- 规划生成失败 → 降级为direct_step模式

## 回退策略

**替代方案**：
1. 使用orchestrator内置的direct_step模式
2. 使用通用工作流模板
3. 请求用户手动设计工作流
4. 使用其他专家技能（如onescience-data-profile）
