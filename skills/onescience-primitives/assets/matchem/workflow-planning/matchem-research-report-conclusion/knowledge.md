# 科研报告结论生成规范

## 适用范围

**触发条件**：
- 需要生成科研报告的结论部分
- 需要确保结论与数据一致
- 需要标记未完成项和部分完成项

**适用场景**：
- DFT计算报告的结论生成
- 实验报告的结论总结
- 数据分析报告的结论提取
- 多步骤工作流的结论整合

**不适用场景**：
- 仅生成数据表格（不需要结论）
- 仅进行数据分析（不需要报告）
- 实时监控报告（需要实时更新）

## 输入

**必要输入**：
- 原始数据或计算结果
- 报告模板或格式要求
- 数据验证结果

**可选输入**：
- 文献参考数据
- 对比分析结果
- 质量门禁状态

**数据要求**：
- 原始数据完整，无缺失
- 数据验证通过，无异常
- 质量门禁状态明确

## 输出

**主要输出**：
- 结论文本（基于数据支撑）
- 未完成项标记（BLOCKED/PARTIAL状态）
- 数据一致性验证结果
- 报告质量门禁状态

**验证标准**：
- 结论有数据支撑，无主观臆断
- 结论与原始数据一致，无矛盾
- 未完成项明确标记，无误导

## 流程节点

### Step 1：数据验证
- **操作**：验证原始数据的完整性和正确性
- **参数**：数据完整性、数据类型、数据范围
- **工具**：数据验证脚本、格式检查工具
- **质量门禁**：数据完整且格式正确
- **验证点**：
  1. 所有必需数据字段存在
  2. 数据类型正确（数值、字符串、布尔值）
  3. 数据值在合理范围
  4. 无重复或异常数据

### Step 2：数据一致性检查
- **操作**：检查结论与原始数据的一致性
- **参数**：结论声明、数据支撑、逻辑关系
- **工具**：一致性检查脚本
- **质量门禁**：结论与数据一致，无矛盾
- **检查点**：
  1. 结论中的数值与数据一致
  2. 结论中的趋势与数据一致
  3. 结论中的比较与数据一致
  4. 无数据不支撑的结论

### Step 3：未完成项识别
- **操作**：识别报告中的未完成项和部分完成项
- **参数**：任务状态、质量门禁状态、交付物状态
- **工具**：状态检查脚本
- **质量门禁**：未完成项明确标记，无误导
- **状态定义**：
  1. COMPLETED：任务完成，数据有效
  2. PARTIAL：部分完成，数据有效但不完整
  3. BLOCKED：任务被阻塞，无法执行
  4. FAILED：任务失败，数据无效

### Step 4：结论生成
- **操作**：基于数据生成结论
- **参数**：数据支撑、逻辑推理、表达规范
- **工具**：结论生成模板
- **质量门禁**：结论有数据支撑，无主观臆断
- **生成原则**：
  1. 结论必须有数据支撑
  2. 结论不能与原始数据矛盾
  3. 未完成项需明确标记
  4. 使用客观、准确的表述

### Step 5：质量门禁检查
- **操作**：检查报告的质量门禁状态
- **参数**：质量门禁标准、验证结果
- **工具**：质量门禁检查脚本
- **质量门禁**：所有门禁状态正确，无遗漏
- **检查点**：
  1. 数据完整性门禁
  2. 数据一致性门禁
  3. 未完成项标记门禁
  4. 结论支撑门禁

### Step 6：报告整合
- **操作**：整合所有部分生成完整报告
- **参数**：报告模板、各部分内容
- **工具**：报告生成脚本
- **质量门禁**：报告完整，格式正确
- **整合要素**：
  1. 摘要
  2. 方法
  3. 结果
  4. 讨论
  5. 结论

## 关键参数

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 结论支撑标准 | 100%数据支撑 | [1] | 无数据支撑的结论不得出现 |
| 数据一致性标准 | 100%一致 | [1] | 结论与数据不能矛盾 |
| 未完成项标记 | 必须标记 | [2] | 未完成项需明确说明 |
| 质量门禁状态 | 必须正确 | [2] | 不能将BLOCKED标记为PARTIAL |
| 报告完整性 | 100%完整 | [3] | 所有必需部分必须存在 |
| 客观性要求 | 无主观臆断 | [1] | 结论必须基于数据 |

## 边界与分流

**异常处理**：
- 数据缺失 → 在结论中明确说明数据缺失
- 数据异常 → 在结论中说明数据异常，不给出结论
- 结论与数据矛盾 → 修改结论或重新分析数据
- 质量门禁失败 → 修复问题或标记为BLOCKED

**降级策略**：
- 数据不足 → 仅给出数据支撑的结论
- 质量门禁失败 → 标记为PARTIAL或BLOCKED
- 报告不完整 → 标记缺失部分

## 质量检查

**验证点**：
1. 数据完整性：所有必需数据字段存在
2. 数据一致性：结论与数据一致，无矛盾
3. 未完成项标记：未完成项明确标记，无误导
4. 结论支撑：结论有数据支撑，无主观臆断
5. 质量门禁：所有门禁状态正确

**失败处理**：
- 数据缺失 → 标记为BLOCKED，不给出结论
- 数据异常 → 标记为PARTIAL，说明异常情况
- 结论矛盾 → 修改结论或重新分析
- 门禁失败 → 修复问题或标记状态

## 回退策略

**替代方案**：
1. 使用文献数据支撑结论
2. 采用简化模型（如仅考虑关键数据）
3. 降级为数据展示（不给出结论）
4. 使用保守表述（避免过度推断）
