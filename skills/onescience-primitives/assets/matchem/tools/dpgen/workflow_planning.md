# description

DP-GEN 原语用于规划基于主动学习（Active Learning / Concurrent Learning）策略自动构建 Deep Potential 势函数训练数据的工作流。当任务目标是为特定材料体系从少量初始数据出发、自动化构建覆盖目标相空间的高质量 MLIP 训练数据集时，DP-GEN 是核心编排引擎。规划重点不仅是配置文件参数，更需通盘考虑初始数据质量、探索策略范围、trust level 校准和 HPC 资源分配。

DP-GEN 的核心定位是 **MLIP 数据生成工作流编排引擎**——它将训练（DeePMD-kit）、探索（LAMMPS）和标注（VASP/CP2K 等 DFT 软件）三个独立环节串联为闭环迭代，实现"端到端"势函数开发。

# when_to_use

## 优先使用 DP-GEN 的场景

### 1. 从零构建 MLIP 训练数据集
- 目标体系缺少现成的 DFT 训练数据，只有少量 AIMD 初始构型（100–500 帧）
- 需要通过主动学习自动探索构型空间并扩大数据集到 10^3–10^4 级别
- 体系元素 ≤ 5 种，原子数 ≤ 200（控制 DFT 计算成本在可行范围内）

### 2. 扩展已有数据集的覆盖范围
- 已有部分 DFT 标注数据，但覆盖的温度/压力/相空间不够
- 需要在特定热力学条件下补充训练数据以提高势函数精度
- DP-GEN 支持在已有训练集基础上直接启动后续迭代

### 3. 多相/多组分体系统一势函数
- 需要构建可同时描述固相、液相、高压相等多个相的势函数
- 通过配置多个探索体系（`sys_configs`）、多组温度和压力，同时覆盖不同相空间

### 4. 势函数质量系统性评估
- 需要通过 Model Deviation 分析势函数在不同热力学条件下的预测不确定性
- DP-GEN 每轮迭代的 model deviation 输出可作为势函数质量的定量指标

### 5. HPC 环境下的自动化势函数开发
- 已有可用的 HPC 集群（Slurm/PBS/LSF），需要自动化提交和管理大量 DFT 计算任务
- DP-GEN 的并发任务管理能力可将多轮计算串行化、并行化高效执行

## 不适用场景及替代方案

| 场景 | 不适用的原因 | 推荐替代方案 |
|------|-------------|-------------|
| **数据量已充足（10^4+ 构型）** | 主动学习的收益递减，直接单次训练效率更高 | 直接用 DeePMD-kit 一次性训练最终模型 |
| **体系原子数过大（>300 atoms）** | 导致大量 DFT 任务成本极高，探索需要巨大计算量 | 缩小超胞、使用 E(3) 等变预训练模型（MACE-MP-0、SevenNet）fine-tune、或使用 CP2K 替代 VASP 以降低计算成本 |
| **需要快速生成势函数（<1 天内）** | 主动学习多轮迭代需要数天至数周 | 直接使用通用预训练 MLIP（MACE-MP-0、CHGNet、ORB）评估可用性；若不满足精度，考虑 fine-tuning |
| **元素种类过多（>10 种）** | DFT 计算量与体系复杂度加剧，主动学习成本过高 | 优先使用高熵合金专用预训练模型或 classical potential |
| **反应力场开发（含键断裂/形成）** | DeePMD-kit 的 DP 模型对键断裂的描述需要特殊技巧 | 考虑 ReaxFF 参数化或 MACE/CHGNet 等消息传递式神经网络 |
| **液态/无定形体系的扩散系数预测** | 主动学习的 MD 探索时间可能不足以采样完整扩散事件 | 增加每轮探索的 MD 步数，或使用 enhanced sampling 方法 |
| **无可用 DFT 许可证** | DP-GEN 需要底层 DFT 软件生成标注数据 | 使用公开数据集（Materials Project、AFLOW）中的数据或完全开源的 DFT 软件（如 CP2K、Quantum ESPRESSO） |
| **仅需要粗略的稳定性判断** | 主动学习构建的势函数精度远超需要 | 使用经典力场（EAM、LJ）或通用 MLIP 直接评估 |

# inputs

规划 DP-GEN 工作流需要明确以下输入：

- **体系信息**：化学元素种类与数量、原子质量、典型超胞大小、初始晶体结构（POSCAR 等）
- **初始数据来源**：AIMD 轨迹（VASP/CP2K）或已有 DFT 数据集，预期初始训练数据量（推荐 100–500 帧）
- **目标应用域**：
  - 热力学条件范围：温度范围（K）、压力范围（bar/atm）
  - 相空间覆盖：单相还是多相（固/液/高压相）
  - 物理性质需求：仅能量和力，还是同时需要应力（virial）
- **精度目标**：
  - 能量 RMSE 目标（meV/atom）
  - 力 RMSE 目标（meV/Å）
  - 最终 Model Deviation 收敛标准
- **DFT 设置**：
  - DFT 软件选择（VASP/CP2K/PWmat/PWscf/SIESTA/Gaussian）
  - 泛函类型（PBE/PBEsol/SCAN/HSE06）
  - ENCUT、k 点密度、赝势类型
  - INCAR 核心参数（ISMEAR、SIGMA、EDIFF 等）
- **资源条件**：
  - 可用 GPU 节点数（训练用）
  - 可用 CPU 节点数（MD 探索 + DFT 标注）
  - 调度器类型（Slurm/PBS/LSF）
  - 队列名称、每节点核数、最大并发任务数限制
- **模型架构选择**：descriptor 类型（se_e2_a / se_e3 / se_atten），fitting_net 配置

# outputs

- **param.json**：完整的 DP-GEN 主配置文件，包含体系定义、模型超参数、探索策略、trust levels、DFT 配置
- **machine.json**：完整的资源调度配置文件，三层（train/model_devi/fp）资源规格
- **DFT 模板文件**：INCAR_template / cp2k_input_template / quantum_espresso_input_template 等
- **初始训练数据**：DeePMD-kit system 格式的初始数据集（iter.000/02.fp/）
- **主动学习迭代方案**：预估迭代轮数、每轮预期并发任务数、总机时估算
- **最终模型训练方案**：收集完整数据集后的 DeePMD-kit input.json 和训练策略
- **风险清单**：trust level 设定不当、初始数据不足、探索覆盖不全、SCF 收敛困难、磁盘空间不足

# procedure

## 阶段 1：体系分析与初始数据评估

1. **明确目标体系**：记录元素种类、原子质量、典型超胞大小和晶胞参数
2. **评估初始数据质量**：
   - 检查能量/力/应力的统计分布（最小值、最大值、均值、标准差）
   - 验证构型覆盖的温度范围
   - 检查是否有原子距离过近的异常构型
   - 确认单位系统一致（推荐 eV/Å）
3. **划分初始训练/验证集**：建议 train:valid = 9:1
4. **将初始数据转换为 DeePMD-kit system 格式**（使用 dpdata）

## 阶段 2：配置文件编写

### 2.1 模型超参数设定

- `descriptor` 类型选择：
  - 简单金属（1-2 元素）→ `se_e2_a`
  - 含氢键/方向性键 → `se_e3` 或 `se_atten`
  - 多元素复杂体系 → `se_atten`
- `rcut`：根据键长和分子间相互作用距离确定（4–7 Å），注意后续 LAMMPS neighbor list 设置需匹配
- `sel`：根据最大配位数设定，预留 20–50% 余量（防止探索中遇到密堆积构型时 neighbor 溢出）
- `numb_steps`：主动学习中每轮训练步数可较最终训练少（200,000–400,000 步），因每轮数据量递增、模型只需适配新数据

### 2.2 Trust Level 校准

Trust level 是 DP-GEN 最关键的参数，直接影响主动学习的效率和最终数据质量。

**力偏差 trust level 校准方法**：
1. 先用较宽松的初始值（如 f_trust_lo=0.05, f_trust_hi=1.0）运行 2-3 轮
2. 检查每轮候选中选构型的 σ_max 分布
3. 如果大量构型集中在低值区（模型偏差收敛快），可降低 f_trust_lo
4. 如果候选中选率过低（<5%），可提高 f_trust_lo 或降低 f_trust_hi
5. 如果出现物理不合理的构型被选中（如原子距离过近），降低 f_trust_hi

**参考校准表**（基于化学键强度）：

| 体系类型 | 典型键能 (eV) | f_trust_lo (eV/Å) | f_trust_hi (eV/Å) | 说明 |
|---------|-------------|-------------------|-------------------|------|
| 惰性气体 (Ar, Xe) | ~0.01 | 0.01–0.03 | 0.10–0.30 | 极弱范德华力 |
| 简单金属 (Al, Cu, Au) | 1–3 | 0.05–0.10 | 0.50–1.00 | 金属键，无方向性 |
| 离子晶体 (NaCl, MgO) | 3–5 | 0.05–0.15 | 0.50–1.50 | 中等强度 |
| 半导体 (Si, Ge, GaAs) | 2–4 | 0.10–0.20 | 1.00–2.00 | 共价键，方向性强 |
| 有机分子/水 | 3–5 (分子内) | 0.10–0.20 | 1.00–2.00 | 分子内共价 + 分子间弱相互作用 |
| 高压相 (金刚石等) | 5–7 | 0.20–0.40 | 2.00–5.00 | 高压导致更大原子力 |

### 2.3 探索策略设计

- **温度范围**：覆盖目标应用的全部操作温度 + 适当外扩（如目标 300–1000 K → 设定 100–1200 K）
- **压力范围**：根据是否需要应力训练决定是否包含压控。对于低温低压应用（如电池电极），NVT 可能足够
- **探索步数**：单轮 MD 步数建议 2000–10000 步，步长 0.5–2.0 fs。步数太少可能无法充分探索，太多会降低效率
- **输出频率**（trj_freq）：建议每 10–50 步输出一个构型。过密会导致过多构型进入偏差判断、增加不必要的计算

### 2.4 DFT 标注配置

- `fp_style`：根据已有软件资源、体系规模和精度需求选择
  - VASP：最成熟，PAW 赝势库完备，适用于 10–200 原子体系
  - CP2K：混合基组，适用于大体系（>200 原子）、液态/无定形体系
  - PWmat：GPU 加速 DFT，速度快但精度依赖设置
  - Quantum ESPRESSO：开源，适用于周期性晶体
- `fp_task_max`：不超过可用 CPU 资源/每任务的核数，通常设为队列并行度限制的 50–80%
- `fp_task_min`：当候选构型低于此值时停止迭代（建议 5–10）

### 2.5 HPC 资源配置

- **训练资源**：GPU 节点，推荐 1 节点 4 GPU 同时训练 4 个 ensemble 模型
- **探索资源**：CPU 节点，使用 `group_size` 参数将多个探索任务打包到一个作业中提交（推荐 group_size=4–8）
- **标注资源**：CPU 节点，每个 DFT 任务独立提交。VASP 推荐每任务 16-64 核
- 三级队列可根据集群配置使用不同队列（gpu 队列用于训练，cpu 队列用于探索和标注）

## 阶段 3：执行与监控

1. **首次启动**：
   ```bash
   dpgen run param.json machine.json
   ```
2. **实时监控**（定期执行）：
   ```bash
   dpgen debug param.json machine.json
   ```
3. **失败任务处理**：
   ```bash
   # 查看失败详情
   dpgen debug param.json machine.json --task failed
   # 修正问题后续传
   dpgen run param.json machine.json --restart
   ```
4. **关键监控指标**：
   - 每轮标注构型数（应呈递减趋势，随模型精度提高而减少）
   - Model deviation 分布（σ_max 峰值应逐渐左移）
   - 训练 loss 曲线（lcurve.out 应稳定下降）
   - DFT 任务成功率（应 >90%，频繁失败可能暗示 trust level 过高导致不合理构型被选中）

## 阶段 4：终止判断与数据收集

主动学习的终止条件（满足任一即终止）：
1. **Model Deviation 收敛**：当前轮次所有探索轨迹中的所有候选构型的 σ_max 均低于 `model_devi_f_trust_lo`（即没有构型需要标注）
2. **候选构型数不足**：当前轮次被选中的候选构型数低于 `fp_task_min`
3. **达到预设最大迭代轮数**（通常在 param.json 中设置，如 `max_iters: 50`）

终止后执行：
```bash
dpgen collect param.json machine.json
```
收集所有轮次数据集到 `collect_dir/`。

## 阶段 5：最终模型训练

使用收集的完整数据集进行最终模型训练（与主动学习中每轮训练不同）：
1. 使用 dpdata 加载 `collect_dir/` 中的数据
2. 按 8:1:1 或 9:1 重新划分 train/valid/test
3. 编写 `final_input.json`，设置更大的 `numb_steps`（500,000–2,000,000）和更精细的学习率调度
4. 执行 `dp train final_input.json`
5. 冻结、压缩并部署最终模型

# constraints

- 初始训练数据不能为空，至少需要几十个已标注的 DFT 构型（建议 ≥ 100 帧）
- DP-GEN 的每轮训练默认从头开始，不支持跨轮 fine-tuning（可通过 `training_init_model` 启用 warm-start）
- Ensemble 模型使用相同的超参数（descriptor、fitting_net），仅 seed 不同
- Sys_configs 中多个体系必须使用相同的元素组成（type_map 一致），不能在同一 DP-GEN 运行中训练多组分体系的势函数
- 在 NPT 探索模式下，DP-GEN 自动生成的 LAMMPS 输入使用各向同性压力耦合（iso），如需各向异性耦合需自定义 LAMMPS 模板
- Trust levels 的设置经验依赖性较强，可能需要多轮迭代后根据 model deviation 分布进行动态调优
- VASP 标注时，相同体系的多个标注任务共享相同的 INCAR 设置，无法为每个构型自定义 INCAR
- 跨调度器（不同集群）运行 DP-GEN 需要为每个集群编写独立的 machine.json

# next_phase_recommendation

- **初始数据质量评估**：建立 AIMD 数据质量检查清单，包括能量/力分布、构型间距、原子距离分布等
- **Trust Level 标定**：对于新体系，建议先运行 3-5 轮调查性迭代来校准 trust levels，然后重新从初始数据开始正式运行
- **描述子选型对比**：在同一数据集上对比 se_e2_a vs se_atten 的 model deviation 收敛速度，选择更适合目标体系的描述子
- **探索策略优化**：分析 model deviation 在温度/压力参数空间中的分布，识别需要更多探索的"盲区"，添加针对性探索任务
- **与预训练模型结合**：评估 DPA-3 等预训练模型在目标体系上的初始 model deviation，判断是否可以通过 fine-tuning 加速主动学习
- **数据质量后处理**：收集完整数据集后，使用 outlier detection 方法识别和移除标注异常的数据点
- **部署验证协议**：建立最终模型在 LAMMPS 中的验证标准（NVE 能量漂移、声子色散、弹性常数），确保势函数质量达到预期
- **建立体系模板库**：对常见体系类型（金属、半导体、离子晶体、水溶液）建立 DP-GEN 参数模板库，降低新项目的启动成本

# fallback

- **初始模型训练不收敛**：
  - 检查初始数据质量（是否包含异常构型、单位是否一致）
  - 降低 learning_rate，增大 numb_steps
  - 减小 descriptor/fitting_net 规模，降低参数冗余
  
- **Model Deviation 收敛过慢**（多轮迭代后仍大量构型被选中）：
  - 表示模型容量不足以拟合目标势能面的复杂度
  - 尝试增大 descriptor neuron 数、增大 rcut、切换到 se_atten/se_e3
  - 检查探索的温度/压力范围是否过大（考虑聚焦到更窄的范围）
  
- **Model Deviation 过快收敛但模型精度差**：
  - Trust level 的 lo 值设得太高，导致有信息量的构型被丢弃
  - 降低 f_trust_lo，或从模型偏差分布中更精确地标定阈值
  
- **DFT 标注任务频繁失败（SCF 不收敛）**：
  - 候选构型可能物理上不合理 → 降低 f_trust_hi
  - 调整 INCAR_template 中的算法参数（ALGO、混合方案）
  - 增加 `fp_accurate_soft_threshold` 允许降低精度
  - 启用 `shuffle_poscar: true`，小幅扰动可帮助 SCF 收敛
  
- **磁盘空间不足**：
  - 启用 `model_devi_clean_traj: true` 自动清理 LAMMPS dump 文件
  - 定期运行 `dpgen collect` 并手动清理旧迭代目录的 DFT 输出（保留 OUTCAR 或 vasprun.xml 即可）
  - 归档早期迭代数据到长期存储

- **HPC 队列拥塞导致迭代间隔过长**：
  - 增加 `group_size` 将多个探索/标注任务打包到一个作业
  - 减少 `fp_task_max` 避免队列积压
  - 优化 DFT 资源请求（减少每任务核数，但增加单任务计算时间）

- **探索覆盖范围达不到所需相空间**：
  - 对于相变体系（如固-液相变），温度范围需跨越相变点
  - 对于需要缺陷/界面的势函数，需要在 `sys_configs` 中提供包含目标缺陷的初始结构
  - 考虑使用增强采样技术（如 metadynamics）扩大探索范围

# teaming_with_deepmd_kit

DP-GEN 与 DeePMD-kit 是一对紧密协作的工具：

```
┌─────────────────────────────────────────────────────────────┐
│                    端到端 MLIP 开发流程                       │
│                                                             │
│  ┌────────────┐      ┌──────────────┐      ┌────────────┐  │
│  │ 初始 AIMD   │─────▶│   DP-GEN     │─────▶│ 完整数据集  │  │
│  │ (VASP/CP2K)│      │ 主动学习循环   │      │ (10³-10⁴帧) │  │
│  └────────────┘      └──────┬───────┘      └──────┬─────┘  │
│                              │                      │        │
│                    ┌─────────┼──────────┐           │        │
│                    ▼         ▼          ▼           ▼        │
│              ┌─────────┐ ┌────────┐ ┌──────┐ ┌──────────┐  │
│              │dp train │ │LAMMPS  │ │VASP  │ │dp train  │  │
│              │(训练)    │ │MD探索  │ │DFT标注│ │(最终训练) │  │
│              └─────────┘ └────────┘ └──────┘ └────┬─────┘  │
│                                                    │        │
│                                          ┌─────────┘        │
│                                          ▼                  │
│                                   ┌──────────────┐          │
│                                   │ LAMMPS/ASE   │          │
│                                   │ 生产部署      │          │
│                                   └──────────────┘          │
└─────────────────────────────────────────────────────────────┘
```

**DP-GEN 中 DeePMD-kit 的角色**：
1. 训练（`dp train`）：每轮迭代训练 4 个 ensemble 模型
2. Model Deviation 计算：筛选候选构型的核心指标
3. 最终训练：收集完整数据集后，使用 DeePMD-kit 进行最终高质量模型训练

**DeePMD-kit 中 DP-GEN 的角色**：
- DP-GEN 是 DeePMD-kit 获取高质量训练数据的"上游"工具
- DeePMD-kit 的工作流规划中提及的 model deviation 方法、ensemble 训练策略、主动学习方案，在 DP-GEN 中得到了完整的工程化实现
