# 原语资源库构建方法

## 适用范围
本方法适用于构建任何科学领域的原语资源库，包括模型、工作流、任务、数据集等原语资产的创建、组织和管理。目标是建立可被OneSkills体系召回和使用的知识资产库。

## 输入
- **领域知识**：目标领域的核心概念、方法和工具。
- **任务需求**：需要支持的科研任务类型。
- **现有资源**：已有的原语资产或参考材料。
- **用户反馈**：从实际任务执行中收集的经验和教训。

## 输出
- **原语资产包**：包含metadata.json和knowledge.md的标准化卡片。
- **目录结构**：按领域和类型组织的资产目录。
- **元数据索引**：可被检索和召回的元数据。
- **使用文档**：原语资产的使用说明和示例。

## 流程节点
1. **需求分析**：识别领域知识缺口和任务需求。
2. **资产规划**：确定需要创建的原语类型和数量。
3. **内容抽取**：从论文、文档或经验中抽取关键知识。
4. **格式标准化**：按照OneSkills规范格式化metadata和knowledge。
5. **质量验证**：检查资产的完整性、准确性和可召回性。
6. **入库管理**：将资产写入文件系统并更新索引。

## 关键参数
| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 资产类型 | model, workflow, task, dataset等 | [用户自有] | 按需选择 |
| 目录结构 | skills/onescience-primitives/assets/<domain>/<category>/ | [用户自有] | 标准路径 |
| 元数据格式 | metadata.json标准9字段 | [用户自有] | 必须包含 |
| 知识格式 | knowledge.md推荐章节 | [用户自有] | 至少5个章节 |
| 质量门禁 | 完整性、准确性、可召回性 | [用户自有] | 必须通过 |

## 边界与分流
- 当领域知识不足时，应先进行文献检索或经验收集，再创建资产。
- 当资产类型不确定时，应默认创建task类型资产。
- 当资产内容冲突时，应进行证据分级和冲突裁决。

## 质量检查
- 验证metadata.json格式正确且包含必要字段。
- 检查knowledge.md内容完整且基于可靠证据。
- 确认资产可被OneSkills体系正确召回。

## 回退策略
- 当资产创建失败时，可先创建简化版本，后续迭代完善。
- 当证据不足时，应如实标注"证据有限"，不编造内容。
- 当格式不规范时，应参考现有资产进行修正。

## 资源召回建议
- 当任务涉及原语资源库构建时，应召回本卡片获取构建方法。
- 配套资源：具体领域原语资产（model, workflow, task等）、知识获取工具（harvester）。
