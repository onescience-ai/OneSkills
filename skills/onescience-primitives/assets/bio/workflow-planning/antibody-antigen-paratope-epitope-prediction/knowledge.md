# 抗体抗原结合位点联合预测（B25）

## 适用范围

**适用场景**：
- 输入包含可识别的抗原、抗体或TCR实体及其链/表位信息，目标是免疫结构、特异性、亲和力或候选设计。
- 有独立的结合标签、结构复合物或合理的阴性对照，能够评估类别不平衡和家族外泛化。
- CDR编号、表位坐标、链配对和物种信息可以核验，且目标序列在模型适用域内。
- 结果用于抗体发现、免疫机制研究或实验优先级排序，并保留人工和实验复核环节。

**不适用场景**：
- 链身份、CDR编号或表位标签不可靠，无法建立输入与输出的逐条对应。
- 样本存在严重近重复或同一抗原泄漏，却需要据此宣称跨抗原泛化。
- 任务要求直接判定免疫安全性、临床疗效或感染保护而缺少实验/临床证据。
- 目标包含模型未覆盖的非天然化学修饰或免疫过程，且没有额外验证方案。

## 研究对象与输入

**研究对象**：抗原、抗体/TCR 序列结构、CDR、表位和免疫配对数据

| 输入项 | 说明 |
|---|---|
| 输入文件 | antibody_antigen.fasta |
| 输入模态 | 抗原/抗体 FASTA、PDB/mmCIF、配对表或表位标签文件 |
| 样本单元 | 一个抗原-受体配对、一个表位或一个抗体候选 |
| 标签/条件 | 链类型、CDR 编号、表位、结合/不结合标签、亲和力或功能标签 |
| 模型引用 | came_ab.pt |

**初始结构**：默认输入名称为“antibody_antigen.fasta”；执行者必须核验格式、版本、实体/样本完整性、缺失值和可解析性，并记录实际使用的相对名称或数据标识。

**表面/硬约束**：保持抗原、重链/轻链或TCR链身份，使用可追溯的CDR编号和表位映射；不把预测结合当作中和、免疫原性或临床有效性证明。

**划分策略**：按抗原家族、受体家族、供体和近重复配对进行严格拆分，并报告表位或序列泄漏风险。

**采样要求**：默认保留不少于 20 个候选或完整的配对预测结果，逐条给出编号、链映射、得分、置信度和异常标记。

## 核心科学问题

1. 在抗原、抗体/TCR 序列结构、CDR、表位和免疫配对数据和输入“antibody_antigen.fasta”上，融合序列和结构模态联合定位互补位与表位，适用于抗体机制解释和界面约束生成能否得到可复核的界面AUPRC结果，并满足任务的硬约束？
2. 输入中的链和编号一致性、界面特异性、亲和力/功能排序与可开发性如何影响抗体抗原结合位点联合预测的输出，哪些样本、区域或候选最容易失败？
3. 模型在独立样本、未见家族/条件或困难子集上的表现是否稳定，误差和不确定度如何量化？
4. 结果是否具有足够的生物学、化学或临床证据支持后续决策，哪些部分只能作为探索性线索？
5. 在当前数据、模型和资源边界下，哪些结论可以签收，哪些结论必须标记为无法回答或需要额外验证？

## 比较与评估

- 主任务：融合序列和结构模态联合定位互补位与表位，适用于抗体机制解释和界面约束生成；核心指标：界面AUPRC。
- 目录模型候选为CAME-AB，需与可解释基线、参考标签或独立质量检查比较。
- 至少按抗原家族、受体家族和阴性对照分别报告性能，不只给总体平均值。
- 比较模型分数与结构/实验标签，并单独审查高分但几何或编号异常的候选。

## 工作流

### 步骤 1：免疫对象与任务定义

**目的**：读取抗体抗原结合位点联合预测所需的抗原、抗体或受体数据。

| 参数 | 变量名 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|---|
| 免疫输入数据 | `{IMMUNE_INPUT}` | doc | 是 | `antibody_antigen.fasta` | 输入序列结构或配对表 |
| 免疫模型 | `{MODEL_NAME}` | enum | 是 | `CAME-AB` | 可选值：`CAME-AB` |
| 任务模式 | `{TASK_MODE}` | enum | 否 | `design` | 可选值：`design`、`prediction`、`ranking` |

**输出**：标准化免疫数据、链与表位映射、任务配置

**质量门禁**：
- 链类型可识别
- 样本标识唯一
- 任务标签定义明确

**操作指令**：`校验{IMMUNE_INPUT}中的链、表位和标签，使用{MODEL_NAME}建立{TASK_MODE}模式的抗体抗原结合位点联合预测任务。`

### 步骤 2：编号与界面特征准备

**目的**：加载权重并构建CDR、表位和界面条件特征。

**依赖步骤**：s01

| 参数 | 变量名 | 类型 | 必填 | 默认值 | 范围 | 说明 |
|---|---|---|---|---|---|---|
| 模型权重 | `{CHECKPOINT}` | doc | 是 | `came_ab.pt` | — | 模型权重名称 |
| 设计CDR区域 | `{CDR_REGIONS}` | list[str] | 否 | ["H1", "H2", "H3"] | — | 选择参与任务的CDR |
| CDR长度上限 | `{MAX_CDR_LENGTH}` | int | 否 | `30` | 3–80 | 限制单段CDR长度 |

**输出**：标准抗体编号、CDR掩码、抗原界面特征

**质量门禁**：
- CDR编号连续
- 长度不超限
- 抗原抗体链映射正确

**操作指令**：`加载{CHECKPOINT}，对{CDR_REGIONS}编号并限制单段长度为{MAX_CDR_LENGTH}，构建界面特征。`

### 步骤 3：免疫预测或候选生成

**目的**：执行任务并产生可重复的得分或设计候选。

**依赖步骤**：s02

| 参数 | 变量名 | 类型 | 必填 | 默认值 | 范围 | 说明 |
|---|---|---|---|---|---|---|
| 候选数量 | `{NUM_CANDIDATES}` | int | 是 | `50` | 1–5000 | 设置候选结果数量 |
| 采样温度 | `{TEMPERATURE}` | float | 否 | `0.3` | 0.01–2 | 控制候选序列多样性 |
| 随机种子 | `{SEED}` | int | 否 | `73` | 0–2147483647 | 固定随机采样结果 |

**输出**：候选序列或配对、模型得分、推理日志

**质量门禁**：
- 候选数量达标
- 序列字符合法
- 得分与样本一一对应

**操作指令**：`运行抗体抗原结合位点联合预测，以温度{TEMPERATURE}和种子{SEED}生成或排序{NUM_CANDIDATES}个候选。`

### 步骤 4：特异性与可开发性质控

**目的**：按界面AUPRC及序列、结构和特异性指标筛选结果。

**依赖步骤**：s03

| 参数 | 变量名 | 类型 | 必填 | 默认值 | 范围 | 说明 |
|---|---|---|---|---|---|---|
| 得分阈值 | `{SCORE_THRESHOLD}` | float | 否 | `0.7` | 0–1 | 设置候选得分下限 |
| 保留数量 | `{TOP_K}` | int | 否 | `20` | 1–500 | 设置最终保留数量 |

**输出**：排序候选、界面AUPRC结果、可开发性报告

**质量门禁**：
- 关键CDR未异常截断
- 低特异候选已标记
- 保留规则可复现

**操作指令**：`计算界面AUPRC和可开发性指标，用{SCORE_THRESHOLD}筛选并保留前{TOP_K}个候选。`

## 验收标准与质量门禁

### 硬约束（不可违反）

- 保持抗原、重链/轻链或TCR链身份，使用可追溯的CDR编号和表位映射；不把预测结合当作中和、免疫原性或临床有效性证明。
- 输入、标签、模型版本、数据划分和实际输出之间的血缘必须可追溯；任何偏离都要记录并经场景确认。
- 不得把平均分数、单个高分样本或模型自评当作生物学、化学或临床事实；正式结论必须有独立证据。
- 历史论文、参考模型和示例文件只能用于方案设计或交叉检查，不能冒充本次任务的新结果。

### 最低证据要求

- 实际研究对象、输入、模型/权重、工具和场景约束与任务书一致，所有偏离均有变更记录。
- 输入、标签/参考数据、版本、筛选规则和训练/评估划分可追溯，泄漏和缺失处理有证据。
- 模型或推理结果有独立于选择过程的界面AUPRC评估、分层统计、最差案例和适用域说明。
- 全量结果、失败样本、异常、拒答或低质量标记均被保存；正式分析只使用质量合格的范围。
- 每个目标结果都有定义、单位/量纲（如适用）、样本量、分析窗口、置信区间或不确定度。
- 比较基线、参考标签或人工复核的口径一致，不能只报告对模型有利的子集。
- 结论明确区分观察、模型误差、标签/采样不确定度、偏差和未验证假设。
- 输出文件、环境、日志、版本和校验信息足以让第三方复核关键数值。

**验收判定**：执行者必须对每个交付项给出 PASS、PARTIAL、REJECT 或 BLOCKED，并附文件、日志、图表或数值证据；没有证据的‘运行正常’或‘效果良好’不能作为签收依据。

## 边界与限制

**本工作流关注**：
- 本任务关注融合序列和结构模态联合定位互补位与表位，适用于抗体机制解释和界面约束生成、链和编号一致性、界面特异性、亲和力/功能排序与可开发性以及界面AUPRC的可复核评估。
- 因果机制、实验功能、临床疗效/安全性或其他超出输入和验证证据的结论不属于默认交付，除非补充方案获得确认。

**不属于默认交付**：
- 场景不要求照抄论文或历史案例的具体命令、软件参数、脚本、目录结构或资源配置。
- 场景不要求在缺少可靠标签、结构、元数据或独立验证时补造训练目标、样本或性能。
- 场景不接受只给模型文件、平均指标或少量成功样本而没有失败记录、数据血缘和适用性说明的交付。

## 执行前确认事项

- 输入格式、版本、样本/实体完整性和链类型、CDR 编号、表位、结合/不结合标签、亲和力或功能标签是否足以支撑任务。
- 模型与权重的许可证、版本、训练覆盖和适用域，及是否需要可解释基线或外部工具。
- 训练/验证/测试划分是否存在同源、患者、样本、位点、化学系列或其他信息泄漏。
- 指标界面AUPRC的定义、方向、单位、分层统计和最低可接受证据。
- 资源、时间和人工/实验复核是否足以完成目标；若冲突，先提交取舍方案。

**信息缺失策略**：如果关键输入、标签、科学口径、许可或资源信息缺失，执行者必须列出缺口、影响和最小补充信息；在确认前不得用默认值静默替代，也不得提交会被误解为正式结论的高成本运行。

## 必要结果项

- **结构结果**：标准抗体/TCR编号、链-表位映射、输入结构/序列质控和界面实体清单；同时说明输入清洗、版本和任何变更。
- **参考标签结果**：结合标签、亲和力、结构复合物和可开发性参考的来源、类别平衡与缺失值说明；标注缺失、噪声、类别不平衡和不可用于正式验收的部分。
- **模型结果**：模型/权重版本、独立抗原或受体家族拆分评估、校准曲线和最差配对分析；明确模型适用的实体、序列/结构/模态范围和不能外推的边界。
- **动力学结果**：候选序列/结构或配对预测、CDR/表位得分、置信区间和推理日志；保留全量候选或逐样本输出、失败原因、随机种子/条件和版本记录。
- **性质结果**：界面接触、特异性、亲和力排序、聚集/可开发性代理指标及不确定度；每个指标给出定义、单位或量纲、样本范围、分析窗口和置信区间。
- **结论结果**：一份将观察结果、独立证据、模型误差、采样/标签不确定度、偏差和无法回答的问题分开的科学结论报告。
