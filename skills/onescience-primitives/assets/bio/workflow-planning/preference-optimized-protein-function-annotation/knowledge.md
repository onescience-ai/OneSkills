# 偏好优化驱动的蛋白功能注释（B32）

## 适用范围

**适用场景**：
- 任务有明确的蛋白序列或结构输入及可追溯的功能、稳定性、适应度或动力学标签。
- 训练与测试可按家族、突变或实验批次独立划分，能够检验真实迁移而非记忆。
- 目标是注释、优先级排序、效应预测或假设生成，且输出会标注模型不确定性。
- 标签单位、方向和缺失机制可解释，允许进行分层指标和误差审查。

**不适用场景**：
- 标签定义、单位或正负方向不一致，或者只有无出处的文本描述而无法建立监督目标。
- 测试集与训练集存在未审计的同源/同突变泄漏，无法支持泛化结论。
- 需要从预测相关性直接推断因果机制、临床风险或实际催化参数。
- 目标蛋白/底物化学空间远超训练数据而没有外推验证或人工审查。

## 研究对象与输入

**研究对象**：蛋白序列、突变、结构域、酶底物或功能标签数据

| 输入项 | 说明 |
|---|---|
| 输入文件 | SwissProt_GO.csv |
| 输入模态 | FASTA、突变/功能表、结构文件或序列-底物配对表 |
| 样本单元 | 一个蛋白、一个突变或一个酶-底物样本 |
| 标签/条件 | 功能类别、适应度、稳定性、动力学常数或实验效应标签 |
| 模型引用 | annodpo.ckpt |

**初始结构**：默认输入名称为“SwissProt_GO.csv”；执行者必须核验格式、版本、实体/样本完整性、缺失值和可解析性，并记录实际使用的相对名称或数据标识。

**表面/硬约束**：固定标签本体、单位、突变表示、野生型参照和序列版本；不能把相关性预测解释成因果机制或未经测量的实验事实。

**划分策略**：按蛋白家族、序列同源性、实验批次和突变位点拆分，去除近重复并记录训练-测试血缘。

**采样要求**：默认覆盖完整独立测试集，并对每个样本输出预测、置信度、校准状态和可解释特征；不因缺失标签而伪造结果。

## 核心科学问题

1. 在蛋白序列、突变、结构域、酶底物或功能标签数据和输入“SwissProt_GO.csv”上，利用优选与拒绝注释对训练蛋白功能模型，减少无依据标签并提升多标签注释质量能否得到可复核的宏平均F1结果，并满足任务的硬约束？
2. 输入中的标签定义、变异效应/功能预测、跨家族泛化和可解释性如何影响偏好优化驱动的蛋白功能注释的输出，哪些样本、区域或候选最容易失败？
3. 模型在独立样本、未见家族/条件或困难子集上的表现是否稳定，误差和不确定度如何量化？
4. 结果是否具有足够的生物学、化学或临床证据支持后续决策，哪些部分只能作为探索性线索？
5. 在当前数据、模型和资源边界下，哪些结论可以签收，哪些结论必须标记为无法回答或需要额外验证？

## 比较与评估

- 主任务：利用优选与拒绝注释对训练蛋白功能模型，减少无依据标签并提升多标签注释质量；核心指标：宏平均F1。
- 目录模型候选为AnnoDPO，需与可解释基线、参考标签或独立质量检查比较。
- 报告总体和按蛋白家族、效应方向、标签来源分层的性能。
- 与简单序列/频率基线或已有实验排序比较，并审查最差和反常样本。

## 批次补充 2026-09-16（基于归因报告的知识缺口填补）

### 知识缺口 1：蛋白功能预测模型权重文件命名规范与获取途径

**问题描述**：执行时发现 annodpo.ckpt 不存在但未事先检索替代方案。

**知识内容**：
- 蛋白功能预测模型权重通常有多种命名变体：`model_best.ckpt`、`model_final.ckpt`、`best_model.pth` 等 [1]
- 预训练模型（如 ESM-2）可通过 HuggingFace Hub 获取，模型 ID 格式为 `facebook/esm2_t33_650M_UR50D` [2][3]
- 论文附件或官方仓库 release 页面是获取特定任务权重的常见来源 [1][2]
- 权重版本必须与模型架构匹配：不同 Transformer 层数（如 33 层 vs 8 层）的权重不兼容 [3]

**应用动作**：在 s02 执行前增加权重文件存在性检查和版本确认步骤；优先从 HuggingFace Hub 下载官方预训练权重。

**验证方式**：加载权重后验证模型参数维度与配置一致。

### 知识缺口 2：蛋白功能预测任务中预测目标与 GO 标签类型的对应关系

**问题描述**：s01 未执行预测目标验证，未检查预测目标类型与 GO 标签的兼容性。

**知识内容**：
- GO 注释为多标签二值类型（每个蛋白可属于多个 GO term，每个 term 为 0/1）[1][2][3]
- 预测目标应设为 `multilabel` 或 `binary`，不应设为 `continuous` [1][3]
- 损失函数应使用 binary cross-entropy (BCE)，而非 MSE 或其他连续损失 [1][2]
- 多标签分类任务的输出层应使用 sigmoid 激活（非 softmax），每个 GO term 独立输出概率 [1][3]

**应用动作**：在 s01 中增加预测目标类型与标签格式的兼容性检查；验证损失函数与预测目标类型匹配。

**验证方式**：检查模型损失函数为 BCE，输出层为 sigmoid，标签为二值向量。

### 知识缺口 3：多标签蛋白功能预测的可解释性方法

**问题描述**：s04 未输出样本层解释，仅完成了指标计算。

**知识内容**：
- **注意力可视化**：Transformer 的 self-attention 权重可揭示蛋白序列中对预测重要的位置 [1][2]
- **梯度归因**：通过计算预测对输入的梯度，识别对预测贡献最大的残基 [1]
- **特征重要性排序**：ESM-2 嵌入向量的各维度可分析对特定 GO term 的贡献 [3]
- **图神经网络解释**：GNN 中的注意力权重可定位结构图中重要的残基对 [2][3]
- 解释需关联到原始样本 ID、蛋白序列位置和 GO 术语 [1][2]

**应用动作**：在 comprehensive_eval.py 中增加基于注意力权重或梯度的样本层解释导出。

**验证方式**：检查解释输出是否包含样本 ID、GO 术语和归因得分。

### 知识缺口 4：多标签蛋白功能预测中标签稀疏性的处理策略

**问题描述**：未评估模型在极端标签稀疏下的性能预期，3627 GO terms 中 3337 类 <10 样本。

**知识内容**：
- **层级 GO 注释**：利用 GO 的有向无环图（DAG）结构，从父节点向子节点传播注释 [2][3]
- **类别分组**：将稀有 GO term 按功能相似性分组，减少类别数 [3]
- **Focal loss**：对难分类样本赋予更高权重，缓解类别不平衡 [1]
- **对比学习**：通过对比损失学习功能相似蛋白的表示，增强少数类学习 [2]
- **稀有 term 过滤**：设定最小样本阈值（如 <10 样本的 term 排除）[3]
- **分层评估**：按 GO 本体（MF/BP/CC）和 term 频率分层报告 F1 [1][2]

**应用动作**：在 s01 阶段增加标签分布分析和性能预期评估；在 s04 中按 term 频率分层报告性能。

**验证方式**：检查标签分布统计和分层 F1 分析。

### 知识缺口 5：ESM-2 蛋白质语言模型的获取途径、加载方法和显存需求

**问题描述**：未使用预训练 ESM-2 而自定义简化编码器。

**知识内容**：
- **获取途径**：HuggingFace Hub，模型 ID `facebook/esm2_t33_650M_UR50D`（650M 参数，33 层）[2][3]
- **加载方法**：`torch.hub.load("facebookresearch/esm", "esm2_t33_650M_UR50D")` 或 HuggingFace `transformers` 库 [2][3]
- **显存需求**：650M 模型约需 2.5GB 显存（FP32），推理时可降至 1.5GB（FP16）[3]
- **嵌入维度**：输出维度为 1024 [3]
- **预计算策略**：可预先计算所有序列嵌入并缓存，减少训练时显存占用 [3]
- **替代模型**：轻量级可选 `esm2_t12_35M_UR50D`（35M 参数，约 0.5GB 显存）[3]

**应用动作**：在 s02 中增加 ESM-2 权重下载和加载步骤；配置 GPU 环境或使用预计算嵌入。

**验证方式**：验证 ESM-2 输出维度（1024）与分类头匹配。

### 知识缺口 6：蛋白功能预测中数据泄漏的检测方法和危害

**问题描述**：检测到 446/446 测试 accessions 与训练 accessions 重叠，但未阻止训练继续进行。

**知识内容**：
- **泄漏类型**：
  - Accession-level 泄漏：同一蛋白的不同序列版本出现在训练和测试集 [1][2]
  - Sequence-level 泄漏：高序列相似性（>30% identity）的蛋白跨集分布 [2]
  - Family-level 泄漏：同一蛋白家族成员同时出现在训练和测试集 [2]
- **检测方法**：
  - 训练/测试 accession 集合交集检查 [1]
  - 序列相似性矩阵计算（如 BLAST all-vs-all）[2]
  - 蛋白家族 ID（Pfam/InterPro）交叉检查 [2]
- **危害**：
  - 模型记忆 accession-specific 模式而非学习通用特征 [1]
  - 评估结果高估泛化性能 [1][2]
  - 无法真实反映模型在新蛋白上的表现 [1][2]
- **正确做法**：
  - 使用 accession-disjoint 分割（确保训练/测试无 accession 重叠）[1]
  - 按序列相似性聚类后分割（如 CD-HIT 90% 阈值）[2]
  - 记录分割策略并报告泄漏检测结果 [1]

**应用动作**：在 s01 中增加数据泄漏检查并在发现泄漏时暂停执行并报告；优先使用 accession-disjoint 分割。

**验证方式**：检查训练和测试 accession 集合的交集为空。
