# 任务拆解原则

## 适用范围
本卡片描述任务拆解的基本原则，即必须依据场景索引中的workflow定义将任务分解为原子步骤。适用于所有需要将复杂任务分解为可执行步骤的场景。

## 输入
- 复杂任务描述
- 场景索引中的workflow定义
- 任务约束条件

## 输出
- 原子步骤列表
- 步骤依赖关系
- 执行顺序规划

## 流程节点
1. **任务理解** → 理解任务目标和约束
2. **Workflow分析** → 分析场景索引中的workflow定义
3. **步骤识别** → 识别workflow中的原子步骤
4. **依赖分析** → 分析步骤间的依赖关系
5. **顺序规划** → 规划执行顺序和并行可能性
6. **验证检查** → 验证分解结果符合workflow定义

每步含：操作、参数、工具、质量门禁

## 关键参数
| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 原子步骤标准 | 不可再分、有明确输入输出 | [1] | 原子步骤定义 |
| 依赖关系类型 | 数据依赖、控制依赖、资源依赖 | [1] | 依赖关系分类 |
| 并行度评估 | 步骤间无依赖时可并行 | [1] | 并行执行可能性 |
| 质量门禁 | 每个步骤有明确验收标准 | 通用 | 步骤完成标准 |

## 边界与分流
- 当workflow定义不明确时：寻求澄清或使用默认拆解策略
- 当步骤间存在循环依赖时：重新设计工作流或引入状态管理
- 当步骤粒度过粗时：进一步细分
- 当步骤粒度过细时：合并相关步骤

## 质量检查
- 验证分解结果覆盖workflow所有要求
- 检查步骤间依赖关系完整性
- 确认每个步骤有明确的输入输出
- 验证执行顺序的可行性

## 回退策略
- 若无法完全按workflow分解，记录差异并说明原因
- 若步骤依赖关系复杂，使用图形化工具辅助分析
- 若分解结果不理想，寻求专家指导
