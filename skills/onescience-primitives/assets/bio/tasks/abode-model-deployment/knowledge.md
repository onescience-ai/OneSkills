# AbODE模型部署与推理

## 适用范围
适用于需要使用AbODE模型进行抗体序列与结构联合生成的任务，包括CDR环设计、抗体骨架生成、抗原-抗体复合物建模等场景。不适用于抗体序列分析、结构预测（无生成需求）或非抗体蛋白质设计。

## 输入
- 抗原特征信息（抗原序列或结构）
- 可选：已知CDR区域约束
- 可选：抗体骨架模板

## 输出
- 生成的抗体重链和轻链序列
- 对应的3D结构坐标
- CDR区域标注

## 流程节点
1. **环境准备** → 安装PyTorch及依赖库，配置GPU环境
2. **权重下载** → 从官方仓库获取abode.ckpt权重文件
3. **模型加载** → 实例化AbODE模型并加载预训练权重
4. **输入预处理** → 将抗原特征转换为模型输入格式
5. **推理执行** → 调用模型生成抗体候选
6. **后处理** → 解析输出，提取序列和结构信息

## 关键参数
| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 框架 | PyTorch | [1] | 深度学习框架要求 |
| 权重文件 | abode.ckpt | [1] | 模型预训练权重 |
| 输入格式 | 抗原-抗体复合物特征图 | [1] | 图结构输入 |
| 输出格式 | 序列 + 结构坐标 | [1] | 生成结果 |
| 生成模式 | de novo | [1] | 无模板从头生成 |

## 边界与分流
- GPU内存不足时：降级为CPU推理，显著降低生成速度
- 权重文件缺失：需从GitHub或论文附录获取官方权重
- 依赖库版本冲突：建议使用conda环境隔离，指定PyTorch版本

## 质量检查
- 模型加载日志确认权重加载成功
- 推理输出验证序列合法性（标准氨基酸组成）
- CDR区域长度在合理范围内（CDR-H3通常6-25残基）

## 回退策略
- AbODE不可用时：使用ABlooper进行CDR环预测，或使用AlphaFold2进行结构预测
- 无GPU环境：使用CPU模式或云计算资源

## 资源召回建议
当任务涉及以下场景时应召回本卡片：
- 抗体从头设计（de novo antibody design）
- CDR环序列与结构联合生成
- 抗原导向的抗体生成

配套资源：
- anarci-antibody-numbering：用于抗体编号标准化
- cdr-rmsd-calculation：用于生成质量验证
- sabdab-antibody-structure：提供训练数据和验证参考
