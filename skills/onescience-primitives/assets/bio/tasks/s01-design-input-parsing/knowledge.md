# s01 设计输入解析与约束定义

## 输入契约

| 输入项 | 来源 | 格式 | 必填 | 说明 |
|--------|------|------|------|------|
| 设计输入 | 用户提供或默认 | PDB文件 | 是 | 包含功能基序的蛋白结构 |
| 设计目标 | 任务prompt | str | 是 | 功能位点约束蛋白骨架生成 |
| 目标长度 | 任务prompt或默认 | int | 是 | 默认256，范围20-1200 |

## 操作步骤

### 步骤1：输入文件验证

1. **文件名核对**：
   - 检查输入文件名是否为标准名称 `motif_5tpn.pdb`
   - 若用户提供了其他文件名，记录变更并确认
   - 若未提供文件名，使用默认值 `motif_5tpn.pdb`

2. **格式验证**：
   ```python
   def validate_pdb(file_path):
       with open(file_path, 'r') as f:
           lines = f.readlines()
       atom_lines = [l for l in lines if l.startswith('ATOM')]
       if len(atom_lines) == 0:
           raise ValueError("PDB文件中无ATOM记录")
       return True
   ```

3. **完整性检查**：
   - 基序残基原子坐标是否完整
   - 链标识是否明确
   - 是否存在缺失原子

### 步骤2：约束解析

1. **固定残基索引提取**：
   - 从用户输入或任务prompt中提取固定残基索引
   - 默认值：`[10, 25]`（1-indexed）
   - 验证索引在目标长度范围内

2. **基序区域定义**：
   - 从PDB中提取基序残基坐标
   - 记录基序残基编号和原子类型

3. **约束清单生成**：
   ```json
   {
     "fixed_residues": [10, 25],
     "motif_residues": [10, 25],
     "target_length": 256,
     "symmetry": "C1"
   }
   ```

### 步骤3：设计区域定义

1. **可设计区域计算**：
   - 总长度减去固定残基数量
   - 确保可设计区域无冲突

2. **约束冲突检查**：
   - 固定残基索引是否重复
   - 基序区域是否重叠

### 步骤4：输出生成

**标准化设计输入**：
```json
{
  "input_file": "motif_5tpn.pdb",
  "target_length": 256,
  "fixed_residues": [10, 25],
  "motif_residues": [10, 25],
  "design_region": "full_length"
}
```

**约束清单**：
```json
{
  "constraints": {
    "fixed_residues": [10, 25],
    "motif_atoms_preserved": true,
    "target_length_valid": true,
    "no_conflict": true
  }
}
```

## 输出产物

| 产物 | 格式 | 说明 |
|------|------|------|
| 标准化设计输入 | JSON | 包含输入文件名、目标长度、固定残基 |
| 约束清单 | JSON | 所有约束条件的验证结果 |
| 设计区域 | JSON | 可设计区域定义 |
| 验证报告 | 文本 | 输入验证结果和变更记录 |

## 质量门禁

### 必须通过

- [ ] 输入文件名与标准一致（或已记录变更）
- [ ] PDB格式正确（ATOM记录完整）
- [ ] 基序残基原子坐标无缺失
- [ ] 固定残基索引在目标长度范围内
- [ ] 约束清单完整且无冲突

### 失败处理

| 失败类型 | 处理方式 |
|----------|----------|
| 文件不存在 | 提示用户提供正确文件 |
| 格式错误 | 要求重新提供PDB文件 |
| 基序原子缺失 | 要求补充完整坐标 |
| 约束冲突 | 要求用户确认或调整 |

## 回退策略

- 输入文件不符合标准 → 使用默认文件名，记录变更
- 固定残基索引超出范围 → 调整至有效范围，记录变更
- 约束清单不完整 → 补充必要约束，记录缺失项

## 边界说明

**本任务负责**：
- 输入文件格式和完整性验证
- 约束条件解析和验证
- 标准化设计输入生成

**本任务不负责**：
- 模型权重加载（s02）
- 候选结构生成（s03）
- 结果筛选和评估（s04）
