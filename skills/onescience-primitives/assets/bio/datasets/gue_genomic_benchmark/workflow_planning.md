## description

为本地 GUE 基因组分类数据选择分支、任务、解析 schema 和模型接入路线，形成可追溯的数据交接信息，保留原始 train/dev/test 边界。

## when_to_use

当请求涉及 GUE、DNABERT-2_dataset、启动子或剪接分类、表观遗传序列分类、EPI 序列对分类及物种相关基准时使用。需要先确认请求与现有任务目录及标签定义一致；本卡不覆盖 DNABERT-2 模型权重，也不代替其他 FASTA/参考基因组数据的接入规范。

## inputs

- 数据根目录：优先 `${ONESCIENCE_DATASETS_DIR}/DNABERT-2_dataset`，默认 `/public/share/sugonhpcapp01/onestore/onedatasets/DNABERT-2_dataset`。
- 数据选择：显式指定 `GUE` 或 `GUE_v2/GUE`，以及相对任务目录；示例检查可单独选择 `sample_data`。
- 消费目标：接口检查、模型适配或正式评测；拟使用的模型/tokenizer、长度预算及单序列或配对能力。
- 任务说明：标签映射、类别数、指标和数据版本来源；缺失项作为待补齐信息交接。

## outputs

输出所选分支与任务的三个 split 路径、实际列结构、标签映射状态、样本与长度检查结果、模糊碱基策略、tokenizer 和配对编码需求。为后续 datapipe 或模型 adapter 保留源文件及记录位置，并列出尚未验证的版本、许可证或评测口径。

输出是数据接入方案与验证结果；本卡自身不生成模型数据、训练结果或官方基准成绩。

## procedure

1. 解析根目录，确认只读访问权限；忽略上传状态文件和上传分片。
2. 选择完整分支及任务，检查 train/dev/test 是否齐全。未指定分支时先返回候选，不能将两个分支合并。
3. 对三个 CSV 核对表头：单序列走 `sequence,label`；EPI 走 `enhancer,promoter,label`。遇到其他结构时记录差异，先补充 schema。
4. 进行样本级解析检查，再统计当前任务的完整样本数、标签值域、长度与字符集合，检查跨 split 重复。不要把卡片中的前 64 条观察值当成全量统计。
5. 将标签说明与原始 ID 对齐，固定映射和类别数；对 `tf`、`mouse` 的编号目录分别处理，取得说明后再决定是否存在折间关系。
6. 根据实际序列长度、tokenizer 和模型限制配置长度策略。EPI 保留两个字段的角色、顺序与配对关系；模糊碱基处理须明确可复现。
7. 固定原始 split，交接 adapter 所需字段和来源信息。若为正式评测，补齐官方指标、版本来源及使用条件，记录实际采用的评测协议。

## constraints

只在同一分支、同一任务内解释标签并使用原始划分；不能用 test 选择模型参数。完整分支各有 36 个本地任务目录，目录数不应直接写成官方独立任务数。`sample_data` 仅支持接口检查。

目录结构相同不足以证明版本等价，数据根目录名称也不能证明 tokenizer 兼容。不得静默丢弃模糊碱基、截断长序列或丢失 EPI 的一个输入字段。

## next_phase_recommendation

当路径、列结构、标签映射和预处理约定明确后，交给 dataset-specific datapipe 或模型 adapter 做最小数据接入验证。单序列与序列对分别验证；验证通过后再根据用户目标进入训练或推理工作流。

若目前仅完成 `sample_data` 接口检查，应先核查目标任务的完整 split 和统计信息，再安排正式评测。需要宣称复现官方 GUE 结果时，先补齐上游版本、任务标签释义与官方评测协议。

## fallback

目录不可读或 split 缺失时，返回具体路径与缺失项；可以提供已发现的任务清单，但不能跨分支自动补文件。标签释义未取得时可保留原始 ID 做解析检查，明确限制生物学解释与官方结果对比。

模型不支持 EPI 配对输入或长序列时，先交接 adapter 适配需求；若仅需验证读取接口，可明确切换至 `sample_data`，并将结果标记为示例检查。未知列结构或版本差异未解决时，保留原始数据与诊断记录，先完成契约补齐。
