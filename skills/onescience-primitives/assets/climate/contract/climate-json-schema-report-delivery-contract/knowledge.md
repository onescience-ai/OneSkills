# JSON Schema 报告交付契约

## 适用范围

**触发条件**：
- 科学计算任务需要输出结构化 JSON 报告（如归因分析、模型评估、数据质量检查）
- CLI 工具生成的报告需要通过 Schema 校验
- 下游系统依赖固定字段结构进行自动化处理

**适用场景**：
- 归因分析 CLI 输出 report.json 的字段完整性验证
- 科学计算工作流中结构化报告的质量保证
- 自动化数据管道中报告格式的标准化
- CI/CD 流水线中报告 Schema 的自动化校验

**不适用场景**：
- 非 JSON 格式的报告（如 CSV、XML、纯文本）
- 仅需字段存在性检查而无需类型校验的简单场景
- 实时流式数据的 Schema 验证（需专用流式 Schema）

## 输入

**输入数据格式**：
- 待验证的 JSON 报告文件
- 预定义的 JSON Schema 定义文件
- 任务元数据（task_id、task name）

**来源**：
- CLI 工具输出的 report.json
- 任务配置文件中的 Schema 定义
- 工作流编排系统传递的任务身份信息

**预处理要求**：
- 确保 JSON 文件可被标准 JSON 解析器解析
- 确认 Schema 版本与报告格式匹配
- 收集任务身份信息用于一致性校验

## 输出

**输出产物**：
- Schema 校验结果（通过/失败）
- 字段级错误详情（缺失字段、类型错误、约束违反）
- 任务身份一致性校验结果

**格式**：
- 校验结果摘要（JSON 格式）
- 详细错误列表（含字段路径、错误类型、期望值）
- 校验通过时的确认信号

**验证标准**：
- 所有必填字段存在且类型正确
- 任务身份字段（task_id、task）与任务索引一致
- 数组字段（issues）符合数组约束
- 无额外顶层字段（除预定义扩展字段外）

## 流程节点

### Step 1：Schema 加载与预处理
- **操作**：加载 JSON Schema 定义，解析为内部校验规则
- **参数**：Schema 文件路径、版本号
- **工具**：JSON Schema 解析器（如 jsonschema、ajv）
- **质量门禁**：Schema 文件可解析，版本匹配

### Step 2：JSON 语法校验
- **操作**：验证报告文件是否为合法 JSON
- **参数**：报告文件路径
- **工具**：JSON 解析器
- **质量门禁**：文件可被标准 JSON 解析器成功解析，无语法错误

### Step 3：必填字段完整性校验
- **操作**：检查所有必填顶层字段是否存在
- **参数**：必填字段列表（如 issues、summary、task、task_id）
- **工具**：字段存在性检查
- **质量门禁**：所有必填字段均存在

### Step 4：字段类型与约束校验
- **操作**：验证每个字段的类型和约束条件
- **参数**：字段类型定义（string、array、object 等）、约束规则
- **工具**：类型检查器、约束验证器
- **质量门禁**：所有字段类型正确，约束条件满足

### Step 5：任务身份一致性校验
- **操作**：验证 task_id 与任务索引一致，task 与任务 name 一致
- **参数**：任务索引、任务名称
- **工具**：字符串匹配、正则表达式
- **质量门禁**：task_id 和 task 字段与任务元数据一致

### Step 6：额外字段检测
- **操作**：检测是否存在非预期的额外顶层字段
- **参数**：允许的顶层字段白名单
- **工具**：字段集合差异检查
- **质量门禁**：无额外顶层字段（或仅在白名单内的扩展字段）

### Step 7：校验报告生成
- **操作**：汇总所有校验结果，生成校验报告
- **参数**：各步骤校验结果
- **工具**：报告生成器
- **质量门禁**：校验报告包含所有错误详情，格式规范

## 关键参数

### 通用判据

| 参数 | 值 | 来源 | 说明 |

| 必填字段完整性 | 100% | [1] | 所有必填字段必须存在 |

## 边界与分流

**关键前提1：JSON 文件语法合法**
- 前提不成立时的改道：检查文件编码、转义字符、注释是否符合 JSON 规范，使用 JSON 修复工具尝试修复

**关键前提2：Schema 定义文件可用**
- 前提不成立时的改道：从任务配置或工作流定义中获取 Schema，或使用默认 Schema

**关键前提3：任务元数据可获取**
- 前提不成立时的改道：跳过任务身份一致性校验，仅执行字段完整性和类型校验

**关键前提4：必填字段列表已定义**
- 前提不成立时的改道：使用通用报告 Schema（含 task_id、task、summary、issues）

**关键前提5：CLI 退出码非零**
- 前提不成立时的改道：当 CLI 退出码为 0 但报告仍不合规时，检查 CLI 输出捕获逻辑

## 质量检查

**验证点**：
1. JSON 语法合法性检查
2. 必填字段完整性检查
3. 字段类型一致性检查
4. 任务身份一致性检查
5. 数组约束检查（issues 必须为数组）
6. 非空约束检查（summary 必须非空）
7. 额外字段检测

**阈值**：
- 必填字段完整性 = 100%
- 字段类型正确率 = 100%
- 任务身份一致性 = 100%
- 数组约束满足率 = 100%
- 非空约束满足率 = 100%

**失败处理**：
- 字段缺失：记录缺失字段名，提示可能原因（CLI 异常、Schema 不匹配）
- 类型错误：记录字段路径、期望类型、实际类型
- 身份不一致：记录 task_id/task 的期望值与实际值
- 额外字段：记录额外字段名，提示是否为已知扩展

## 回退策略

**Schema 校验失败时的替代方案**：
1. 简化校验范围，仅检查核心必填字段（task_id、task、summary、issues）
2. 使用宽松模式校验，容忍非关键字段缺失
3. 生成部分校验报告，标注已知问题
4. 记录校验失败原因，为后续 Schema 修订提供依据

**报告生成失败时的替代方案**：
1. 生成简化版报告，包含核心字段
2. 输出原始日志供人工分析
3. 记录失败原因，为后续改进提供依据
