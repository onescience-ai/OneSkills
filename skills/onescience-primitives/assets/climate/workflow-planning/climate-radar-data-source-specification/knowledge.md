# 天气雷达临近预报真实数据获取规范

## 适用范围
适用于天气雷达驱动的0—2小时冰雹概率临近预报任务，特别是需要真实雷达观测数据作为输入的场景。不适用于仅使用合成数据进行算法流程验证的场景。

## 输入
- 任务需求：近期观测序列（真实雷达回波数据）
- 时间范围：临近预报（0-2小时）
- 空间范围：中国区域（优先）或全球区域

## 输出
- 真实雷达反射率数据文件（如numpy数组或NetCDF格式）
- 数据来源元数据（数据源名称、获取时间、时空覆盖范围）
- 数据质量检查报告

## 流程节点
1. **数据源识别** → 2. **数据获取** → 3. **格式转换** → 4. **质量检查** → 5. **数据整合**

### 步骤1：数据源识别
- 操作：根据任务需求选择合适的数据源
- 参数：优先级：CINRAD组合反射率产品 > MRMS > NEXRAD
- 工具：数据源目录查询、API文档查阅
- 质量门禁：确认数据源可用性、时空覆盖范围匹配

### 步骤2：数据获取
- 操作：通过API或文件下载获取数据
- 参数：时间范围、空间范围、产品类型
- 工具：wget/curl、Python requests、API客户端
- 质量门禁：下载完整性校验、文件大小检查

### 步骤3：格式转换
- 操作：将原始数据转换为标准格式（numpy数组）
- 参数：目标格式、插值方法、投影转换
- 工具：Py-ART、wradlib、xarray
- 质量门禁：数据完整性、值域检查

### 步骤4：质量检查
- 操作：检查数据质量指标
- 参数：缺失值比例、异常值检测、时间连续性
- 工具：自定义质量检查脚本
- 质量门禁：缺失率<5%、无异常跳变

### 步骤5：数据整合
- 操作：将多源数据整合为统一输入格式
- 参数：时间对齐、空间插值、变量匹配
- 工具：xarray、pandas
- 质量门禁：输出格式符合任务输入要求

## 关键参数
| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| CINRAD数据格式 | ODIM_H5/CF/Radial | [归因报告issue1] | 中国气象局雷达数据标准格式 |
| MRMS数据分辨率 | 1km, 2min | [归因报告issue1] | 多源融合雷达产品 |
| NEXRAD数据格式 | NEXRAD Level II/III | [归因报告issue1] | 美国雷达数据标准 |
| 数据时效性 | ≤15分钟延迟 | [归因报告issue1] | 临近预报要求近实时数据 |
| 空间覆盖范围 | 全国/区域 | [归因报告issue1] | 根据预报区域选择 |

## 边界与分流
- **数据不可用**：降级为合成数据，但必须在元数据中明确标注"synthetic"
- **格式不兼容**：使用标准转换工具（如py-art）进行格式转换
- **质量不达标**：标记数据质量异常，跳过该时段数据
- **多源数据冲突**：以高分辨率数据源为准，低分辨率数据作为补充

## 质量检查
- 验证点：数据完整性、时空一致性、值域合理性
- 阈值：缺失率<5%、反射率值域[-32, 95] dBZ
- 失败处理：记录质量异常，降级处理或跳过

## 回退策略
1. 优先回退到其他可用数据源（如从CINRAD降级到MRMS）
2. 使用合成数据替代，但必须在execution-manifest中明确标注
3. 调整时间范围，使用可用时段数据

## 资源召回建议
- 何时召回：当任务需要真实雷达观测数据作为输入时
- 配套资源：climate-radar-diffusion-model、climate-nowcast-verification-standard
