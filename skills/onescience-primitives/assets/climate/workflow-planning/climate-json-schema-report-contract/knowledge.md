# JSON Schema报告交付契约

## 适用范围

**触发条件**：
- 需要生成符合特定Schema的结构化报告
- 报告需要通过自动化校验
- 报告需要包含任务身份信息

**适用场景**：
- 归因分析报告生成与验证
- 科学计算任务结果的结构化输出
- 自动化质量检查和数据验证
- CI/CD流水线中的报告生成

**不适用场景**：
- 非结构化文本报告生成
- 自由格式的数据可视化
- 实时流数据处理

## 输入

**输入数据格式**：
- JSON Schema定义文件
- 原始数据或分析结果
- 任务元数据（任务ID、任务名称、时间戳等）

**来源**：
- 任务配置文件
- 分析工具输出
- 用户提供的元数据

**预处理要求**：
- 验证Schema文件的完整性和有效性
- 准备符合Schema要求的数据结构
- 收集必要的任务身份信息

## 输出

**输出产物**：
- 符合Schema的JSON报告文件
- Schema验证结果（通过/失败）
- 验证错误详情（如果失败）

**格式**：
- JSON格式的报告文件
- 结构化的验证结果
- 人类可读的错误描述

**验证标准**：
- 报告通过Schema验证
- 所有必填字段存在且类型正确
- 任务身份信息准确无误

## 流程节点

### Step 1：Schema定义与加载
- **操作**：加载和解析JSON Schema定义
- **参数**：Schema文件路径、版本信息、验证规则
- **工具**：JSON Schema解析器、验证引擎
- **质量门禁**：Schema解析成功率 100%

### Step 2：数据准备与转换
- **操作**：将原始数据转换为符合Schema的结构
- **参数**：数据源、转换规则、类型映射
- **工具**：数据转换工具、类型检查器
- **质量门禁**：数据转换成功率 ≥ 95%

### Step 3：必填字段验证
- **操作**：检查所有必填字段是否存在
- **参数**：必填字段列表、字段存在性检查规则
- **工具**：字段验证器、存在性检查器
- **质量门禁**：必填字段完整率 = 100%

### Step 4：字段类型验证
- **操作**：验证每个字段的数据类型是否正确
- **参数**：字段类型定义、类型检查规则
- **工具**：类型检查器、正则表达式验证器
- **质量门禁**：类型检查通过率 ≥ 98%

### Step 5：数组约束验证
- **操作**：验证数组字段的约束条件
- **参数**：数组长度限制、元素类型约束、唯一性要求
- **工具**：数组验证器、约束检查器
- **质量门禁**：数组约束通过率 ≥ 95%

### Step 6：任务身份验证
- **操作**：验证报告中的任务身份信息是否正确
- **参数**：任务ID、任务名称、预期值
- **工具**：身份验证器、匹配检查器
- **质量门禁**：任务身份匹配率 = 100%

### Step 7：报告生成与输出
- **操作**：生成最终的结构化报告
- **参数**：验证结果、错误信息、元数据
- **工具**：报告生成器、格式化工具
- **质量门禁**：报告生成成功率 100%

## 边界与分流

**关键前提1：Schema定义有效**
- 前提不成立时的改道：使用标准Schema验证工具检查Schema文件，修复语法错误或引用缺失

**关键前提2：数据源可用**
- 前提不成立时的改道：检查数据源连接、权限设置，使用备用数据源或缓存数据

**关键前提3：任务身份信息完整**
- 前提不成立时的改道：从任务配置文件、环境变量或用户输入中获取缺失信息

**关键前提4：验证引擎可用**
- 前提不成立时的改道：使用简化验证规则，或生成基本验证报告供人工审核

**关键前提5：输出路径可写**
- 前提不成立时的改道：检查输出目录权限，使用临时目录或内存缓冲区

## 质量检查

**验证点**：
1. Schema文件完整性检查
2. 必填字段存在性检查
3. 字段类型正确性检查
4. 数组约束满足性检查
5. 任务身份匹配性检查
6. 报告结构完整性检查

**阈值**：
- Schema解析成功率 = 100%
- 必填字段完整率 = 100%
- 类型检查通过率 ≥ 98%
- 数组约束通过率 ≥ 95%
- 任务身份匹配率 = 100%
- 报告生成成功率 = 100%

**失败处理**：
- 验证失败时，生成详细的错误报告
- 无法自动修复时，提供修复建议
- 严重错误时，阻止报告发布并通知相关人员

## 回退策略

**验证失败时的替代方案**：
1. 使用简化Schema进行基本验证
2. 生成部分报告，标记验证失败的字段
3. 输出原始数据供人工审核
4. 记录验证失败原因，为Schema改进提供依据

**报告生成失败时的替代方案**：
1. 生成最小化报告，包含核心任务信息
2. 输出验证错误详情，帮助定位问题
3. 使用模板生成基础报告，后续补充完整数据
