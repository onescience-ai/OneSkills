# 气象预报数据预处理与质量控制规范

## 适用范围

面向气象预报任务的输入数据准备阶段，提供标准化的数据预处理与质量控制规范。适用于所有earth域多站点时序预报任务，包括但不限于温度、湿度、风速等气象变量的联合预报。规范涵盖输入数据契约验证、资料截止时间检查、时空对齐标准化流程和数据时点规则执行。

## 输入

| 输入类型 | 来源 | 预处理要求 |
|---------|------|-----------|
| 站点观测数据 | 地面气象站、自动站 | 需验证来源、版本、时空覆盖、单位、质量标志和使用权限 |
| 再分析数据（ERA5等） | ECMWF、NOAA等 | 需验证版本、网格分辨率、变量清单和资料截止时间 |
| 站点位置信息 | 地理信息系统 | 需验证坐标系统（WGS84）、高程信息和站点元数据 |
| 时间特征 | 数据源自带 | 需统一为UTC时间基准，验证时间覆盖范围 |

## 输出

| 输出类型 | 格式 | 验证标准 |
|---------|------|---------|
| 输入数据与版本清单 | Markdown/JSON | 包含每项必填输入的来源URL/路径、版本号、时间覆盖范围、变量清单和质量标志 |
| 任务范围和资料截止时间表 | Markdown/JSON | 明确资料截止时间定义（观测签发时点），验证所有输入数据的观测时间早于资料截止时间 |
| 输入完整性预检报告 | Markdown/JSON | 逐项核验数据源版本、时空覆盖、单位、质量标志和使用权限 |
| 对齐后的标准输入 | NetCDF/CSV | 时间轴为UTC、坐标为WGS84、单位符合气象标准 |
| 掩膜与样本索引 | JSON | 记录每个样本的数据来源和处理状态 |
| 预处理转换记录 | JSON | 记录每一项转换的处理方法、参数和影响范围 |

## 流程节点

### 步骤1：输入数据契约验证

**操作**：
1. 逐项列出所有必需输入的来源、版本、区域、时段、变量、单位、缺测和资料截止时间
2. 验证数据源版本与任务要求一致
3. 检查数据时空覆盖范围是否满足预报需求
4. 确认数据使用权限和许可证合规性

**质量门禁**：
- 所有必需输入均存在且路径、版本和来源可追溯
- 任务区域、时段、变量和输出目标无歧义
- 缺测、重复和异常资料已记录且未擅自补造

**失败处理**：任一必填项缺失时标记BLOCKED，禁止使用模拟数据降级执行

### 步骤2：资料截止时间验证

**操作**：
1. 定义资料截止时间（观测签发时点，即观测数据可被预报系统使用的最早时间）
2. 对每条输入数据检查观测时间是否早于资料截止时间
3. 排除目标时刻之后形成的再分析数据
4. 记录数据时点检查结果

**质量门禁**：
- 所有动态输入的有效时间均不晚于资料截止时间
- 不使用事后分析数据作为输入
- 模拟数据仅用于方法验证，不得用于业务验收

**失败处理**：违反数据时点规则时标记BLOCKED

### 步骤3：时空对齐标准化

**操作**：
1. 时间轴UTC对齐：统一所有数据的时间基准为UTC，执行时区转换
2. 空间坐标统一：将所有站点坐标转换为WGS84坐标系统
3. 单位标准化：温度转为°C、湿度转为%RH、风速转为m/s
4. 质量标志关联：为每个数据点关联质量标志编码
5. 缺测处理：配置缺测处理策略（前后插值、空间插值、标记但不插值）
6. 信息泄漏检查：确保验证期或目标时刻之后的信息未进入输入

**质量门禁**：
- 预处理后的时间轴、坐标、单位和形状可检查
- 每项插值、归一化、掩膜和缺测处理均有记录
- 不存在由验证资料或未来资料造成的信息泄漏
- 时次、变量、单位和坐标满足任务契约

**失败处理**：时空对齐失败时标记BLOCKED

## 关键参数

### 通用判据（方法层，同类体系可参考）

| 参数 | 推荐值 | 来源 | 说明 |
|------|--------|------|------|
| 时间基准 | UTC | 气象行业标准 | 所有气象数据必须统一为UTC时间基准 |
| 坐标系统 | WGS84 | 地理信息标准 | 站点坐标必须使用WGS84坐标系统 |
| 温度单位 | °C | 气象观测标准 | 温度变量的标准单位 |
| 湿度单位 | %RH | 气象观测标准 | 相对湿度的标准单位 |
| 风速单位 | m/s | 气象观测标准 | 风速的标准单位 |
| 资料截止时间 | 观测签发时点 | 业务规范 | 观测数据可被预报系统使用的最早时间 |

### 校准数值（供量级校准）

以下数值来自典型气象预报任务，供量级校准；其他体系需以自身证据重新锚定：

| 参数 | 典型值 | 来源 | 说明 |

## 边界与分流

**前提否定即改道**：
1. 若数据源版本与任务要求不匹配 → 检查是否有兼容版本可用，否则BLOCKED
2. 若资料截止时间无法确定 → 采用保守估计（最早可用数据时间），并记录不确定性
3. 若时空对齐失败（如坐标系统不兼容） → 尝试坐标转换，失败则BLOCKED
4. 若单位标准化失败（如单位信息缺失） → 查阅数据源文档，无法确定则BLOCKED

**降级策略**：
- 当部分数据源不可用时，可使用同类型替代数据源，但必须重新执行数据契约验证
- 当缺测率超过阈值时，可使用空间插值或统计方法填补，但必须记录填补方法和影响

## 质量检查

**验证点**：
1. 输入数据完整性检查：所有必填项是否存在、格式是否正确
2. 资料截止时间检查：所有数据的观测时间是否早于截止时间
3. 时空对齐检查：时间轴、坐标、单位是否符合标准
4. 质量标志检查：每个数据点是否有对应的质量标志
5. 信息泄漏检查：验证期或目标时刻之后的信息是否已排除

**阈值**：
- 缺测率 < 5%
- 异常值比例 < 1%
- 单位转换成功率 = 100%

**失败处理**：
- 任何一项质量检查失败 → 标记BLOCKED并记录失败原因
- 不得跳过质量检查直接执行后续步骤

## 回退策略

1. **数据源不可用** → 尝试替代数据源，重新执行数据契约验证
2. **资料截止时间不确定** → 采用保守估计，记录不确定性，不用于业务验收
3. **时空对齐失败** → 尝试坐标转换或时间重采样，失败则BLOCKED
4. **质量标志缺失** → 使用默认质量标志，但必须标注"质量标志缺失"
