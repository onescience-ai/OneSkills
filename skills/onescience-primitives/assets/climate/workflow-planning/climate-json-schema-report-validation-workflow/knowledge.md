# JSON Schema 报告交付契约验证工作流

## 适用范围
面向科学计算任务产生的结构化报告（如归因分析、数据校验、模型评估报告），提供JSON Schema验证方法论，确保输出符合预定义的字段约束、任务身份匹配和数组格式规范。适用于需要将计算结果以标准化JSON格式交付给下游系统或用户的场景，支持数据集成、自动化验证和互操作性。

## 输入
- **报告数据**：科学计算任务生成的JSON格式报告
- **Schema定义**：预定义的JSON Schema文档，规定必填字段、数据类型、数组约束等
- **任务元数据**：任务ID、任务名称等身份信息，用于验证报告与任务的一致性

## 输出
- **验证结果**：通过/失败状态，包含具体错误信息
- **修正建议**：针对验证失败的字段提供修正指导
- **合规报告**：验证通过后生成的合规性证明

## 流程节点
1. **Schema加载与解析** → 加载JSON Schema文档，解析字段定义和约束规则
2. **报告预处理** → 提取报告数据，规范化格式（如日期时间、数值类型）
3. **字段存在性验证** → 检查必填字段是否完整，任务身份字段是否匹配
4. **数据类型验证** → 验证每个字段的数据类型是否符合Schema定义
5. **数组约束验证** → 检查数组字段的长度、元素类型和嵌套结构
6. **语义验证** → 验证字段值是否在合理范围内，业务逻辑是否一致
7. **错误聚合与报告** → 收集所有验证错误，生成结构化错误报告
8. **修正建议生成** → 基于错误类型提供具体的修正指导

## 关键参数
| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 必填字段检查 | 严格模式 | [1] | 所有标记为required的字段必须存在 |
| 任务身份匹配 | 精确匹配 | [1] | task_id和task字段必须与任务索引完全一致 |
| 数组约束 | 类型检查 | [1] | 数组元素类型必须符合items定义 |
| 数据类型验证 | 强类型 | [1] | 字符串、数字、布尔值等必须严格匹配 |
| 错误阈值 | 0错误 | 任务要求 | 验证失败时返回非零退出码 |

## 边界与分流
- **Schema缺失**：当没有预定义Schema时，转向基础字段存在性检查和类型推断
- **任务身份不匹配**：报告中的task_id或task与任务索引不一致时，标记为身份验证失败
- **格式不兼容**：报告不是有效JSON格式时，先尝试解析修复，失败则返回格式错误
- **性能约束**：大规模报告验证时，可采用分批验证策略

## 质量检查
- **Schema一致性**：验证结果必须与Schema定义完全一致
- **错误完整性**：所有验证错误必须被捕捉和报告
- **性能基准**：验证过程应在合理时间内完成
- **可追溯性**：每个验证错误必须关联到具体的Schema规则

## 回退策略
- **Schema降级**：当完整Schema验证失败时，可降级到基础字段检查
- **部分验证**：对于部分字段验证失败，可提供部分合规证明
- **手动验证**：自动化验证失败时，支持人工验证流程
