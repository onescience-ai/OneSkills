# 雷达驱动的0—3小时极端降水集合临近预报（E2）

## 适用范围

**适用场景**：
- 任务目标与“雷达驱动的0—3小时极端降水集合临近预报”的对象、时空范围和输出定义一致。
- 能够在任务截止时间前获得并核实连续雷达历史序列、起报时间、历史帧数、雷达帧间隔、预报时长、资料截止时间，且数据覆盖和质量足以支持短时风险预警。
- 能够获得与目标结果独立且口径一致的检验指标，或明确将任务限定为不作性能PASS判定的探索性运行。
- 目标区域、时间、变量和数据分布位于可验证的适用范围内，资源与交付期限不存在未确认的冲突。

**不适用场景**：
- 不包含同期定量降水估计、卫星或NWP融合、洪水模拟及3小时以上预报。
- 关键输入缺失、来源不可追溯、使用权限不明确，且场景不允许补充或调整任务范围。
- 客户要求作性能PASS或正式业务验收，但只能使用参与训练或调参的数据，且无法建立独立、同协议的验证或回放。
- 目标区域、时段、变量、传感器或事件类型明显超出可验证范围，且没有经确认的补充数据与验证方案。

## 研究对象与输入

## 核心科学问题

1. 在遵守数据时点、任务边界和输入输出契约的前提下，能否可靠完成“雷达驱动的0—3小时极端降水集合临近预报”的核心分析与目标结果生成并形成降水率集合成员或集合统计、逐阈值逐时效超阈概率、概率校准记录或未校准标识、产品元数据与文件清单？
2. 结果在场景要求的区域、时段、提前期、目标类别或强度区间内表现如何，能否围绕“分时效多阈值检验与交付判定”与同协议基线进行公平比较？
3. 缺测、观测误差、样本不均衡、初始条件、外部强迫或方法随机性带来的不确定性有多大，概率、区间或质量标志是否与独立样本误差相符？
4. 哪些结论由当前数据和独立检验直接支持，哪些只适用于特定区域、季节、事件或传感器条件，哪些因数据、资源或适用域限制不能得出？

## 工作流

### 步骤 1：起报范围与雷达序列预检

**目的**：固定起报时间和预报时效，核验连续雷达历史序列的时间间隔、覆盖范围、变量、单位、缺测与资料截止时间。

| 参数 | 变量名 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|---|
| 连续雷达历史序列 | `{RADAR_HISTORY}` | str | 是 | — | 输入连续雷达数据路径。 |
| 起报时间 | `{FORECAST_START_TIME}` | str | 是 | — | 输入UTC起报时间。 |
| 历史帧数 | `{HISTORY_FRAMES}` | str | 是 | `9` | 输入连续历史雷达帧数。 |
| 雷达帧间隔 | `{FRAME_INTERVAL_MINUTES}` | str | 是 | `10` | 输入帧间隔，单位分钟。 |
| 预报时长 | `{FORECAST_HORIZON_MINUTES}` | str | 是 | `180` | 输入预报时长，不超过180分钟。 |
| 资料截止时间 | `{DATA_CUTOFF_TIME}` | str | 是 | — | 输入资料截止时间。 |

**输出**：雷达输入文件与资料截止时间清单、历史帧时间轴与覆盖报告、雷达序列预检报告

**质量门禁**：
- 所有输入雷达帧的有效时间均不晚于起报时间
- 历史帧数量和时间间隔满足模型契约
- 雷达变量、单位、投影和覆盖范围均可识别
- 缺帧、缺测区和异常回波已显式记录

**操作指令**：`读取{RADAR_HISTORY}，以{FORECAST_START_TIME}为起报时间，检查{HISTORY_FRAMES}帧、{FRAME_INTERVAL_MINUTES}分钟间隔和{DATA_CUTOFF_TIME}，并确认{FORECAST_HORIZON_MINUTES}不超过180分钟。报告覆盖、单位、缺帧、异常值和时间连续性；存在未来观测泄漏或关键帧缺失时停止并标记BLOCKED。`

### 步骤 2：雷达质控与模型输入构造

**目的**：执行缺测掩膜、异常值处理、网格统一、雨强变换和历史序列堆叠，形成模型输入。

**依赖步骤**：s01

| 参数 | 变量名 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|---|
| 雷达预处理配置 | `{PREPROCESS_CONFIG}` | str | 是 | — | 输入预处理配置路径。 |
| 雷达网格规格 | `{RADAR_GRID_SPEC}` | str | 是 | — | 输入投影、分辨率和网格范围。 |
| 缺测处理策略 | `{MISSING_VALUE_POLICY}` | str | 是 | — | 输入掩膜或拒绝策略。 |

**输出**：标准化雷达历史张量、有效区与缺测掩膜、雷达预处理转换清单

**质量门禁**：
- 时间维、空间维、投影、单位和通道顺序与模型输入契约一致
- 缺测区与无降水区能够区分
- 裁剪和重采样没有引入时间错位
- 输入张量不存在未解释的NaN、Inf或异常负值

**操作指令**：`依据{PREPROCESS_CONFIG}和{RADAR_GRID_SPEC}处理通过预检的雷达序列，应用{MISSING_VALUE_POLICY}，统一投影、网格、单位和值域，生成按时间堆叠的输入张量和有效区掩膜。不得将缺测编码为零降水。`

### 步骤 3：预测组件与参数兼容性验证

**目的**：加载所选预测组件的配置和参数文件，核验输入输出尺寸及成员采样接口并执行单次干运行。

**依赖步骤**：s01

| 参数 | 变量名 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|---|
| 预测组件参数路径 | `{MODEL_CHECKPOINT}` | str | 是 | — | 输入模型权重文件路径。 |
| 预测组件配置路径 | `{MODEL_CONFIG}` | str | 是 | — | 输入模型配置文件路径。 |
| 权重SHA-256 | `{CHECKPOINT_SHA256}` | str | 否 | — | 输入权重SHA-256。 |
| 集合成员数 | `{ENSEMBLE_SIZE}` | str | 是 | `20` | 输入集合成员数量。 |
| 随机种子 | `{RANDOM_SEED}` | str | 否 | — | 输入随机种子。 |

**输出**：模型与检查点身份报告、输入输出兼容性矩阵、单成员干运行日志、集合采样配置

**质量门禁**：
- 检查点SHA-256与登记值一致
- 代码、配置、预处理参数和检查点属于兼容版本
- 单成员输出时空尺寸和值域正确
- 固定随机种子时结果可复现，不同成员具有可辨别差异
- 集合规模对应的推理和存储资源已核算

**操作指令**：`加载{MODEL_CONFIG}和{MODEL_CHECKPOINT}，核对{CHECKPOINT_SHA256}，使用{RANDOM_SEED}执行单次成员干运行，并确认能够生成{ENSEMBLE_SIZE}个独立成员。报告代码、依赖、配置和权重版本；存在输入输出不兼容或随机接口失效时停止。`

### 步骤 4：0—3小时集合降水生成

**目的**：使用已验证的时空预测组件和成员生成配置，生成未来多时次高分辨率降水率集合。

**依赖步骤**：s02、s03

| 参数 | 变量名 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|---|
| 输出时间间隔 | `{OUTPUT_INTERVAL_MINUTES}` | str | 是 | `10` | 输入输出间隔，单位分钟。 |
| 保存成员格点场 | `{SAVE_MEMBER_FIELDS}` | str | 是 | `true` | 输入是否保存成员场。 |

**输出**：多成员降水率预报序列、集合均值与分位数场、逐成员推理日志与资源统计

**质量门禁**：
- 预报时次完整且不超过180分钟
- 所有成员的空间网格、时间轴和单位一致
- 输出不存在未解释的NaN、Inf或负雨强
- 成员差异来自登记的随机采样而非版本或输入不一致
- 推理过程中未读取起报时间之后的雷达观测

**操作指令**：`使用已验证的模型、雷达张量和集合配置，按{OUTPUT_INTERVAL_MINUTES}分钟间隔生成至{FORECAST_HORIZON_MINUTES}分钟的降水率集合。根据{SAVE_MEMBER_FIELDS}保存成员格点场，逐成员记录随机种子、输出值域、耗时和异常状态。`

### 步骤 5：概率校准与短临产品生成

**目的**：计算雨强超阈概率和集合统计，并在独立校准资料可用时执行概率校准。

**依赖步骤**：s04

| 参数 | 变量名 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|---|
| 独立校准资料 | `{CALIBRATION_REFERENCE}` | str | 否 | — | 输入校准资料路径。 |
| 概率校准模式 | `{CALIBRATION_MODE}` | str | 是 | — | 输入校准方式或不校准。 |
| 雨强阈值 | `{RAIN_RATE_THRESHOLDS}` | str | 是 | — | 输入雨强阈值，逗号分隔。 |
| 输出格式 | `{OUTPUT_FORMAT}` | str | 是 | — | 输入NetCDF或Zarr。 |
| 结果保存路径 | `{OUTPUT_DIRECTORY}` | str | 是 | — | 输入预报结果保存路径。 |

**输出**：降水率集合成员或集合统计、逐阈值逐时效超阈概率、概率校准记录或未校准标识、产品元数据与文件清单

**质量门禁**：
- 概率值位于0到1且随阈值变化不存在逻辑矛盾
- 校准资料与训练及最终测试资料相互独立
- 没有校准证据时未将原始生成集合声称为已校准概率预报
- 输出文件能够重新打开且坐标、单位、时效和成员维完整
- 模型、检查点、随机种子和校准版本可追溯

**操作指令**：`依据{RAIN_RATE_THRESHOLDS}计算各时效的超阈概率、集合均值和分位数。若{CALIBRATION_MODE}为independent_validation_calibration，必须使用{CALIBRATION_REFERENCE}拟合并记录校准映射；否则把产品明确标记为未校准。按{OUTPUT_FORMAT}写入{OUTPUT_DIRECTORY}并保存完整元数据。`

### 步骤 6：分时效多阈值检验与交付判定

**目的**：未来雷达资料可用时，对位置、结构、极端雨强和概率可靠性开展分时效验证。

**依赖步骤**：s05

| 参数 | 变量名 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|---|
| 未来验证雷达资料 | `{VERIFICATION_RADAR}` | str | 否 | — | 输入未来雷达资料路径。 |
| 基线临近预报 | `{BASELINE_NOWCASTS}` | str | 否 | — | 输入基线预报路径。 |
| 检验指标 | `{METRICS}` | str | 是 | — | 输入检验指标，逗号分隔。 |
| 验证与验收协议 | `{VALIDATION_PROTOCOL}` | str | 否 | — | 输入验收协议路径。 |

**输出**：分时效分阈值分尺度技能报告、概率可靠性与集合离散度报告、同协议基线比较报告、强降水与普通样本分层结果、质量判定与交付清单

**质量门禁**：
- 预报、基线和验证雷达采用一致的网格、掩膜、单位和有效时刻
- 验证资料未参与模型输入、训练或概率校准
- 确定性、空间结构和概率指标均按提前量分层报告
- 重要性抽样与连续时段验证结果分别报告
- 只有达到预先登记的验收门限才能判定性能PASS
- 验证资料或门限缺失时不作性能通过声明
- 配置、命令、退出码、日志、产物路径和文件哈希可追溯

**操作指令**：`若{VERIFICATION_RADAR}可用，依据{VALIDATION_PROTOCOL}计算{METRICS}，并与相同起报时间和输入截止时间的{BASELINE_NOWCASTS}比较。分别报告普通样本、强降水样本和不同提前量，不得把重要性抽样结果外推为全年总体表现。资料或门限缺失时不得判定性能PASS。`

- 变量定义、单位、坐标、网格、时间含义、缺测规则和质量标志是否与目标结果一致。
- 训练、参数选择、阈值调优、验证和基线样本是否相互独立，是否存在时间或空间泄漏。
- 所选方法工件、配置和运行环境是否兼容，最小干运行是否满足输入输出契约且无异常数值。
- 客户期望的范围、时限、资源、指标和验收门限是否完整且彼此可行；存在冲突时先提交取舍方案。

**信息缺失策略**：若必需输入、科学口径、资料截止时间或独立验证目标缺失，agent必须列出缺口、影响和最小补充信息；可选输入缺失本身不得阻塞任务，除非客户明确将其提升为必需项。在场景确认前不得用未经声明的默认值替代，也不得启动高成本执行；缺少合规验证或预先确认门限时不得宣称性能通过。

## 必要结果项

- **input_data_result**：输入数据与版本清单、时空和变量覆盖、质量与缺测报告、资料截止时间、预处理记录、样本索引及数据血缘。
- **core_result**：按冻结输入输出契约得到的雷达驱动的0—3小时极端降水集合临近预报核心结果、中间状态、运行日志、配置身份和异常记录；具体算法不得被反写为客户需求。
- **product_result**：可重新读取的降水率集合成员或集合统计、逐阈值逐时效超阈概率、概率校准记录或未校准标识、产品元数据与文件清单，并附单位、坐标、有效时间、质量标志、派生规则、文件清单和校验信息。
- **validation_result**：使用独立资料完成“分时效多阈值检验与交付判定”的分层指标、同协议基线比较、误差案例和验收判定；若没有预先确认的验收门限，不得把指标结果标记为性能PASS。
- **uncertainty_and_limit_result**：说明数据误差、抽样误差、方法随机性、情景或外部强迫、外推和适用域限制；概率、区间或质量标志应给出可验证样本上的校准证据，无法量化时须明确原因。
- **结论结果**：给出区分已验证结果、探索性观察、未通过项和无法回答问题的结论报告，不得把文件生成成功等同于科学或业务性能通过。
