# 基于SPEI的多时间尺度干旱预测方法

## 适用范围
面向基于标准化降水蒸散发指数（SPEI）的多时间尺度干旱预测任务，该协议提供了一套从气象数据到区域特异性预测模型构建、干旱特征分析及评估的完整流程。该流程适用于评估和预测因降水亏缺与高温蒸散共同作用引发的农业及水文干旱。典型应用场景包括区域干旱风险制图、季节性干旱预测以及分析气候变化对干旱强度和频率的影响。协议的触发条件通常为拥有包含降水、气温等关键气象变量的长时间序列站点数据。

## 输入
- **必需输入**：
  1. **气象数据集**：来自多个站点的长时间序列日尺度数据，至少包含降水量（PRCP）、最高气温（TMAX）、最低气温（TMIN）、平均气温（TMEAN）、日照时数（SS）、风速（WS）和相对湿度（RH）等参数。
  2. **潜在蒸散发（PET）**：基于输入气象变量计算的月尺度PET数据。标准计算方法推荐采用FAO Penman-Monteith方程，以确保物理基础的一致性。
  3. **训练数据集**：将SPEI值（作为目标变量）与对应时段的气候特征（作为预测变量）进行匹配后形成的结构化数据集。
- **可选输入**：
  1. **土地利用/覆盖数据**：用于在时空模式分析中辅助解释干旱成因。
  2. **先验干旱阈值定义**：用于辅助结果解释。

## 输出
- **核心产物**：
  1. **区域特异性干旱预测模型**：针对每个分析站点或地理区域，在不同时间尺度上（如SPEI1, SPEI3, SPEI6, SPEI12）筛选出的最佳机器学习模型（例如Ranger随机森林）。
  2. **关键气候驱动因子列表**：通过特征选择确定的对SPEI预测贡献最大的气象变量（例如水位平衡WB、降水量PRCP、最低温TMIN等）。
- **分析成果**：
  1. **干旱特征阈值**：通过偏依赖图（PDP）和个体条件期望（ICE）分析，得到的各关键气候变量触发干旱的数值阈值范围。
  2. **干旱时空模式**：干旱强度与频率在不同季节（如雨季、旱季）和不同年代间的分布与变化趋势图。
  3. **模型性能评估报告**：包括各模型在验证集上的RMSE、MAE、R²等指标的综合排名。

## 流程节点
该协议包含一个7个核心步骤的有向无环图（DAG）工作流，各步骤依次依赖。

### s1: 数据收集与预处理
- **目标**：构建标准化的多时间尺度SPEI数据库。
- **上游依赖**：无（起点）。
- **输入参数**：
  - `weather_data` (str, 必需)：原始气象站点数据集，包含日尺度变量。
  - `pet_method` (str, 必需)：潜在蒸散发计算方法，默认采用`Penman-Monteith方程`。
- **操作**：首先根据日尺度气象数据计算月尺度PET。然后，对每个月计算降水与PET的差值（水位平衡Di），并在设定的时间尺度（1、3、6、12个月）上进行累积和标准化，最终生成SPEI数据库。
- **质量门**：生成的SPEI数据库必须包含所有目标时间尺度（如1, 3, 6, 12个月）的指数序列。
- **输出**：标准化的多时间尺度SPEI数据库。

### s2: 特征选择
- **目标**：识别对SPEI预测最具影响力的气候变量，以构建简洁高效的预测模型。
- **上游依赖**：s1。
- **输入参数**：
  - `spei_db` (str, 必需)：来自s1的SPEI数据库。
  - `feature_methods` (str, 必需)：特征选择方法组合，默认为`随机森林(RF)、Boruta算法与相关性分析`。
- **操作**：结合多种方法以提高结果的稳健性。先使用皮尔逊相关性分析初步筛选，再利用随机森林模型评估变量重要性，最后应用Boruta算法（一种基于随机森林的包装器方法）确认特征的重要性，通过引入随机化特征来减少相关性干扰和过拟合风险。
- **质量门**：最终特征集需包含至少3个统计上显著且重要的特征。
- **输出**：每个时间尺度对应的关键预测变量列表。

### s3: 模型选择与交叉验证
- **目标**：训练并初步评估多种候选机器学习模型的预测性能。
- **上游依赖**：s2。
- **输入参数**：
  - `features` (str, 必需)：来自s2的精选特征集。
  - `split_ratio` (float, 必需)：训练集比例，默认0.8，范围0.5-0.9。
  - `cv_setting` (str, 必需)：交叉验证设置，默认为`10折重复5次`以增强评估稳定性。
- **操作**：将数据集随机划分为训练集和测试集。在训练集上，使用多种算法（如Ranger、bagEarth、SVM、RF等）构建模型，并通过指定的重复交叉验证策略进行调优和评估。记录每个模型在所有站点、所有时间尺度上的性能指标。
- **质量门**：主要模型在训练集和测试集上应获得合理的预测性能，例如R² > 0.5（具体阈值需结合问题定义）。
- **输出**：每个模型在各站点各时间尺度的性能指标，以及基于这些指标的初步模型排名。

### s4: 模型评估与比较
- **目标**：系统性地比较所有候选模型，确定最稳健的模型子集。
- **上游依赖**：s3。
- **输入参数**：
  - `model_predictions` (str, 必需)：来自s3的模型预测与性能结果。
  - `eval_metrics` (str, 必需)：评估指标，默认为`RMSE, MAE, R²`。
- **操作**：汇总所有模型的RMSE、MAE和R²值。通常，最佳模型应具有最高的R²和最低的RMSE/MAE。根据综合表现，选出排名靠前的若干模型（例如前四名）进入后续分析。
- **质量门**：评估指标应能清晰区分不同模型的性能，且最优模型的指标在预期合理范围内。
- **输出**：综合性能排名及确定的最优模型候选列表（例如Ranger, bagEarth, SVM, RF）。

### s5: 区域特异性分析
- **目标**：为每个地理单元（如气象站点）分配最适用的预测模型。
- **上游依赖**：s4。
- **输入参数**：
  - `station_models` (str, 必需)：来自s3或s4的站点级模型性能详细数据。
  - `selection_criteria` (str, 必需)：模型选择标准，如`最高R²和最低MAE/RMSE`。
- **操作**：遍历每个站点在各时间尺度下的模型性能数据，依据选定标准为每个站点单独选择表现最佳的模型。将选择结果可视化（例如使用热力图），以分析不同模型在地理空间上的主导模式。
- **质量门**：确保为每个分析站点都确定了一个明确的最佳模型。
- **输出**：各站点、各时间尺度的最佳模型分布图及列表。

### s6: 干旱特征阈值分析
- **目标**：利用训练好的模型，定量解析关键气候变量影响干旱发生的阈值。
- **上游依赖**：s5。
- **输入参数**：
  - `best_models` (str, 必需)：来自s5的各区域最佳模型。
  - `features` (str, 必需)：用于分析的气候特征列表。
- **操作**：应用模型无关的解释工具，如偏依赖图（PDP）和个体条件期望（ICE）曲线。这些方法能展示一个特征对模型预测（SPEI）的边际效应，从而揭示出变量与干旱之间的非线性关系，并定位引发干旱状态（如SPEI < -1）的阈值范围。
- **质量门**：生成的PDP/ICE曲线应能清晰揭示变量值变化与SPEI响应之间的非线性趋势和潜在阈值。
- **输出**：各气候变量在不同时间尺度下引发干旱的阈值范围报告与图表。

### s7: 时空干旱模式分析
- **目标**：预测并分析区域干旱强度与频率的长期变化规律。
- **上游依赖**：s6（或s5，若跳过阈值分析）。
- **输入参数**：
  - `region_models` (str, 必需)：来自s5的区域最佳模型。
  - `time_periods` (str, 必需)：分析时段划分，例如分为四个十年期：`1981-1990, 1991-2000, 2001-2010, 2011-2020`。
  - `seasons` (str, 必需)：分析季节，需根据研究区定义，例如孟加拉国的`Pre-kharif, Kharif, Rabi`季。
- **操作**：使用各站点的最佳模型预测所有历史时期的SPEI值。根据预定义的干旱分类阈值（例如SPEI < -1为干旱），计算各时段、各季节的干旱强度（平均SPEI亏缺量）和频率（干旱发生次数）。绘制时空分布图，分析干旱模式的演变趋势（如强度是否减轻、频率是否增加，是否存在空间转移）。
- **质量门**：可视化结果应能清晰、直观地展示干旱强度和频率的时空演变模式。
- **输出**：干旱强度与频率的时空分布图，以及关于模式变化的定量结论。

## 边界与分流
- **适用边界**：
  1. 该协议**核心优势**在于处理中长期（月尺度以上）干旱预测，依赖于可靠的气候驱动因子。
  2. 对于**短期（日尺度）或水文干旱**预测，若主导因素为径流或土壤湿度，可能需要采用其他指数（如标准径流指数SRI）或融合水文模型。
  3. 模型的预测能力受输入数据质量和站点密度制约，在气候高度异质或站点稀疏区域，预测不确定性会增大。
- **上下游衔接**：
  - **上游**：可接入任何提供标准化气象数据的数据处理管线。
  - **下游**：输出的干旱预测模型和阈值分析结果可直接服务于农业灌溉调度、水资源优化分配等决策支持系统。输出的干旱时空模式分析是气候变化影响评估报告的重要组成部分。
- **替代方案**：
  - 若特征间存在高度非线性交互且样本量充足，可尝试梯度提升树（如XGBoost）或神经网络模型作为替代算法。
  - 若主要关注干旱的**空间相关性**而非时间预测，可转向空间统计或地理加权回归模型。

## 质量检查
- **模型验证**：使用与训练集分离的测试集（占总数据约20%）进行最终验证。关注R²、RMSE、MAE等指标，并检查残差是否存在系统性偏差。
- **特征稳定性**：通过比较不同交叉验证折或不同特征选择方法得出的关键特征列表，检查其一致性。
- **结果合理性**：检查生成的干旱阈值和时空模式是否符合研究区域的水文气候学常识。例如，干旱频率的增加是否与已知的气候趋势相符。
- **过拟合检查**：确保模型在训练集和测试集上的性能差异不大。使用交叉验证策略（如重复10折）是防止过拟合的重要手段。

## 回退策略
针对已识别的失败模式，采取以下应对措施：
1. **数据质量问题**：
   - **缺失值/异常值**：在s1前增加数据清洗与插补步骤（如线性插值、基于邻站的插补）。
   - **PET计算不准**：验证PET计算方法（如Penman-Monteith）所需输入参数的完备性，或采用更简单的经验公式（如Hargreaves）作为备选。
2. **模型性能不佳**：
   - **特定区域/时间尺度R²低**：回退至s3，尝试引入更多候选算法（如Boosted Regression Trees），或增加特征工程（如构建降水距平、累积温度等衍生变量）。
   - **普遍过拟合**：在s3中简化模型复杂度（如降低树的深度、增加正则化），或增加训练数据量。
3. **特征选择失效**：
   - **关键特征不稳定**：放宽Boruta算法的显著性阈值，或结合领域知识强制保留关键物理变量（如降水）。
4. **分析结果不符合预期**：
   - **时空模式混乱**：回退至s5，重新审视区域划分的合理性，或考虑采用基于聚类的区域划分方法替代固定站点分析。
