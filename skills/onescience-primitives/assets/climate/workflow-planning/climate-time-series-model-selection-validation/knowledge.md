# 气象时序预报模型选择与验证规范

## 适用范围

面向气象时序预报任务的模型选择与配置验证阶段，提供标准化的模型选择与验证规范。适用于所有earth域时序预报任务，包括温度、湿度、风速等气象变量的24-72小时联合预报。规范涵盖LSTM/Transformer/GRU等模型的适用条件、输入输出契约定义、最小干运行验证流程、随机性控制要求和性能评估标准。

## 输入

| 输入类型 | 来源 | 预处理要求 |
|---------|------|-----------|
| 预处理后的训练数据 | 步骤2输出 | 需确保时空对齐已完成、单位已标准化 |
| 模型配置参数 | 任务定义或用户指定 | 需验证参数与数据特征匹配 |
| 随机种子 | 任务定义或默认值 | 需固定全局随机种子以保证可复现性 |
| 验证集 | 数据划分 | 需确保未参与训练和参数选择 |

## 输出

| 输出类型 | 格式 | 验证标准 |
|---------|------|---------|
| 方法工件与配置身份报告 | Markdown/JSON | 记录模型类型、参数数量、输入输出维度、版本信息 |
| 输入输出兼容性矩阵 | Markdown/JSON | 验证输入特征维度与模型输入维度匹配性 |
| 最小干运行日志 | Markdown/JSON | 记录小batch前向传播检查、梯度检查、输出范围检查结果 |
| 训练好的模型 | .pth/.h5 | 验证模型能正常加载和推理 |
| 性能评估报告 | Markdown/JSON | 包含R2、RMSE、Skill Score等指标，验证指标合理性 |

## 流程节点

### 步骤1：模型选择决策

**操作**：
1. 根据数据特征选择合适的模型架构：
   - **LSTM/GRU**：适用于序列长度中等（<100时间步）、多变量交互程度低的场景
   - **Transformer**：适用于序列长度长（>100时间步）、多变量交互程度高的场景
   - **混合模型**：适用于复杂时空依赖关系的场景
2. 评估模型复杂度与数据量的匹配性
3. 确定预报时效对应的模型配置差异（24h/48h/72h）

**质量门禁**：
- 模型架构与数据特征匹配
- 模型复杂度与数据量匹配（避免过拟合或欠拟合）
- 预报时效对应的模型配置合理

**失败处理**：模型选择不合理时重新选择，无法确定时使用保守配置

### 步骤2：输入输出契约验证

**操作**：
1. 定义输入契约：
   - 输入特征矩阵shape：[batch_size, sequence_length, num_features]
   - 目标变量与预测变量的对应关系
2. 定义输出契约：
   - 输出预报序列shape：[batch_size, forecast_horizon, num_targets]
   - 输出范围检查（温度、湿度、风速的物理合理范围）
3. 验证输入输出维度匹配性

**质量门禁**：
- 输入特征维度与模型输入维度匹配
- 输出预报维度与任务要求匹配
- 输出值在物理合理范围内

**失败处理**：契约验证失败时BLOCKED

### 步骤3：最小干运行验证

**操作**：
1. 使用小batch数据（如batch_size=2）执行前向传播
2. 检查输出是否存在NaN或Inf
3. 验证梯度计算正常（反向传播不报错）
4. 检查输出范围是否合理
5. 记录干运行日志

**质量门禁**：
- 最小干运行正常退出
- 结果不存在NaN或Inf
- 梯度计算正常
- 输出范围在物理合理范围内

**失败处理**：干运行失败时BLOCKED，记录失败原因

### 步骤4：随机性控制

**操作**：
1. 设置全局随机种子（Python、NumPy、PyTorch/TensorFlow）
2. 配置CUDA确定性（如适用）
3. 记录随机种子配置

**质量门禁**：
- 随机种子已固定
- 多次运行结果可复现

**失败处理**：随机性控制失败时记录警告，继续执行

### 步骤5：性能评估

**操作**：
1. 计算评估指标：
   - **R²**：决定系数，>0为基本要求，>0.5为良好
   - **RMSE**：均方根误差，温度<3°C（短期）、<5°C（中期）
   - **MAE**：平均绝对误差
   - **Skill Score**：技巧评分，>0表示优于基线
2. 执行性能门禁检查：
   - R²<0时自动标记为REJECT
   - RMSE超过合理范围时标记为REJECT
3. 诊断性能问题（如过拟合、数据特征不匹配）

**质量门禁**：
- R²>0为基本要求
- Skill Score>0表示优于基线
- RMSE在合理范围内

**失败处理**：性能不达标时触发模型回退或参数调整

## 边界与分流

**前提否定即改道**：
1. 若数据量不足以训练复杂模型 → 使用简单模型（如线性回归、ARIMA）作为基线
2. 若模型选择不合理（R²<0） → 回退到更简单的模型或调整特征工程
3. 若性能评估发现过拟合 → 增加正则化、减少模型复杂度或增加数据
4. 若性能评估发现欠拟合 → 增加模型复杂度或改进特征工程

**降级策略**：
- 当复杂模型训练失败时，可使用简单模型（如持续性预报）作为备选
- 当性能不达标时，可降低预报时效或缩小预报范围

## 质量检查

**验证点**：
1. 模型选择合理性检查：模型架构与数据特征匹配
2. 输入输出契约检查：维度匹配、值范围合理
3. 最小干运行检查：前向传播正常、无NaN/Inf
4. 随机性控制检查：随机种子已固定、结果可复现
5. 性能评估检查：R²>0、Skill Score>0、RMSE在合理范围

**阈值**：
- R² > 0
- Skill Score > 0
- 温度RMSE < 3°C（短期）或 < 5°C（中期）
- 湿度RMSE < 15%
- 风速RMSE < 2m/s

**失败处理**：
- 任何一项质量检查失败 → 标记REJECT或BLOCKED
- 性能不达标 → 触发模型回退或参数调整

## 回退策略

1. **模型选择不合理** → 回退到更简单的模型（如线性回归、ARIMA）
2. **性能不达标（R²<0）** → 触发模型回退或参数调整
3. **过拟合** → 增加正则化、减少模型复杂度或增加数据
4. **欠拟合** → 增加模型复杂度或改进特征工程
5. **训练失败** → 使用持续性预报作为基线
