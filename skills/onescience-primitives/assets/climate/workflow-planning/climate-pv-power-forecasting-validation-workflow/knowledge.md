# 光伏功率预测验证与工作流规划

## 适用范围

**触发条件**：
- 需要规划或执行光伏功率预测任务（特别是多站联合预报）
- 需要验证光伏功率预测模型的性能
- 需要了解光伏功率预测的数据来源规范
- 需要遵循标准工作流步骤（s01-s06）

**适用场景**：
- 多站光伏电站0-48小时功率联合预报
- 光伏功率预测模型的开发与评估
- 光伏功率预测任务的验证与报告生成
- 光伏功率预测系统的部署与监控

**不适用场景**：
- 非光伏可再生能源预测（如风电、水电）
- 短期（<1小时）或长期（>7天）功率预测
- 单一电站的功率预测（不涉及多站联合）

## 输入

**必需输入数据**：
1. **天气预报数据**：来自气象局签发的数值天气预报（NWP），必须是签发时可获得的数据，不能使用目标时刻之后形成的观测
2. **历史功率数据**：来自电站SCADA系统的实际功率输出记录，至少需要1-2年历史数据
3. **电站属性数据**：来自电站设计文档，包括容量、组件类型、安装角度、经纬度等
4. **多站拓扑信息**：电站之间的空间关系、网络连接、调度约束

**数据时点规则**：
- 所有输入数据必须是签发时可获得的，不能使用未来数据
- 如果数据不可用，应标记任务为BLOCKED，不能使用模拟数据
- 数据获取失败时，应明确记录缺失信息，不能补造数据

**预处理要求**：
- 容量归一化：将功率数据除以电站容量，得到标幺值
- 缺测处理：识别并处理缺失数据（插值、删除或标记）
- 异常值检测：识别并处理异常功率值（如夜间非零功率）
- 时间对齐：确保所有数据时间戳一致（通常为15分钟或1小时分辨率）

## 输出

**主要输出产物**：
1. **验证报告**：包含分层验证指标、基线比较结果、爬坡事件分析
2. **模型性能评估**：包含训练集/验证集性能差异、过拟合检测、模型选择依据
3. **工作流执行清单**：包含每个步骤的输入输出契约、完成状态、质量门禁
4. **最终报告**：包含任务执行摘要、关键发现、改进建议

**验证标准**：
- 分层指标必须包含：按站点、按预测时效、按天气类型
- 基线比较必须包含：持久性预报、气候平均、线性趋势
- 爬坡事件检测：识别功率快速变化事件并单独评估
- 验收门限：RMSE < 10% 容量（具体门限根据电站特性调整）

**报告格式**：
- 验证报告：JSON格式，包含指标计算结果和统计检验
- 最终报告：Markdown格式，包含图表、表格和文字说明
- 执行清单：结构化格式，记录每个步骤的执行状态

## 流程节点

### Step 1：数据预检（s01）
- **操作**：检查所有输入数据的可用性、完整性和质量
- **参数**：数据源列表、时间范围、缺失率阈值（<5%）
- **工具**：数据质量检查脚本、可视化工具
- **质量门禁**：所有必需数据可用，缺失率<5%，无重大异常
- **输出**：数据质量报告、数据可用性声明

### Step 2：时空对齐（s02）
- **操作**：将不同来源的数据对齐到统一的时间网格和空间参考
- **参数**：时间分辨率（15分钟/1小时）、空间参考系、时区
- **工具**：时间对齐脚本、空间插值工具
- **质量门禁**：时间对齐误差<1个时间步，空间插值误差<5%
- **输出**：对齐后的数据集、对齐质量报告

### Step 3：方法配置与输入输出契约验证（s03）
- **操作**：配置预测方法，验证输入输出契约是否满足
- **参数**：预测方法（物理模型/统计模型/机器学习模型）、输入特征、输出格式
- **工具**：方法配置工具、契约验证脚本
- **质量门禁**：输入数据满足方法要求，输出格式符合标准
- **输出**：方法配置文件、契约验证报告

### Step 4：核心计算（s04）
- **操作**：执行光伏功率预测的核心计算
- **参数**：模型参数、训练配置、预测配置
- **工具**：预测引擎、模型训练框架
- **质量门禁**：计算完成无错误，输出结果在合理范围内
- **输出**：预测结果、模型参数、计算日志

### Step 5：结果恢复与产品生成（s05）
- **操作**：将预测结果恢复为实际功率值，生成标准产品
- **参数**：容量归一化参数、产品格式、发布渠道
- **工具**：结果恢复脚本、产品生成工具
- **质量门禁**：结果恢复正确，产品格式符合标准
- **输出**：功率预测产品、结果恢复报告

### Step 6：分层验证（s06）
- **操作**：按标准协议执行分层验证
- **参数**：验证指标（RMSE、MAE、R²）、分层维度（站点、时效、天气类型）、基线方法
- **工具**：验证脚本、统计分析工具
- **质量门禁**：验证指标计算正确，基线比较完成，爬坡事件分析完成
- **输出**：验证报告、基线比较报告、爬坡事件分析报告

## 边界与分流

**数据不可用时的处理**：
- 如果天气预报数据不可用：标记任务为BLOCKED，不能使用模拟数据
- 如果历史功率数据不足：使用可用数据，但注明数据限制
- 如果电站属性缺失：使用默认值或估算值，但标注不确定性

**模型选择分流**：
- 如果训练/验证R²差异>0.1：选择过拟合较小的模型
- 如果所有模型性能都低于基线：考虑更换方法或重新设计特征
- 如果计算资源有限：选择计算复杂度较低的模型

**验证失败时的处理**：
- 如果验证指标远低于基线：重新检查数据质量和方法选择
- 如果爬坡事件检测失败：调整检测阈值或使用其他方法
- 如果分层验证不一致：分析不一致原因，可能需要分层建模

## 质量检查

**数据质量检查点**：
1. 数据完整性检查：缺失率<5%
2. 数据一致性检查：功率值在合理范围内（0-容量）
3. 数据时点检查：所有数据是签发时可获得的

**模型质量检查点**：
1. 过拟合检测：训练/验证R²差异<0.1
2. 泛化能力检查：验证集性能优于基线
3. 计算稳定性检查：模型训练收敛，无数值问题

**验证质量检查点**：
1. 指标计算正确性：验证指标计算无错误
2. 基线比较完整性：所有基线方法都已比较
3. 爬坡事件分析完整性：所有爬坡事件都已检测和评估

## 回退策略

**数据问题回退**：
- 数据质量差：使用更严格的清洗规则，或标记部分数据不可靠
- 数据不足：使用迁移学习或领域知识增强
- 数据不一致：重新对齐数据，或使用鲁棒性更强的模型

**模型问题回退**：
- 过拟合严重：增加正则化、减少模型复杂度、增加训练数据
- 性能不足：尝试其他模型架构、增加特征工程、调整超参数
- 计算失败：简化模型、增加计算资源、检查代码错误

**验证问题回退**：
- 验证不通过：重新检查数据、调整验证方法、修改验收门限
- 报告生成失败：简化报告格式、手动验证关键指标
- 工作流不匹配：调整工作流步骤，确保关键步骤不被遗漏
