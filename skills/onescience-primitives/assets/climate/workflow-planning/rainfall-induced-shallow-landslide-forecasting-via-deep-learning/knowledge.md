# 基于深度学习的降雨诱发浅层滑坡预测

## 适用范围

面向利用小时级降雨观测进行区域滑坡预警的任务，适用于以降雨为主要驱动因素的浅层滑坡预测。典型触发场景包括：运营级滑坡预警系统（LEWS）需要在降雨过程中实时判别当前降雨条件能否触发滑坡；区域风险评估中需要用数据驱动方法替代或补充经验降雨阈值；以及需要在大空间尺度（数百至数千站点）和长时间序列（数年至数十年）上对降雨-滑坡关系进行建模与预测。

该方法的核心假设是：在一个由瞬态降雨驱动的景观中，滑坡能否发生主要受降雨条件控制，局部地形与环境条件的差异在区域尺度上被视为次要因素。因此，该方法特别适用于地质与植被条件相对均质、或这些条件在建模时被隐式吸收的区域。当地质、气候或植被条件发生显著空间或时间变化时，模型可能需要区域性重训或引入额外特征。

## 输入

- **必需输入：**
  - **小时降雨时间序列：** 来自密集雨量计网络的逐小时降雨记录，覆盖目标区域和训练/预测时段。典型网络规模为数百至数千个自动记录雨量计。
  - **历史滑坡目录：** 包含滑坡发生时间、位置信息的结构化列表，时间跨度越长越好（建议至少覆盖一个完整的降雨-干旱周期，如十年以上）。滑坡目录的完整性和时间精度直接影响模型训练质量。

- **可选输入：**
  - **模型超参数配置：** 包括正则化参数（L2惩罚因子、dropout比例）、优化器参数（学习率、衰减率）、集成规模（bagging模型数量）等。未指定时使用默认值（见流程节点）。
  - **新降雨事件数据：** 预测阶段所需的实时或历史小时降雨记录。

## 输出

- **滑坡发生概率/分类预测：** 对给定降雨事件，输出滑坡发生（触发）或不发生（未触发）的概率或二分类标签。
- **不确定性度量：** 通过bagging集成中100个模型的投票方差（σ²）量化预测的不确定性。方差越大，表示模型对当前预测的信心越低。
- **逐滞后预测结果：** 每个滞后ℓ（1至24小时）的独立投票结果Vℓ，可追溯哪些触发时段的降雨对预测贡献最大。

## 流程节点

### s1 — 降雨事件重建

**步骤描述：** 使用CTRL-T（Calculation of Thresholds for Rainfall-induced Landslides Tool）从历史降雨和滑坡数据中客观划分和定义独立的降雨事件。

**输入参数：**
| 参数名 | 类型 | 默认值 | 范围 | 说明 |
|--------|------|--------|------|------|
| rainfall_data | str | — | — | 来自密集雨量计网络的时序数据（必需） |
| landslide_catalogue | str | — | — | 包含滑坡发生时间、位置的列表（必需） |
| dry_period_threshold | int | 48 | 24–168 | 用于分隔降雨事件的最小干燥期长度（小时）。湿季典型值为96小时，干季为48小时 |

**上游依赖：** 无（流程起点）。

**输出：** 降雨事件列表，每个事件包含持续时间D、累积降雨量E、是否发生滑坡的标签。

**质量门：** 成功重建出与目标区域降雨事件数量级匹配的结果。例如，在意大利全国二十年的数据中，该步骤重建出约78万个降雨事件，其中约0.3%伴随至少一次滑坡。

**提示词模板：**
```
基于提供的小时降雨数据和滑坡目录，使用CTRL-T工具进行降雨事件重建。干季分隔阈值设为48小时，湿季设为96小时。输出每个事件的持续时间、累积降雨量和滑坡标签。
```

### s2 — 降雨变量计算与数据集构建

**步骤描述：** 为每个滞后ℓ，将每个降雨事件分解为前驱期（antecedent period）和触发期（triggering period），计算降雨变量并构建建模数据集。

**输入参数：**
| 参数名 | 类型 | 默认值 | 范围 | 说明 |
|--------|------|--------|------|------|
| reconstructed_events | str | — | — | 来自s1的降雨事件列表（必需） |
| max_triggering_period | int | 24 | 1–24 | 最大触发期长度（小时）。默认24小时 |

**上游依赖：** s1。

**核心概念：**
- **前驱期降雨变量（Da, Ea）：** Da为前驱期持续时间，Ea为前驱期累积降雨量。前驱期反映了触发前土壤的水分累积状态。
- **触发期降雨变量（Do, Eo）：** Do = Dℓ（由滞后ℓ参数化的触发期持续时间），Eo为触发期累积降雨量。滞后ℓ从1到24小时，捕获不同时间窗口内触发降雨的强度变化。
- **建模数据集：** 对每个滞后ℓ，构建一个数据集，包含特征向量[Da, Ea, Eo]和对应的二分类标签（有/无滑坡）。由于有滑坡的事件（正样本）远少于无滑坡的事件（负样本），需处理类别不平衡问题（如欠采样负样本、过采样正样本，或使用类别权重）。

**输出：** 每个滞后ℓ的建模子集。

**质量门：** 能正确区分有滑坡和无滑坡的降雨事件数据点，正负样本比例在训练集中达到合理平衡。

**提示词模板：**
```
将每个降雨事件拆分为前驱期和触发期。对滞后ℓ从1到24，计算前驱期参数（Da, Ea）和触发期参数（Do=Dℓ, Eo）。构建特征向量[Da, Ea, Eo]，标注滑坡标签，输出为每个滞后ℓ的建模子集。处理正负样本的类别不平衡。
```

### s3 — 模型训练与集成

**步骤描述：** 为每个滞后ℓ训练一个由全连接神经网络组成的bagging集成模型。

**输入参数：**
| 参数名 | 类型 | 默认值 | 范围 | 说明 |
|--------|------|--------|------|------|
| modeling_dataset | str | — | — | 来自s2的建模数据集，已平衡处理（必需） |
| regularization_params | str | L2 penalty=0.001, dropout=0.25 | — | 正则化参数，用于防止过拟合（可选） |
| optimizer_params | str | Adam: lr=1e-4, decay_rate=0.05/100 steps, β1=0.9, β2=0.999 | — | 优化器参数（可选） |

**上游依赖：** s2。

**模型架构：**
- 输入层：3个神经元（接收[Da, Ea, Eo]特征向量）
- 隐藏层1：4个神经元，激活函数tanh
- 隐藏层2：4个神经元，激活函数tanh
- 输出层：1个神经元，激活函数sigmoid（输出滑坡发生概率，0 ≤ p(y="yes") ≤ 1）
- 网络总参数：32个权重θ + 9个偏置β

**训练细节：**
- 权重初始化：正态分布，μ=0，σ=0.1；偏置初始化为0
- 正则化：L2权重衰减δ=0.001 + dropout γ=0.25
- 损失函数：二元交叉熵（假设滑坡发生服从伯努利分布）
- 优化器：Adam，初始学习率1e⁻⁴，每100步衰减率δ=0.05，β₁=0.9，β₂=0.999，ε=1e⁻⁷
- 每个滞后ℓ训练100个模型（bagging集成），使用100对独立的训练-验证子集

**输出：** 每个滞后ℓ的100个训练好的模型组成的集成集合。

**质量门：** 训练准确率和验证准确率相近，表明模型未严重过拟合。

**提示词模板：**
```
对每个滞后ℓ（1-24），使用其建模数据集训练100个4×4全连接神经网络。网络输入层3神经元，两个隐藏层各4神经元（tanh激活），输出层1神经元（sigmoid激活）。使用L2正则化（δ=0.001）和dropout（γ=0.25）。损失函数为二元交叉熵，优化器为Adam（lr=1e-4，每100步衰减0.05）。每轮使用不同的训练-验证子集进行bagging。
```

### s4 — 预测演示与聚合

**步骤描述：** 对新的降雨事件，使用所有滞后ℓ的模型集合进行预测，通过投票和聚合得到最终结果。

**输入参数：**
| 参数名 | 类型 | 默认值 | 范围 | 说明 |
|--------|------|--------|------|------|
| new_event_rainfall | str | — | — | 新降雨事件的小时降雨记录（必需） |
| final_model_set_O | str | — | — | 包含所有滞后ℓ的100个模型的最终模型集（必需） |

**上游依赖：** s3。

**聚合方法：**
- 对每个滞后ℓ，100个模型各自输出一个预测结果（"滑坡"或"无滑坡"）
- 投票聚合：Vℓ = argmax(#"landslides" / #"no landslides")，即得票多的类别获胜
- 不确定性估计：σ² = (#"landslides"/100) × (#"no landslides"/100)，反映投票的离散程度
- 最终预测：合并所有24个滞后的投票结果，得到综合预测^V

**输出：**
- 每个滞后ℓ的投票结果Vℓ
- 最终聚合预测^V（滑坡发生概率或类别）
- 不确定性度量σ²

**质量门：** 在演示集上达到高F1分数（如≥0.90）和Cohen's kappa系数（如≥0.795）。

**提示词模板：**
```
对新降雨事件，计算其在24个滞后下的特征向量[Da, Ea, Eo]。对每个滞后ℓ，用100个模型分别预测，统计投票结果Vℓ和方差σ²。合并所有滞后的预测，输出最终滑坡发生概率、分类标签和不确定性度量。
```

## 边界与分流

**适用边界：**
- 该方法假设降雨是浅层滑坡的主要驱动力。在滑坡由地震、火山活动或其他非降雨因素触发的区域，该方法不适用，应转向地震触发模型或物理力学模型。
- 模型依赖于区域降雨-滑坡关系的稳定性。当气候模式、植被覆盖或土地利用发生显著变化时，模型性能可能下降，需要使用新数据重新训练或校准。

**与同类方法的对比：**
- **经验降雨阈值方法：** 计算更简单、可解释性强，但通常基于区域或站点尺度的统计阈值，难以捕获降雨时序的动态特征。深度学习方法在预测精度上通常优于经验阈值，但需要更多训练数据。
- **物理模型方法（水文-边坡稳定性耦合模型）：** 物理机理清晰，可模拟土壤水分运移和边坡稳定性，但计算成本高、需要大量地质与水文参数。深度学习方法在数据充足的区域更具优势，物理模型则在数据稀疏或地质条件复杂的区域更可靠。

**上下游衔接：**
- **上游：** CTRL-T工具是降雨事件重建的关键前置组件。若无法使用CTRL-T，需用其他降雨事件分割算法（如基于固定干燥期阈值的简单分割），但可能影响事件划分的客观性。
- **下游：** 预测结果可直接接入滑坡预警系统（LEWS）的决策模块，作为预警触发的参考依据之一。预警级别划分需结合当地防灾响应流程和决策阈值。

## 回退策略

- **滑坡目录不完整或时间精度不足：** 模型训练质量受限，建议使用已有的高精度子集进行训练，或转向仅依赖降雨数据的经验阈值方法作为初步替代。
- **降雨事件在历史记录中缺乏代表性（如极端罕见事件）：** 预测不确定性显著增大，建议输出高不确定性警示，并辅以物理模型或专家判断进行综合决策。
- **模型在新区域部署时性能显著下降：** 可能反映气候、地质或植被条件的差异，建议先在小范围子区域进行模型验证，确认适用性后再扩展部署；若性能仍不达标，需收集本地数据重新训练模型。
- **实时计算资源不足：** 若无法运行完整的24滞后×100模型集成，可减少bagging模型数量（如降至50个）或仅使用关键滞后窗口，但会牺牲预测精度和不确定性量化的可靠性。

## 资源召回建议

- **CTRL-T工具：** 用于降雨事件的客观重建，是流程的关键前置组件。需配合小时降雨数据和滑坡目录使用。
- **深度学习框架：** 模型训练可使用TensorFlow、PyTorch等主流框架实现全连接神经网络的构建、训练和推理。
- **类别不平衡处理工具：** scikit-learn中的SMOTE、RandomUnderSampler等采样工具，或框架内置的类别权重参数，可用于处理正负样本比例悬殊的问题。
- **模型评估指标库：** AROC（曲线下面积）、平衡准确率、F1分数、Cohen's kappa系数等指标可通过scikit-learn或框架内置函数计算，用于全面评估模型性能。
