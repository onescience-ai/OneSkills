# ERA5再分析数据源核验工作流

## 适用范围

**触发条件**：
- 需要获取ERA5再分析数据作为气象分析输入
- 需要验证ERA5数据的来源、版本、时空覆盖和数据质量
- 需要区分真实观测数据与合成数据

**适用场景**：
- 气象数据分析任务中的数据源验证
- ERA5数据获取前的完整性预检
- 数据质量评估和来源追溯

**不适用场景**：
- 非ERA5数据的源验证（需参考其他数据源规范）
- 仅需数据下载而不需质量验证的场景
- 合成数据生成任务（合成数据不得替代真实观测）

## 输入

**必需输入**：
- 目标数据变量列表（如温度、湿度、气压、风场）
- 目标区域和时段
- 数据分辨率要求（0.25°或0.1°）

**可选输入**：
- 数据格式偏好（NetCDF、GRIB）
- 质量标志要求

## 输出

**输出产物**：
- 数据来源追溯报告
- 版本信息（ERA5/ERA5-Land/ERA5 hourly）
- 时空覆盖验证结果
- 质量标志说明
- 数据完整性预检报告

**验证标准**：
- 所有必需字段（Conventions、title、source）存在
- 版本信息明确
- 时空覆盖与任务要求一致
- 质量标志可解读

## 流程节点

### Step 1：CDS API认证与连接
- **操作**：配置ECMWF CDS API密钥，建立API连接
- **参数**：CDS_URL=https://cds.climate.copernicus.eu, API_KEY=用户密钥
- **工具**：cdsapi库
- **质量门禁**：API连接成功，认证有效

### Step 2：数据变量与时空范围定义
- **操作**：定义目标变量、区域、时段和分辨率
- **参数**：变量列表、区域边界、时间频率、网格分辨率
- **工具**：ERA5变量字典
- **质量门禁**：变量名称符合CDS标准，时空范围在ERA5覆盖内

### Step 3：数据下载与元数据检查
- **操作**：通过CDS API下载数据，检查全局属性
- **参数**：产品类型、数据格式、下载路径
- **工具**：cdsapi、xarray/netCDF4
- **质量门禁**：文件可读取，元数据字段完整

### Step 4：版本标识核验
- **操作**：检查数据版本、生产时间、处理版本
- **参数**：版本字段（如`product_version`、`creation_date`）
- **工具**：NetCDF全局属性读取
- **质量门禁**：版本信息明确，与官方发布一致

### Step 5：时空覆盖验证
- **操作**：验证数据的时间轴和空间网格覆盖
- **参数**：时间范围、纬度/经度范围、网格点数
- **工具**：xarray坐标检查
- **质量门禁**：时间轴连续，空间网格完整

### Step 6：质量标志解读
- **操作**：检查数据质量标志和缺测处理
- **参数**：质量变量、_FillValue、valid_range
- **工具**：NetCDF属性解析
- **质量门禁**：质量标志存在，缺测值已标记

### Step 7：数据血缘记录
- **操作**：记录数据获取全过程，建立可追溯性
- **参数**：获取时间、API参数、文件哈希
- **工具**：元数据记录脚本
- **质量门禁**：血缘信息完整，哈希值可验证

## 关键参数

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 数据源 | ECMWF CDS API | [1] | 官方数据获取途径 |
| 产品类型 | ERA5 hourly/pressure levels | [1] | 再分析数据产品 |
| 空间分辨率 | 0.25°×0.25° | [1] | 全球网格 |
| 时间覆盖 | 1979至今 | [1] | 历史数据范围 |
| 标准变量 | temperature, specific_humidity, u_component_of_wind, v_component_of_wind | [1] | 标准气象变量 |
| 质量标志 | quality_flag, generation_time | [1] | 数据质量信息 |
| 文件格式 | NetCDF-4 | [2] | 标准气候数据格式 |
| 版本字段 | product_version, creation_date | [1] | 数据版本标识 |

## 边界与分流

**异常处理**：
- API连接失败：检查网络、代理、API密钥
- 数据不存在：验证变量名称、时空范围是否在ERA5覆盖内
- 下载中断：支持断点续传，验证文件完整性
- 版本不匹配：记录实际版本，评估对任务的影响

**降级策略**：
- 完整ERA5不可用时，可考虑ERA5-Land（仅陆面变量）
- 高分辨率数据不可用时，可降级到标准分辨率
- 实时数据不可用时，可使用再分析数据

**分支条件**：
- 若任务要求实时观测，ERA5不适用（需使用卫星或地面观测）
- 若任务仅需趋势分析，可接受较低分辨率数据

## 质量检查

**验证点**：
- 文件全局属性包含Conventions、title、source等ERA5标准字段
- 时间轴连续且覆盖目标时段
- 空间网格完整且覆盖目标区域
- 变量单位符合ERA5标准（K, kg/kg, Pa, m/s）
- 质量标志变量存在且可解读
- 文件大小与预期相符

**阈值**：
- 元数据字段缺失率=0
- 时间覆盖率≥99%
- 空间覆盖率≥99%
- 质量标志解释率=100%

**失败处理**：
- 元数据不完整：重新下载或补充元数据
- 覆盖率不足：调整时空范围或使用补充数据源
- 质量标志缺失：标注数据质量未知，降低验收等级

## 回退策略

**替代方案**：
- CDS API不可用时，可使用本地镜像或缓存数据
- 特定变量不可用时，可使用替代变量或插值方法
- 高分辨率数据不可用时，可使用降尺度方法

**应急措施**：
- 紧急任务可先使用合成数据进行方法开发，但必须明确标注为非正式结果
- 长期任务应建立数据缓存和备份机制

## 资源召回建议

**何时召回**：
- 任务需要ERA5再分析数据作为输入
- 需要验证气象数据的来源和质量
- 需要区分真实观测与合成数据

**配套资源**：
- 气象数据时空对齐工作流（climate-meteorological-data-spatiotemporal-alignment）
- 气象产品质控工作流（climate-meteorological-product-quality-control）
- 文件完整性校验工作流（climate-file-integrity-verification）
