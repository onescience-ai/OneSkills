# OneScience 领域分类标准与路由规则

## 适用范围

科研任务初始化阶段的领域归属判定场景。当用户提交科研任务时，需要正确识别任务所属的一级领域（bio / matchem / climate / cfd / general），以便后续知识路由、资源召回和专家匹配。领域标签错误会导致知识检索偏差——例如将地球科学全领域任务错误归类为气候子领域，可能遗漏海洋、固体地球等相关知识资源。

## 输入

- 任务描述文本
- 场景索引中的 domain 字段（标准参考值）
- domain_profile.md 领域定义文档

## 输出

- 确定的领域标签（应与场景索引一致）
- 领域判定理由

## 流程节点

1. 场景索引 domain 字段确认 → 2. 领域定义匹配 → 3. 标签一致性校验

### 步骤1：场景索引 domain 字段确认

场景索引（scenario_workflow_capabilities_overview.jsonl）中每个任务条目包含 `domain` 字段，这是领域分类的标准参考值。任务初始化时必须首先读取并保留此字段，不得擅自修改。

### 步骤2：领域定义匹配

根据 OneScience domain_profile.md 的定义：

| 一级领域 | 覆盖范围 | 典型任务 |
|----------|----------|----------|
| **earth** | 地球科学全领域，包含但不限于：天气监测与预报、气候模拟、海洋动力学、固体地球物理、大气化学、水文、生态遥感 | 天气雷达临近预报、地震预警、海洋环流模拟 |
| **climate** | 气候预测与气候模拟子领域：长期气候趋势、气候情景分析、气候模式评估、气候变化影响 | CMIP6 数据分析、RCP 情景预估 |
| **bio** | 生物信息学与生命科学：基因组学、蛋白质组学、代谢组学、分子进化 | RNA-seq 差异表达、蛋白质结构预测 |
| **matchem** | 材料科学与化学计算：材料设计、分子模拟、催化机理、电池模拟 | DFT 计算、材料筛选 |
| **cfd** | 计算流体力学：流场模拟、湍流建模、空气动力学 | N-S 方程求解、翼型优化 |
| **general** | 通用科研方法与工具：数据分析、可视化、机器学习通用方法 | 通用数据处理流程 |

**关键区分（earth vs climate）**：
- earth 是**父领域**，覆盖地球科学全领域
- climate 是 earth 的**子领域**，专指气候预测与模拟
- 天气监测/预报（如雷达临近预报）属于 **earth**（天气是 earth 的组成部分），不属于 climate（climate 特指气候时间尺度）
- 将天气任务归为 climate 属于领域术语理解错误

### 步骤3：标签一致性校验

- 对比 execution-manifest.json 中 task_understanding.domain 与场景索引的 domain 字段
- 不一致时以场景索引为准，修正 execution-manifest

## 关键参数

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 场景索引 domain 字段 | 由场景定义确定 | [系统内部] | 标准参考值，不可修改 |
| weather vs climate 判据 | 时间尺度 < 年 → weather/earth；时间尺度 ≥ 年 → climate | [通用] | 近临预报（0-2h）明确属于 weather/earth |
| domain_profile.md 读取 | 必须在 domain 标签设置前完成 | [系统内部] | 用于理解领域定义 |

## 边界与分流

- **场景索引缺失 domain 字段**：根据任务内容手动判定，优先匹配最具体的子领域
- **跨领域任务**：当任务同时涉及多个领域时，以主要计算内容所属领域为准，其他领域标签作为辅助
- **general 兜底**：无法匹配到具体领域时使用 general，但应尽量避免（降低知识召回精度）

## 质量检查

- 对比 execution-manifest.json 与 scenario_workflow_capabilities_overview.jsonl 中同一任务的 domain 字段
- 确认 domain 标签与实际任务内容一致

## 回退策略

- 标签不确定时：优先使用场景索引值，其次使用任务内容推断
- 错误标签已传播：在 observation 中记录不一致，建议后续修正
