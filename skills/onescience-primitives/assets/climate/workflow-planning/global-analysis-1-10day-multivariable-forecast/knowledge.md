# 全球分析场驱动的1—10天多变量确定性天气预报（E1）

## 适用范围

**适用场景**：
- 任务目标与“全球分析场驱动的1—10天多变量确定性天气预报”的对象、时空范围和输出定义一致。
- 能够在任务截止时间前获得并核实全球分析初场、起报时间、预报步长、变量与层次、资料截止时间，且数据覆盖和质量足以支持预测与情景评估。
- 能够获得与目标结果独立且口径一致的检验指标，或明确将任务限定为不作性能PASS判定的探索性运行。
- 目标区域、时间、变量和数据分布位于可验证的适用范围内，资源与交付期限不存在未确认的冲突。

**不适用场景**：
- 不包含原始观测同化、集合概率预报、公里级强对流或气候模拟。
- 关键输入缺失、来源不可追溯、使用权限不明确，且场景不允许补充或调整任务范围。
- 客户要求作性能PASS或正式业务验收，但只能使用参与训练或调参的数据，且无法建立独立、同协议的验证或回放。
- 目标区域、时段、变量、传感器或事件类型明显超出可验证范围，且没有经确认的补充数据与验证方案。

## 研究对象与输入

## 核心科学问题

1. 在遵守数据时点、任务边界和输入输出契约的前提下，能否可靠完成“全球分析场驱动的1—10天多变量确定性天气预报”的核心分析与目标结果生成并形成全球多层多变量确定性预报场、经明确配置的派生产品、产品元数据与文件清单？
2. 结果在场景要求的区域、时段、提前期、目标类别或强度区间内表现如何，能否围绕“同协议检验与交付判定”与同协议基线进行公平比较？
3. 缺测、观测误差、样本不均衡、初始条件、外部强迫或方法随机性带来的不确定性有多大，概率、区间或质量标志是否与独立样本误差相符？
4. 哪些结论由当前数据和独立检验直接支持，哪些只适用于特定区域、季节、事件或传感器条件，哪些因数据、资源或适用域限制不能得出？

## 工作流

### 步骤 1：起报范围与分析场预检

**目的**：固定起报时间、预报时效和变量范围，核验全球分析场的时次、层次、单位、坐标、缺测与资料截止时间。

| 参数 | 变量名 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|---|
| 全球分析初场 | `{INITIAL_ANALYSIS}` | str | 是 | — | 输入ERA5或业务分析场路径。 |
| 起报时间 | `{FORECAST_START_TIME}` | str | 是 | — | 输入UTC起报时间。 |
| 预报步长 | `{LEAD_DAYS}` | str | 是 | `1` | 输入待预报的步长。 |
| 变量与层次 | `{VARIABLES_AND_LEVELS}` | str | 是 | — | 输入变量名称和气压层。 |
| 资料截止时间 | `{DATA_CUTOFF_TIME}` | str | 是 | — | 输入资料截止时间。 |

**输出**：输入文件与资料截止时间清单、变量—层次—单位矩阵、分析初场预检报告

**质量门禁**：
- 所有动态输入的有效时间均不晚于起报时间
- 输入时次数量满足所选模型的单时次或双时次要求
- 必需变量、层次、单位和坐标均可识别
- 缺测、重复时次和异常值已记录且未擅自补造

**操作指令**：`读取{INITIAL_ANALYSIS}，以{FORECAST_START_TIME}为起报时间、{LEAD_DAYS}天为目标时效，核验{VARIABLES_AND_LEVELS}和{DATA_CUTOFF_TIME}。逐项报告时次、层次、单位、网格、缺测和异常；发现未来资料泄漏、关键时次缺失或变量不兼容时停止并标记BLOCKED。`

### 步骤 2：网格对齐与输入标准化

**目的**：依据版本化模型输入契约执行重网格、变量排序、单位换算、标准化及静态地理特征编码。

**依赖步骤**：s01

| 参数 | 变量名 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|---|
| 模型输入规格 | `{MODEL_INPUT_SPEC}` | str | 是 | — | 输入模型类型，如Swin-transformer、GNN、AFNO。 |
| 预处理配置 | `{PREPROCESS_CONFIG}` | str | 是 | — | 输入预处理配置路径。 |
| 缺测处理策略 | `{MISSING_VALUE_POLICY}` | str | 是 | — | 输入拒绝或插补策略。 |

**输出**：标准化模型输入张量、输入掩膜与静态特征、预处理转换清单

**质量门禁**：
- 张量维度、变量顺序、时次顺序和坐标方向与模型输入契约一致
- 经度周期、极点、日历和气压层顺序已核验
- 归一化参数与检查点版本一致
- 不存在模型不支持的NaN或Inf

**操作指令**：`根据{MODEL_INPUT_SPEC}和{PREPROCESS_CONFIG}处理通过预检的分析场，执行{MISSING_VALUE_POLICY}，生成与模型严格兼容的输入张量。记录每项重网格、单位换算、变量排序和标准化参数，保证处理可追溯。`

### 步骤 3：模型与检查点兼容性验证

**目的**：加载模型代码、配置和检查点，核验版本、哈希、输入输出通道并执行单步干运行。

**依赖步骤**：s01

| 参数 | 变量名 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|---|
| 模型权重路径 | `{MODEL_CHECKPOINT}` | str | 是 | — | 输入模型权重文件路径。 |
| 模型配置路径 | `{MODEL_CONFIG}` | str | 是 | — | 输入模型配置文件路径。 |
| 权重SHA-256 | `{CHECKPOINT_SHA256}` | str | 否 | — | 输入权重SHA-256。 |
| 推理设备 | `{RUNTIME_DEVICE}` | str | 是 | — | 输入运行设备，如GPU。 |

**输出**：模型与检查点身份报告、输入输出兼容性矩阵、单步干运行日志

**质量门禁**：
- 检查点SHA-256与登记值一致
- 代码、配置、标准化参数和检查点属于兼容版本
- 不存在缺失或意外的权重、变量和通道
- 单步干运行正常退出且输出形状和值域可检查

**操作指令**：`加载{MODEL_CONFIG}和{MODEL_CHECKPOINT}，核对{CHECKPOINT_SHA256}，在{RUNTIME_DEVICE}上执行一个原生时间步的干运行。报告代码、依赖、配置和权重版本；存在通道错配、缺失权重或未登记转换时停止。`

### 步骤 4：1—10天确定性状态滚动

**目的**：按模型原生推进方式生成目标时段内的全球多变量确定性预报轨迹。

**依赖步骤**：s02、s03

| 参数 | 变量名 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|---|
| 状态推进策略 | `{ROLLOUT_STRATEGY}` | str | 是 | — | 输入自回归或多时效推进。 |
| 输出时间间隔 | `{OUTPUT_INTERVAL_HOURS}` | str | 是 | `6` | 输入输出间隔，单位小时。 |
| 保存中间状态 | `{SAVE_INTERMEDIATE_STATES}` | str | 否 | `true` | 输入是否保存中间状态。 |
| 运行随机种子 | `{RANDOM_SEED}` | str | 否 | — | 输入随机种子。 |

**输出**：标准化全球确定性预报序列、中间状态检查点、推理日志与资源统计

**质量门禁**：
- 目标时段内预报时次完整且不存在重复、跳步或时间错位
- 所有输出的维度、变量顺序和坐标与模型契约一致
- 每一步输出均不存在NaN或Inf
- 滚动过程中未读取起报时间之后的分析或验证资料
- 断点续算未混用不同检查点、配置或预处理版本

**操作指令**：`采用{ROLLOUT_STRATEGY}，以{OUTPUT_INTERVAL_HOURS}小时为间隔，把标准化初场推进至{LEAD_DAYS}天。按{SAVE_INTERMEDIATE_STATES}保存中间状态并固定{RANDOM_SEED}；逐步记录有效时刻、输入来源、输出形状、数值范围、耗时和资源占用。`

### 步骤 5：物理量恢复与产品生成

**目的**：执行反标准化、单位恢复和必要的网格转换，生成带完整时空坐标与版本元数据的多变量产品。

**依赖步骤**：s04

| 参数 | 变量名 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|---|
| 交付网格 | `{OUTPUT_GRID}` | str | 是 | — | 输入目标网格。 |
| 输出格式 | `{OUTPUT_FORMAT}` | str | 是 | — | 输入NetCDF、Zarr或GRIB2。 |
| 派生产品 | `{DERIVED_PRODUCTS}` | str | 否 | — | 输入派生产品，逗号分隔。 |
| 结果保存路径 | `{OUTPUT_DIRECTORY}` | str | 是 | — | 输入预报结果保存路径。 |

**输出**：全球多层多变量确定性预报场、经明确配置的派生产品、产品元数据与文件清单

**质量门禁**：
- 反标准化参数与输入预处理版本严格对应
- 变量单位、物理范围、坐标、日历和有效时间已核验
- 输出文件能够重新打开且维度、变量和元数据完整
- 派生变量均有明确公式和源变量

**操作指令**：`将预报序列反标准化并恢复物理单位，按{OUTPUT_GRID}和{OUTPUT_FORMAT}写入{OUTPUT_DIRECTORY}。仅生成可由现有变量和明确公式得到的{DERIVED_PRODUCTS}，同时写入起报时间、有效时间、模型、检查点、配置、变量、单位和处理历史。`

### 步骤 6：同协议检验与交付判定

**目的**：验证资料可用时按变量、层次、区域和时效计算确定性技巧，并与同条件基线比较。

**依赖步骤**：s05

| 参数 | 变量名 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|---|
| 独立验证资料 | `{VERIFICATION_REFERENCE}` | str | 否 | — | 输入验证资料路径。 |
| 基线预报 | `{BENCHMARK_FORECAST}` | str | 否 | — | 输入基线预报路径。 |
| 检验指标 | `{METRICS}` | str | 是 | — | 输入检验指标，逗号分隔。 |
| 验证与验收协议 | `{VALIDATION_PROTOCOL}` | str | 否 | — | 输入验收协议路径。 |

**输出**：分变量分层分区域分时效技能报告、同协议基线比较报告、频谱、活动度与稳定性诊断、质量判定与交付清单

**质量门禁**：
- 预报、基线和参考资料采用一致的起报时间、网格和面积权重
- 验证资料未参与本次模型输入或参数选择
- 指标按变量、层次、区域和时效分层报告
- 只有达到预先登记的验收门限才能判定性能PASS
- 验证资料或门限缺失时不作性能通过声明
- 配置、命令、退出码、日志、产物路径和文件哈希可追溯

**操作指令**：`若{VERIFICATION_REFERENCE}可用，依据{VALIDATION_PROTOCOL}计算{METRICS}，并在同起报、同参考和同网格条件下比较{BENCHMARK_FORECAST}；同时检查频谱、预报活动度、异常极值和长滚动稳定性。资料或门限缺失时不得用论文结果替代本次验证。`

## 执行前确认事项

- 所有输入是否真实存在、可读、获准使用，并具有可追溯的来源、版本、时间和空间覆盖。
- 变量定义、单位、坐标、网格、时间含义、缺测规则和质量标志是否与目标结果一致。
- 训练、参数选择、阈值调优、验证和基线样本是否相互独立，是否存在时间或空间泄漏。
- 所选方法工件、配置和运行环境是否兼容，最小干运行是否满足输入输出契约且无异常数值。

## 必要结果项

- **input_data_result**：输入数据与版本清单、时空和变量覆盖、质量与缺测报告、资料截止时间、预处理记录、样本索引及数据血缘。
- **core_result**：按冻结输入输出契约得到的全球分析场驱动的1—10天多变量确定性天气预报核心结果、中间状态、运行日志、配置身份和异常记录；具体算法不得被反写为客户需求。
- **product_result**：可重新读取的全球多层多变量确定性预报场、经明确配置的派生产品、产品元数据与文件清单，并附单位、坐标、有效时间、质量标志、派生规则、文件清单和校验信息。
- **validation_result**：使用独立资料完成“同协议检验与交付判定”的分层指标、同协议基线比较、误差案例和验收判定；若没有预先确认的验收门限，不得把指标结果标记为性能PASS。
- **uncertainty_and_limit_result**：说明数据误差、抽样误差、方法随机性、情景或外部强迫、外推和适用域限制；概率、区间或质量标志应给出可验证样本上的校准证据，无法量化时须明确原因。
- **结论结果**：给出区分已验证结果、探索性观察、未通过项和无法回答问题的结论报告，不得把文件生成成功等同于科学或业务性能通过。
