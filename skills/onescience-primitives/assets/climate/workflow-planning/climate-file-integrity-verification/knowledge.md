# 文件完整性校验工作流

## 适用范围

**触发条件**：
- 需要验证文件在传输和存储过程中未被篡改
- 需要建立文件可追溯性
- 需要确保交付物完整性

**适用场景**：
- 科学数据产品的交付与验证
- 研究成果的可复现性保证
- 业务系统中的文件完整性检查

**不适用场景**：
- 实时数据流的完整性检查（需流式哈希算法）
- 大规模文件系统的批量校验（需专用工具）
- 非文件形式的数据完整性检查

## 输入

**必需输入**：
- 待校验的文件列表
- 元数据模板（用于记录哈希值）
- 哈希算法选择（默认SHA-256）

**可选输入**：
- 已有哈希值参考
- 校验频率要求
- 自动化脚本模板

## 输出

**输出产物**：
- 文件哈希值列表
- 完整性验证报告
- 元数据更新（包含哈希值）
- 校验日志

**验证标准**：
- 哈希值计算正确
- 元数据格式规范
- 校验报告完整
- 可追溯性建立

## 流程节点

### Step 1：文件清单准备
- **操作**：准备待校验的文件清单
- **参数**：文件路径、文件类型、重要性等级
- **工具**：文件扫描工具
- **质量门禁**：文件清单完整，路径正确

### Step 2：哈希算法选择
- **操作**：选择适当的哈希算法
- **参数**：算法类型（SHA-256、MD5等）、性能要求
- **工具**：算法选择指南
- **质量门禁**：算法选择合理，满足安全要求

### Step 3：SHA-256哈希计算
- **操作**：计算每个文件的SHA-256哈希值
- **参数**：计算参数、错误处理
- **工具**：hashlib库（Python）
- **质量门禁**：哈希计算正确，结果一致

### Step 4：哈希值记录
- **操作**：将哈希值记录在元数据中
- **参数**：记录格式、字段名称
- **工具**：元数据更新脚本
- **质量门禁**：记录格式规范，字段完整

### Step 5：完整性验证
- **操作**：验证文件完整性（与参考哈希值比较）
- **参数**：参考哈希值、比较方法
- **工具**：验证脚本
- **质量门禁**：验证方法正确，结果明确

### Step 6：校验报告生成
- **操作**：生成完整性校验报告
- **参数**：报告模板、证据来源
- **工具**：报告生成工具
- **质量门禁**：报告完整，结论明确

### Step 7：元数据更新
- **操作**：更新元数据文件（如execution-manifest.json）
- **参数**：更新字段、格式要求
- **工具**：元数据更新脚本
- **质量门禁**：元数据更新正确，格式规范

### Step 8：校验日志记录
- **操作**：记录整个校验过程
- **参数**：日志级别、记录内容
- **工具**：日志记录工具
- **质量门禁**：日志完整，可追溯

| 参数 | 值 | 来源 | 说明 |

## 边界与分流

**异常处理**：
- 哈希计算失败：检查文件权限、磁盘空间
- 哈希值不匹配：记录差异，评估影响
- 元数据更新失败：检查格式、字段名

**降级策略**：
- SHA-256不可用时，可使用MD5（但安全性较低）
- 完整校验不可行时，可进行抽样校验
- 自动化脚本不可用时，可手动计算并记录

**分支条件**：
- 若文件为关键交付物，必须进行完整校验
- 若文件为中间结果，可进行基本校验
- 若文件为临时文件，可跳过校验

## 质量检查

**验证点**：
- 哈希值计算正确
- 元数据格式规范
- 校验报告完整
- 可追溯性建立

**阈值**：
- 哈希计算成功率=100%
- 元数据格式正确率=100%
- 校验报告完整率=100%
- 可追溯性建立率=100%

**失败处理**：
- 哈希计算失败：修复文件权限或磁盘问题
- 哈希值不匹配：重新传输或修复文件
- 元数据更新失败：修复格式或字段错误
- 校验报告不完整：补充缺失内容

## 回退策略

**替代方案**：
- SHA-256不可用时，可使用MD5（但需标注安全性较低）
- 完整校验不可行时，可使用抽样校验
- 自动化脚本不可用时，可手动计算

**应急措施**：
- 紧急任务可先使用简单校验，但必须标注为初步结果
- 长期任务应建立标准化校验流程和模板
