# 用于淹没深度预报的NARX网络配置

## 适用范围

适用于需要基于外生输入（如降雨、风速等）进行**多步超前时间序列预报**，且在实际预报阶段目标变量（如洪水淹没深度）的实时观测值不可用或不可靠的场景。典型问题包括洪水淹没深度预报、短期气象预报、水质预测等，其共同特征是：1) 存在显著的外部驱动因素；2) 预报步长可能较长（例如数小时）；3) 使用模型自身预测值进行反馈会引入误差累积风险。本方案提供了一种通过网络结构设计（循环反馈）来缓解误差累积的方法，并给出了明确的实施流程和性能基准。

## 输入

- **必需输入**：
    - **外生输入序列**：来自监测站点（如雨量站）的历史或实时观测数据。典型配置需要至少包含当前时刻及若干个滞后时刻的数据。例如，对于三个站点，使用当前及前两个时刻（t, t-1, t-2）的降雨强度，共6个输入值。
    - **训练数据集**：由历史事件或经过验证的水文水动力模型生成的大量“外生输入-目标变量”数据对，用于训练网络。
    - **目标变量**（训练阶段）：用于监督学习的历史目标变量观测值或模拟值。

- **可选输入**：
    - **网络结构参数**：如外生输入的滞后阶数（p）、反馈输入的滞后阶数（q）、隐藏层节点数等。若未提供，需通过试验误差法确定。
    - **训练超参数**：如学习率。

## 输出

- **多步预报值**：模型输出的未来第1步至第n步的目标变量预测序列。对于循环配置（R-NARX），这是在线持续生成的预报。
- **训练好的模型权重**：保存的神经网络参数，用于后续的在线预报。
- **性能评估指标**：常用指标包括均方根误差（RMSE）和平均归一化峰值误差（ANPE）。

## 流程节点

1.  **数据生成与准备 (s1)**
    *   **步骤描述**：利用经过充分验证的水文/水动力模型（如HEC-1、SWMM、二维非惯性地表径流模型）生成覆盖不同重现期事件的训练与测试数据集。
    *   **上游依赖**：无。
    *   **输入**：
        | 参数名 | 类型 | 默认值 | 是否必需 | 说明 |
        | :--- | :--- | :--- | :--- | :--- |
        | `rainfall_events` | `str` | “设计降雨事件和历史台风事件” | 是 | 包括用于训练的设计降雨事件（如24个）和用于测试的历史降雨事件（如31个） |
    *   **质量门**：数据应由经验证的模型生成，覆盖足够多的降雨事件，保证代表性。

2.  **网络构建与参数设置 (s2)**
    *   **步骤描述**：确定循环NARX网络（R-NARX）的拓扑结构。其核心是将模型自身的预测输出作为网络的一个额外输入。
    *   **上游依赖**：s1。
    *   **输入**：
        | 参数名 | 类型 | 默认值 | 取值范围 | 是否必需 | 说明 |
        | :--- | :--- | :--- | :--- | :--- | :--- |
        | `p` | `int` | 2 | >=0 | 是 | 外生输入（如降雨）的滞后阶数，即使用t, t-1, ..., t-p+1时刻的数据 |
        | `q` | `int` | 1 | >=1 | 是 | 模型输出反馈的滞后阶数，通常反馈前一时刻(t-1)的预测值 |
    *   **输出**：定义好的R-NARX网络架构。总输入维度 = (外生输入站点数 * p) + q。
    *   **质量门**：网络结构（如隐藏层节点数）应通过试验误差法在训练集上优化确定。一个典型值是单隐藏层，3个节点。

3.  **在线训练与权重调整 (s3)**
    *   **步骤描述**：使用在线反向传播算法对网络进行训练。在每个训练样本呈现时，将模型自身的输出（在训练阶段为真实值或带噪声值）反馈至输入层，并计算误差，通过最陡下降法调整权重。
    *   **上游依赖**：s1, s2。
    *   **输入**：
        | 参数名 | 类型 | 默认值 | 是否必需 | 说明 |
        | :--- | :--- | :--- | :--- | :--- |
        | `learning_rate` | `float` | 无 | 是 | 控制权重更新步长的超参数，需根据误差能量函数调整 |
    *   **输出**：训练稳定的神经网络权重矩阵。
    *   **质量门**：网络权重应达到稳定，误差在训练集上无法进一步显著减小。

4.  **在线多步超前预报 (s4)**
    *   **步骤描述**：固定训练好的权重，进入纯预报模式。模型仅接收实时外生输入（如降雨）和自身前一步的预测输出，持续生成未来1至n步的预报值，可连续运行较长时间（如24小时）。
    *   **上游依赖**：s3。
    *   **输入**：
        | 参数名 | 类型 | 是否必需 | 说明 |
        | :--- | :--- | :--- | :--- |
        | `realtime_rainfall` | `float` | 是 | 来自雨量站的实时小时降雨强度序列，是驱动预报的唯一外部信息 |
    *   **输出**：未来1至n步的淹没深度预报值序列。
    *   **质量门**：预报过程能持续进行，且误差累积增长速率应显著低于无反馈的配置（如O-NARX）。

5.  **性能评估与比较 (s5)**
    *   **步骤描述**：使用测试集数据评估模型性能。将预报值与模拟真实值对比，计算RMSE和ANPE。通常会将R-NARX与性能上限（T-NARX）和基准（如O-NARX）进行比较。
    *   **上游依赖**：s4。
    *   **输入**：
        | 参数名 | 类型 | 是否必需 | 说明 |
        | :--- | :--- | :--- | :--- |
        | `forecast_values` | `float` | 是 | 模型产生的预报值序列 |
        | `simulated_values` | `float` | 是 | 测试集中的模拟真实值 |
    *   **输出**：性能指标（RMSE, ANPE）以及与对比模型的差异分析。
    *   **质量门**：R-NARX模型的RMSE增长率应显著低于O-NARX，且相对于O-NARX的性能提升建议超过30%才具有实用价值。

## 边界与分流

- **使用T-NARX的边界**：当且仅当在**实际预报阶段也能获得目标变量的准确实时观测值**时，才应使用T-NARX（静态配置）。它提供了在理想输入条件下的理论最优解，常作为评估其他实时预报模型性能的**上限基准**。在实际缺乏观测值的在线预报中，T-NARX无法应用。
- **使用R-NARX的边界**：适用于需要**在线、多步、持续**预报，且**实时观测目标变量不可得**的场景。其优势在于抑制误差累积，但性能受限于反馈预测值的质量。若反馈预测误差过大，性能仍会下降。
- **与传统NARX的分流**：传统（前馈）NARX网络在训练和测试时都使用真实的目标变量作为输入。这在实时预报超过一步时会导致“信息泄露”问题（测试时无法获得未来真实值）。R-NARX通过使用模型自身输出作为反馈解决了此问题，使其能用于实际的在线多步预报。
- **上下游衔接**：上游通常需要一个水文或水动力模型（如HEC-1, SWMM）来生成训练数据，并可能在预报流程中负责提供初始状态。下游可对接洪水预警系统、应急决策平台等。

## 回退策略

- **误差累积严重时**：若R-NARX的预报误差仍随步长快速累积，首先检查训练数据的代表性和质量，确保覆盖了极端事件。其次，可尝试调整网络结构（如增加隐藏层节点数）或反馈滞后阶数（q）。若仍无法满足要求，可能需要考虑其他抑制误差的方法，如集成预报、数据同化，或缩短单次持续预报的时长。
- **网络结构选择不当**：若初始性能不佳，应返回步骤s2，通过系统的试验误差法重新优化网络超参数（p, q, 隐藏层节点数）。
- **训练数据不足或不具代表性**：若模型在未见过的事件上表现差，需要扩充和更新训练数据集，增加更多类型和强度的降雨-洪水事件。可利用水文模型生成更多情景数据作为补充。
- **实时数据缺失或延迟**：在线预报高度依赖实时外生数据（如降雨）。如果数据中断，预报流程应暂停或切换至基于预报降雨的预测模式，并需明确标注此时预报的不确定性大幅增加。

## 资源召回建议

- **核心算法与工具**：需基于反向传播算法实现或调用神经网络工具包（如MATLAB Neural Network Toolbox, Python的PyTorch/TensorFlow/Keras）来构建、训练R-NARX模型。
- **水文水动力模型**：为生成高质量训练数据，可调用HEC-1、SWMM（用于城市排水）、二维浅水方程求解器（用于地表漫流）等模型。
- **参数调优**：网络结构的超参数（如节点数）通过试验误差法确定，需要可靠的计算资源进行网格搜索或随机搜索。学习率等训练参数需在训练过程中监控调整。
- **性能评估**：RMSE和ANPE是常用的回归任务评估指标，可利用标准统计软件库（如scikit-learn, NumPy）计算。
