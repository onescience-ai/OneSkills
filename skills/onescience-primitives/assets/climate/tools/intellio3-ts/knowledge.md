# 基于CNN的臭氧预测深度学习模型与评估方法

## 适用范围

适用于需要基于地面监测站多变量时间序列对未来数天近地面臭氧浓度进行统计预报或数据驱动预报的场景。典型触发条件包括：拥有至少数年的臭氧及其前体物（NO、NO₂）小时浓度观测，同时具备同步的气象驱动数据（温度、云量、相对湿度、风速等）；目标为输出日最大8小时平均臭氧浓度（dma8eu）的 1–4 天逐日预报；并需要与线性回归、气候学、持续性等基线模型进行技能对比。

该方案特别适合背景站点（受局地排放干扰较小）的区域臭氧预报，也可作为区域空气质量模型（如 CMAQ、WRF-Chem）后处理或统计降尺度的参考架构。对于需要逐小时精细时间分辨率或预报超过4天以上的中长期预报场景，可能需要补充其他建模策略。

## 输入

- **必需**
  - 过去 6 天（−6 至 0 天）的多变量时间序列，包含以下 9 个变量：
    - 化学观测：臭氧浓度、NO 浓度、NO₂ 浓度
    - 气象变量：温度、云量、相对湿度、风速（以及相关的分量或派生量）
  - 每个变量需按日聚合，具体采用日最大8小时平均（dma8eu）指标。
- **可选**
  - 其他前体物浓度（如 CO、VOCs）或卫星遥感反演产品，可用于扩展输入维度。
  - 站点元数据（海拔、坐标、土地利用类型），可用于站点分组或迁移学习。

数据来源的典型方案：
- 臭氧及前体物浓度数据从 TOAR 数据库通过 REST API 获取。
- 气象变量从 COSMO-ERA6 再分析数据集获取。

## 输出

- 未来 1–4 天的日最大8小时平均臭氧浓度（dma8eu）逐日预测值。
- 模型评估指标（如 RMSE、MSE、技能评分 skill score），用于与基线模型比较。
- 输入变量重要性排序（基于自助法技能评分归因）。

## 流程节点

### 1. 数据获取与连接

从 TOAR 数据库（REST API）获取德国背景监测站的臭氧、NO、NO₂ 浓度小时数据。同时从 COSMO-ERA6 再分析数据集获取同步的气象变量。确保时间覆盖范围满足训练集至少 10 年数据的要求。

### 2. 特征工程与预处理

将小时级原始数据聚合为日最大8小时平均（dma8eu）指标。对每个变量进行缺失值处理和质量控制，确保各站点在训练时间范围内有效数据完整。将化学观测与气象变量按日期对齐，形成统一的多变量时间序列。

### 3. 时间划分数据集构建

采用严格的时间划分法，避免随机划分导致的时间自相关泄漏：
- 训练集：1997-01-01 至 2007-12-31
- 验证集：2008-01-01 至 2009-12-31
- 测试集：2010-01-01 至 2015-12-31

各站点需满足在训练集内至少拥有 1 年有效数据的最低要求。验证集用于超参数调优，测试集用于最终的独立性能评估。

### 4. 模型架构设计

构建包含两个 inception 块的卷积神经网络。每个 inception 块并行执行多种卷积操作（核大小包括 1×1、3×1、5×1），在最后一层将所有输出拼接。该架构的并行多尺度卷积能够同时捕捉短期突变和中期趋势模式。

输入为过去 6 天（7 个时间步 × 9 个变量）的展平时间序列，输出为未来 1–4 天的臭氧浓度预测值。

### 5. 模型训练

在高性能计算环境（如 JUWELS）上训练模型，关键超参数如下：

| 参数 | 取值 |
|---|---|
| 优化器 | Adam |
| 初始学习率 | 10⁻⁴ |
| 批量大小（batch size） | 512 |
| 训练轮数（epochs） | 300 |
| 卷积核大小 | 1×1, 3×1, 5×1 |

训练过程在验证集上监控性能，防止过拟合。

### 6. 独立测试评估与基线比较

使用时间上完全独立的测试集（2010–2015）评估模型最终预报技能。与以下基线模型进行比较：
- 持续性模型（persistence）：以当前值作为未来预报值。
- 气候学模型（climatology）：以历史同期均值作为预报值。
- 普通最小二乘线性回归（OLS）模型。

### 7. 输入变量重要性分析

对每个监测站和每个输入变量，使用自助法进行归因分析：
- 保留 8 个变量不变，对目标变量进行随机置换抽样（每个变量每站重复 20 次）。
- 将修改后的输入送入已训练模型，获得新的预测值。
- 基于 MSE 计算技能评分，以原始预测为参考，量化各变量对预报性能的贡献。

## 边界与分流

- **预报时长边界**：该模型的训练与验证针对 1–4 天的短期预报。当预报时长超过 2 天时，模型性能可能低于气候学参考模型，因为单站时间序列数据包含的确定性信息随预报时长衰减。对于中长期预报（>4 天），应考虑使用数值天气预报（NWP）产品作为驱动场，或采用气候统计降尺度方法。
- **数据划分约束**：必须使用时间划分而非随机划分，否则因臭氧浓度的强时间自相关性，评估结果可能过于乐观。
- **极端事件捕捉**：模型对训练集中稀少的极端高浓度事件的捕捉能力有限。对于极端事件预警需求，可结合化学传输模型（CTM）的物理机制输出或极端值统计方法（如 EVT）进行补充。
- **变量相关性影响**：当输入变量间存在强相关性时（如 NO 与 NO₂），自助法归因可能低估被随机化变量的真实影响，因为剩余相关变量可部分补偿信息损失。
- **空间迁移**：该模型的训练数据来自德国背景监测站，若迁移至其他地理区域或城市站点，需根据当地污染特征重新训练或进行迁移学习微调。

## 质量检查

- **时间完整性**：确认各站点在训练、验证、测试时间范围内数据连续性，有效数据占比应满足最低阈值（如训练集至少 1 年）。
- **数据一致性**：核对化学观测数据与气象再分析数据的时间对齐性，确保无日期错位。
- **评估指标合理性**：对比模型与基线的技能评分（skill score），确认模型相对于气候学和持续性模型具有正技能。若模型在某类站点或某季节表现异常，需检查训练数据分布。
- **变量重要性稳健性**：检查自助法重复次数（20次）是否足以提供稳定的变量重要性排序，必要时可增加重复次数。

## 回退策略

- **数据获取失败**：若 TOAR API 或 COSMO-ERA6 数据不可用，可从本地存档或其他空气质量数据平台（如 EEA AirBase、OpenAQ）获取同源变量，但需确保变量定义（如 dma8eu 计算方式）一致。
- **训练数据不足**：若某站点训练期内有效数据不足 1 年，可将该站点从训练集中剔除，或采用多站联合训练（pooling）策略，利用区域站点的共同模式进行预训练。
- **模型性能不及基线**：若模型在测试集上的 RMSE 高于气候学模型，可能表明输入信号中的确定性成分不足。此时应检查数据质量、扩展输入变量（如增加卫星遥感产品）、或简化模型结构以减少过拟合。
- **极端值预测失效**：若模型在高浓度事件期间系统性低估，可在训练目标中引入加权损失函数（对高浓度样本赋予更高权重），或在后处理阶段结合分位数回归进行校正。

## 资源召回建议

- **模型代码**：IntelliO3-ts 模型的完整实现代码可在 GitLab 项目中获取（Jülich 超算中心 toar/mlair 仓库）。
- **训练框架**：模型基于 Keras 2.2.4 构建，使用 TensorFlow 1.13.1 作为后端。用户可根据环境选择兼容版本。
- **数据接口**：TOAR 数据库 REST API 位于 join.fz-juelich.de，提供标准化的臭氧及前体物时序数据访问。
- **气象再分析**：COSMO-ERA6 数据集可通过对应的数据中心获取，需注意空间分辨率和时间分辨率的匹配。
- **计算资源**：模型训练在大规模 HPC 环境（如 JUWELS）上完成，300 epochs 的训练对 GPU 资源有一定需求。在个人工作站上可适当减少 epochs 或采用早停策略。
- **相关基线工具**：OLS 回归可使用 scikit-learn 实现；持续性与气候学基线模型的计算简单，可作为任何预报系统的标准对照。
