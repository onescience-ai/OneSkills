# Aardvark端到端数据驱动天气预测系统

## 适用范围

面向直接从原始观测数据（原位站点与卫星遥感）生成全球网格预报和本地站点预报的需求，端到端数据驱动天气预测系统提供了绕过传统数值天气预报（NWP）数据同化与模式积分环节的替代路径。典型适用场景包括：

- 快速生成全球多变量网格预报（如2米温度、10米风速等），用于气象决策支持或可视化；
- 生成本地站点级预报产品，对接区域预报服务需求；
- 在NWP系统不可用或计算资源受限时，作为预报补充或替代方案；
- 研究数据同化与预报一体化的机器学习架构设计。

该系统在训练阶段依赖高质量再分析数据（如ERA5），部署阶段则完全独立于NWP产品，仅需原始观测数据即可运行。

## 输入

- 必需：原始观测数据，包括原位站点观测（地面站、探空等）和卫星遥感数据（光谱亮温、辐射率等）。
- 可选：历史再分析数据用于模型训练与校准；特定变量的先验统计信息。

输入数据通常具有以下特征：
- 异构来源（站点、卫星、再分析）；
- 空间分布不规则（站点稀疏、卫星覆盖密集）；
- 时间序列连续但采样率各异。

对于高维光谱数据，可能需要通过主成分分析（PCA）等降维方法限制输入数据量，以适应模型处理能力。

## 输出

- 全球网格预报：多个气象变量的网格化预报场，空间分辨率1.50°，垂直分层5层。
- 本地站点预报：针对特定站点的变量预报（如2米温度、10米风速）。

输出格式通常为标准气象数据格式（如NetCDF），可直接用于后续分析、可视化或与其他预报系统集成。

## 流程节点

1. **数据预处理与编码**：将异构观测数据（原位站点与卫星遥感）通过编码器模块进行统一表征。编码器基于视觉Transformer架构，能够处理不规则分布的观测数据，并估计初始大气状态。

2. **状态更新与预报生成**：编码后的状态表示送入处理器模块（同样基于视觉Transformer），进行时序演化与空间插值，生成未来时刻的大气状态预测。

3. **解码与输出生成**：处理器输出通过解码器模块（轻量卷积架构）映射为目标预报变量，生成全球网格场和本地站点预报。

4. **质量检查与后处理**：对生成的预报场进行物理一致性检查（如变量范围、空间平滑度），必要时进行后处理校准。

整个流程从观测数据输入到预报输出，在4块NVIDIA A100 GPU上约1秒完成，相比传统NWP系统（如HRES）的数据同化与预报流程需约1000节点小时，计算效率显著提升。

## 边界与分流

- **与NWP系统的关系**：该系统设计为NWP的补充或替代，而非改进。当需要高分辨率、物理一致性更强的预报时，传统NWP（如HRES、GFS）可能更合适。

- **数据依赖**：训练阶段需要高质量再分析数据（如ERA5）作为监督信号，若缺乏此类数据，模型性能可能受限。

- **变量覆盖**：当前系统主要输出常见气象变量（温度、风速等），对于专业变量（如化学成分、云微物理）可能不适用。

- **空间分辨率**：当前分辨率为1.50°，对于需要更高分辨率（如区域精细化预报）的应用，需考虑其他方案。

## 质量检查

- **预报一致性**：检查预报变量是否在物理合理范围内（如温度无异常极端值）。
- **空间连续性**：验证网格场是否平滑、无明显伪影或断裂。
- **站点-网格一致性**：比较站点预报与同位置网格预报，确保局部与整体协调。
- **时间演变合理性**：检查预报随时间变化是否符合大气动力学规律。

## 回退策略

- **观测数据缺失或质量差**：当输入观测数据严重不足或质量低下时，系统可能生成不准确的预报。此时应回退至基于再分析数据的后处理方法，或使用传统NWP系统（如GFS）作为补充。

- **模型性能局限**：系统在较高大气层和较短预报提前时间误差较大，长预报提前时间可能出现频谱模糊。对于这些场景，建议结合其他预报方法（如集合预报）进行综合决策。

- **计算资源不足**：虽然系统本身计算效率高，但若部署环境无法支持GPU推理，可考虑使用预训练模型在CPU上运行（性能可能下降），或回退至传统NWP。

## 资源召回建议

- **代码与模型**：开源实现可在GitHub获取（aardvark-weather-public）。
- **训练数据**：ERA5再分析数据可通过ECMWF数据中心获取。
- **相关工具**：可与传统NWP系统（如GFS、NDFD）的结果进行对比或集成。
- **架构组件**：系统采用视觉Transformer、卷积条件神经过程、SetConv层等技术，相关实现可参考对应的机器学习库。
