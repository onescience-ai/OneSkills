# 分时段闪电发生概率场生成

## 适用范围

适用于0-6小时闪电发生临近预报任务的s04阶段，当需要从训练好的深度学习模型对新数据执行推理并生成分时效闪电概率场时使用。不适用于模型训练过程、模型选择和超参调优、超出0-6小时的预报。

## 输入

- 训练好的模型检查点：包含模型权重和配置的文件（如.ckpt、.pt、.h5格式）
- 对齐后的输入数据：经过s02时空对齐的标准输入（雷达体扫、闪电历史、对流环境场）
- 推理配置：起报时间、预报时效、输入时间窗口长度、批处理大小
- 模型架构参数：网络结构、输入通道数、输出维度

## 输出

- 分时效闪电概率场栅格：T+1h至T+6h共6个时段的概率场（NetCDF格式）
- 推理运行日志：每时段推理耗时、GPU内存使用、异常记录
- 模型置信度场（可选）：每个网格点的预测不确定性估计

## 流程节点

### 1. 模型加载与配置冻结 → 2. 输入数据预处理 → 3. 逐时段推理 → 4. 概率场后处理 → 5. 输出格式化与元数据

**步骤1：模型加载与配置冻结**
- 操作：加载训练好的模型检查点，冻结模型参数
- 参数：
  - 检查点路径：指向训练产出的模型文件
  - 设备配置：GPU/CPU选择
  - 随机种子：确保推理可复现
- 质量门禁：模型加载成功，参数冻结；输入输出维度与训练时一致

**步骤2：输入数据预处理**
- 操作：将s02对齐后的数据转换为模型输入格式
- 参数：
  - 输入时间窗口：通常取最近6-12帧历史数据作为输入
  - 归一化参数：使用训练时的均值和标准差
  - 数据类型：float32（GPU推理）或float16（混合精度）
- 质量门禁：输入形状匹配模型期望；无NaN/Inf值

**步骤3：逐时段推理**
- 操作：对每个目标提前期（T+1h至T+6h）分别执行模型推理
- 参数：
  - 目标提前期：T+1h, T+2h, T+3h, T+4h, T+5h, T+6h
  - 时间切分方法：按业务需求划分，每段1小时
  - 推理模式：滑动窗口（每5分钟更新一次预报）
- 关键约束：
  - 仅使用起报时间及之前的观测数据，不得使用未来观测
  - 每个提前期独立推理，不共享中间状态
- 质量门禁：每个提前期均生成概率场；无未来信息泄漏

**步骤4：概率场后处理**
- 操作：对模型原始输出进行校准和平滑
- 参数：
  - 概率校准：Platt scaling或等渗回归（使用验证集校准）
  - 空间平滑：高斯平滑（σ=1-2网格点），减少噪声
  - 概率裁剪：[0, 1]区间裁剪
- 质量门禁：校准后概率分布在[0,1]；空间平滑后极值减少但整体分布不变

**步骤5：输出格式化与元数据**
- 操作：将概率场保存为标准NetCDF格式
- 参数：
  - 文件命名：`lightning_prob_T+{leadtime}h_{init_time}.nc`
  - 变量名：`lightning_probability`
  - 维度：time, latitude, longitude
  - 元数据：起报时间、坐标系、单位、数据来源、模型版本
- 质量门禁：文件可被xarray/NetCDF4正确打开；元数据完整

## 边界与分流

### 模型加载失败
- **前提**：检查点文件存在且格式正确
- **不成立时**：检查检查点路径和格式；若版本不兼容，尝试使用旧版推理代码
- **改道目标**：模型版本管理、检查点修复

### 输入数据不完整
- **前提**：s02对齐后的数据完整且无NaN
- **不成立时**：检查缺失帧；若缺失≤2帧，使用前向填充；否则标记该时段不可用
- **改道目标**：数据完整性检查、缺测填充

### 推理超时
- **前提**：单次推理在合理时间内完成（<30秒/帧）
- **不成立时**：减小批处理大小；启用混合精度推理；检查GPU内存
- **改道目标**：推理优化、资源调整

### 概率分布异常
- **前提**：输出概率在[0,1]且分布合理
- **不成立时**：检查归一化参数；若概率集中在0或1附近，调整校准参数
- **改道目标**：概率校准调整

## 质量检查

- 文件完整性：6个提前期文件全部生成
- 格式检查：NetCDF文件可正确打开，变量名和维度正确
- 元数据检查：起报时间、坐标系、单位信息完整
- 概率范围检查：所有值在[0,1]区间
- 信息泄漏检查：推理仅使用起报时间及之前的观测
- 空间连续性检查：概率场无异常断裂或空洞

## 回退策略

- 模型加载失败：使用备用检查点或重新训练
- 推理超时：降低分辨率或启用模型量化
- 概率分布异常：使用训练集统计量重新校准
