# CLI非交互执行故障诊断工作流

## 适用范围

面向科学计算工作流中命令行接口（CLI）的非交互执行场景，提供故障分类、退出码诊断、标准错误判读与恢复策略的通用方法框架。适用于各类需要自动化调用CLI工具的科研工作流，包括但不限于CFD求解器、归因分析器、数据处理管道等工具的稳定性保障。不适用于交互式命令行会话或图形界面工具的故障诊断。

## 输入

- CLI命令及其参数配置
- 执行环境信息（操作系统、shell版本、依赖库版本）
- 故障现场证据（退出码、标准错误输出、日志文件）
- 预期执行行为描述（正常退出条件、超时阈值）

## 输出

- 故障分类报告（故障类别、根因分析、影响范围）
- 恢复策略建议（配置修正、重试策略、降级方案）
- 诊断证据链（退出码映射、错误模式匹配、日志关键片段）

## 流程节点

1. **故障检测** → 收集退出码、标准错误、超时状态
2. **故障分类** → 按退出码映射表归类故障类型
3. **根因分析** → 结合错误信息和上下文确定根本原因
4. **恢复策略生成** → 根据故障类别选择对应修复方案
5. **验证执行** → 执行修复后重新运行CLI验证恢复效果

每步含：操作、参数、工具、质量门禁

## 边界与分流

- **认证故障**：当退出码指示权限问题时，转向认证配置检查流程（检查API key、token、证书等）
- **沙箱限制**：当标准错误包含权限拒绝或资源限制信息时，转向沙箱环境配置调整
- **超时故障**：当退出码为137或标准错误包含OOM信息时，转向资源分配优化或任务拆分
- **Schema校验失败**：当退出码为3或标准错误包含"validation"关键词时，转向报告格式检查流程
- **依赖缺失**：当退出码为127时，转向依赖环境安装或PATH配置检查

## 质量检查

- 退出码必须与标准错误信息一致，不一致时标记为"异常退出"
- 恢复策略必须包含验证步骤，确认修复后CLI可正常执行
- 诊断报告必须包含完整的证据链（退出码→错误模式→根因→修复方案）

## 回退策略

- 当无法确定具体故障类别时，执行通用诊断流程：检查依赖→检查权限→检查资源→检查配置
- 当恢复策略无效时，记录详细诊断信息并标记为"需人工介入"
