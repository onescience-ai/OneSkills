# JSON Schema 报告交付契约

## 适用范围

面向科学计算工作流中的结构化报告交付场景，提供JSON Schema校验、字段约束、任务身份匹配与输出格式规范的通用方法框架。适用于各类需要输出结构化报告的科研工具，包括归因报告、实验报告、分析报告等产物的质量保障。不适用于非结构化文本输出或二进制产物的校验。

## 输入

- JSON Schema定义文件（规定必填字段、类型约束、格式要求）
- 待校验的JSON报告文件
- 任务身份信息（task_id、task名称）
- 校验规则配置（严格模式/宽松模式、错误处理策略）

## 输出

- 校验结果报告（通过/失败、错误详情、警告信息）
- 修复建议（缺失字段提示、类型修正建议、格式调整方案）
- 校验证据链（字段→约束→校验结果→错误位置）

## 流程节点

1. **Schema加载** → 解析JSON Schema定义，提取校验规则
2. **报告解析** → 读取待校验JSON文件，验证基础格式
3. **字段校验** → 按Schema逐字段校验必填性、类型、格式
4. **身份匹配** → 验证task_id、task名称与任务索引一致性
5. **数组约束校验** → 验证数组字段的存在性、元素类型、非空约束
6. **校验报告生成** → 汇总校验结果，生成结构化诊断报告

每步含：操作、参数、工具、质量门禁

## 边界与分流

- **字段缺失**：当必填字段不存在时，生成"字段缺失"错误，建议补充字段或修改Schema
- **类型不匹配**：当字段类型与Schema定义不符时，生成"类型错误"错误，建议类型转换或修正Schema
- **任务身份不一致**：当task_id与任务索引不匹配时，生成"身份不一致"错误，建议核对任务配置
- **数组约束违反**：当数组字段违反非空或元素类型约束时，生成"数组约束错误"，建议调整数组内容
- **JSON解析失败**：当报告文件无法解析为有效JSON时，生成"格式错误"，建议检查文件编码或内容格式

## 质量检查

- 校验报告必须包含完整的错误位置信息（字段路径、行号、列号）
- 校验结果必须区分"错误"和"警告"级别
- 修复建议必须具体可操作，不泛泛建议

## 回退策略

- 当Schema文件无法加载时，执行基础格式校验（JSON解析、必填字段检查）
- 当校验规则不明确时，采用最严格的校验模式，宁可误报不可漏报
