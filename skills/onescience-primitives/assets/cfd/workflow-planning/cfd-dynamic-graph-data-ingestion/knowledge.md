# 动态图数据接入与契约核验

## 适用范围

**触发条件**：
- 已有动态图或拉格朗日粒子时序数据，需要在模型训练前完成数据审计
- 需要建立数据契约以确保后续步骤的数据格式一致性
- 需要检测数据质量问题（缺失值、单位不一致、训练测试泄漏）

**适用场景**：
- CFD数据集的接入与质量审计
- 物理模拟数据的变量和单位核验
- 图结构数据的拓扑和坐标系一致性检查

**不适用场景**：
- 已有标准化数据契约的成熟数据集（可跳过本步骤）
- 纯图像或规则网格数据（本卡针对动态图和粒子数据）

## 输入

- **{DATASET_PATH}**：数据集目录或清单文件路径（必需）
- **{DATASET_NAME}**：数据集名称，标识来源与版本（必需）
- **{DATA_CONTRACT}**：数据契约定义，含变量、单位、网格坐标规范（可选）

## 输出

- **dataset_manifest.json**：数据文件清单，含文件名、大小、格式、样本数
- **data_contract.json**：机器可读的数据契约，含变量名、单位、坐标系、网格拓扑定义
- **data_audit.md**：数据审计报告，含质量发现和风险标注

## 流程节点

### Step 1.1：文件可读性检查
- **操作**：遍历数据集目录，验证所有数据文件可读、格式正确、无损坏
- **参数**：数据集路径、支持的文件格式列表
- **工具**：文件系统遍历、格式解析器
- **质量门禁**：所有声明的文件均可成功读取；无零字节或损坏文件

### Step 1.2：样本与变量核验
- **操作**：统计样本数量，提取变量名列表，核验输入变量与目标变量的完整性
- **参数**：数据契约（如有）
- **工具**：数据解析脚本、JSON Schema校验器
- **质量门禁**：样本数可追溯（与元数据一致）；输入目标变量定义完整

### Step 1.3：单位与坐标系检查
- **操作**：核验物理量单位一致性、坐标系定义完整性、网格拓扑有效性
- **参数**：数据契约中的单位和坐标定义
- **工具**：单位转换库、坐标系校验器
- **质量门禁**：所有变量单位明确且一致；坐标系定义完整；网格拓扑无孤立节点

### Step 1.4：泄漏检测
- **操作**：检查是否存在训练集与测试集信息泄漏风险（如同一轨迹同时出现在训练和测试中）
- **参数**：数据集分组标识（如有）
- **工具**：集合交集检测
- **质量门禁**：不存在训练测试泄漏；数据集分组边界清晰

### Step 1.5：契约生成
- **操作**：汇总审计结果，生成结构化数据契约和审计报告
- **参数**：审计发现汇总
- **工具**：JSON生成器、Markdown模板
- **质量门禁**：契约包含所有必需字段；审计报告列出所有发现

## 关键参数

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 必需输入 | DATASET_PATH, DATASET_NAME | [场景CFD_S020] | 缺少任一则返回BLOCKED |
| 可选输入 | DATA_CONTRACT | [场景CFD_S020] | 缺省时按数据集原生格式解析 |
| 输出格式 | JSON + Markdown | [场景CFD_S020] | 契约为JSON，审计为Markdown |
| 缺失值处理 | 标注但不填充 | [场景CFD_S020] | 审计阶段只发现不修复 |

## 边界与分流

- **缺少必填输入**：返回BLOCKED并列出缺项清单，不得编造数据
- **数据格式不支持**：列出支持的格式，标注不支持的格式供后续处理
- **单位冲突**：标注冲突变量，建议统一方案但不自动转换
- **泄漏风险**：标注泄漏来源，在后续切分步骤中强制规避

## 质量检查

- 文件完整性：100%文件可读
- 变量完整性：所有声明变量均有定义
- 单位一致性：同类变量单位统一
- 坐标有效性：所有坐标在合理范围内
- 拓扑有效性：图连接无自环、无孤立节点

## 回退策略

- 文件损坏时：标注损坏文件，跳过继续审计其余文件
- 格式不支持时：记录格式信息，等待格式转换工具
- 单位缺失时：在契约中标注"待确认"，不推断默认单位
