# Orchestrator 规划阶段时间预算管理规则

## 适用范围
本卡片服务于CFD任务编排中的时间预算管理问题，面向需要将复杂CFD任务拆分为多个执行步骤的orchestrator系统。当规划阶段消耗时间超过总预算50%时，应强制生成最小化execution-manifest.json并转入执行阶段，避免因过度规划导致任务超时。适用于任何需要平衡规划质量与执行时间的科学计算任务编排场景。

## 输入
- **任务总时间预算**：用户指定的总超时时间（如20分钟）
- **当前规划阶段耗时**：从规划开始到当前时刻的时间消耗
- **已识别的步骤列表**：规划阶段已识别的执行步骤（如s01-s05）
- **每个步骤的executor绑定**：已确定的执行技能映射
- **步骤间依赖关系**：已识别的步骤依赖

## 输出
- **最小化execution-manifest.json**：包含task_id、步骤列表、每步的executor绑定、输入输出契约和依赖关系
- **时间预算监控状态**：规划阶段剩余时间百分比
- **强制转换触发信号**：当规划时间超过阈值时触发执行阶段转换

## 流程节点
时间监控 → 阈值检测 → 最小manifest生成 → 执行阶段转换

**时间监控**：
- 操作：在规划阶段持续监控时间消耗，记录每个规划子步骤的耗时
- 参数：总时间预算T_total，当前耗时T_current
- 质量门禁：时间监控本身不应消耗超过总预算的5%

**阈值检测**：
- 操作：检查当前规划耗时是否超过总预算的50%
- 条件：T_current / T_total > 0.5
- 质量门禁：阈值检测应准确，避免误触发

**最小manifest生成**：
- 操作：基于已识别的步骤列表，生成最小化的execution-manifest.json
- 内容：task_id、steps数组（每步含step_id、goal、executor、inputs、outputs、dependencies）
- 质量门禁：manifest必须包含所有已识别步骤，即使部分细节未完善

**执行阶段转换**：
- 操作：将控制权从规划阶段转移到执行阶段，启动第一个执行步骤
- 质量门禁：转换过程不应丢失已规划的步骤信息

## 关键参数

### 通用判据（方法层）
| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 规划阶段时间预算占比 | 30-40% | [通用实践] | 规划阶段应占总预算的30-40% |
| 强制转换阈值 | 50% | [1] | 当规划耗时超过总预算50%时触发 |
| 最小manifest完整性 | 100% | [通用实践] | 必须包含所有已识别步骤 |
| 时间监控开销 | <5% | [通用实践] | 监控本身不应消耗过多时间 |
| 步骤信息保留率 | 100% | [通用实践] | 转换时不应丢失已规划步骤 |

### 校准数值（CFD任务专属值）
| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 典型CFD任务总预算 | 20分钟 | [CFD_S010] | 汽车几何到阻力系数回归任务 |
| 规划阶段合理耗时 | 6-8分钟 | [CFD_S010] | 基于总预算20分钟 |
| 执行阶段合理耗时 | 12-14分钟 | [CFD_S010] | 基于总预算20分钟 |
| 步骤数量典型值 | 5-6步 | [CFD_S010] | s01-s05或s01-s06 |
| 单步执行时间 | 2-3分钟 | [CFD_S010] | 平均每步执行时间 |

## 边界与分流
- 规划阶段耗时未超过50% → 继续完善规划，不触发强制转换
- 规划阶段耗时超过50%但未生成manifest → 立即生成最小化manifest并转入执行
- 已生成manifest但未转换 → 直接启动执行阶段，跳过剩余规划
- 任务总预算未知 → 使用默认值（如30分钟），或向用户询问
- 规划阶段完全无进展 → 立即生成空manifest（仅含task_id和空步骤列表）并转入执行，记录异常

## 质量检查
- 时间监控准确性：验证时间测量误差小于1%
- 阈值检测正确性：验证在阈值边界时的触发行为
- manifest完整性：验证生成的manifest包含所有已识别步骤
- 转换无损性：验证转换后所有规划信息完整保留

## 回退策略
- 时间监控失效 → 使用固定时间间隔检查（如每30秒）
- 阈值检测误判 → 采用保守策略，宁可提前转换也不超时
- manifest生成失败 → 使用模板生成最小化manifest，仅包含task_id和步骤ID列表
- 转换过程失败 → 记录错误状态，允许用户手动干预
