# CFD流水线执行容错与状态管理

## 适用范围

面向CFD仿真任务的多步骤流水线，提供数据获取、预处理、模型训练、推理和评估等步骤的执行管理、容错策略和状态跟踪方案。适用于需要处理复杂依赖关系、部分步骤可能失败且需要保留中间结果的科学计算工作流。

## 输入

- 任务配置文件（如config.yaml），包含物理参数、模型参数和评估指标
- 数据源路径或数据获取方式
- 执行环境信息（本地或HPC集群）

## 输出

- 结构化的执行清单（execution-manifest.json），记录每个步骤的状态、时间戳和错误信息
- 可恢复的中间产物（数据文件、模型检查点、评估结果）
- 最终报告，包含成功/失败状态和质量评估

## 流程节点

1. **任务初始化** → 生成初始execution-manifest.json
   - 操作：在流水线启动时立即创建manifest文件，包含task_id、初始状态和时间戳
   - 参数：task_id, 初始状态
   - 工具：Python文件操作
   - 质量门禁：manifest文件存在且为有效JSON

2. **步骤执行** → 每个步骤独立执行并更新manifest
   - 操作：执行当前步骤，捕获异常，更新manifest中的步骤状态
   - 参数：步骤配置、前置产物路径
   - 工具：具体步骤脚本、异常处理
   - 质量门禁：步骤执行完成且manifest已更新

3. **步骤依赖检查** → 检查前置产物是否存在
   - 操作：在执行每个步骤前检查所需数据文件是否存在
   - 参数：前置产物路径列表
   - 工具：文件系统检查
   - 质量门禁：所有必需的前置产物存在

4. **错误处理** → 根据错误类型决定继续或终止
   - 操作：分析错误类型（数据缺失、类型错误、计算失败等），决定是否跳过当前步骤或终止流水线
   - 参数：错误信息、步骤配置
   - 工具：异常处理逻辑
   - 质量门禁：错误被正确分类且决策合理

5. **状态报告** → 生成最终报告
   - 操作：汇总所有步骤状态，生成结构化报告
   - 参数：execution-manifest.json内容
   - 工具：报告生成脚本
   - 质量门禁：报告包含所有步骤的状态和错误摘要

## 关键参数

### 通用判据（方法层，同类体系可参考）

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| manifest生成时机 | 流水线启动时 | [1] | 必须在首个步骤执行前生成，确保即使第一步失败也有记录 |
| 步骤独立性检查 | 每个步骤执行前 | [1] | 检查前置产物是否存在，而非依赖前一步骤的状态标记 |
| 错误分类 | 数据缺失、类型错误、计算失败 | [1] | 不同错误类型需要不同的处理策略 |
| 恢复策略 | 跳过失败步骤继续执行 | [1] | 当前置产物已存在时，可跳过失败步骤继续后续执行 |

### 校准数值（体系专属值）

以下数值来自对流与标量混合湍流热通量预测任务，供量级校准；其他体系需以自身证据重新锚定。

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| Rayleigh数类型 | float | [2] | YAML解析器通常将1e6解析为浮点数，但需显式类型转换 |
| 网格分辨率 | 可变 | [1] | 取决于具体CFD问题和求解器 |
| 时间步长 | 可变 | [1] | 取决于CFL条件和数值稳定性要求 |

## 边界与分流

1. **数据源不存在**：如果原始数据文件不存在，应检查是否有公开数据集可用，或使用合成数据生成器作为临时方案
2. **类型转换失败**：当YAML配置参数类型不匹配时，应在数据加载时进行显式类型转换
3. **步骤间依赖不满足**：如果前置产物不存在，应跳过当前步骤并记录状态，而非终止整个流水线
4. **计算资源不足**：当HPC作业失败时，应检查资源请求是否合理，并尝试调整参数重试

## 质量检查

1. **manifest完整性**：检查execution-manifest.json是否存在且包含所有步骤的状态
2. **数据一致性**：验证生成的数据文件符合预期的物理量级和统计特性
3. **类型安全**：确保所有数值参数经过适当的类型转换
4. **错误记录**：检查所有失败步骤是否被正确记录并包含错误信息

## 回退策略

1. **数据获取失败**：回退到合成数据生成器，但需在报告中标注数据来源为合成数据
2. **类型错误**：添加显式类型转换代码，如`float(config['physics']['rayleigh_number'])`
3. **步骤执行失败**：跳过失败步骤，基于已有数据继续执行后续步骤
4. **manifest生成失败**：在流水线入口处添加冗余的manifest生成逻辑

- 当需要处理步骤间依赖关系和容错策略时召回本卡片
