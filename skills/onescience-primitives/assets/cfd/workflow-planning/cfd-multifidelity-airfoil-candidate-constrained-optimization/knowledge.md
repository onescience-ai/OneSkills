# 候选生成与约束优化

## 适用范围

**触发条件**：
- 已完成模型训练，需要围绕目标性能生成候选并执行约束优化
- 需要保留完整搜索轨迹与Pareto前沿
- 需要确保候选满足几何和物理硬约束

**适用场景**：
- 多保真代理辅助翼型优化的候选生成与优化阶段
- 需要多目标Pareto前沿搜索
- 需要完整记录优化历史与随机种子

**不适用场景**：
- 单目标简单优化（无需Pareto前沿）
- 无约束优化问题
- 无需保留搜索轨迹的场景

## 输入

**必需输入**：
- 模型权重（通过训练门限权重）
- 计算设备（CPU或CUDA设备）

**可选输入**：
- 推理批大小（按显存调整批量）

**预处理要求**：
- 依赖s03的训练权重与数据契约
- 检查权重可加载性

## 输出

**核心产物**：
- design_candidates/：设计候选目录
- optimization_history.csv：优化历史记录
- pareto_front.json：Pareto前沿解集

**验证标准**：
- 候选满足几何和物理硬约束
- 优化轨迹与随机种子完整
- 最优候选未混用测试标签

## 流程节点

### Step 1：候选生成
- **操作**：基于代理模型在设计空间中采样生成候选设计
- **参数**：模型权重、采样策略、采样数量
- **工具**：代理模型推理工具、采样工具
- **质量门禁**：候选数量满足要求，候选在设计空间内

### Step 2：约束评估
- **操作**：评估候选是否满足几何和物理硬约束
- **参数**：约束定义、可行性阈值
- **工具**：约束评估脚本
- **质量门禁**：0个硬约束违反

### Step 3：优化搜索
- **操作**：执行贝叶斯优化搜索，保留完整搜索轨迹
- **参数**：优化器配置、探索参数
- **工具**：贝叶斯优化库
- **质量门禁**：优化轨迹与随机种子完整

### Step 4：Pareto前沿提取
- **操作**：从优化历史中提取Pareto前沿解集
- **参数**：目标函数、约束条件
- **工具**：Pareto前沿提取工具
- **质量门禁**：Pareto前沿解满足约束

## 边界与分流

**可行域为空时的改道**：
- 约束过于严格 → 放宽约束或引入松弛变量
- 设计空间定义不合理 → 调整设计空间边界

**Pareto前沿退化时的改道**：
- 前沿退化为单点 → 简化为单目标优化
- 前沿不连续 → 检查约束定义与目标函数

**优化搜索陷入局部最优时的改道**：
- 增加采样点数量
- 调整贝叶斯优化探索参数（如增大探索权重）

## 质量检查

| 检查项 | 阈值/判据 | 失败处理 |
|--------|-----------|----------|
| 约束满足 | 0个硬约束违反 | 过滤不可行候选 |
| 轨迹完整性 | 随机种子与评估记录完整 | 补充缺失记录 |
| 标签隔离 | 最优候选未混用测试标签 | 重新检查切分 |
| Pareto前沿有效性 | 前沿解满足约束 | 检查提取逻辑 |
| 候选多样性 | 候选覆盖设计空间 | 增加采样策略 |

## 回退策略

- 约束评估失败 → 检查约束定义，调整约束阈值
- 优化搜索失败 → 调整优化器参数，尝试其他优化策略
- Pareto前沿提取失败 → 检查目标函数定义，调整提取算法
