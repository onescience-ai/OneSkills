# CFD任务数据类型选择与模型适配边界

## 适用范围

本卡片为CFD任务中的数据类型选择提供边界知识，适用于隐式神经场（INR/CROM）降阶建模、神经算子学习、物理信息神经网络等需要输入数据类型匹配的场景。当任务要求连续坐标采样的PDE快照数据时，规则网格数据不满足要求；反之，当任务基于卷积神经网络时，连续坐标数据需要重新网格化。

## 输入

### 连续坐标采样数据
- 格式：(x, y, z, t) → (u, v, w, p) 的函数映射
- 特点：任意空间位置的采样点，不依赖规则网格
- 适用模型：隐式神经表示（INR）、连续降阶模型（CROM）、神经算子（如FNO、UNO）
- 证据：[1] 论文1使用分布函数f(x,t)作为连续空间场，通过神经算子学习时空演化

### 规则网格数据
- 格式：(i, j, k, t) → (u, v, w, p) 的数组映射
- 特点：固定网格分辨率，像素/体素对齐
- 适用模型：卷积神经网络（CNN）、U-Net、ResNet等
- 证据：[2] 论文2使用256×256像素的二值图像作为输入，通过CNN预测速度场

## 输出

### 数据类型匹配验证
- 检查数据格式是否满足模型输入要求
- 不匹配时返回BLOCKED状态并说明原因
- 验证标准：连续坐标数据适用于INR/CROM，规则网格数据适用于CNN

### 模型选择建议
- 根据数据类型推荐合适的模型架构
- 连续坐标数据 → INR/CROM/神经算子
- 规则网格数据 → CNN/U-Net/ResNet

## 流程节点

1. **数据格式检测** → 2. **模型需求分析** → 3. **匹配性验证** → 4. **BLOCKED/PASS判定**

### 步骤1：数据格式检测
- 操作：分析输入数据的坐标系统和采样方式
- 参数：坐标类型（连续/离散）、采样密度、网格分辨率
- 工具：数据审计脚本
- 质量门禁：明确识别数据类型

### 步骤2：模型需求分析
- 操作：检查目标模型的输入要求
- 参数：模型架构、输入维度、坐标系统
- 工具：模型配置解析
- 质量门禁：明确模型数据类型需求

### 步骤3：匹配性验证
- 操作：对比数据类型与模型需求
- 参数：匹配规则、边界条件
- 工具：匹配性检查逻辑
- 质量门禁：明确匹配/不匹配结论

### 步骤4：BLOCKED/PASS判定
- 操作：根据匹配性结果做出判定
- 参数：匹配性结论、替代方案
- 工具：判定逻辑
- 质量门禁：不匹配时必须返回BLOCKED

## 关键参数

### 通用判据
| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 连续坐标数据适用模型 | INR/CROM/神经算子 | [1] | 隐式神经场模型需要连续坐标输入 |
| 规则网格数据适用模型 | CNN/U-Net/ResNet | [2] | 卷积模型需要规则网格输入 |
| 数据类型不匹配处理 | 返回BLOCKED | 任务要求 | 缺少关键输入时必须如实标注 |

### 校准数值
| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| DeepCFD网格分辨率 | 172×79 | [2] | 规则网格示例 |
| 多孔介质图像分辨率 | 256×256 | [2] | 规则网格示例 |
| 神经算子网格泛化 | 跨分辨率推理 | [1] | 神经算子可泛化到不同网格分辨率 |

## 边界与分流

### 数据类型不匹配时
- 连续坐标场景使用规则网格数据 → 返回BLOCKED，说明数据类型不满足要求
- 规则网格场景使用连续坐标数据 → 需要重新网格化或使用适合连续坐标的模型

### 数据缺失时
- 无用户数据且无法获取公开数据 → 返回BLOCKED
- 有公开数据但类型不匹配 → 返回BLOCKED并建议替代数据源

### 模型选择错误时
- 使用CNN处理连续坐标数据 → 性能下降或失败
- 使用INR处理规则网格数据 → 可能工作但非最优

## 质量检查

### 验证点
1. 数据类型识别准确性
2. 模型需求分析完整性
3. 匹配性验证正确性
4. BLOCKED判定合理性

### 阈值
- 数据类型识别：100%准确
- 匹配性验证：0错误
- BLOCKED判定：不匹配时100%触发

### 失败处理
- 数据类型识别错误 → 重新审计数据格式
- 匹配性验证错误 → 重新分析模型需求
- BLOCKED判定遗漏 → 强制中断流程

## 回退策略

### 数据类型不匹配时
1. 检查是否有其他可用数据源
2. 评估是否可以转换数据格式
3. 如果无法转换，返回BLOCKED

### 模型选择错误时
1. 重新评估数据类型
2. 选择匹配的模型架构
3. 更新任务配置
