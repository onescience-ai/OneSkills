# CFD工作流超时监控与恢复机制

## 适用范围

适用于CFD工作流执行阶段，当任务在给定时间预算内无法完成时，需要超时监控机制来检测执行进度、保存中间状态、并触发优雅降级。该知识帮助确保任务在超时时不会完全丢失执行进度，而是输出当前执行快照供人工干预。

## 输入

- 工作流执行环境
- 任务执行状态信息
- 时间预算配置

## 输出

- 超时检测报告
- 中间状态快照（execution-manifest.json更新）
- 部分执行结果（如有）

## 流程节点

1. 任务启动 → 2. 时间预算分配 → 3. 执行进度监控 → 4. 超时检测 → 5. 优雅降级

### 步骤1：任务启动
- 操作：orchestrator启动任务并记录启动时间
- 参数：任务ID、工作流配置、总时间预算
- 工具：OneScience orchestrator技能
- 质量门禁：任务启动成功，时间预算记录完整

### 步骤2：时间预算分配
- 操作：根据工作流步骤复杂度分配每步时间预算
- 参数：总时间预算、步骤数量、步骤复杂度权重
- 工具：orchestrator技能
- 质量门禁：时间预算分配合理，总和不超过总预算

### 步骤3：执行进度监控
- 操作：在每个步骤执行期间监控执行进度
- 参数：当前步骤、预期完成时间、实际执行时间
- 工具：监控脚本或orchestrator内置监控
- 质量门禁：监控数据实时更新

### 步骤4：超时检测
- 操作：检测当前步骤或总任务是否超过时间预算
- 参数：当前时间、步骤开始时间、时间预算
- 工具：超时检测脚本
- 质量门禁：超时检测准确，无误报

### 步骤5：优雅降级
- 操作：当检测到超时时，保存当前执行状态并输出部分结果
- 参数：当前执行状态、已完成步骤、中间产物
- 工具：状态保存脚本
- 质量门禁：状态保存成功，部分结果可读

## 关键参数

### 通用判据
| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 超时检测频率 | 每步骤完成时 | [1] | 在每个步骤完成时检测是否超时 |
| 时间预算分配策略 | 按步骤复杂度加权 | [2] | 复杂步骤分配更多时间 |
| 状态保存内容 | execution-manifest.json + 当前步骤产物 | [3] | 保存可恢复的中间状态 |
| 降级输出格式 | 部分结果 + 阻塞原因 | [4] | 输出当前可用的结果和阻塞原因 |

### 校准数值
以下数值来自科学计算工作流实践，供量级校准；其他体系需以自身证据重新锚定。

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 典型总超时 | 3600s（1小时） | [4] | 单任务总超时阈值 |
| 单步超时比例 | 20%-30% | [2] | 单步占总预算的最大比例 |
| 状态保存开销 | <5% | [3] | 状态保存不应显著影响执行时间 |

## 边界与分流

- **总时间预算未设置**：使用默认值（如3600s）并记录WARNING
- **单步执行超过预算**：触发该步骤的优雅降级，保存当前状态
- **总任务超时**：触发全局优雅降级，保存所有已完成步骤的状态
- **状态保存失败**：记录错误但不阻塞降级流程，输出最小化状态

## 质量检查

| 检查项 | 判据 | 失败处理 |
|--------|------|----------|
| 时间预算分配 | 总和不超过总预算 | 重新分配 |
| 超时检测准确性 | 无误报漏报 | 调整检测阈值 |
| 状态保存完整性 | 关键字段全部保存 | 重试保存 |
| 部分结果可读性 | 输出文件可解析 | 重新生成 |

## 回退策略

- 超时检测失败时，使用固定间隔检查作为备用
- 状态保存失败时，输出最小化状态（仅task_id和BLOCKED状态）
- 部分结果生成失败时，输出阻塞原因说明文件
