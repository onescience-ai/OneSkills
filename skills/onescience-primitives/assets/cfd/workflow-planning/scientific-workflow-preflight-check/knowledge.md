# 科研工作流预检流程设计

## 适用范围

本卡面向所有需要外部数据输入的科研计算任务（含 CFD、气象、生信、材料等领域），定义在核心工作流步骤执行前插入标准化预检（Preflight）流程的设计规范。预检步骤作为独立于业务逻辑的前置检查层，确保任务在遇到根本性输入缺失或环境问题时能快速、清晰地失败，而非在业务步骤中陷入难以诊断的错误。不适用于纯数值求解或无需外部输入的任务。

## 输入

- 任务配置参数（含数据集路径、运行站点配置、计算资源需求等）
- 场景索引定义的步骤依赖关系
- 编排器传入的 `step_handoff` 结构

## 输出

- 预检报告（precheck-report）：包含每个检查项的状态（pass/fail/needs_confirmation）、失败原因、建议修复措施
- 任务状态决策：`PRECHECK_PASSED`（继续执行）、`PRECHECK_FAILED`（终止）、`PRECHECK_NEEDS_CONFIRMATION`（等待人工确认）
- 结构化错误信息：供编排器和用户系统解析

## 流程节点

1. **参数完整性扫描** → 遍历任务配置，识别所有标记为"必填"的参数
2. **路径存在性验证** → 对所有文件/目录类必填参数执行存在性检查
3. **文件可读性验证** → 对已存在的文件执行可读性检查（权限、编码）
4. **基本格式预校验** → 对数据文件执行轻量级格式检查（文件头、扩展名）
5. **环境依赖检查** → 验证运行环境（conda 环境、Python 包、HPC 软件）是否就绪
6. **计算资源可用性检查** → 验证目标运行站点的计算资源（GPU/DCU、内存、队列）是否可用
7. **生成预检报告** → 汇总所有检查项，输出结构化报告
8. **决策路由** → 根据预检结果决定任务状态：通过→继续调度、失败→终止并报告、需确认→挂起等待

每步含：操作（具体检查逻辑）、参数（检查阈值、超时设置）、工具（文件系统 API、环境检测脚本、资源查询接口）、质量门禁（所有必填项通过才允许继续）

## 关键参数

### 通用判据

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 预检步骤位置 | 在所有业务步骤（s01-s0N）之前 | [论文4] | 预检必须是工作流的第一个执行步骤 |
| 必填参数检查 | 100% 覆盖 | [论文1] | 任何必填参数缺失即判定预检失败 |
| 预检超时 | ≤ 30 秒 | 通用实践 | 预检应是轻量级操作，不应阻塞过久 |
| 预检报告持久化 | 必须保存 | [论文4] | 供后续审计和问题排查使用 |
| 失败时终止策略 | 立即终止，不重试 | [论文4] | 根本性输入缺失不应触发自动重试 |

### 校准数值（来自具体 CFD 体系，供量级校准；其他体系需以自身证据重新锚定）

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| ChannelFlow-Tools 配置驱动检查 | 几何生成→SDF 体素化→LBM 模拟→ML 张量打包 | [论文1] | 每个阶段有独立的数据完整性校验点 |
| LBM 管道验证 | Strouhal 数、阻力系数、湍流脉动与实验对标 | [论文2] | 物理一致性验证作为数据质量门禁 |
| GenCast 数据初始化 | ERA5 分析数据 0.25° 网格，6 地表 + 6 大气变量 × 13 层 | [论文3] | 输入数据契约的完整定义示例 |
| Flow-Bench 异常检测 | 工作流执行日志注入异常并收集 | [论文4] | 异常检测作为预检流程的补充手段 |

## 边界与分流

- **预检通过**：继续调度后续业务步骤，预检报告作为执行记录保存
- **预检失败（数据缺失）**：任务以 `PRECHECK_FAILED` 状态终止，报告中包含缺失参数名和建议修复路径
- **预检失败（环境未就绪）**：任务以 `PRECHECK_FAILED` 终止，报告中建议调用 `onescience-installer` 技能修复环境
- **预检失败（运行站点不可用）**：任务以 `PRECHECK_FAILED` 终止，报告中建议调用 `onescience-runsite` 技能配置站点
- **预检失败（资源不足）**：任务以 `PRECHECK_FAILED` 终止，报告中列出可用资源和所需资源的差异
- **预检超时**：任务以 `PRECHECK_FAILED` 终止，报告中标注超时原因
- **需人工确认**：任务挂起，等待用户确认后继续或终止。仅用于网格分辨率偏差在容忍范围内等非致命场景

## 质量检查

- 预检步骤必须独立于业务逻辑，不得在预检中执行任何数据处理或模型训练操作
- 预检报告必须包含：检查项名称、状态、失败原因（如有）、建议修复措施（如有）、检查耗时
- 预检结果必须以结构化格式输出（JSON），便于编排器解析和用户界面展示
- 预检步骤本身不得引入新的数据依赖（即预检不需要额外的外部数据来验证当前数据）

## 回退策略

- 预检失败时，任务终止并返回明确的错误信息，不执行任何后续步骤
- 若系统支持降级模式（如使用默认数据路径），需在预检报告中标注降级原因
- 不允许"跳过预检直接执行"的模式，除非用户显式授权且记录在审计日志中
- 预检步骤本身的异常（如文件系统不可用）应被捕获并作为 `PRECHECK_FAILED` 报告

## 资源召回建议

- 当任务编排器准备调度任何需要外部数据输入的科研任务前，应先召回本卡
- 配套资源：`cfd-data-input-contract-validation` 卡（CFD 专用的数据验证规则）、`onescience-installer` 技能（环境安装）、`onescience-runsite` 技能（运行站点配置）
- 本卡可作为编排器的固定前置任务，也可作为独立的预检技能被调用
