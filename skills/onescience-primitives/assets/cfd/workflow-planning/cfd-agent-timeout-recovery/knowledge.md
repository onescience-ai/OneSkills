# 科研任务执行智能体超时处理与异常恢复策略

## 适用范围

面向科研任务执行智能体在工作流预检、步骤执行和资源调度过程中遇到的超时问题，提供超时检测、异常捕获、重试策略、优雅降级和状态持久化的系统性方法。适用于 OneScience 工作流引擎、科学计算工作流调度系统以及需要高可靠性的自主任务执行框架。

## 输入

- 任务执行环境配置（超时阈值、最大重试次数、降级策略）
- 工作流步骤定义（步骤类型、资源需求、依赖关系）
- 执行状态信息（当前步骤、已完成步骤、中间产物路径）
- 异常日志（超时错误、退出码、资源释放状态）

## 输出

- 超时检测结果（是否触发超时、超时时长）
- 异常处理决策（重试/降级/终止）
- 状态恢复信息（可恢复点、中间产物清单）
- 执行结果报告（成功/失败/降级完成）

## 流程节点

### 超时检测与监控

1. **超时阈值设定**
   - 根据步骤类型和资源需求设定超时阈值
   - 预检阶段：通常 5-15 分钟
   - 计算密集型步骤：根据任务复杂度动态调整
   - I/O 密集型步骤：考虑网络延迟和数据传输时间

2. **实时监控**
   - 启动后台监控线程，定期检查任务状态
   - 使用心跳机制检测任务是否响应
   - 记录任务执行时间线，用于后续分析

### 异常捕获与分类

1. **异常类型识别**
   - 超时异常（TimeoutError）
   - 资源不足异常（ResourceError）
   - 网络异常（NetworkError）
   - 依赖缺失异常（DependencyError）
   - 权限异常（PermissionError）

2. **异常上下文收集**
   - 异常发生时的执行状态
   - 已完成的工作量和中间产物
   - 系统资源使用情况（CPU、内存、磁盘）
   - 网络连接状态

### 重试策略

1. **指数退避重试**
   - 初始等待时间：1 秒
   - 退避因子：2（每次重试等待时间翻倍）
   - 最大等待时间：60 秒
   - 最大重试次数：3 次

2. **条件重试**
   - 仅对可恢复的异常进行重试
   - 检查资源是否可用后再重试
   - 避免在相同条件下重复失败

3. **重试状态保存**
   - 每次重试前保存当前状态
   - 记录重试次数和原因
   - 支持从断点恢复

### 优雅降级

1. **降级策略选择**
   - 降低计算精度以减少资源需求
   - 简化工作流步骤（跳过非关键步骤）
   - 使用替代算法或模型
   - 分批处理大数据集

2. **降级决策依据**
   - 资源可用性评估
   - 任务优先级判断
   - 用户配置的降级策略
   - 历史执行数据参考

3. **降级执行**
   - 记录降级决策和原因
   - 保存降级后的执行状态
   - 生成降级完成报告

### 状态保存与恢复

1. **检查点机制**
   - 在关键步骤完成后保存检查点
   - 检查点包含：步骤状态、中间产物、配置信息
   - 支持本地和远程检查点存储

2. **状态恢复**
   - 从最近的检查点恢复执行
   - 验证中间产物的完整性
   - 重新加载配置和依赖

3. **执行清单生成**
   - 无论成功或失败，都生成 execution-manifest.json
   - 记录执行状态、步骤结果、异常信息
   - 支持后续分析和调试

### 单任务总超时预算管理

1. **超时预算设置**
   - 单任务总超时预算应覆盖所有步骤的执行时间
   - 预算计算：步骤数 × 平均步骤时间 × 安全系数（通常1.5-2.0）
   - 动态调整：根据历史执行数据调整超时预算

2. **超时后状态保存**
   - 超时触发时，立即保存当前执行状态
   - 保存内容：当前步骤、已完成步骤、中间产物、错误信息
   - 状态保存到 task_state.json 和 execution-manifest.json

3. **超时恢复策略**
   - 从最近的检查点恢复执行
   - 跳过已完成的步骤
   - 重新计算剩余步骤的超时预算

### execution-manifest.json 生成时机与内容

1. **生成时机**
   - 计划完成后立即生成 execution-manifest.json
   - 包含完整步骤列表和依赖关系
   - 步骤执行前验证清单完整性

2. **必填内容**
   - task_id：任务唯一标识符
   - workflow_steps：步骤列表（id、name、status、dependencies）
   - resource_bindings：资源绑定信息
   - input_files：输入文件路径和格式
   - execution_config：执行环境配置

3. **清单校验**
   - 所有必填字段非空
   - 步骤依赖关系无循环
   - 资源绑定有效

## 边界与分流

### 超时阈值设定不当时
- 阈值过小：导致正常任务被误判为超时 → 转向调整阈值策略
- 阈值过大：导致资源长时间占用 → 转向资源监控和强制终止策略

### 重试失败时
- 连续 3 次重试失败 → 转向优雅降级策略
- 降级后仍无法完成 → 转向任务终止和状态保存

### 资源不足时
- 计算资源不足 → 转向降低计算精度或分批处理
- 内存不足 → 转向数据分块处理
- 磁盘空间不足 → 转向清理中间文件或使用远程存储

### 网络异常时
- 短暂网络中断 → 使用指数退避重试
- 长时间网络不可达 → 转向本地缓存和离线模式

## 质量检查

### 超时检测验证
- 模拟超时场景，验证智能体能否正确捕获超时异常
- 检查超时日志是否完整记录
- 验证超时后的状态保存

### 重试机制验证
- 模拟可恢复异常，验证重试策略是否生效
- 检查重试次数和等待时间是否符合预期
- 验证重试后的状态恢复

### 降级策略验证
- 模拟资源不足场景，验证降级决策
- 检查降级后的执行结果质量
- 验证降级报告的完整性

### 状态保存验证
- 验证检查点是否正确保存
- 测试从检查点恢复执行
- 检查 execution-manifest.json 的完整性

## 回退策略

### 重试失败回退
- 放弃当前任务，保存已执行状态
- 生成失败报告，记录失败原因
- 通知用户并提供手动干预选项

### 降级失败回退
- 尝试更激进的降级策略
- 如果仍无法完成，终止任务并保存状态
- 提供详细的日志和诊断信息

### 系统级回退
- 如果整个执行环境不可用，保存任务到持久化存储
- 提供任务恢复接口，支持后续重新执行
- 生成系统级错误报告
