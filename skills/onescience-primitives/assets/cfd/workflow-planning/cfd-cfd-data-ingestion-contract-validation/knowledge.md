# CFD数据接入与契约核验

## 适用范围

**触发条件**：
- 需要为CFD流场补全任务接入原始数据
- 需要验证数据完整性并建立机器可读的数据契约
- 数据来源为稀疏或缺损的CFD流场

**适用场景**：
- PIV实验数据接入
- CFD模拟输出数据接入
- 多源异构CFD数据的标准化接入
- 数据质量审计与契约生成

**不适用场景**：
- 数据已通过核验且契约已建立（跳至预处理步骤）
- 非CFD领域数据（需使用对应领域卡）

## 输入

| 输入项 | 格式 | 必填 | 说明 |
|--------|------|------|------|
| {DATASET_PATH} | 路径 | 是 | 数据集目录或清单文件路径 |
| {DATASET_NAME} | 字符串 | 是 | 数据集名称与版本标识 |
| {DATA_CONTRACT} | JSON对象 | 否 | 预定义的变量、单位、坐标系契约 |

## 输出

| 输出项 | 格式 | 说明 |
|--------|------|------|
| dataset_manifest.json | JSON | 数据集清单：文件列表、样本数、变量名、单位、坐标系 |
| data_contract.json | JSON | 机器可读数据契约：输入字段、目标字段、单位映射、坐标定义 |
| data_audit.md | Markdown | 数据审计报告：可读性、完整性、缺失值、许可信息 |

## 流程节点

### Step 1.1：文件可读性检查
- **操作**：遍历{DATASET_PATH}下所有数据文件，验证格式可解析（NetCDF/HDF5/CSV）
- **参数**：文件路径列表
- **质量门禁**：100%文件可解析

### Step 1.2：变量与单位核验
- **操作**：提取所有变量名、检查单位完整性、验证输入与目标变量定义
- **参数**：{DATA_CONTRACT}中的变量定义
- **质量门禁**：输入目标变量单位坐标定义完整

### Step 1.3：网格与坐标核验
- **操作**：检查网格拓扑（结构化/非结构化）、坐标系定义、维度一致性
- **参数**：坐标系类型、网格维度
- **质量门禁**：坐标系定义明确、维度一致

### Step 1.4：样本完整性检查
- **操作**：统计样本数、检查时间/工况范围、识别缺失值比例
- **参数**：时间/工况维度定义
- **质量门禁**：样本可追溯、缺失值比例已记录

### Step 1.5：训练测试泄漏检查
- **操作**：初步检查数据是否存在时间泄漏或轨迹交叉
- **参数**：切分前预检
- **质量门禁**：不存在训练测试泄漏

### Step 1.6：契约生成
- **操作**：汇总所有核验结果，生成机器可读的data_contract.json和data_audit.md
- **参数**：核验结果汇总
- **质量门禁**：契约字段覆盖率100%

## 关键参数

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 支持格式 | NetCDF, HDF5, CSV | [场景需求书] | 主流CFD数据格式 |
| 坐标系 | dataset_native | [场景需求书] | 默认使用数据集原始坐标系 |
| 缺失值检查 | 必须 | [场景需求书] | 记录比例但不阻塞 |
| 许可检查 | 必须 | [场景需求书] | 记录使用限制 |

## 边界与分流

- **文件不可读**：记录错误文件列表，部分可读时继续但标注受限
- **变量缺失**：若必需输入变量缺失 → BLOCKED并列出缺项
- **单位未定义**：强制要求单位信息，缺失则BLOCKED
- **坐标系不明**：默认dataset_native，但在audit中标注需用户确认
- **许可受限**：记录限制条件，不阻塞后续步骤但需在报告中说明

## 质量检查

- 所有数据文件格式可解析
- 输入/目标变量清单完整
- 单位映射无歧义
- 坐标系定义明确
- 样本数与预期一致
- 缺失值比例已量化

## 回退策略

- 格式不支持 → 转换工具预处理后重新接入
- 变量/单位缺失 → 联系数据提供方补充
- 泄漏风险 → 调整切分策略或标记隔离
