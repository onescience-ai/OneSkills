# onescience工作流编排中executor技能调用方式

## 适用范围
适用于onescience工作流编排中需要调用executor技能的场景，包括：
- 复杂科研任务的多步骤执行
- 技能编排和调度
- 工作流步骤的实现
- 执行状态的跟踪和传递

不适用场景：
- 简单单步骤任务（直接调用技能即可）
- 技能内部实现细节（由executor技能自身处理）
- 非onescience工作流编排

## 输入
- 步骤ID：当前步骤的唯一标识
- 任务上下文：用户目标、约束条件、相关产物
- 输入参数：步骤所需的具体输入
- 依赖关系：前置步骤的输出

## 输出
- 执行结果：步骤执行的成功/失败状态
- 产物文件：步骤生成的中间或最终产物
- 状态传递：供后续步骤使用的信息
- 执行日志：详细的执行过程记录

## 流程节点
1. **步骤解析** → 确定步骤ID和执行技能
2. **上下文准备** → 构建step_handoff结构
3. **技能调用** → 通过orchestrator调度executor技能
4. **状态跟踪** → 监控执行进度和状态
5. **结果回传** → 收集执行结果并传递给下一步

## 关键参数
| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| step_handoff格式 | YAML结构 | [onescience规范] | 标准输入格式 |
| 执行技能 | onescience-coder/runtime等 | [任务需求] | 根据步骤类型选择 |
| 状态传递 | execution_result | [输出契约] | 标准输出格式 |
| 完成标准 | 明确定义 | [任务规划] | 步骤完成的判定条件 |
| 错误处理 | 回退策略 | [最佳实践] | 失败时的处理方式 |

## 边界与分流
- **技能不可用**：记录阻塞原因并建议替代方案
- **依赖缺失**：检查前置步骤是否完成
- **参数错误**：提供参数格式说明和示例
- **执行超时**：设置合理的超时时间
- **资源不足**：检查计算资源并调整任务规模

## 质量检查
1. **格式验证**：确认step_handoff格式正确
2. **依赖检查**：确保所有前置条件满足
3. **执行记录**：检查skill_calls数组长度
4. **状态一致性**：验证执行结果与预期一致
5. **日志完整性**：确保执行过程可追溯

## 回退策略
1. **技能调用失败**：尝试其他执行技能或简化任务
2. **参数解析错误**：提供详细的参数说明和示例
3. **依赖循环**：重新设计工作流步骤顺序
4. **资源限制**：调整任务规模或使用更轻量级的技能
5. **执行超时**：增加超时时间或优化任务执行
