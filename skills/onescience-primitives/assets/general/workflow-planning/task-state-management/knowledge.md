# 任务状态管理规范

## 适用范围
当工作流包含多个步骤，需要跟踪每个步骤的完成状态、开始时间、结束时间、错误信息时使用本知识。适用于编排器、任务调度器、自动化流水线等场景。不适用于单步任务或无状态的工作流。

## 输入
- 任务定义：步骤列表、依赖关系、超时设置
- 执行上下文：当前步骤ID、执行结果、错误信息
- 状态文件路径：task_state.json、execution-manifest.json

## 输出
- 状态文件：包含所有步骤的当前状态、时间戳、错误信息
- 状态日志：状态变更历史记录
- 状态报告：任务进度摘要

## 流程节点
1. 状态定义 → 2. 状态初始化 → 3. 状态更新 → 4. 状态同步 → 5. 状态验证 → 6. 状态恢复

每步含：
- **操作**：状态字段定义、更新时机、同步机制
- **参数**：状态值（pending/running/completed/failed）、时间戳格式
- **工具**：JSON读写工具、文件锁机制
- **质量门禁**：状态一致性检查、时间戳合理性验证

## 关键参数

### 通用判据（方法层，同类体系可参考）
| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 状态值定义 | pending/running/completed/failed | 通用 | 四种基本状态 |
| 更新时机 | 步骤完成时立即更新 | 通用 | 避免状态丢失 |
| 时间戳格式 | ISO 8601 | 通用 | 跨平台兼容 |
| 状态文件格式 | JSON | 通用 | 人类可读、易于解析 |

### 校准数值（体系专属值）
| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 状态同步间隔 | 立即同步 | 任务需求 | 步骤完成后立即更新 |
| 状态文件备份 | 每次更新前备份 | 通用实践 | 防止文件损坏 |

以下数值来自通用实践，供量级校准；其他体系需以自身证据重新锚定。

## 边界与分流
- **状态丢失风险**：使用原子写入或文件锁防止并发写入导致状态丢失
- **状态不一致**：定期校验状态文件与实际执行状态的一致性
- **性能影响**：状态更新不应成为性能瓶颈，考虑批量更新或异步写入
- **恢复机制**：任务中断后能从状态文件恢复执行
- **状态更新滞后**：每个步骤完成后必须立即更新task_state.json中的current_phase和completed_steps字段，确保状态与实际执行进度保持一致

## 质量检查
1. 状态一致性：状态文件中的状态与实际执行状态一致
2. 时间戳合理性：开始时间早于结束时间，时间间隔合理
3. 完整性检查：所有步骤都有状态记录
4. 错误信息：失败步骤有错误详情

## 回退策略
- 如果状态文件损坏，从备份恢复或重新初始化
- 如果状态不一致，重新同步或重新执行相关步骤
- 如果性能瓶颈，优化状态更新频率或使用缓存

## task_state.json 与 execution-manifest.json 的关系

### 文件职责区分
- **task_state.json**：实时记录任务执行状态，包含当前步骤、已完成步骤、错误信息
- **execution-manifest.json**：任务执行清单，包含完整步骤列表、依赖关系、资源绑定

### 同步更新策略
1. **计划完成后**：立即生成 execution-manifest.json，包含完整步骤列表和依赖关系
2. **步骤执行中**：实时更新 task_state.json，记录当前步骤状态
3. **步骤完成后**：同步更新两个文件，确保状态一致

### 原子更新策略
1. **写入前备份**：每次更新前备份当前文件
2. **写入后验证**：验证文件格式和内容完整性
3. **异常恢复**：如果写入失败，从备份恢复

### 故障恢复检查点设计
1. **检查点时机**：每个关键步骤完成后保存检查点
2. **检查点内容**：步骤状态、中间产物、配置信息
3. **恢复流程**：从最近的检查点恢复执行，验证中间产物完整性
