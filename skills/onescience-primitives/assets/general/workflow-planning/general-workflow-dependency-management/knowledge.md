# 工作流依赖管理知识卡片

## 适用范围

### 触发条件
- 任务需要设计多步骤工作流
- 需要定义步骤间的依赖关系
- 需要确保工作流符合标准规范

### 适用场景
- 气象预报任务规划
- 科学计算工作流设计
- 多步骤数据处理流程

### 不适用场景
- 简单单步任务
- 实时流式处理

## 输入

### 任务信息
| 信息类型 | 说明 | 用途 |
|---------|------|------|
| 任务目标 | 最终要达到的目的 | 确定工作流终点 |
| 可用资源 | 数据、模型、工具 | 确定可执行步骤 |
| 约束条件 | 时间、计算、数据限制 | 确定步骤顺序 |
| 标准流程 | 领域标准工作流 | 确定依赖规范 |

### 依赖类型
| 依赖类型 | 说明 | 示例 |
|---------|------|------|
| 数据依赖 | 步骤B需要步骤A的输出 | 预处理→模型输入 |
| 资源依赖 | 步骤B需要步骤A释放的资源 | 训练→推理 |
| 时间依赖 | 步骤B必须在步骤A之后 | 数据准备→模型验证 |
| 逻辑依赖 | 步骤B依赖步骤A的结论 | 检查→决策 |

## 流程节点

### 依赖管理标准流程
```
任务分解 → 依赖分析 → 依赖图生成 → 依赖验证 → 执行计划生成 → 执行监控
```

### 每步操作
| 步骤 | 操作 | 工具 | 参数 | 质量门禁 |
|------|------|------|------|---------|
| 1. 任务分解 | 将任务分解为子任务 | 任务规划器 | - | 子任务完整 |
| 2. 依赖分析 | 分析步骤间依赖 | 依赖分析器 | - | 依赖正确 |
| 3. 图生成 | 生成依赖关系图 | DOT/Graphviz | - | 图可读 |
| 4. 依赖验证 | 检查循环依赖 | 环检测算法 | - | 无循环 |
| 5. 计划生成 | 生成执行计划 | 调度器 | - | 计划可行 |
| 6. 监控执行 | 监控执行状态 | 监控器 | - | 状态可见 |

## 关键参数

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 最大并行度 | CPU核心数 | 资源限制 | 控制并发 |
| 超时时间 | 3600秒 | 任务需求 | 单步超时 |
| 重试次数 | 3 | 最佳实践 | 失败重试 |
| 日志级别 | INFO | 调试需求 | 日志详细度 |

## 边界与分流

### 异常处理
| 异常情况 | 处理策略 | 降级方案 |
|---------|---------|---------|
| 循环依赖 | 重新设计依赖关系 | 简化工作流 |
| 依赖缺失 | 补充依赖定义 | 添加占位步骤 |
| 执行失败 | 重试或跳过 | 降级执行 |

### 分支条件
- 若存在循环依赖：报错并要求重新设计
- 若依赖缺失：添加默认依赖或询问用户
- 若资源不足：串行执行或降低并行度

## 质量检查

### 验证点
1. 依赖完整性：所有必要依赖已定义
2. 无循环：依赖图无环
3. 可执行性：计划可执行
4. 效率：并行度合理

### 阈值
| 指标 | 阈值 | 失败处理 |
|------|------|---------|
| 依赖完整性 | 100% | 补充缺失 |
| 循环检测 | 0 | 重新设计 |
| 计划可行性 | 100% | 调整计划 |

## 回退策略

1. **依赖复杂**: 简化工作流，合并可合并步骤
2. **资源不足**: 串行执行或使用外部计算资源
3. **执行失败**: 使用降级方案或跳过非关键步骤
