# CLI非交互执行与故障分类知识

## 适用范围
面向CLI非交互执行场景，覆盖命令参数、认证、沙箱、超时、退出码和标准错误判读的故障分类与诊断。适用于自动化脚本、CI/CD流水线、远程执行环境中的CLI工具故障诊断，不适用于交互式CLI调试或图形界面故障。

## 输入
- CLI命令及其参数
- 执行环境信息（操作系统、Shell类型、权限）
- 错误日志（stdout/stderr）
- 退出码
- 超时设置

## 输出
- 故障分类（参数错误、认证失败、沙箱限制、超时、退出码异常、标准错误判读）
- 诊断报告（根因分析、修复建议）
- 恢复策略（重试、降级、配置修正）

## 流程节点
1. **退出码分析** → 2. **标准错误解析** → 3. **故障分类** → 4. **根因定位** → 5. **修复建议生成**

每步含：操作、参数、工具、质量门禁

### 步骤1：退出码分析
- **操作**：解析CLI进程退出码，映射到标准错误类别
- **参数**：退出码值（0-255）、Shell类型（bash/powershell/cmd）
- **工具**：退出码映射表、Shell文档
- **质量门禁**：退出码必须在0-255范围内，且与Shell标准一致

### 步骤2：标准错误解析
- **操作**：解析stderr输出，提取错误模式
- **参数**：错误文本、堆栈跟踪、错误代码
- **工具**：正则表达式匹配、错误模式库
- **质量门禁**：错误模式必须可追溯到具体代码行或模块

### 步骤3：故障分类
- **操作**：将错误映射到预定义故障类别
- **参数**：错误模式、退出码、环境信息
- **工具**：故障分类树、决策矩阵
- **质量门禁**：分类必须覆盖所有已知故障类型

### 步骤4：根因定位
- **操作**：分析故障上下文，确定根本原因
- **参数**：故障类别、相关日志、配置文件
- **工具**：因果分析、代码追踪
- **质量门禁**：根因必须有证据支持，不能是猜测

### 步骤5：修复建议生成
- **操作**：基于根因生成具体修复步骤
- **参数**：根因、环境约束、历史修复案例
- **工具**：修复模板、最佳实践库
- **质量门禁**：修复建议必须可执行，且有成功案例支持

## 边界与分流
- **参数错误**：检查命令语法、参数顺序、引号转义
- **认证失败**：检查凭证、权限、环境变量
- **沙箱限制**：检查资源限制、网络访问、文件系统权限
- **超时**：检查执行时间、资源竞争、死锁
- **退出码异常**：检查信号处理、异常捕获、资源泄漏
- **标准错误判读**：检查错误模式、堆栈跟踪、上下文信息

当关键前提不成立时转向方案族：
- 无退出码信息 → 转向日志分析方案
- 无标准错误 → 转向资源监控方案
- 无环境信息 → 转向通用诊断方案

## 质量检查
- 验证退出码在有效范围内
- 验证错误模式可追溯到具体代码
- 验证故障分类覆盖所有已知类型
- 验证根因有证据支持
- 验证修复建议可执行

## 回退策略
- 无法确定根因时，提供诊断清单
- 无法生成修复建议时，提供降级方案
- 无法分类时，标记为未知故障并收集更多信息

- **工具代码生成器**：为各种任务合成可执行Python代码 [5]
- **科学调解器**：协调通信，促进科学家反馈 [5]
