# 场景执行前预确认流程

## 适用范围

**触发条件**：orchestrator 生成 Global Plan 后、进入 step 执行前的阶段转换点。

**适用场景**：
- 任何需要必需输入（mandatory inputs）的任务
- 涉及目标范围、数据口径、成本或验收标准的关键取舍
- 用户明确要求预确认的场景

**不适用场景**：
- 纯本地执行、无需用户确认的自动化流程
- 可选输入缺失（不阻塞执行）

## 输入

- **Global Plan**：包含执行计划、步骤序列、资源绑定
- **任务上下文**：用户目标、约束、相关产物
- **必需输入清单**：从任务需求中提取的 mandatory inputs

## 输出

- **预确认报告**（pre_execution_confirmation_report）：
  - 任务理解摘要
  - 数据可用性检查结果
  - 方法选择理由
  - 输入输出契约
  - 验证设计
  - 时间与资源估算
  - 质量门禁
  - 主要风险
  - 失败分支
  - 替代方案
  - 缺失信息清单
  - 需要场景确认的事项

## 流程节点

```
Global Plan 生成完成
    ↓
[pre_execution_confirmation 阶段]
    ↓
生成预确认报告
    ↓
等待用户确认
    ↓
用户提供输入 / 确认取舍 / 补充信息
    ↓
进入 step 执行阶段
```

**每步操作**：
1. 从 Global Plan 提取执行计划和必需输入
2. 组织预确认报告的各个章节
3. 明确标注需要用户确认的关键取舍
4. 输出报告并阻塞等待用户确认
5. 用户确认后，将新增信息纳入 task_context 再执行

## 关键参数

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 触发时机 | Global Plan 生成后 | orchestrator 规范 | 必须在 step 执行前 |
| 报告内容 | 11 个必填章节 | 归因报告 Issue 1 | 任务理解、数据可用性等 |
| 关键取舍 | 目标范围、数据口径、成本、验收标准 | 归因报告 Issue 1 | 须先确认再执行 |
| 阻塞行为 | 等待用户确认 | orchestrator 规范 | 不可跳过 |

## 边界与分流

**必需输入缺失**：生成预确认报告后 BLOCKED，等待用户补充。

**可选输入缺失**：记录在缺失信息清单，不阻塞执行。

**关键取舍未确认**：在报告中标注需要确认的事项，阻塞等待。

**用户拒绝确认**：根据用户反馈调整计划或终止任务。

## 质量检查

| 检查点 | 验证方式 | 失败处理 |
|--------|----------|----------|
| 预确认报告完整性 | 检查 11 个必填章节 | 补充缺失章节 |
| 关键取舍明确性 | 检查是否标注需要确认的事项 | 重新梳理 |
| 用户确认记录 | 检查 agent-events.log 中的确认记录 | 重新提交报告 |

## 回退策略

- 预确认报告不完整：补充缺失信息后重新提交
- 用户拒绝确认：根据反馈调整计划
- 执行阶段发现遗漏：回到预确认阶段补充

## 资源召回建议

**何时召回本卡片**：
- orchestrator 规划阶段完成后、执行阶段开始前
- 任务包含必需输入（mandatory inputs）
- 涉及关键取舍需要用户确认

**配套资源**：
- `general-executor-inventory-validation`：executor inventory 校验
- `general-executor-skill-invocation-contract`：executor 技能调用契约

- 本卡片定义预确认流程的规范，不涉及具体领域的预确认内容
- 预确认报告的具体格式可根据任务类型调整
- 关键取舍的定义可能因任务类型而异
