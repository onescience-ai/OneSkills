# CLI 非交互执行与故障分类

## 适用范围

在自动化工作流中，通过子进程方式调用外部 CLI 工具时，需要一套标准化的故障分类与诊断框架。本卡覆盖命令参数验证、认证、沙箱隔离、超时处理、退出码判读和标准错误捕获，适用于任何需要非交互式执行外部命令并处理失败情况的场景。

## 输入

- 待执行的 CLI 命令及参数列表
- 可选的超时时间限制
- 可选的环境变量配置
- 可选的工作目录设置

## 输出

- 进程执行结果（成功/失败状态）
- 标准输出和标准错误内容
- 退出码及故障分类
- 结构化错误报告（含故障类别、原因、建议修复点）

## 流程节点

### 1. 命令构建与参数验证

**操作**：将命令分解为参数列表形式传递，避免 shell 注入风险。

**参数**：
- `args`：命令参数序列（推荐）或单字符串
- `shell`：默认 `False`，仅在需要 shell 特性时设为 `True`

**工具**：`subprocess.Popen` 或 `subprocess.run`

**质量门禁**：
- 优先使用列表形式传递参数，避免字符串拼接
- 使用 `shlex.split()` 解析复杂命令字符串
- 验证可执行文件路径存在性

### 2. 进程启动与执行监控

**操作**：启动子进程并监控执行状态。

**参数**：
- `timeout`：超时时间（秒），超时后进程被终止
- `cwd`：工作目录
- `env`：环境变量映射
- `stdin/stdout/stderr`：管道重定向配置

**工具**：`subprocess.Popen.communicate()` 或 `subprocess.run()`

**质量门禁**：
- 设置合理超时防止进程挂起
- 使用 `PIPE` 捕获输出用于诊断
- 避免在 `stdout=PIPE` 时使用 `wait()`（会死锁）

### 3. 退出码分类与诊断

**操作**：根据退出码分类故障类型。

**退出码分类表**：

| 退出码 | 类别 | 含义 | 诊断建议 |
|--------|------|------|----------|
| 0 | 成功 | 正常完成 | 无需处理 |
| 1 | 通用错误 | 命令执行失败 | 检查 stderr 输出 |
| 2 | 用法错误 | 参数格式错误 | 检查命令语法 |
| 126 | 权限错误 | 无法执行 | 检查文件权限 |
| 127 | 命令未找到 | 路径错误 | 检查 PATH 或使用绝对路径 |
| 128+N | 信号终止 | 被信号 N 终止 | 检查系统资源限制 |
| 130 | SIGINT (2) | 用户中断 | 正常中断行为 |
| 137 | SIGKILL (9) | 强制终止 | 超时或资源耗尽 |
| 143 | SIGTERM (15) | 正常终止 | 请求终止 |

**负值退出码**：`-N` 表示被信号 N 终止（仅 POSIX）

### 4. 异常处理与降级策略

**操作**：捕获并处理各类异常。

**异常类型表**：

| 异常类 | 触发条件 | 处理策略 |
|--------|----------|----------|
| `TimeoutExpired` | 超时未完成 | 杀死进程，收集部分输出 |
| `CalledProcessError` | 非零退出码（check=True） | 解析 returncode 分类故障 |
| `OSError` | 可执行文件不存在 | 检查路径和环境 |
| `ValueError` | 参数无效 | 检查调用参数 |

**降级策略**：
- 超时后尝试 `proc.kill()` 清理
- 捕获部分输出用于诊断
- 记录完整上下文用于事后分析

### 5. 诊断证据收集

**操作**：收集故障诊断所需信息。

**必须记录**：
- 完整命令及参数
- 退出码
- 标准输出内容
- 标准错误内容
- 执行耗时
- 环境快照（关键变量）

**质量门禁**：
- 使用 `text=True` 获取可读字符串输出
- 区分 `stdout` 和 `stderr` 内容
- 保留原始字节流用于二进制输出分析

## 关键参数

### 通用判据

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| timeout | 按任务设定 | [D1] | 防止进程挂起，需根据任务复杂度调整 |
| shell | False（默认） | [D1] | 避免 shell 注入，仅在必要时启用 |
| check | True（需严格检查时） | [D1] | 自动抛出 CalledProcessError |
| capture_output | True（需诊断时） | [D1] | 捕获 stdout 和 stderr |
| text | True（需可读输出时） | [D1] | 输出为字符串而非字节 |

### 校准数值

以下数值来自 Python 标准库实现，供量级校准；其他系统需以自身证据重新锚定。

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 默认 bufsize | -1 (io.DEFAULT_BUFFER_SIZE) | [D1] | 系统默认缓冲区大小 |
| 超时最小单位 | 秒（浮点数） | [D1] | 支持亚秒级超时 |
| 管道缓冲区 | 平台相关 | [D1] | Linux 可通过 pipesize 调整 |

## 边界与分流

### 前提条件不满足时的改道

| 前提条件 | 不满足时转向 |
|----------|--------------|
| 可执行文件存在 | 转向路径诊断，检查 PATH 环境变量或使用绝对路径 |
| 超时设置合理 | 转向资源评估，检查系统负载和任务复杂度 |
| 输出可捕获 | 转向日志文件重定向，使用文件描述符代替 PIPE |
| 权限充足 | 转向权限检查，确认文件可执行位和用户权限 |

### 平台差异处理

- **POSIX**：支持信号终止、进程组管理
- **Windows**：使用 `CREATE_NEW_PROCESS_GROUP` 隔离进程，`terminate()` 等效于 `TerminateProcess()`
- **跨平台**：使用 `sys.executable` 启动 Python 子进程确保兼容性

## 质量检查

### 验证点

1. **退出码校验**：0 表示成功，非零需进一步诊断
2. **输出完整性**：stdout/stderr 内容完整且可解析
3. **超时处理**：超时后进程被正确清理
4. **异常捕获**：所有预期异常被捕获并记录
5. **资源清理**：管道文件描述符正确关闭

### 阈值

- 超时：根据任务复杂度设定（建议 30s-300s）
- 输出大小：超过内存限制时使用流式处理
- 重试次数：建议最多 3 次，指数退避

### 失败处理

- 超时：杀死进程，记录部分输出
- 非零退出码：解析 stderr，分类故障
- 异常：记录完整堆栈，回退到安全状态

## 回退策略

1. **超时回退**：`proc.kill()` → `proc.communicate()` → 记录诊断信息
2. **权限回退**：检查并修复文件权限，或使用 sudo/管理员权限重试
3. **路径回退**：使用 `shutil.which()` 定位可执行文件
4. **环境回退**：清理或设置必要的环境变量
