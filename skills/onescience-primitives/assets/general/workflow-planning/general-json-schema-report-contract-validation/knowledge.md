# JSON Schema报告契约验证

## 适用范围

**触发条件**：
- 需要生成符合特定JSON Schema的结构化报告
- 需要验证JSON数据是否符合预定义契约
- 需要标准化错误信息和验证反馈

**适用场景**：
- API响应格式验证
- 数据交换格式标准化
- 配置文件验证
- 任何需要数据完整性保证的JSON处理

**不适用场景**：
- 非JSON格式数据（XML、YAML、CSV）
- 运行时动态Schema变更（需要版本管理）
- 性能关键型实时验证（需要优化策略）

## 输入

**输入数据**：
- JSON Schema定义文件（.json）
- 待验证的JSON数据
- 验证选项（严格模式、错误容忍度等）
- 上下文信息（数据来源、使用场景）

**数据来源**：
- Schema设计文档
- API规范文件
- 配置文件模板
- 数据生成器输出

**预处理要求**：
- Schema需为有效JSON
- 数据需可解析为JSON
- 选项需为键值对格式

## 输出

**输出产物**：
- 验证结果（通过/失败）
- 错误详情（路径、消息、严重程度）
- 修正建议（可选）
- 验证报告（结构化）

**格式要求**：
- 验证结果：布尔值或枚举
- 错误详情：JSON数组，每项包含path、message、schemaPath
- 修正建议：具体修改指令
- 验证报告：Markdown或HTML

**验证标准**：
- 验证结果准确（与Schema定义一致）
- 错误信息清晰（人类可读）
- 修正建议可执行（具体操作）

## 流程节点

### Step 1：Schema加载与解析
- **操作**：加载JSON Schema并解析为内部表示
- **参数**：加载方式=文件读取或网络获取，解析器=官方验证器
- **工具**：JSON Schema验证库（如ajv、jsonschema）
- **质量门禁**：Schema本身有效，无语法错误

### Step 2：数据预处理
- **操作**：清理和标准化待验证数据
- **参数**：清理规则=移除空值、类型转换、编码统一
- **工具**：数据清理函数
- **质量门禁**：数据可解析为JSON，无编码错误

### Step 3：验证执行
- **操作**：应用Schema验证数据
- **参数**：验证模式=严格/宽松，错误收集=全部/首个
- **工具**：JSON Schema验证器
- **质量门禁**：验证过程无异常，结果完整

### Step 4：错误处理与报告
- **操作**：格式化验证错误，生成报告
- **参数**：报告格式=Markdown/HTML，详细程度=摘要/完整
- **工具**：模板引擎、格式化函数
- **质量门禁**：报告包含所有错误，格式一致

### Step 5：修正建议生成（可选）
- **操作**：根据错误类型生成修正建议
- **参数**：建议类型=自动修正/手动指导
- **工具**：规则引擎、模板库
- **质量门禁**：建议具体可执行，不引入新错误

## 边界与分流

**关键前提不成立时的改道方案**：

1. **前提：Schema有效**
   - 不成立场景：Schema本身有语法错误或不兼容
   - 改道方案：使用Schema验证工具检查Schema，修复后重试

2. **前提：数据可解析**
   - 不成立场景：数据格式错误或编码问题
   - 改道方案：使用数据清理工具预处理，或要求数据源修复

3. **前提：验证器兼容**
   - 不成立场景：验证器不支持某些Schema特性
   - 改道方案：升级验证器或使用替代工具

4. **前提：性能可接受**
   - 不成立场景：大数据量验证超时
   - 改道方案：分片验证、异步处理或使用流式验证

## 质量检查

**验证点**：
- Schema验证准确性（100%符合规范）
- 错误信息清晰度（人类可读）
- 修正建议可执行性（具体操作）

**阈值**：
- 验证耗时<1秒（标准数据量）
- 错误覆盖率100%（所有违规都被捕获）
- 报告生成<5秒

**失败处理**：
- 验证失败：生成详细错误报告，标记需修复字段
- 性能不足：优化验证流程，使用缓存或预处理

## 回退策略

**失败时的替代方案**：
1. **Schema验证失败**：使用宽松模式验证，标记警告而非错误
2. **验证器崩溃**：回退到基础验证（类型检查、必填字段）
3. **性能瓶颈**：采样验证，只检查关键字段
4. **兼容性问题**：使用最保守的Schema子集
