# 工作流步骤与执行器步骤映射规则

## 适用范围

面向场景工作流定义与执行器工作流执行的步骤映射需求，定义步骤数量一致性、依赖关系传递和质量门禁继承的规则。适用于需要将场景工作流（如knowledge.md定义的步骤）映射到执行器工作流（如executor实际执行的步骤）的编排场景，确保步骤结构一致性和执行流程可追溯性。当场景工作流定义N个步骤时，执行器是否允许拆分为更多步骤、拆分的约束条件和审批流程需要明确规则。

## 输入

**必要输入**：
- 场景工作流定义（knowledge.md中的步骤列表）
- 执行器工作流定义（executor实际执行的步骤）
- 步骤依赖关系矩阵

**可选输入**：
- 步骤合并/拆分申请
- 质量门禁定义
- 审批流程配置

**数据要求**：
- 步骤列表完整，包含步骤ID和描述
- 依赖关系明确，无循环依赖
- 质量门禁定义清晰

## 输出

**主要输出**：
- 步骤映射规则文档
- 步骤数量校验结果
- 依赖关系传递验证结果
- 质量门禁继承规则

**验证标准**：
- 步骤映射规则覆盖所有可能场景
- 依赖关系传递无遗漏
- 质量门禁继承无冲突

## 流程节点

### Step 1：步骤数量校验
- **操作**：检查场景工作流步骤数量与执行器工作流步骤数量的一致性
- **参数**：场景步骤数量N，执行器步骤数量M
- **工具**：步骤数量校验器
- **质量门禁**：步骤数量一致，或不一致时有明确的合并/拆分说明

### Step 2：依赖关系传递验证
- **操作**：验证步骤间依赖关系在映射后保持正确传递
- **参数**：依赖关系矩阵，映射规则
- **工具**：依赖关系验证器
- **质量门禁**：依赖关系传递无遗漏，无循环依赖

### Step 3：质量门禁继承规则应用
- **操作**：将场景工作流的质量门禁规则正确传递给执行器工作流
- **参数**：质量门禁定义，继承规则
- **工具**：质量门禁继承器
- **质量门禁**：质量门禁继承无冲突，所有门禁均可执行

### Step 4：步骤合并/拆分审批
- **操作**：处理步骤数量不一致时的合并/拆分申请
- **参数**：合并/拆分申请，审批规则
- **工具**：审批流程管理器
- **质量门禁**：审批流程完整，决策有依据

### Step 5：映射规则文档生成
- **操作**：生成完整的步骤映射规则文档
- **参数**：校验结果，传递验证结果，继承规则，审批决策
- **工具**：文档生成器
- **质量门禁**：文档完整，规则清晰

## 关键参数

### 通用判据（方法层）

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 步骤数量校验 | 场景步骤数 = 执行器步骤数 | [1] | 除非有明确合并/拆分说明 |
| 依赖关系传递 | 直接依赖完整传递 | [1] | 间接依赖可省略 |
| 质量门禁继承 | 所有门禁必须继承 | [1] | 不得遗漏关键门禁 |
| 合并/拆分审批 | 需要明确审批记录 | [2] | 审批依据需文档化 |
| 映射规则完整性 | 覆盖所有步骤 | [1] | 不得有遗漏步骤 |

### 校准数值

以下数值来自典型场景，供量级校准；其他场景需以自身证据重新锚定。

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 步骤数量差异阈值 | ±2步 | [1] | 超过此阈值需重新评估 |
| 依赖关系传递完整性 | ≥95% | [1] | 直接依赖传递比例 |
| 质量门禁继承率 | 100% | [1] | 所有门禁必须继承 |
| 审批流程完成时间 | ≤24小时 | [2] | 合并/拆分审批时限 |

## 边界与分流

**异常处理**：
- 步骤数量不一致 → 启动合并/拆分审批流程
- 依赖关系传递遗漏 → 重新设计映射规则
- 质量门禁继承冲突 → 调整继承规则或标记BLOCKED
- 审批流程超时 → 升级至更高级别审批

**降级策略**：
- 无法完成完整映射时 → 执行简化映射，仅保留关键步骤
- 审批流程不可用时 → 使用默认规则，但需记录偏离
- 质量门禁无法继承时 → 标记BLOCKED，等待人工干预

**分支条件**：
- 步骤数量一致 → 直接应用映射规则
- 步骤数量不一致 → 启动审批流程
- 审批通过 → 执行合并/拆分
- 审批拒绝 → 重新设计工作流

## 质量检查

**验证点**：
1. 步骤数量校验：场景步骤数与执行器步骤数一致
2. 依赖关系传递：所有直接依赖完整传递
3. 质量门禁继承：所有门禁正确继承
4. 审批流程完整：所有决策有文档记录
5. 映射规则完整：覆盖所有步骤，无遗漏

**阈值**：
- 步骤数量一致性：100%（除非有明确合并/拆分说明）
- 依赖关系传递完整性：≥95%
- 质量门禁继承率：100%
- 审批流程完成率：100%

**失败处理**：
- 步骤数量不一致且无审批 → 标记BLOCKED
- 依赖关系传递遗漏 → 重新设计映射规则
- 质量门禁继承失败 → 标记BLOCKED
- 审批流程不完整 → 标记PARTIAL

## 回退策略

**替代方案**：
1. 使用默认映射规则（步骤数量一致时）
2. 采用简化映射（仅保留关键步骤）
3. 降级为人工映射（复杂场景）
4. 使用历史成功案例作为参考

**回退触发条件**：
- 映射规则无法覆盖当前场景
- 审批流程不可用
- 质量门禁继承冲突无法解决
- 依赖关系传递验证失败
