# JSON Schema 报告交付契约验证方法论

## 适用范围
面向需要结构化输出的任务，定义和验证JSON Schema报告交付契约。适用于任何生成结构化报告（如归因分析报告、实验报告、数据质量报告）的场景，确保输出符合预定义的字段、类型和约束要求。不适用于非结构化输出或简单键值对输出。

## 输入
- 报告生成系统产生的JSON输出
- 预定义的JSON Schema（定义必填字段、数据类型、格式约束、条件依赖等）
- 可选的参考数据集或基准（用于评估报告质量）

## 输出
- 验证通过的JSON报告（符合Schema约束）
- 验证错误报告（指出不匹配的字段、类型错误、缺失字段等）
- 质量评估指标（如Schema符合度、字段完整性、类型准确性等）

## 流程节点
1. **Schema加载与解析** → 加载JSON Schema，解析为可执行验证规则
2. **报告预处理** → 清洗、标准化报告JSON，确保基本格式正确
3. **字段级验证** → 逐个字段检查必填性、类型、格式、枚举值等
4. **结构级验证** → 检查嵌套结构、数组约束、条件依赖（if/then/else）
5. **语义级验证** → 检查业务逻辑约束（如字段间关系、跨文档一致性）
6. **错误聚合与报告** → 收集所有验证错误，生成结构化错误报告
7. **质量评估** → 计算Schema符合度指标，评估报告质量

每步含：操作、参数、工具、质量门禁

## 边界与分流
- **Schema缺失**：转向基于通用JSON验证（如required、type检查）或回退到人工审核
- **报告格式错误**：尝试自动修复（如类型转换、字段重命名），失败则拒绝报告
- **复杂条件依赖**：简化验证规则，仅检查核心业务逻辑
- **性能瓶颈**：采用增量验证或抽样验证，仅对关键字段做深度检查
- **跨文档一致性**：扩展验证范围，引入数据集级统计检查

## 质量检查
- **验证覆盖度**：确保Schema中所有约束都被检查（字段、类型、格式、条件）
- **错误可追溯性**：每个错误必须包含字段路径、错误类型、期望值/实际值
- **误报率控制**：验证规则不应过于严格，避免合法报告被误判
- **性能基准**：单次验证延迟应小于100ms（对于典型报告大小）

## 回退策略
- **Schema不可用**：使用基础JSON验证（如JSONLint）并记录缺失Schema
- **验证工具故障**：回退到手动抽样检查，并记录验证中断状态
- **部分验证失败**：允许报告以“部分通过”状态交付，附带未验证字段列表
