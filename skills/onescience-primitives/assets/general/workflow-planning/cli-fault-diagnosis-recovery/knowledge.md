# CLI非交互执行故障诊断与恢复

## 适用范围

面向命令行工具在自动化流水线、批处理脚本和远程执行环境中的非交互执行场景，提供进程退出码分类、标准错误诊断、超时检测与故障恢复的系统化方法。适用于需要稳定调用外部CLI工具并对其执行结果进行自动化判断的软件工程任务，不适用于交互式终端会话或图形界面应用。

## 输入

- CLI工具的命令行参数与执行环境配置
- 进程退出码（exit code）或信号码
- 标准错误输出（stderr）内容
- 执行超时阈值设置
- 可选：进程资源使用监控数据

## 输出

- 故障分类结果（成功/警告/失败/致命）
- 诊断日志与错误详情
- 恢复策略建议（重试/降级/终止）
- 执行状态报告

## 流程节点

### 1. 进程启动与参数验证

**操作**：验证CLI命令参数格式、认证凭据、沙箱权限

**参数**：
- 命令路径与参数列表
- 工作目录与环境变量
- 超时设置（秒）

**质量门禁**：参数解析失败时返回明确错误信息，不执行后续流程

### 2. 进程执行监控

**操作**：启动子进程并监控其执行状态

**参数**：
- 进程PID
- 标准输出/错误管道
- 资源限制（CPU、内存）

**质量门禁**：进程响应超时时触发终止信号

### 3. 退出码分类

**操作**：根据POSIX标准对进程退出码进行分类

**退出码分类规则**（基于POSIX.1-2017标准）：

| 退出码范围 | 分类 | 语义 | 处理策略 |
|-----------|------|------|---------|
| 0 | 成功 | 命令正常执行完成 | 继续后续流程 |
| 1-125 | 应用错误 | 命令遇到具体错误条件 | 记录日志，根据错误码决定重试或终止 |
| 126 | 权限错误 | 命令不可执行（权限不足） | 检查文件权限，修正后重试 |
| 127 | 命令未找到 | 命令不存在或路径错误 | 检查PATH环境变量和命令路径 |
| 128+N | 信号终止 | 命令被信号N终止（N≤125） | 分析信号类型（SIGTERM=15, SIGKILL=9） |
| 129-255 | 自定义错误 | 应用自定义错误码 | 参考应用文档处理 |

**工具**：使用`subprocess.Popen`或系统调用获取退出码

**质量门禁**：退出码必须为整数，记录完整退出码值而非仅判断非零

### 4. 标准错误诊断

**操作**：解析stderr输出提取错误关键信息

**参数**：
- stderr缓冲区大小
- 错误模式匹配规则
- 日志级别配置

**诊断模式**：
- 关键词匹配：Error, Exception, Fatal, Critical
- 正则表达式：提取文件名、行号、错误码
- 上下文窗口：错误前后N行内容

**质量门禁**：stderr为空时仍需记录"无错误输出"状态

### 5. 超时检测与处理

**操作**：检测进程执行是否超过预设阈值

**参数**：
- 超时阈值（毫秒）
- 检测间隔
- 终止信号类型（SIGTERM先尝试，超时后SIGKILL）

**流程**：
1. 记录进程启动时间
2. 定期检查进程状态
3. 超时时发送SIGTERM信号
4. 等待grace period后发送SIGKILL

**质量门禁**：超时终止后必须记录进程最后输出和资源使用情况

### 6. 恢复策略执行

**操作**：根据故障分类结果选择恢复路径

**策略映射**：
- 成功（exit 0）：继续执行
- 暂时性错误（exit 1-125）：指数退避重试（最多N次）
- 配置错误（exit 126-127）：终止并报告配置问题
- 致命错误（exit 128+N）：终止并记录信号信息
- 超时：增加超时阈值或优化命令参数后重试

**质量门禁**：重试次数不得超过配置上限，避免无限循环

## 关键参数

### 通用判据

| 参数 | 判据 | 来源 | 说明 |
|------|------|------|------|
| 退出码语义 | 遵循POSIX.1-2017标准 | [D1] | 标准规定0=成功，1-125=应用错误，126=权限错误，127=命令未找到，128+N=信号终止 |
| 信号终止码计算 | exit_code = 128 + signal_number | [D1] | 信号编号参考系统信号表（如SIGTERM=15, SIGKILL=9） |
| 异常分类层级 | BaseException → Exception → 具体异常 | [D2] | Python异常体系提供细粒度错误分类 |
| 超时检测间隔 | 建议100ms-1s | [D2] | 平衡响应性与系统开销 |

### 校准数值

以下数值来自典型CLI工具执行场景，供量级校准；其他体系需以自身证据重新锚定：

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 默认超时阈值 | 30秒 | 工程实践 | 适用于大多数网络IO密集型CLI工具 |
| 重试次数上限 | 3次 | 工程实践 | 避免暂时性错误导致的无限重试 |
| SIGTERM等待时间 | 5秒 | 工程实践 | 给进程清理资源的合理时间 |
| stderr缓冲区大小 | 64KB | 工程实践 | 足够捕获大多数错误输出 |

## 边界与分流

### 前提条件不成立时的分流

1. **命令路径不可达** → 转向配置检查流程（验证PATH环境变量、文件权限）
2. **认证凭据缺失** → 转向凭据获取流程（检查环境变量、配置文件、密钥管理服务）
3. **沙箱权限不足** → 转向权限申请流程（检查用户组、sudo配置）
4. **系统资源不足** → 转向资源清理流程（释放内存、关闭句柄）

### 异常处理分支

1. **退出码不在已知范围** → 记录原始值并标记为"未知错误码"，供人工审核
2. **stderr输出格式异常** → 保留原始输出，跳过模式匹配，标记为"非标准错误格式"
3. **信号终止但无coredump** → 记录信号信息，跳过core分析，标记为"无coredump"

## 质量检查

### 验证点

1. **退出码记录完整性**：每次执行必须记录完整退出码（包括0）
2. **stderr捕获完整性**：必须捕获并记录标准错误输出，即使为空
3. **超时检测准确性**：超时阈值误差应在±10%以内
4. **日志时间戳**：所有诊断日志必须包含精确到毫秒的时间戳
5. **恢复策略可追溯**：每次重试或降级必须记录决策依据

### 阈值

| 检查项 | 阈值 | 失败处理 |
|--------|------|---------|
| 退出码记录率 | 100% | 中断执行，报告日志系统故障 |
| stderr捕获率 | 100% | 中断执行，报告管道故障 |
| 超时检测延迟 | <1s | 调整检测间隔，记录系统负载 |
| 重试间隔精度 | ±100ms | 记录系统调度延迟 |

## 回退策略

当自动化故障诊断失败时：

1. **降级到人工诊断**：收集完整执行上下文（命令、参数、退出码、stderr、日志）并输出诊断报告
2. **跳过当前任务**：记录跳过原因，继续执行流水线下一步（适用于非关键路径任务）
3. **终止整个流水线**：当遇到致命错误或资源耗尽时，安全终止所有子进程并清理临时文件
