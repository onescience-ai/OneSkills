# CLI 非交互执行与故障分类知识

## 适用范围
适用于命令行界面（CLI）工具在非交互环境中的执行监控、故障检测与错误处理。覆盖自动化脚本、CI/CD流水线、批处理任务和远程执行场景。不适用于交互式shell会话或图形用户界面应用。

## 输入
- CLI命令执行日志（标准输出、标准错误、退出码）
- 进程状态信息（PID、资源使用、运行时间）
- 执行环境上下文（操作系统、shell类型、依赖工具版本）

## 输出
- 退出码分类结果（成功、可恢复错误、致命错误、信号终止）
- 故障诊断报告（错误类型、可能原因、建议恢复操作）
- 错误处理策略（重试、降级、终止、告警）

## 流程节点
1. **退出码捕获** → 捕获进程退出码（$? in bash, $LASTEXITCODE in PowerShell）
2. **退出码分类** → 将退出码映射到故障类别（0=成功，1-125=应用错误，126=权限错误，127=命令未找到，128+=信号终止）
3. **故障检测** → 基于退出码和输出内容检测故障类型
4. **错误处理** → 执行预定义的错误处理策略
5. **恢复操作** → 根据故障类别选择恢复方案

## 关键参数
| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 成功退出码 | 0 | POSIX标准 | 命令执行成功 |
| 应用错误范围 | 1-125 | POSIX标准 | 应用程序定义的错误 |
| 权限错误 | 126 | POSIX标准 | 命令不可执行 |
| 命令未找到 | 127 | POSIX标准 | 命令或脚本不存在 |
| 信号终止基础值 | 128 | POSIX标准 | 进程被信号终止（128+信号编号） |
| 常见信号 | SIGTERM(15), SIGKILL(9), SIGINT(2) | POSIX标准 | 终止信号类型 |

## 边界与分流
- **退出码缺失**：当无法获取退出码时，检查进程是否超时或被外部终止
- **非标准退出码**：某些应用程序使用非标准退出码（>125），需查阅特定应用程序文档
- **信号混合**：多个信号同时发送时，可能产生复合退出码，需优先处理致命信号
- **环境差异**：不同操作系统（Windows/Linux/macOS）的退出码语义可能不同

## 质量检查
- 验证退出码捕获机制在所有执行路径中都能正常工作
- 定期测试错误处理策略对不同故障类型的响应
- 监控错误处理过程中的资源泄漏（文件句柄、网络连接）
- 检查错误日志是否包含足够的诊断信息

## 回退策略
- 当主要错误处理机制失败时，记录原始退出码并终止执行
- 对于可恢复错误，实施指数退避重试策略
- 对于致命错误，立即终止并发送告警通知
- 保留完整的执行上下文用于事后分析
