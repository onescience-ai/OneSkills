# 机器学习工程配置-代码一致性保障规范

## 适用范围

**触发条件**：
- 模型训练配置文件（如JSON/YAML）与实际代码接口不一致
- 模型重构、简化或参数增删后需要同步更新配置
- 需要保障训练配置的可复现性和可维护性

**适用场景**：
- PyTorch/TensorFlow模型训练脚本的配置管理
- 模型超参数从配置文件加载的工程实践
- 多人协作项目中配置-代码一致性维护
- 模型简化后遗留配置参数的清理

**不适用场景**：
- 纯代码内联配置（无外部配置文件）
- 配置无关的简单脚本
- 配置仅用于记录而非程序化加载的场景

## 输入

- 现有模型代码接口（__init__签名、forward参数）
- 现有配置文件内容
- 模型变更历史（新增/移除/重命名的参数）

## 输出

- 配置-代码一致性检查报告
- 更新后的配置文件（与代码接口匹配）
- 配置同步清单（变更后的同步步骤）

## 流程节点

### Step 1：配置接口审计
- **操作**：解析模型代码的__init__签名，提取所有接受的参数
- **方法**：inspect.signature() 或 ast解析
- **参数**：模型类文件路径
- **工具**：Python inspect/ast模块
- **质量门禁**：完整提取所有模型参数，无遗漏

### Step 2：配置文件解析
- **操作**：解析配置文件，提取所有配置项
- **方法**：json.load() 或 yaml.safe_load()
- **参数**：配置文件路径
- **工具**：json/yaml模块
- **质量门禁**：配置文件格式正确，可正常解析

### Step 3：差异检测
- **操作**：对比配置项与模型参数，识别不一致
- **类型**：
  - 配置中有但代码中无的参数（遗留参数）
  - 代码中有但配置中无的参数（缺失参数）
  - 参数名或类型不匹配
- **工具**：集合运算
- **质量门禁**：无遗留参数，无缺失参数

### Step 4：配置更新
- **操作**：根据差异结果更新配置文件
- **原则**：
  - 移除代码中不存在的参数
  - 添加代码中存在但配置中缺失的参数（使用默认值）
  - 更新参数名或类型以匹配代码
- **工具**：json/yaml写入
- **质量门禁**：更新后的配置可成功传入模型构造函数

### Step 5：验证测试
- **操作**：用更新后的配置文件构造模型，验证无报错
- **方法**：model = ModelClass(**config) 
- **参数**：配置字典
- **工具**：Python
- **质量门禁**：模型构造成功，无TypeError

### Step 6：文档同步
- **操作**：更新配置文件的注释或文档，说明每个参数的含义
- **参数**：配置文件
- **工具**：文本编辑
- **质量门禁**：配置文件包含参数说明

## 边界与分流

- **配置文件缺失**：根据模型代码自动生成默认配置文件
- **模型接口频繁变更**：考虑使用配置管理工具（如Hydra/OmegaConf）自动从代码生成配置
- **多模型共用配置**：使用继承或覆盖机制，基础配置+模型特定覆盖
- **配置验证失败**：回退到代码默认值，记录不一致原因

## 质量检查

- [ ] 配置文件中所有参数均被模型代码接受
- [ ] 模型代码中所有必要参数在配置中有对应项
- [ ] 用配置文件构造模型无TypeError
- [ ] 参数名与代码变量名一致（无映射层）
- [ ] 配置文件包含参数说明注释

## 回退策略

- 若配置管理过于复杂，至少在模型代码中添加配置验证逻辑
- 使用Python dataclass或Pydantic BaseModel定义模型配置
- 定期运行配置-代码一致性检查脚本
