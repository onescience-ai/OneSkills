# CLI 非交互执行故障分类与诊断

## 适用范围

**触发条件**：
- 命令行工具在非交互式环境（批处理、自动化流水线、远程SSH/SLURM）中执行异常
- CLI进程以非零退出码终止，需要诊断故障类型
- 需要区分命令参数错误、环境问题、资源限制、超时等不同故障类别

**适用场景**：
- 科学计算工作流中的CLI工具执行失败
- 自动化测试流水线中的命令执行异常
- 远程HPC环境中的作业执行故障诊断
- 容器化或沙箱环境中的命令执行问题

**不适用场景**：
- 交互式命令行调试（需要用户输入的场景）
- 图形界面应用程序故障
- 网络服务端故障诊断

## 输入

- **CLI执行日志**：包含stdout/stderr输出的完整日志
- **退出码**：进程返回的exit code
- **执行环境信息**：操作系统、shell版本、环境变量、资源限制
- **命令参数**：完整的命令行参数列表
- **超时配置**：预设的执行时间限制（如有）

## 输出

- **故障分类结果**：将故障归入预定义类别
- **根因分析**：基于退出码和错误信息的诊断结论
- **恢复建议**：针对各类故障的修复或重试策略
- **结构化报告**：包含故障类型、证据、建议的JSON格式输出

## 流程节点

### Step 1：退出码采集与初步分类
- **操作**：捕获进程退出码，映射到POSIX标准语义
- **参数**：exit_code ∈ [0, 1-125, 126, 127, 128+n, >128]
- **工具**：shell $? 变量、wait系统调用
- **质量门禁**：退出码必须为整数值，范围在0-255之间

### Step 2：标准错误流解析
- **操作**：分析stderr输出，提取关键错误信息
- **参数**：错误模式匹配（正则表达式库）
- **工具**：grep/awk/sed或编程语言正则库
- **质量门禁**：错误信息必须可追溯到具体错误源

### Step 3：故障类别判定
- **操作**：根据退出码和错误信息判定故障类别
- **参数**：故障分类矩阵（见关键参数表）
- **工具**：规则引擎或决策树
- **质量门禁**：分类结果必须有明确证据支持

### Step 4：环境与资源检查
- **操作**：检查执行环境是否满足命令要求
- **参数**：文件权限、依赖库、磁盘空间、内存限制
- **工具**：系统调用（stat、ldd、df、ulimit）
- **质量门禁**：环境检查结果必须与故障类别一致

### Step 5：生成诊断报告
- **操作**：汇总分析结果，生成结构化报告
- **参数**：报告模板（JSON Schema）
- **工具**：JSON序列化库
- **质量门禁**：报告必须包含故障类别、证据链、恢复建议

## 关键参数

### 通用判据（方法层）

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 退出码0 | 成功 | [D1] POSIX标准 | 命令正常完成 |
| 退出码1-125 | 应用错误 | [D1] POSIX标准 | 命令自身的错误条件 |
| 退出码126 | 权限问题 | [D1] POSIX标准 | 命令不可执行或非文件 |
| 退出码127 | 命令未找到 | [D1] POSIX标准 | 搜索路径中无此命令 |
| 退出码128+n | 信号终止 | [D1] POSIX标准 | 命令被信号n终止 |
| 退出码>128 | 扩展错误 | [D1] POSIX标准 | 实现自定义的错误码 |

### 校准数值（诊断阈值）

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 超时阈值 | 可配置 | 实践经验 | 以下数值来自典型科学计算场景，其他场景需重新锚定 |
| 内存告警 | 80%使用率 | 实践经验 | 触发资源不足预警的阈值 |
| 磁盘告警 | 90%使用率 | 实践经验 | 触发存储空间预警的阈值 |
| 重试次数 | 3次 | 实践经验 | 临时性故障的最大重试次数 |

## 边界与分流

### 退出码不可用
- **前提**：进程异常终止（如SIGKILL）导致无退出码
- **改道方案**：检查系统日志（dmesg、/var/log/messages）、检查coredump文件

### 错误信息为空
- **前提**：stderr无输出或被重定向
- **改道方案**：检查stdout中的错误提示、检查日志文件、增加调试输出

### 环境信息不完整
- **前提**：无法获取完整的执行环境信息
- **改道方案**：使用最小化环境重现问题、对比正常环境与异常环境差异

### 故障类别模糊
- **前提**：多个故障类别均有可能
- **改道方案**：按概率排序逐一验证、增加日志级别重新执行

## 质量检查

- **退出码有效性**：exit_code ∈ [0, 255]
- **错误信息完整性**：必须包含错误源、错误类型、上下文信息
- **分类一致性**：同一错误模式应映射到相同故障类别
- **报告完整性**：JSON报告必须包含所有必填字段

## 回退策略

1. **日志增强**：启用DEBUG级别日志重新执行
2. **环境隔离**：在干净的容器/虚拟机中重现问题
3. **二分排查**：逐步禁用功能模块定位问题范围
4. **人工介入**：将诊断报告提交给领域专家
