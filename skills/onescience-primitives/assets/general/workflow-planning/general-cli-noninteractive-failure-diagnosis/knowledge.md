# CLI 非交互执行故障诊断

## 适用范围

当命令行工具在自动化流水线、脚本调用或远程执行环境中运行时，工具进程可能因非交互模式特有的约束条件（如 stdin 不可用、终端信号缺失、沙箱隔离）而产生不同类型的失败。本卡定义了一套从退出码、标准错误输出到进程状态的系统化诊断流程，用于将模糊的"命令失败"转化为可操作的根因分类，进而选择对应的恢复策略。

适用场景包括但不限于：自动化测试套件调用外部 CLI 工具、CI/CD 流水线中的构建与部署脚本、批量数据处理任务、远程 SSH/SLURM 环境下的作业提交。本卡聚焦于诊断阶段，不涉及工具本身的领域逻辑。

## 输入

- 进程退出码（exit code）
- 标准错误输出（stderr）
- 进程状态信息（超时、信号、资源限制）
- 执行环境信息（stdin 类型、沙箱配置、网络隔离）
- 原始命令及参数

## 输出

- 故障根因分类（权限、依赖、配置、超时、信号、沙箱）
- 诊断报告（含退出码语义、错误模式匹配、环境因素）
- 恢复建议（重试、降级、配置修正、人工介入）

## 流程节点

1. **退出码获取** → 获取进程返回的退出状态码
2. **退出码语义映射** → 将数值映射到标准语义分类
3. **标准错误分析** → 解析 stderr 中的错误模式和关键词。例如，错误信息可能包含“缺少顶层字段: ['issues', 'summary', 'task', 'task_id']”，这表明JSON报告不符合预定义schema。
4. **环境因素评估** → 检查 stdin 类型、沙箱约束、资源限制
5. **根因分类** → 综合以上信息确定故障类别
6. **恢复策略选择** → 根据根因类别选择对应处理方案

每步含：操作、参数、工具、质量门禁

## 关键参数

### 通用判据

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| EXIT_SUCCESS | 0 | [D1][D2] | 成功退出，所有操作正常完成 |
| EXIT_FAILURE | 1 | [D1][D3] | 通用错误，catchall for general errors |
| SHELL_MISUSE | 2 | [D3] | 误用 shell 内置命令 |
| CMD_NOT_EXECUTABLE | 126 | [D3] | 命令不可执行（权限问题） |
| CMD_NOT_FOUND | 127 | [D3] | 命令未找到（PATH 问题） |
| FATAL_SIGNAL_BASE | 128 | [D3] | 致命信号基数，实际退出码 = 128 + 信号编号 |
| CTRL_C_TERMINATION | 130 | [D3] | Ctrl-C 终止（128 + SIGINT=2） |
| CUSTOM_EXIT_RANGE | 64-113 | [D3] | 建议的用户自定义退出码范围 |

### 校准数值

以下数值来自 POSIX/Linux 标准实践，供量级校准；其他操作系统需以自身证据重新锚定。

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 低8位传递 | status & 0xFF | [D1][D2] | exit() 仅保留退出码最低有效 8 位传递给父进程 |
| SIGKILL 退出码 | 137 | [D3] | 128 + 9（SIGKILL），进程被强制杀死 |
| SIGTERM 退出码 | 143 | [D3] | 128 + 15（SIGTERM），进程被优雅终止 |
| 超时退出码约定 | 124 | [D3] | timeout 命令的约定退出码（部分工具采用） |

## 边界与分流

- **前提：退出码可获取** — 若进程未正常退出（如系统崩溃、OOM killer），退出码不可用，转向系统日志分析和核心转储检查。
- **前提：stderr 有输出** — 若 stderr 为空但退出码非零，可能是静默失败（如配置文件缺失但无报错），转向日志文件和配置验证。
- **前提：标准语义适用** — 若工具使用非标准退出码（如 Java 应用返回 -1），转向工具特定文档查找退出码约定。
- **前提：环境信息完整** — 若缺少执行环境信息（如未知是否沙箱化），先收集环境信息再继续诊断。

## 质量检查

- 退出码解析后必须验证其在有效范围内（0-255 或符号扩展后的有效值）
- stderr 模式匹配必须考虑多语言环境（如错误消息可能被本地化）
- 根因分类必须与所有已收集证据一致（退出码、stderr、环境信息）
- 恢复建议必须考虑副作用（如重试可能导致重复写入）

## 回退策略

- 若退出码语义不明确，记录为"未知退出码"并建议查看工具文档
- 若 stderr 包含堆栈跟踪但无法解析，提供原始错误输出供人工分析
- 若所有自动诊断失败，建议启用调试模式重新执行
