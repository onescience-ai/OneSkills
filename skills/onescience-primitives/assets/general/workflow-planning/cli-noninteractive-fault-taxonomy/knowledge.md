# CLI Non-Interactive Fault Taxonomy

## 适用范围

本方法论面向非交互式命令行工具（CLI）在自动化流水线中的执行故障诊断与恢复。覆盖科研计算、数据处理、模型训练等场景中 CLI 进程的启动、运行、超时、退出全流程。适用于 Python subprocess、shell 脚本、SLURM 作业提交等任意进程管理方式。

## 输入

- CLI 命令及其参数
- 预期退出码语义（0=成功，非零=失败）
- 超时阈值（秒）
- 认证凭据（API Key、Token 等）

## 输出

- 退出码语义映射表
- 故障分类体系（启动失败/运行时错误/超时/资源耗尽/认证失败）
- 标准错误解析策略
- 恢复建议与重试逻辑

## 流程节点

1. **进程启动** → 检查命令是否存在、路径是否正确、权限是否足够
2. **运行时监控** → 采集 stdout/stderr、检测超时
3. **退出码解析** → 根据语义映射表判定故障类别
4. **标准错误判读** → 提取关键错误信息、分类错误来源
5. **恢复决策** → 根据故障类别选择重试/降级/终止策略

## 关键参数

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 成功退出码 | 0 | [D1] | 标准成功状态 |
| 信号终止码 | -N（N为信号编号） | [D1] | POSIX 信号终止 |
| 超时异常 | TimeoutExpired | [D1] | subprocess.run() 超时触发 |
| 非零退出 | CalledProcessError | [D1] | check=True 时非零退出触发 |
| stderr 捕获 | PIPE/STDOUT | [D1] | 错误流重定向选项 |

## 边界与分流

- **启动失败**：命令不存在、权限不足 → 检查 PATH、安装依赖、修改权限
- **运行时崩溃**：进程被信号终止 → 检查内存限制、系统资源
- **超时**：超过阈值未完成 → 检查死锁、网络阻塞、优化超时设置
- **认证失败**：API Key 过期或无效 → 刷新凭据、检查环境变量
- **沙箱限制**：容器/虚拟环境权限不足 → 检查挂载点、用户权限

## 质量检查

- 退出码必须与语义映射表一致
- stderr 必须被捕获并解析
- 超时异常必须有日志记录
- 重试策略必须有最大重试次数

## 回退策略

1. 退出码无法解析 → 记录原始输出，标记为未知故障
2. 超时后进程未终止 → 强制 kill()，记录未完成原因
3. 认证失败 → 降级到无认证模式（如有）
