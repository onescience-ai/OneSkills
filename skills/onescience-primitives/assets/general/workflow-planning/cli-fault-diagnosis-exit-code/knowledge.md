# CLI非交互执行与故障诊断：退出码分类与自动化恢复

## 适用范围

本卡服务的问题类是：在CLI非交互执行场景中，如何根据进程退出码进行故障分类，识别命令执行失败的根本原因，并实施自动化恢复策略。适用于任何需要通过命令行接口自动化执行任务并处理异常的场景，包括但不限于批处理作业、CI/CD流水线、科学计算工作流和远程任务调度。不适用于交互式命令行操作或图形界面应用。

## 输入

- **命令执行结果**：包括标准输出(stdout)、标准错误(stderr)和退出码(exit code)
- **执行上下文**：命令参数、执行环境、资源限制配置
- **历史执行记录**：成功/失败模式、恢复策略执行结果

## 输出

- **故障分类报告**：基于退出码的故障类型判定
- **根因分析**：结合stderr和执行上下文的故障原因定位
- **恢复策略建议**：自动重试、降级处理或人工干预建议
- **执行状态确认**：区分"观察到的输出"与"已持久化的结果"

## 流程节点

### 1. 退出码捕获与分类

```bash
# 执行命令并捕获退出码
command; EXIT_CODE=$?
```

**标准退出码分类表**：

| 退出码范围 | 类别 | 典型原因 | 处理策略 |
|-----------|------|---------|---------|
| 0 | 成功 | 命令正常完成 | 继续后续流程 |
| 1-125 | 用户错误 | 参数错误、资源不足、权限问题 | 检查输入、日志分析 |
| 126 | 无法执行 | 文件不可执行或权限不足 | 检查文件权限 |
| 127 | 命令未找到 | 命令不存在或PATH配置错误 | 检查安装和环境变量 |
| 128+ | 信号终止 | 进程被信号终止 | 根据信号类型处理 |
| 130 (128+2) | SIGINT | 用户中断(Ctrl+C) | 可选重试 |
| 137 (128+9) | SIGKILL | 强制终止(OOM或kill -9) | 检查资源限制 |
| 143 (128+15) | SIGTERM | 优雅终止(timeout或kill) | 重试或检查超时设置 |

### 2. 观察与持久化状态区分

**关键原则**：CLI输出是临时的，文件写入是持久的。

**状态验证流程**：
1. 检查退出码是否为0
2. 若退出码非0，验证输出文件是否已完整写入
3. 区分"在终端观察到的输出"与"已确认持久化的结果"
4. 对于SIGTERM(143)等情况，部分输出不可信

### 3. 故障诊断与根因分析

**诊断检查清单**：
- [ ] 退出码是否在预期范围内
- [ ] stderr输出是否包含错误信息
- [ ] 资源使用情况(CPU/内存/磁盘)是否超限
- [ ] 网络连接是否正常(如适用)
- [ ] 依赖服务是否可用

### 4. 自动化恢复策略

**恢复策略决策树**：
- 退出码=0 → 验证输出完整性 → 继续
- 退出码=1-125 → 分析日志 → 修正输入或配置 → 重试
- 退出码=126-127 → 检查环境配置 → 修复后重试
- 退出码=137 → 增加资源限制 → 重试
- 退出码=143 → 检查超时设置 → 调整超时或优化性能 → 重试

### 通用判据

| 参数 | 值 | 来源 | 说明 |

## 边界与分流

### 异常处理
- **无限循环检测**：监控进程CPU使用率，持续高占用超过阈值时强制终止
- **僵尸进程处理**：父进程需正确回收子进程资源
- **资源泄漏**：文件句柄、内存泄漏需监控和限制

### 降级策略
- 当主命令不可执行时，尝试备用命令或脚本
- 当网络超时时，启用本地缓存或离线模式
- 当资源不足时，降低并行度或分批处理

### 分支条件
- 退出码=0且输出文件完整 → 成功路径
- 退出码非0但输出文件存在 → 部分成功，需验证
- 退出码非0且无输出 → 失败路径，需重试或人工介入

## 质量检查

### 验证点
1. 退出码分类是否准确
2. 故障根因分析是否有证据支持
3. 恢复策略是否可执行
4. 状态区分（观察vs持久化）是否正确

### 阈值
- 退出码捕获率：100%（必须捕获）
- 故障诊断准确率：≥80%（基于历史验证）
- 恢复成功率：≥70%（自动化恢复）

### 失败处理
- 诊断失败：记录原始错误信息，转人工处理
- 恢复失败：重试次数耗尽后告警，保留现场证据

## 回退策略

- 当自动化诊断无法确定根因时，输出完整日志供人工分析
- 当恢复策略执行失败时，回滚到上一个稳定状态
- 当退出码不符合标准分类时，记录异常并扩展分类表
