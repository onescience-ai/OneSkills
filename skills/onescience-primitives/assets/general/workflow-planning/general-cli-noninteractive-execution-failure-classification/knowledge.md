# CLI 非交互执行与故障分类

## 适用范围

面向命令行工具在自动化流水线中的可靠执行，提供从参数校验到故障诊断的系统化方法。适用于需要在无人值守环境下调用 CLI 工具、捕获并分类执行故障、设计恢复策略的场景。当 CLI 工具的执行结果需要作为下游流程的输入，或需要将故障信息结构化上报时，本卡提供分类框架与处理流程。

不适用于交互式 CLI 会话（如 REPL 环境）、图形界面工具调用，或不涉及退出码/标准错误的纯库函数调用。

## 输入

- CLI 命令字符串或参数列表
- 执行环境配置（操作系统、shell 类型、依赖版本）
- 超时阈值（默认值或自定义）
- 认证凭据（如需要）
- 沙箱隔离要求（可选）

## 输出

- 退出码分类结果（成功/警告/非致命错误/致命错误/信号终止）
- stderr 结构化解析（错误类型、错误消息、错误位置）
- 执行诊断证据包（stdout、stderr、退出码、耗时、资源使用）
- 恢复策略建议（重试/降级/终止/人工介入）

## 流程节点

### Step 1：命令构建与参数校验
- **操作**：构建 CLI 命令，验证参数合法性
- **参数**：命令路径、参数列表、环境变量
- **工具**：shell 解析器、参数校验库
- **质量门禁**：参数数量与类型匹配、必填参数非空、路径可达

### Step 2：沙箱化隔离执行
- **操作**：在隔离环境中启动 CLI 进程
- **参数**：超时阈值、资源限制（CPU/内存）、工作目录
- **工具**：subprocess（Python）、Process（Node.js）、timeout 命令
- **质量门禁**：进程成功启动、无立即崩溃（exit code != 126/127）

### Step 3：超时监控与自适应调整
- **操作**：监控执行时间，超时则终止
- **参数**：初始超时值、最大重试次数、退避策略
- **工具**：timer、watchdog
- **质量门禁**：超时终止后保留诊断信息、记录实际耗时

### Step 4：退出码分类
- **操作**：根据退出码判断执行结果类别
- **参数**：退出码值、工具特定约定
- **工具**：shell 退出码语义
- **质量门禁**：分类结果与 stderr 内容一致

### Step 5：标准错误解析
- **操作**：从 stderr 提取结构化错误信息
- **参数**：错误格式模式、日志级别
- **工具**：正则表达式、日志解析器
- **质量门禁**：错误类型可识别、错误消息完整

### Step 6：诊断证据收集与上报
- **操作**：汇总执行证据，生成结构化报告
- **参数**：报告格式（JSON/文本）、必填字段
- **工具**：JSON 序列化器
- **质量门禁**：报告可解析、字段完整、与任务身份一致

## 关键参数

### 通用判据

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 退出码 0 | 成功 | [1] | 标准成功退出，无错误 |
| 退出码 1-2 | 通用错误 | [1] | 应用级错误，具体语义由工具定义 |
| 退出码 126 | 权限拒绝 | [1] | 命令不可执行（非目录、无执行权限） |
| 退出码 127 | 命令未找到 | [1] | 命令不存在或不在 PATH 中 |
| 退出码 128+N | 信号终止 | [1] | 被信号 N 终止（如 130=SIGINT, 137=SIGKILL） |
| 退出码 255 | 退出码溢出 | [1] | 超出 0-255 范围的退出码被模 256 截断 |
| 超时退出 | 自定义（如 124） | [2] | timeout 命令超时后的退出码 |
| stderr 非空 | 非致命警告 | [1][3] | 有警告但退出码为 0 |

### 校准数值

以下数值来自特定系统的研究结果，供量级校准；其他系统需以自身证据重新锚定。

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 测试超时失败占比 | 约 70% | [2] | SAP HANA 系统测试中，超时导致的 flaky 失败占总 flaky 失败的 70% |
| 超时优化后 flaky 减少 | 约 80% | [2] | 自动调整超时值后，超时相关 flaky 失败减少 80% |
| CLI 工具生成成功率上限 | 约 43.8% | [1] | 当前最强 LLM 在端到端 CLI 工具生成任务中的最高成功率 |
| CLI 命令组合攻击成功率 | 约 96.59% | [4] | 独立无害的 CLI 命令组合后可形成危险的 producer-consumer 关系 |

## 边界与分流

- **退出码语义不明确**：当工具未遵循 POSIX 退出码约定时，需查阅工具文档获取自定义退出码表；若文档缺失，将退出码视为"未知"并记录原始值。
- **超时值难以确定**：初始超时应基于历史执行数据的 P95 分位值；无历史数据时采用渐进式探测（从低超时开始逐步增加）。
- **stderr 格式不规范**：当 stderr 不包含结构化信息时，退化为全文存储，标记为"非结构化错误"。
- **沙箱环境不可用**：降级为进程级隔离（subprocess + timeout），记录隔离级别降级。
- **认证失败**：区分"凭据过期"（可重试）和"凭据无效"（需人工介入）。

## 质量检查

- 退出码分类结果与 stderr 内容交叉验证（若退出码为 0 但 stderr 含 error 级别日志，标记为异常）
- 超时终止的进程必须记录实际耗时和终止信号
- 诊断证据包包含完整的 stdout、stderr、退出码、耗时
- 恢复策略与故障类别匹配（可恢复故障→重试，不可恢复→终止+上报）
- 使用成功、非零退出和超时用例验证状态及日志

## 回退策略

- 退出码分类失败时，将原始退出码和 stderr 原文一并上报，由下游人工判读
- 超时自适应调整失败时，使用默认超时值并在诊断中标注"超时策略降级"
- 沙箱隔离失败时，记录环境限制并继续执行（降低隔离级别）
