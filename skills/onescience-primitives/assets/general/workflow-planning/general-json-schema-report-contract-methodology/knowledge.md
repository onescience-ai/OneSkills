# 通用JSON Schema报告交付契约方法论

## 适用范围
面向结构化数据报告交付场景，提供基于JSON Schema的验证契约方法论框架。适用于任何需要以JSON格式交付结构化报告的场景，包括科学计算结果、数据分析报告、API响应、配置文件等。本卡解决的核心问题是：如何确保交付的JSON报告符合预定义的格式规范，包含所有必填字段，且字段类型和约束正确。不适用于非JSON格式的数据交付或纯文本报告。

## 输入
- JSON Schema定义文件（draft-04/06/07/2019-09/2020-12）
- 待验证的JSON报告数据
- 验证规则配置（严格模式、附加验证器）
- 任务身份信息（任务ID、任务名称、版本号）

## 输出
- 验证结果（通过/失败）
- 详细错误信息（缺失字段、类型错误、约束违反）
- 验证报告（包含统计信息、警告、建议）
- 修复建议（针对验证失败的具体修复步骤）

## 流程节点
1. **Schema加载** → 2. **数据预处理** → 3. **验证执行** → 4. **错误分析** → 5. **报告生成** → 6. **修复验证**

### 步骤1：Schema加载
- 操作：加载并解析JSON Schema定义
- 参数：Schema路径、版本检测、引用解析
- 工具：JSON Schema解析器、$ref解析器
- 质量门禁：Schema可解析，无语法错误

### 步骤2：数据预处理
- 操作：准备待验证的JSON数据
- 参数：数据编码、BOM处理、空值转换
- 工具：JSON解析器、编码检测器
- 质量门禁：数据可解析为有效JSON对象

### 步骤3：验证执行
- 操作：按照Schema规则验证数据
- 参数：验证模式（strict/lenient）、自定义验证器
- 工具：JSON Schema验证器、验证上下文
- 质量门禁：验证过程无异常，结果完整

### 步骤4：错误分析
- 操作：分析验证错误，分类问题类型
- 参数：错误分类树、置信度阈值
- 工具：错误分析器、模式匹配器
- 质量门禁：错误分类准确，可操作性强

### 步骤5：报告生成
- 操作：生成结构化验证报告
- 参数：报告模板、输出格式、详细程度
- 工具：报告生成器、模板引擎
- 质量门禁：报告包含所有必要信息，格式一致

### 步骤6：修复验证
- 按照修复建议修改数据后重新验证
- 参数：修复策略、重试逻辑
- 工具：验证器、修复器
- 质量门禁：修复后验证通过

## 边界与分流
- **Schema版本不兼容前提不成立**：当使用旧版Schema时，降级验证模式并记录兼容性警告
- **数据编码不支持前提不成立**：当遇到非UTF-8编码时，尝试编码转换或报告编码错误
- **验证超时前提不成立**：当数据量极大时，分块验证或跳过非关键验证
- **严格模式不适用前提不成立**：当数据质量要求不高时，切换到宽松模式并记录警告

## 质量检查
- Schema验证准确率 > 99%
- 错误消息可读性评分 > 4.0（5分制）
- 修复建议执行成功率 > 85%
- 验证性能：10KB JSON验证时间 < 1秒
- 覆盖率：所有必填字段100%检查

## 回退策略
- 当Schema无法解析时，使用基础JSON语法验证作为降级方案
- 当验证器不支持特定关键字时，跳过该验证并记录警告
- 当验证超时时，执行简化验证（仅检查必填字段）
- 当报告生成失败时，输出原始错误信息作为最小化报告
