# CLI非交互执行与故障分类

## 适用范围
面向命令行接口（CLI）的非交互执行场景，提供故障分类方法论，适用于任何需要自动化执行CLI工具并处理其退出状态的应用。覆盖命令参数验证、认证失败、沙箱环境异常、超时处理、退出码判读和标准错误解析，确保自动化流水线中的CLI调用具备可恢复性与可诊断性。

## 输入
CLI命令及其参数，可能包含认证信息、沙箱配置、超时设置等。

## 输出
结构化的退出状态报告，包括退出码、标准错误输出、故障分类（如参数错误、认证失败、超时、沙箱限制等）。

## 流程节点
1. 命令解析 → 2. 参数验证 → 3. 认证检查 → 4. 沙箱配置 → 5. 超时设置 → 6. 执行 → 7. 退出码收集 → 8. 标准错误判读 → 9. 故障分类

## 关键参数

### 通用判据（方法层）

| 参数 | 推荐值 | 来源 | 说明 |
|------|--------|------|------|
| 退出码范围划分 | 0:成功, 1-99:用户错误, 100-199:环境错误, 200-299:认证错误, ≥300:系统错误 | 行业惯例 | 不同工具可能有自定义退出码，需查阅工具文档确认 |
| stderr关键词匹配阈值 | 至少匹配2个特征词 | 经验值 | 单一关键词匹配可能存在误判 |
| 超时默认阈值 | 300秒（复杂计算任务可延长） | 行业惯例 | 根据任务复杂度调整 |
| 认证失败重试次数 | 最多3次，指数退避 | 行业惯例 | 避免无限重试导致资源耗尽 |

### 校准数值（示例场景）

| 参数 | 值 | 说明 |
|------|-----|------|
| Python脚本退出码1 | 未捕获异常 | 标准Python脚本未处理异常的默认退出码 |
| Bash脚本退出码126 | 权限被拒绝 | 文件不可执行 |
| Bash脚本退出码127 | 命令未找到 | 可执行文件路径错误或未安装 |
| HTTP 429状态码 | Too Many Requests | API限流，需等待后重试 |
| HTTP 401状态码 | Unauthorized | 认证凭据无效或过期 |

## 边界与分流
- 参数错误：退出码非0，标准错误包含"invalid argument"等关键词 → 检查命令语法
- 认证失败：退出码非0，标准错误包含"authentication failed"等关键词 → 检查凭证
- 超时：退出码124（timeout命令）或类似 → 增加超时时间或优化命令
- 沙箱限制：退出码非0，标准错误包含"permission denied"等关键词 → 检查沙箱权限
- **退出码无法获取时**：转向进程信号分析（SIGTERM/SIGKILL等），记录为"进程异常终止"
- **stderr为空但退出码非零时**：检查是否输出被重定向，或工具将错误输出到stdout
- **认证信息无法验证时**：标记为"待确认"，不自动重试，等待人工介入

## 质量检查
- 退出码是否在预期范围内
- 标准错误输出是否包含明确错误信息
- 故障分类是否与错误模式匹配
- 每次故障记录必须包含：时间戳、退出码、错误消息、环境快照

## 回退策略
- 如果故障分类不确定，记录原始退出码和标准错误输出，交由人工处理
- 无法确定故障类别时：记录所有可用信息，标记为"需人工诊断"
- 恢复策略执行失败时：记录失败原因，建议人工介入或环境重建

## 批次补充（来自任务252知识补充）

### 校准数值补充（Linux退出码规范）
- 退出码1：通用错误（如除零、其他不允许的操作）
- 退出码2：Shell内置命令误用（缺少关键字、权限问题）
- 退出码126：命令无法执行（权限问题或非可执行文件）
- 退出码127：命令未找到（PATH问题或拼写错误）
- 退出码128+n：致命信号n（如kill -9返回137=128+9）
- 退出码130：脚本被Ctrl+C终止（信号2）
- 退出码255：退出状态超出范围（exit仅接受0-255整数）
