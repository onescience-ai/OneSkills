# OneScience工作流编排与executor技能调用

## 适用范围
当需要编排OneScience工作流并正确调用executor技能时，本卡提供step_handoff格式规范、输入输出契约和状态传递机制的知识。适用于确保工作流步骤可追溯、可复现的执行过程。

## 输入
- 工作流步骤：需要执行的具体步骤（如s01-s04）
- 步骤目标：每个步骤的预期输出和验证标准
- 上下文信息：前序步骤的输出和状态

## 输出
- 执行记录：每个步骤的executor调用记录
- 状态传递：步骤间的数据传递和状态更新
- 验证结果：步骤执行的成功/失败状态

## 流程节点
1. **步骤规划** → 2. **executor选择** → 3. **step_handoff构建** → 4. **执行调度** → 5. **状态回传**

### 步骤1：步骤规划
- 操作：分析工作流步骤的依赖关系和执行顺序
- 参数：步骤列表、依赖图、前置条件
- 工具：工作流分析工具
- 质量门禁：步骤依赖关系正确，无循环依赖

### 步骤2：executor选择
- 操作：为每个步骤选择合适的executor技能
- 参数：步骤类型、执行要求、资源需求
- 工具：技能目录查询
- 质量门禁：executor能力匹配步骤需求

### 步骤3：step_handoff构建
- 构建标准格式的step_handoff参数
- 参数：step_id、execution_skill、step_goal、task_context、inputs、expected_outputs
- 工具：YAML/JSON构建器
- 质量门禁：格式符合规范，所有必需字段完整

### 步骤4：执行调度
- 操作：调用executor技能执行步骤
- 参数：step_handoff、执行选项、超时设置
- 工具：onescience-orchestrator
- 质量门禁：executor成功调用，执行过程可追溯

### 步骤5：状态回传
- 操作：接收executor的执行结果并更新状态
- 参数：execution_result、状态更新、错误处理
- 工具：状态管理器
- 质量门禁：状态正确更新，错误适当处理

## 边界与分流
- **executor不可用**：检查技能目录，确认executor已安装和配置
- **step_handoff格式错误**：验证必需字段，修正格式问题
- **执行超时**：调整超时设置或优化步骤执行
- **状态传递失败**：检查数据格式，确保契约兼容性

## 质量检查
- 验证点：step_handoff格式正确性、executor调用记录完整性、状态传递准确性
- 阈值：每个步骤有对应executor调用记录
- 失败处理：记录具体失败原因，提供修复建议

## 回退策略
- 标准方法不适用时，考虑使用简化工作流或手动执行
- executor技能缺失时，记录缺失信息并建议安装
- 状态管理复杂时，使用中间文件或数据库进行状态持久化
