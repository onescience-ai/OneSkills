# JSON Schema 验证与评估框架

## 适用范围
适用于从无模式文档数据库（如MongoDB、CouchDB等）中提取的JSON Schema质量评估场景。当需要系统化评估提取的Schema在结构、语义和时间行为上的可靠性时，可使用本框架。不适用于关系型数据库的Schema验证，也不适用于实时数据流的Schema验证。

## 输入
- 数据集：由无模式JSON文档组成的集合
- 提取的Schema：从数据集中推断出的JSON Schema表示
- 参考Schema（可选）：专家定义的基准Schema或数据集的真实结构

## 输出
- Schema质量评分（Schema Quality Score, SQS）
- 六个维度的详细评估报告
- 各维度的量化指标和可视化结果

## 流程节点
1. 数据准备 → 收集JSON文档集合，预处理为标准格式
2. Schema提取 → 使用推断算法从数据中提取Schema
3. 维度评估 → 按六个维度分别计算量化指标
4. 综合评分 → 加权聚合各维度得分，生成总体质量评分
5. 报告生成 → 输出详细的评估报告和可视化结果

每步含：操作、参数、工具、质量门禁

## 关键参数

### 通用判据
| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 数据类型准确性阈值 | ≥0.8 | [1] | 推断类型与观察类型的一致性度量 |
| 字段存在性准确性 | ≥0.85 | [1] | 正确识别必需和可选字段的比例 |
| 依赖关系置信度阈值 | ≥0.8 | [1] | 关联规则的置信度下限 |
| 依赖关系提升度阈值 | ≥1.2 | [1] | 关联规则的提升度下限 |
| 实体关系F1分数 | ≥0.7 | [1] | 边级别关系恢复的F1度量 |
| 图编辑距离归一化 | ≤0.3 | [1] | 全局结构相似性度量 |

### 校准数值
以下数值来自电子商务订单数据集示例，供量级校准；其他体系需以自身证据重新锚定。

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 订单ID字段类型 | string | [1] | 标识符字段应推断为字符串类型 |
| 价格字段类型 | number | [1] | 数值字段应推断为数字类型 |
| 是否加急字段 | boolean | [1] | 布尔字段应推断为布尔类型 |
| 折扣码出现频率 | <0.3 | [1] | 低频字段应标记为可选 |
| 支付方式依赖 | payment_details | [1] | 支付方式字段依赖支付详情字段 |

## 边界与分流
- 当数据集规模过小（<100文档）时，统计指标可能不稳定，建议使用更保守的阈值
- 当Schema推断算法产生高度泛化的结果时，应检查是否过度简化了数据结构
- 当时间演化检测失败时，可能表明数据集缺乏时间维度或Schema变化过于频繁
- 当实体关系恢复效果差时，可能需要考虑更复杂的嵌套或引用模式

## 质量检查
- 验证推断的Schema是否包含所有必需的字段
- 检查数据类型推断的准确性
- 评估可选字段识别的合理性
- 验证依赖关系的完整性
- 检查数组结构的正确表示
- 评估实体关系的恢复质量

## 回退策略
- 当参考Schema不可用时，可使用数据集统计信息作为基准
- 当量化指标计算失败时，可使用定性评估作为补充
- 当框架不适用时，可考虑使用其他验证方法或工具

## 资源建议
- 当需要从JSON文档中提取Schema时，可参考Schema推断算法相关资源
- 当需要处理大规模数据集时，可参考分布式处理框架
- 当需要可视化评估结果时，可参考数据可视化工具
