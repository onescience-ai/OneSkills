# AI编排系统异常自恢复策略

## 适用范围

面向AI编排系统中智能体在工具调用失败或陷入循环时的异常恢复场景，解决检测到连续相同调用模式后无法自动切换执行路径的问题。适用于所有需要状态感知策略切换的编排系统，包括但不限于OneScience编排体系、多智能体协作系统、以及需要容错能力的自动化工作流。

## 输入

- 工具调用历史记录
- 当前任务状态
- 异常检测信号（连续相同调用模式）
- 可用的替代执行路径

## 输出

- 异常诊断结果
- 降级策略选择
- 替代执行路径启动
- 恢复事件日志

## 流程节点

1. **异常检测** → 监控工具调用模式，检测连续相同调用行为
2. **根因诊断** → 分析异常原因（参数错误、技能不可用、循环依赖等）
3. **策略选择** → 根据诊断结果选择合适的降级策略
4. **路径切换** → 执行降级策略，切换到替代执行路径
5. **状态恢复** → 更新任务状态，记录恢复事件

每步含：操作、参数、工具、质量门禁

## 关键参数

### 通用判据（方法层）

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 异常检测阈值 | 3次 | 归因报告 | 连续3次相同调用模式触发降级 |
| 诊断时间窗口 | 5分钟 | 实践经验 | 在时间窗口内分析调用历史 |
| 策略选择延迟 | 1秒 | 实践经验 | 策略选择后的等待时间 |

### 校准数值

以下数值来自OneScience编排体系，供量级校准；其他体系需以自身证据重新锚定：

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 最大重试次数 | 3 | 归因报告 | 超过此次数应触发降级 |
| 降级策略类型 | 2种 | 归因报告 | 直接规划或跳过专家召回 |
| 恢复事件记录 | 必须 | 归因报告 | 所有恢复事件必须记录到task_state.json |

## 边界与分流

- **异常检测失败**：当无法检测异常模式时，应记录警告日志并继续当前执行
- **无可用替代路径**：当所有降级策略均不可用时，应向用户报告任务阻塞
- **降级策略执行失败**：当降级策略本身执行失败时，应触发更高级别的异常处理
- **状态不一致**：当降级后状态不一致时，应回滚到最近的一致状态

## 质量检查

- 验证异常检测阈值配置正确
- 验证降级策略选择逻辑合理
- 验证替代执行路径可达
- 验证恢复事件完整记录
- 失败处理：检测失败时记录警告，策略选择失败时使用默认策略

## 回退策略

- 当自动恢复失败时，向用户报告任务状态并请求手动干预
- 当降级策略不可用时，尝试其他可用的替代路径
- 当所有路径均失败时，生成详细的错误报告供后续分析
