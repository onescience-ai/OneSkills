# 场景执行前预确认流程

## 适用范围

当任务执行需要用户提供关键输入或确认关键取舍时，必须在正式执行前提交预确认报告并等待用户确认。本卡提供预确认流程的规范，包括预确认报告的生成时机、内容要求和等待用户确认的机制。适用于orchestrator在执行前必须确保用户理解任务并提供必要输入的场景。

**不适用场景**：
- 用户明确要求"一直执行"或"自动完成"的自主执行模式
- 无需用户输入的纯自动化任务
- 可选输入缺失不阻塞但须记录的场景

## 输入

- 任务目标和约束
- 已获取的资源摘要
- 意图分析结果
- 可用的executor技能能力视图

## 输出

- 预确认报告（任务理解、数据可用性、方法选择、I/O契约、验证设计、资源估算、质量门禁、风险、失败分支、替代方案、缺失信息）
- 用户确认记录
- 更新后的Task State

## 流程节点

1. **任务理解分析** → 2. **预确认报告生成** → 3. **用户确认等待** → 4. **确认结果处理** → 5. **Task State更新**

### 步骤1：任务理解分析
- **操作**：分析任务提示词，提取核心目标、约束和关键取舍
- **参数**：任务描述、输入要求、输出期望、用户请求
- **工具**：自然语言处理
- **质量门禁**：任务目标明确，约束完整，关键取舍识别准确

### 步骤2：预确认报告生成
- **操作**：生成预确认报告，包含任务理解、数据可用性、方法选择理由、输入输出契约、验证设计、时间与资源估算、质量门禁、主要风险、失败分支、替代方案和缺失信息
- **参数**：任务理解结果、资源摘要、executor能力视图
- **工具**：报告生成器
- **质量门禁**：报告内容完整，覆盖所有必需字段

### 步骤3：用户确认等待
- **操作**：输出预确认报告给用户，等待用户确认
- **参数**：预确认报告、确认机制
- **工具**：用户界面
- **质量门禁**：报告清晰，确认机制有效

### 步骤4：确认结果处理
- **操作**：处理用户确认结果，记录确认信息
- **参数**：用户反馈、确认状态
- **工具**：状态管理器
- **质量门禁**：确认记录完整，状态正确更新

### 步骤5：Task State更新
- **操作**：将确认结果写入Task State，记录用户确认事件
- **参数**：确认结果、事件记录
- **工具**：状态更新器
- **质量门禁**：Task State正确更新，事件可追溯

## 关键参数

### 通用判据（方法层）

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 预确认报告字段 | 任务理解、数据可用性等 | [OneScience规范] | 报告必须包含的字段 |
| 确认等待机制 | 用户确认后执行 | [OneScience规范] | 执行前的用户确认要求 |
| 关键取舍识别 | 目标范围、数据口径、成本、验收标准 | [OneScience规范] | 需要用户确认的取舍 |
| 缺失信息处理 | 记录并等待补充 | [OneScience规范] | 必需输入缺失时的处理 |

## 边界与分流

- **用户确认通过**：继续执行任务，进入下一个步骤
- **用户确认拒绝**：重新规划或修改任务目标
- **必需输入缺失**：记录缺失信息，等待用户补充
- **关键取舍未确认**：停止执行，等待用户确认
- **自主执行模式**：跳过预确认，直接执行（用户已明确授权）

## 质量检查

- 验证点：预确认报告完整性、用户确认记录完整性、Task State更新准确性
- 阈值：预确认报告必须包含所有必需字段，用户确认必须明确记录
- 失败处理：预确认失败时记录原因，提供调整建议

## 回退策略

- 预确认报告生成失败时：使用简化报告，标注"报告生成异常"
- 用户确认超时：记录超时事件，建议用户重新确认
- Task State更新失败：重试更新，记录更新失败事件
