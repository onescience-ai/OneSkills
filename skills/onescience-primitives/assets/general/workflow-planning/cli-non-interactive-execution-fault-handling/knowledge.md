# CLI 非交互执行故障诊断与处理

## 适用范围

本卡面向任意命令行界面（CLI）工具的非交互执行场景，提供系统化的故障诊断与处理方法论。适用于科研计算、数据处理流水线、自动化测试、持续集成等需要可靠 CLI 执行的环境。覆盖从命令启动到结果返回的全生命周期故障处理，包括参数配置错误、认证失败、资源超时、进程异常退出和结构化输出解析失败等常见问题类型。

## 输入

- CLI 工具可执行文件路径或命令
- 命令行参数与选项
- 运行环境配置（沙箱、资源限制、超时设置）
- 输入数据（文件、管道、标准输入）
- 期望的输出格式（JSON、文本、二进制）

## 输出

- 执行状态码（exit code）
- 标准输出（stdout）
- 标准错误（stderr）
- 结构化执行报告（可选）
- 故障分类与诊断建议

## 流程节点

### 1. 命令预检阶段
- 验证可执行文件存在性和权限
- 检查依赖库和环境变量
- 预估资源需求（内存、磁盘、CPU）
- 确定超时阈值

### 2. 命令执行阶段
- 以非交互模式启动进程（stdin 重定向到 /dev/null 或管道）
- 实时监控进程状态
- 收集 stdout 和 stderr 输出
- 记录执行时间戳

### 3. 退出码分类与判读
根据退出码判断执行结果：

| 退出码范围 | 类别 | 典型原因 | 处理策略 |
|-----------|------|---------|---------|
| 0 | 成功 | 正常完成 | 继续后续流程 |
| 1-125 | 应用错误 | 参数错误、数据格式异常、业务逻辑失败 | 解析 stderr 获取详细错误信息，修正参数后重试 |
| 126 | 权限错误 | 可执行文件无执行权限 | 修复文件权限 |
| 127 | 命令未找到 | 路径错误或工具未安装 | 检查 PATH 或安装工具 |
| 128+N | 信号终止 | 进程被信号 N 终止（如 SIGTERM=143, SIGKILL=137） | 检查资源限制、超时设置 |
| 130 | Ctrl+C | 用户中断（SIGINT） | 检查是否需要优雅退出 |
| 137 | OOM Kill | 内存不足被系统杀死（SIGKILL） | 增加内存限制或优化数据处理 |
| 超时退出 | 超时 | 执行时间超过阈值 | 增加超时、优化算法或拆分任务 |

### 4. 结构化输出验证（可选）
- 检查 stdout 是否为有效 JSON
- 验证字段完整性（必填字段是否存在）
- 校验数据类型和约束
- 生成验证报告

### 5. 故障恢复策略
- **可重试错误**：网络超时、临时资源不可用 → 指数退避重试
- **参数错误**：格式不正确、值越界 → 修正参数后重试
- **资源错误**：内存不足、磁盘满 → 释放资源或增加配额
- **权限错误**：认证失败、访问被拒 → 刷新凭证或申请权限
- **不可恢复错误**：工具崩溃、数据损坏 → 记录诊断信息，上报人工处理

## 边界与分流

### 超时场景
- **短任务** (<60s)：超时设为预期时间 3 倍
- **长任务** (60s-1h)：超时设为预期时间 2 倍
- **批处理任务** (>1h)：按任务粒度设置检查点，支持断点续传

### 认证失败分流
- **凭证过期** → 刷新凭证后重试
- **权限不足** → 上报权限申请
- **认证服务不可用** → 降级到缓存凭证或跳过认证

### 资源限制分流
- **内存不足** → 优化数据处理或增加内存配额
- **CPU 限制** → 降低并发度或增加 CPU 配额
- **磁盘满** → 清理临时文件或增加存储

## 质量检查

| 检查项 | 验证方式 | 通过标准 |
|--------|---------|---------|
| 退出码有效性 | 解析 exit code | 已知退出码范围内 |
| 输出可解析性 | JSON/文本格式校验 | 符合预期格式 |
| 错误信息完整性 | 检查 stderr 内容 | 包含有意义的错误描述 |
| 执行时间合理性 | 对比预期时间 | 不超过预期时间 2 倍 |

## 回退策略

1. **主通道失败**：退出码非 0 或超时 → 降级到只读模式或跳过非关键步骤
2. **输出解析失败**：stdout 无效 → 尝试从 stderr 提取信息
3. **认证失败**：无法刷新凭证 → 使用本地缓存或上报人工介入
4. **资源不可用**：沙箱/容器启动失败 → 回退到本地执行
