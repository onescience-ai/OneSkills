# CLI非交互执行与故障分类

## 适用范围
适用于所有通过命令行接口（CLI）执行的自动化任务，包括批处理脚本、CI/CD流水线、科学计算工作流调度等非交互场景。当CLI进程异常退出、返回非零退出码或产生标准错误输出时，本卡片提供故障分类与诊断框架。

不适用于：交互式终端会话中的用户输入错误；图形界面应用的异常处理。

## 输入
- CLI命令及参数列表
- 执行环境（操作系统、shell类型、conda环境）
- 预期退出码（通常为0表示成功）
- 超时阈值（可选）

## 输出
- 退出码分类（成功/参数错误/运行时错误/超时/被中断）
- 标准错误（stderr）解析结果
- 故障根因定位（参数校验失败、依赖缺失、超时、沙箱限制等）
- 修复建议

## 流程节点
1. 捕获进程退出码 → 2. 分类退出码含义 → 3. 解析stderr输出 → 4. 关联异常类型 → 5. 定位故障根因 → 6. 生成修复建议

### 节点1：捕获进程退出码
- **操作**：通过subprocess.run()或os.system()执行CLI命令，获取returncode
- **参数**：timeout（秒）、capture_output=True
- **工具**：Python subprocess模块
- **质量门禁**：必须捕获returncode，不得忽略非零退出

### 节点2：分类退出码含义
- **操作**：根据退出码范围判断故障类别
- **参数**：returncode值
- **工具**：条件判断逻辑
- **质量门禁**：退出码分类必须符合POSIX约定

### 节点3：解析stderr输出
- **操作**：读取并解析标准错误输出
- **参数**：stderr内容
- **工具**：正则表达式匹配
- **质量门禁**：保留原始错误信息，不得截断

### 节点4：关联异常类型
- **操作**：将退出码与Python异常类型对应
- **参数**：退出码、stderr内容
- **工具**：异常映射表
- **质量门禁**：映射关系必须基于官方文档

### 节点5：定位故障根因
- **操作**：结合退出码、stderr和异常类型定位根因
- **参数**：综合诊断信息
- **工具**：决策树
- **质量门禁**：根因必须有证据支撑

### 节点6：生成修复建议
- **操作**：根据故障类别给出修复方案
- **参数**：故障类别、根因
- **工具**：建议模板
- **质量门禁**：建议必须可执行

## 关键参数

### 通用判据（方法层）
| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 退出码0 | 成功 | [D1] argparse文档 | 进程正常完成 |
| 退出码1 | 运行时错误 | [D2] SystemExit文档 | 程序执行过程中发生未捕获异常 |
| 退出码2 | 参数错误 | [D1] argparse文档 | 命令行参数解析失败 |
| 退出码126 | 权限不足 | POSIX标准 | 命令不可执行 |
| 退出码127 | 命令未找到 | POSIX标准 | 命令不存在或PATH配置错误 |
| 退出码130 | 被中断 | POSIX标准 | Ctrl+C（SIGINT）终止 |
| 退出码143 | 被终止 | POSIX标准 | SIGTERM信号终止 |

### 校准数值
以下数值来自Python argparse实现，供量级校准；其他系统需以自身证据重新锚定。

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| argparse退出码 | 2 | [D1] argparse文档 | 参数解析失败时的默认退出码 |
| SystemExit参数 | 整数或字符串 | [D2] SystemExit文档 | 整数指定退出状态，字符串打印后退出码为1 |
| 超时退出 | 自定义 | 运行时实现 | 超时通常返回124或自定义码 |

## 边界与分流
- **退出码0但stderr有输出**：警告信息，非致命错误，记录但不阻断流程
- **退出码非0但无stderr**：检查是否为信号终止（如OOM Killer），查看系统日志
- **退出码126/127**：检查命令路径和执行权限，确认conda环境已激活
- **退出码130/143**：检查是否有外部中断信号，确认是否为用户手动终止或调度系统超时
- **退出码>128**：信号终止，退出码=128+信号编号，需查信号表

## 质量检查
- 退出码是否在预期范围内（0或约定的非零码）
- stderr是否包含关键错误信息（Traceback、Error、Exception）
- 超时是否在合理范围内（科学计算任务可能需要较长超时）
- 并发执行时是否存在竞争条件

## 回退策略
- 无法获取退出码时：检查进程是否为守护进程或被init收养
- stderr被重定向时：检查文件描述符2是否被正确捕获
- 跨平台差异时：参考POSIX退出码规范与Windows ERRORLEVEL对照
