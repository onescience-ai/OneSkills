# JSON Schema 报告验证与评估方法论

## 适用范围
面向 JSON Schema 报告交付的验证与评估方法论，适用于任何需要生成结构化报告的场景，确保报告质量与一致性。该方法论提供六个互补的验证维度，覆盖数据类型准确性、必需和可选字段、多类型支持、集合结构一致性、实体关系恢复和时间演化检测。

## 输入
- JSON 数据集：待评估的 JSON 数据文档集合。
- 推断的 Schema：从数据集中提取的 Schema 表示。
- 参考 Schema（可选）：专家定义的基准 Schema 或真实 Schema。

## 输出
- Schema 质量评估报告：包括六个维度的分数和总体 Schema 质量分数（SQS）。
- 维度级分析：每个维度的详细评估结果和改进建议。

## 流程节点
1. **数据类型准确性评估**：比较推断 Schema 与数据集中观察到的原始类型，计算类型一致性分数。
2. **必需和可选字段评估**：检查推断 Schema 是否正确区分必需字段和可选字段，并捕获字段间的依赖关系。
3. **多类型支持评估**：评估推断 Schema 对异构类型模式的支持能力，包括联合类型和类型替代。
4. **集合结构一致性评估**：分析数组结构的嵌套深度和类型同质性，确保推断 Schema 准确反映数组组织。
5. **实体关系恢复评估**：评估推断 Schema 恢复实体间关系的能力，包括聚合和引用关系。
6. **时间演化检测评估**：检测 Schema 随时间的变化，包括版本检测和变化检测率。

## 关键参数
### 通用判据
| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 维度权重 | DTA: 0.20, ROF: 0.15, MTS: 0.15, CSC: 0.15, ERR: 0.20, TED: 0.15 | [1] | 用于计算总体 Schema 质量分数（SQS）的加权系数 |
| 存在阈值 | 0.90 | [1] | 属性被视为“必需”的最小经验频率 |
| 依赖匹配规则 | 精确集合相等性 | [1] | 仅当推断的前件集合与基准精确匹配时，才认为逻辑依赖正确 |
| 类型异质性惩罚系数 λ | 0.5 | [1] | 控制对过度泛化类型联合的惩罚相对于观察覆盖率的权重 |
| 同质性-深度权衡 α | 0.7 | [1] | 在 CSC 分数中平衡类型同质性（基于熵）和嵌套深度一致性 |
| 关系匹配规则 | 规范化（源，目标）对 | [1] | 关系在规范化实体名称上匹配，忽略非关键属性差异 |
| ERR 平衡系数 β | 0.7 | [1] | 在 ERR 分数中权衡 F1 分数与图编辑距离归一化 |
| 参考 CDR | 1.0 | [1] | 理想的变化检测率，用于比较推断的检测率 |

### 校准数值
以下数值来自 JSON 数据库 Schema 提取评估场景，供量级校准；其他体系需以自身证据重新锚定。
| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 数据类型准确性 (DTA) | 接近 1.0 | [1] | 在基准测试中，所有方法在数据类型准确性上得分很高 |
| 必需和可选字段 (ROF) | 较低 | [1] | 所有方法在必需和可选字段维度上得分系统性较低 |
| 多类型支持 (MTS) | 中等 | [1] | 方法在联合类型建模上表现差异显著 |
| 集合结构一致性 (CSC) | 中等 | [1] | 方法在数组结构建模上表现差异显著 |
| 实体关系恢复 (ERR) | 中等 | [1] | 方法在实体关系恢复上表现差异显著 |
| 时间演化检测 (TED) | 低到高 | [1] | 仅配备时间演化跟踪机制的方法得分高 |

## 边界与分流
- 当参考 Schema 不可用时，可以使用数据集中的结构证据进行评估，但某些维度（如时间演化检测）可能无法完全评估。
- 如果数据集规模过大，可以采样评估以降低计算成本。
- 当推断 Schema 与参考 Schema 差异过大时，可能需要重新设计 Schema 提取方法。

## 质量检查
- 验证每个维度的分数是否在 0 到 1 之间。
- 检查总体 SQS 是否合理，权重之和是否为 1。
- 确保评估结果在不同数据集和方法间具有一致性。

## 回退策略
- 如果某些维度无法评估，可以跳过该维度并调整权重，重新计算 SQS。
- 如果数据集不包含时间演化模式，可以跳过时间演化检测维度。
- 如果参考 Schema 不可用，可以使用半监督评估方法，仅评估可观察维度。
