# CLI非交互执行与故障分类方法论

## 适用范围

**触发条件**：
- 需要自动化执行命令行工具并处理执行异常
- CLI工具非正常退出或未产生预期输出
- 需要诊断命令执行失败的根本原因

**适用场景**：
- 科研计算工作流中的CLI工具执行
- 批量数据处理脚本的故障诊断
- 自动化测试和持续集成中的错误处理
- 跨平台命令行工具的兼容性验证

**不适用场景**：
- 交互式命令行操作（需要用户输入）
- 图形用户界面应用的故障诊断
- 网络服务或API调用的错误处理

## 输入

**输入数据格式**：
- 命令字符串或参数列表
- 执行环境信息（操作系统、shell类型、环境变量）
- 预期输出格式和验证标准

**来源**：
- 用户提供的命令执行需求
- 自动化工作流中的CLI调用
- 测试用例中的命令执行

**预处理要求**：
- 命令语法验证
- 环境依赖检查
- 权限验证

## 输出

**输出产物**：
- 结构化故障分类报告（JSON格式）
- 修复建议和重试策略
- 环境兼容性评估

**格式**：
```json
{
  "fault_category": "exit_code|timeout|permission|dependency|runtime",
  "severity": "critical|high|medium|low",
  "exit_code": 0,
  "stderr_summary": "错误信息摘要",
  "root_cause": "根本原因分析",
  "repair_suggestions": ["修复建议1", "修复建议2"],
  "retry_strategy": "retry|abort|fallback"
}
```

**验证标准**：
- 故障分类准确率 ≥ 90%
- 根本原因识别覆盖率 ≥ 80%
- 修复建议可执行率 ≥ 70%

## 流程节点

### Step 1：命令预检查
- **操作**：验证命令语法、检查依赖、评估权限
- **参数**：命令字符串、执行环境、权限要求
- **工具**：shell解析器、依赖检查器、权限验证器
- **质量门禁**：命令语法正确、依赖满足、权限足够

### Step 2：执行环境配置
- **操作**：设置超时、环境变量、工作目录
- **参数**：超时时间、环境变量映射、工作目录路径
- **工具**：环境配置器、超时管理器
- **质量门禁**：环境变量正确设置、超时配置合理

### Step 3：命令执行与监控
- **操作**：执行命令、监控输出、检测异常
- **参数**：执行命令、输入数据、输出捕获配置
- **工具**：进程管理器、输出捕获器、异常检测器
- **质量门禁**：命令正常启动、输出实时捕获、异常及时检测

### Step 4：故障检测与分类
- **操作**：分析退出码、解析标准错误、识别故障类型
- **参数**：退出码、标准错误内容、执行日志
- **工具**：退出码映射器、错误解析器、故障分类器
- **质量门禁**：退出码正确解释、错误信息准确解析、故障类型正确分类

### Step 5：根因分析与修复建议
- **操作**：分析根本原因、生成修复建议、制定重试策略
- **参数**：故障分类结果、环境信息、历史执行记录
- **工具**：根因分析器、建议生成器、策略制定器
- **质量门禁**：根因分析准确、修复建议可行、重试策略合理

## 边界与分流

**前提1：命令语法正确**
- 不成立时：进行命令解析和语法修复，或提示用户修正命令格式

**前提2：依赖环境满足**
- 不成立时：执行依赖安装或环境配置，或提供环境准备指南

**前提3：权限足够**
- 不成立时：提升权限或调整执行策略，或提示权限不足

**前提4：资源可用**
- 不成立时：释放资源或调整资源限制，或提示资源不足

**前提5：网络可达（如需要）**
- 不成立时：检查网络配置或使用离线模式，或提示网络问题

## 质量检查

**验证点**：
1. 命令语法验证：解析命令字符串，确保语法正确
2. 依赖检查：验证所有依赖组件已安装且版本兼容
3. 权限验证：检查执行权限和文件访问权限
4. 资源评估：评估CPU、内存、磁盘空间等资源
5. 环境一致性：验证环境变量和配置与预期一致

**阈值**：
- 语法验证通过率：100%
- 依赖满足率：≥95%
- 权限验证通过率：100%
- 资源充足率：≥90%

**失败处理**：
- 语法错误：提供修正建议并终止执行
- 依赖缺失：自动安装或提供安装指南
- 权限不足：提权或调整执行策略
- 资源不足：释放资源或调整限制

## 回退策略

**策略1：命令重试**
- 适用于：临时性故障（网络超时、资源竞争）
- 实施：指数退避重试，最多3次
- 监控：记录重试次数和成功率

**策略2：环境降级**
- 适用于：环境配置不兼容
- 实施：使用兼容模式或简化配置
- 监控：记录降级效果和性能影响

**策略3：替代方案**
- 适用于：当前方案不可行
- 实施：使用替代工具或方法
- 监控：记录替代方案效果

**策略4：人工介入**
- 适用于：自动化无法解决的问题
- 实施：收集诊断信息并通知相关人员
- 监控：记录问题详情和解决过程
