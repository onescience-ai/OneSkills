# 命令行工具执行与 JSON 输出验证指南

## 适用范围
本卡片为需要可靠执行外部命令行程序并验证其结构化输出（特别是 JSON 格式）的自动化任务提供方法论框架。适用于任何涉及 CLI 调用、进程管理、错误处理及输出格式校验的场景，例如科学计算流水线、数据处理管道、持续集成脚本等。不适用于交互式命令行会话或需要用户实时输入的场景。

## 输入
- 待执行的命令行程序及其参数序列
- 预期的输出格式规范（如 JSON Schema）
- 可选的执行环境配置（工作目录、环境变量、超时限制）
- 可选的认证凭据或沙箱约束

## 输出
- 命令的退出状态码（exit code）
- 标准输出（stdout）与标准错误（stderr）的内容
- 经过 JSON Schema 校验的结构化报告（如果适用）
- 故障分类与诊断信息

## 流程节点
1. **命令构建与转义** → 根据参数序列构建命令，处理 shell 元字符转义
2. **进程启动与管道管理** → 使用 `subprocess.run()` 或 `Popen` 创建子进程，配置 stdin/stdout/stderr 管道
3. **超时控制与资源回收** → 设置合理的超时时间，捕获 `TimeoutExpired` 异常并强制终止进程
4. **退出码分析** → 检查返回码：0 表示成功，非零表示特定错误，负值表示信号终止（POSIX）
5. **输出捕获与解码** → 根据编码设置读取 stdout/stderr，处理二进制与文本模式
6. **JSON 校验** → 若输出应为 JSON，则解析并使用预定义 Schema 进行验证
7. **故障分类** → 根据退出码、异常类型和错误输出，将故障归类为：命令不存在、参数错误、超时、权限不足、输出格式错误等
8. **诊断报告生成** → 整合退出码、错误消息、输出片段，生成结构化诊断报告

## 关键参数
### 通用判据
| 参数 | 推荐值 | 来源 | 说明 |
|------|--------|------|------|
| 超时时间 | 根据任务复杂度设定（如 30-300 秒） | [D1] | 避免无限挂起，保护系统资源 |
| 检查退出码 | `check=True` 或手动验证 | [D1] | 确保非零退出码被正确捕获 |
| 输出捕获 | `capture_output=True` 或 `stdout=PIPE, stderr=PIPE` | [D1] | 获取完整输出用于后续分析 |
| 编码处理 | `text=True` 或指定 `encoding` | [D1] | 避免二进制解码错误 |
| shell 参数 | 除非必要，保持 `shell=False` | [D1] | 减少 shell 注入风险 |

## 边界与分流
- **命令不存在**：捕获 `FileNotFoundError` 或退出码 127（POSIX），转向检查 PATH 环境或使用绝对路径。
- **权限不足**：退出码 126（POSIX）或 `PermissionError`，建议以适当权限重试或修改文件权限。
- **超时**：捕获 `TimeoutExpired`，可选择重试、增加超时或终止进程。
- **输出格式错误**：JSON 解析失败时，记录原始输出并标记为“输出格式不符合预期”。
- **沙箱限制**：在受限环境中执行时，可能遇到额外的权限或资源限制，需提前配置沙箱参数。

## 质量检查
- 验证退出码是否在预期范围内（成功码通常为 0）。
- 检查 stderr 是否包含错误关键字（如 "Error", "Exception", "Permission denied"）。
- 对 JSON 输出进行 Schema 验证，确保所有必需字段存在且类型正确。
- 监控进程资源使用（CPU、内存），防止资源泄漏。

## 回退策略
- 若命令执行失败，尝试使用更简单的参数集重试。
- 若超时频繁发生，可增加超时时间或优化命令性能。
- 若 JSON 校验失败，可降级为纯文本处理或请求人工干预。
- 记录详细的错误日志，用于后续分析和改进。

## 资源召回建议

- 输出格式为 JSON，需要验证其结构正确性
- 需要设计健壮的进程管理策略（超时、资源回收）
