# 编排智能体技能调用接口契约与异常恢复

## 适用范围

面向多技能编排智能体系统中 type=expert 技能的调用接口契约与异常恢复策略。当编排智能体需要通过 skill 工具向专家技能传递规划请求（planning_request）以获取局部计划提案（planner_proposal）时，必须遵循结构化请求负载的传递规范。本卡适用于以下场景：编排智能体在资源召回后需调用专家技能进行工作流规划、专家技能返回内容不符合预期需检测异常、以及异常发生后需要自动降级到替代规划路径。

**触发条件**：
- 编排智能体需要调用 type=expert 技能获取规划提案
- skill 工具连续多次返回相同的内容（如技能文档摘要而非规划结果）
- 编排智能体检测到自身陷入重复调用模式

**不适用场景**：
- 直接调用 type=executor 技能执行具体任务
- 调用 type=resource 技能获取资源信息
- 单步无需专家规划的简单任务

## 输入

- **Task State**：当前任务状态，包含用户目标、已完成步骤、资源绑定等
- **intent_profile**：意图识别结果，包含 intent_aspects（意图方面列表）
- **matched_resources**：已召回的资源摘要列表
- **assigned_aspect**：当前需要专家规划的意图方面

## 输出

- **正确的 skill 调用格式**：包含结构化 planning_request 的工具调用
- **异常恢复决策树**：检测到异常后的降级路径选择
- **降级后的 Global Plan**：跳过专家规划直接生成的全局计划

## 流程节点

### Step 1：正确构造 skill 工具调用

- **操作**：向 type=expert 技能传递完整的 planning_request 负载
- **参数**：planning_request 必须包含以下字段：
  - `from_skill`：调用方技能标识（通常为 orchestrator）
  - `task_state_summary`：当前任务状态摘要
  - `intent_profile`：意图识别结果（含 intent_aspects）
  - `matched_resources`：已召回的资源摘要
  - `assigned_aspect`：当前需要规划的意图方面
- **工具**：skill 工具
- **质量门禁**：返回内容应为 planner_proposal 而非技能文档摘要

### Step 2：异常检测——连续相同调用模式识别

- **操作**：监控 skill 工具调用结果，检测是否连续返回相同内容
- **参数**：
  - 检测窗口：连续 N 次相同调用（建议 N=3）
  - 相同内容判定：返回内容与前次调用相同或为技能文档摘要
- **工具**：编排智能体内部状态检查
- **质量门禁**：连续 3 次相同调用模式即触发异常标志

### Step 3：异常根因诊断

- **操作**：分析异常原因，判断是请求格式问题还是专家技能不可用
- **参数**：
  - 检查返回内容是否为技能文档摘要（表明请求未被正确接收）
  - 检查专家技能是否确实存在且可调用
- **工具**：编排智能体内部分析
- **质量门禁**：明确区分"请求格式错误"与"专家技能不可用"两种根因

### Step 4：降级策略选择

- **操作**：根据诊断结果选择降级路径
- **参数**：
  - 若为请求格式错误：尝试修正格式后重试一次
  - 若修正后仍失败或专家技能不可用：进入直接规划模式
- **工具**：编排智能体决策模块
- **质量门禁**：降级决策必须在 3 次异常调用内完成

### Step 5：直接规划模式执行

- **操作**：跳过专家规划，基于已召回的资源直接构建 Global Plan
- **参数**：
  - 使用 intent_profile 作为规划依据
  - 查询所有 type=executor 技能并建立能力台账
  - 基于 executor 能力台账规划步骤
- **工具**：编排智能体规划模块
- **质量门禁**：生成的 Global Plan 必须覆盖所有 intent_aspects

## 关键参数

### 通用判据（方法层，同类体系可参考）

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 异常检测窗口 | 连续 3 次相同调用 | [U1] | 编排智能体应在 3 次无效调用内触发降级 |
| planning_request 必含字段 | from_skill, task_state_summary, intent_profile, matched_resources, assigned_aspect | [D1] | 缺少任一字段可能导致专家技能无法正确处理 |
| 降级触发条件 | 返回内容为技能文档摘要且连续 ≥3 次 | [U1] | 表明请求未被专家技能正确接收 |
| 直接规划前置条件 | 阶段一资源召回完成 + 阶段二专家召回已执行且记录为空结果 | [D1] | 不得跳过专家召回阶段直接进入降级 |

### 校准数值（体系专属，供量级校准）

以下数值来自 OneScience 编排体系的具体实例，供量级校准；其他体系需以自身证据重新锚定。

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 最大异常调用次数 | 60+ 次（未触发降级的失败案例） | [U1] | 归因报告中记录的实际失败次数 |
| 专家技能类型 | type=expert | [D1] | OneScience 体系中专家技能的类型标识 |
| 降级后规划模式 | direct_step | [D1] | 编排智能体 SKILL.md 中定义的降级规划模式 |

## 边界与分流

### 当 planning_request 格式不正确时

编排智能体应首先尝试修正请求格式，将缺失字段补充完整后重试一次。若修正后仍返回技能文档摘要，判定为专家技能层面的问题，转入降级路径。

### 当专家技能不存在或不可用时

编排智能体应直接进入直接规划模式，跳过专家召回阶段。此时必须确保阶段一的资源召回已完成，且已通过领域知识缺口检测（knowledge_gap=false）。

### 当降级后的直接规划也失败时

编排智能体应进入阻断状态（blocked），向用户报告异常情况并提供诊断信息。不得在无规划的情况下尝试执行。

### 当异常检测机制本身失效时

编排智能体应设置硬性上限（如总调用次数不超过 10 次），超过上限自动进入阻断状态。

## 质量检查

- **skill 调用验证**：每次调用 type=expert 技能后，检查返回内容是否为 planner_proposal 格式
- **异常模式检测**：维护调用历史记录，检测是否存在连续相同调用模式
- **降级触发验证**：降级触发后，验证是否成功进入直接规划模式
- **规划完整性检查**：降级后生成的 Global Plan 必须覆盖所有 intent_aspects

## 回退策略

- **修正重试**：发现请求格式错误后，修正格式并重试一次
- **直接规划**：专家技能调用失败后，跳过专家规划直接生成 Global Plan
- **阻断上报**：所有降级路径均失败时，进入阻断状态并向用户报告

## 资源召回建议

当编排智能体调用 type=expert 技能时：
- 若返回内容为技能文档摘要（非 planner_proposal），召回本卡片
- 若连续多次相同调用模式，召回本卡片
- 若需要了解 skill 工具的正确调用格式，召回本卡片
