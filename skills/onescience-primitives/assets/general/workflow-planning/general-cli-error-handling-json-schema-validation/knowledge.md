# 自动化流程中的CLI执行与JSON Schema验证知识

## 适用范围

**触发条件**：
- 需要确保命令行接口工具在非交互环境下稳定执行
- 需要验证生成的报告符合预定义的JSON Schema契约
- 需要对CLI执行故障进行分类和恢复

**适用场景**：
- 自动化数据处理工作流中的CLI工具集成
- 科学计算任务中的报告生成与验证
- 持续集成/持续部署（CI/CD）流水线中的脚本执行
- 大规模批处理作业的监控与错误处理

**不适用场景**：
- 交互式命令行会话的错误处理
- 非JSON格式的报告验证
- 实时流式数据处理中的错误恢复

## 输入

**输入数据格式**：
- CLI命令及其参数（字符串数组）
- JSON Schema定义文件（JSON格式）
- 待验证的报告文件（JSON格式）
- 可选的配置文件（指定超时、重试策略等）

**来源**：
- 用户提供的命令行指令
- 预定义的Schema规范文件
- CLI工具生成的输出报告

**预处理要求**：
- CLI命令需确保在目标环境中可执行
- JSON Schema需符合JSON Schema规范（如Draft-07）
- 报告文件需为有效的JSON格式

## 输出

**输出产物**：
- 故障分类报告（包含错误类型、严重程度、恢复建议）
- 验证结果报告（通过/失败，及详细错误信息）
- 修复建议清单（针对验证失败的项目）

**格式**：
- 故障分类：结构化JSON，包含error_type、severity、recovery_suggestion字段
- 验证结果：结构化JSON，包含valid、errors、warnings字段
- 修复建议：Markdown或JSON格式的列表

**验证标准**：
- 故障分类覆盖常见CLI执行错误（超时、非零退出码、输出解析失败等）
- 验证结果准确反映Schema符合性
- 修复建议具体可操作

## 流程节点

### Step 1：CLI执行监控
- **操作**：启动CLI进程并监控其执行状态
- **参数**：超时时间（默认300秒）、重试次数（默认3次）、日志级别
- **工具**：进程管理库（如Python的subprocess）、日志记录器
- **质量门禁**：进程成功退出（退出码0）且输出可解析

### Step 2：故障分类
- **操作**：根据退出码、输出内容和异常信息对故障进行分类
- **参数**：错误码映射表、关键词匹配规则
- **工具**：正则表达式匹配、错误码查询表
- **质量门禁**：故障分类准确率≥90%（基于历史数据验证）

### Step 3：JSON Schema验证
- **操作**：使用JSON Schema验证器检查报告文件
- **参数**：Schema文件路径、验证严格程度（strict/moderate/lenient）
- **工具**：JSON Schema验证库（如jsonschema、ajv）
- **质量门禁**：验证结果与参考实现一致（对于标准测试用例）

### Step 4：错误诊断与修复建议
- **操作**：分析验证错误并生成具体修复建议
- **参数**：错误类型映射、最佳实践知识库
- **工具**：错误模式匹配、建议生成引擎
- **质量门禁**：修复建议覆盖率≥80%（常见错误类型）

### Step 5：报告生成
- **操作**：汇总所有结果生成最终报告
- **参数**：报告模板、输出格式（JSON/Markdown）
- **工具**：模板引擎、文件写入器
- **质量门禁**：报告包含所有必要字段且格式正确

## 边界与分流

**前提1：CLI命令在目标环境中可执行**
- 不成立时转向：环境检查与依赖安装流程，或提供容器化执行方案

**前提2：JSON Schema文件符合规范**
- 不成立时转向：Schema语法检查与修复工具，或提供Schema简化版本

**前提3：报告文件为有效JSON格式**
- 不成立时转向：输出格式转换器，或降级为文本解析模式

**前提4：故障分类规则覆盖目标错误类型**
- 不成立时转向：错误模式学习与规则更新流程

**前提5：验证器支持目标Schema版本**
- 不成立时转向：Schema版本转换工具，或提供兼容性适配层

## 质量检查

**验证点**：
1. CLI进程监控：进程启动成功率、超时发生率
2. 故障分类：分类准确率、未识别错误比例
3. Schema验证：验证结果一致性、性能开销
4. 修复建议：建议采纳率、问题解决率

**阈值**：
- CLI进程启动成功率：≥99%
- 故障分类准确率：≥90%
- Schema验证一致性：100%
- 修复建议覆盖率：≥80%

**失败处理**：
- 监控失败：回退到基础日志记录
- 分类失败：标记为“未识别错误”并记录原始信息
- 验证失败：提供详细错误位置和上下文
- 建议生成失败：提供通用故障排除步骤

## 回退策略

**CLI执行失败回退**：
1. 增加超时时间并重试
2. 简化命令参数并重试
3. 切换到替代执行环境
4. 记录详细错误信息并通知管理员

**Schema验证失败回退**：
1. 使用宽松验证模式
2. 跳过非关键字段验证
3. 提供手动验证接口
4. 记录验证差异并更新Schema
