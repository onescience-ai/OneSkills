# CLI 非交互执行与故障分类处理

## 适用范围

面向命令行工具在非交互环境（自动化流水线、批处理脚本、CI/CD 管道）中的执行异常诊断与恢复。适用于需要自动化调用 CLI 工具并处理其非零退出状态的工作流，覆盖退出码分类、超时处理、沙箱限制、认证失败和标准错误判读等场景。不适用于交互式终端调试或 GUI 应用故障排查。

## 输入

- CLI 命令及参数
- 执行环境信息（操作系统、shell 类型、用户权限）
- 预期退出码范围（成功码、可恢复错误码、致命错误码）
- 超时阈值配置

## 输出

- 故障类别判定（退出码语义映射）
- 对应修复建议与恢复策略
- 故障诊断日志（含退出码、stderr 输出、执行时长）

## 流程节点

### Step 1：退出码语义映射
- **操作**：捕获 CLI 进程退出码，映射到标准分类
- **参数**：退出码 0=成功，1-2=通用错误，126=权限问题，127=命令未找到，128+n=致命信号，130=Ctrl-C 终止，255=退出码超范围
- **工具**：shell $? 变量、POSIX exit status 规范
- **质量门禁**：退出码必须在 0-255 范围内，超出范围取模 256

### Step 2：错误分类分级
- **操作**：根据退出码和 stderr 内容进行错误分级
- **参数**：exit code=1 为可恢复错误（参数错误、文件缺失），exit code=2 为 shell 内建命令误用，exit code=126-127 为环境配置问题，exit code=128+n 为信号中断
- **工具**：错误模式匹配、日志分析
- **质量门禁**：每个错误类别必须有明确的判定标准

### Step 3：故障恢复策略选择
- **操作**：根据错误类别选择恢复方案
- **参数**：重试策略（指数退避）、降级策略（跳过非关键步骤）、人工介入触发条件
- **工具**：重试逻辑、降级逻辑、告警通知
- **质量门禁**：恢复策略必须覆盖所有可恢复错误类别

### Step 4：诊断证据保留
- **操作**：记录完整诊断信息用于后续分析
- **参数**：退出码、stderr 内容、stdout 内容、执行时长、重试次数
- **工具**：日志写入、诊断报告生成
- **质量门禁**：诊断信息必须完整，可用于复现问题

## 关键参数

### 通用判据（方法层）

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 成功退出码 | 0 | [D1] | 进程正常完成 |
| 通用错误 | 1-2 | [D1] | 参数错误、文件缺失、shell 内建命令误用 |
| 权限问题 | 126 | [D1] | 命令无法执行（权限不足或非可执行文件） |
| 命令未找到 | 127 | [D1] | 路径配置错误或命令不存在 |
| 信号中断 | 128+n | [D1] | 收到致命信号 n（如 137=SIGKILL） |
| Ctrl-C 终止 | 130 | [D1] | 用户中断（信号 2） |
| 退出码超范围 | 255 | [D1] | exit 参数超出 0-255 范围 |

### 校准数值（环境专属值）

以下数值来自 POSIX/Linux 环境，供量级校准；Windows CMD/PowerShell 退出码语义可能不同，需以自身证据重新锚定。

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 退出码模数 | 256 | [D1] | 超出 0-255 的值取模 256 |
| 信号偏移 | 128 | [D1] | 退出码 = 128 + 信号编号 |
| 用户自定义范围 | 64-113 | [D1] | 建议用户自定义退出码在此范围 |

## 边界与分流

- **退出码为 0 但 stderr 有内容**：视为警告级别，记录但不触发恢复流程
- **退出码超出 0-255 范围**：取模 256 后重新映射，记录原始值用于诊断
- **非 POSIX 环境**：Windows 退出码语义可能不同，需查阅目标平台文档
- **信号中断无法重试**：SIGKILL（137）、SIGTERM（143）等信号中断不应自动重试，需人工介入
- **超时中断**：超时应设置独立的退出码或错误类型，区别于正常错误

## 质量检查

- 退出码必须被捕获并记录，不能静默忽略
- stderr 输出必须被完整记录，不能截断
- 诊断日志必须包含退出码、stderr、执行时长
- 重试策略必须有最大重试次数限制
- 恢复策略必须覆盖所有可恢复错误类别

## 回退策略

- 退出码无法分类时：记录原始退出码和 stderr，标记为"未知错误"，触发人工介入
- 恢复策略失败时：回滚到最近的稳定状态，记录完整故障链
- 诊断信息不完整时：尝试从相关日志补充上下文信息
