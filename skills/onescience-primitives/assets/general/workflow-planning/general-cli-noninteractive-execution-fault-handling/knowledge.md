# CLI非交互执行与故障分类

## 适用范围

**触发条件**：
- 需要在自动化脚本、批处理作业或远程环境中执行命令行接口（CLI）工具
- CLI工具未正常退出或未产生有效响应
- 需要诊断命令执行失败的原因并采取恢复策略

**适用场景**：
- 自动化测试脚本中的CLI命令执行
- 批处理作业中的命令行工具调用
- 远程服务器上的非交互式命令执行
- CI/CD流水线中的命令行操作

**不适用场景**：
- 交互式命令行会话（需要用户输入）
- 图形用户界面（GUI）应用程序
- 实时流式数据处理

## 输入

**输入数据格式**：
- 命令行命令字符串或参数列表
- 可选的输入数据（通过标准输入或文件）
- 环境变量配置

**来源**：
- 用户提供的命令行指令
- 脚本或配置文件中的命令定义
- 系统环境配置

**预处理要求**：
- 命令路径必须有效且可执行
- 输入数据需符合命令行工具的格式要求
- 环境变量需正确设置

## 输出

**输出产物**：
- 命令执行结果（标准输出）
- 错误信息（标准错误）
- 退出状态码
- 执行日志和诊断信息

**格式**：
- 文本输出（stdout/stderr）
- 整数退出码（0表示成功，非0表示失败）
- 结构化日志（可选）

**验证标准**：
- 退出码为0表示命令成功执行
- 非零退出码表示不同类型的错误
- 输出内容符合预期格式

## 流程节点

### Step 1：命令解析与验证
- **操作**：解析命令行参数，验证命令路径和权限
- **参数**：命令字符串或参数列表，工作目录
- **工具**：shell解析器，文件系统权限检查
- **质量门禁**：命令路径存在且可执行，参数格式正确

### Step 2：进程创建与执行
- **操作**：创建子进程并执行命令
- **参数**：标准输入/输出/错误重定向，环境变量
- **工具**：操作系统进程管理API，subprocess模块
- **质量门禁**：进程成功创建，无立即崩溃

### Step 3：沙箱与环境约束检查
- **操作**：诊断子进程在沙箱环境下的执行限制
- **常见问题**：工作目录（cwd）不可写或不存在；环境变量缺失（如 conda 环境未激活）；文件系统权限不足；网络访问受限（沙箱模式）；进程数/内存限制触发 OOM
- **工具**：检查 subprocess.Popen 的 cwd、env 参数；读取 stderr 中的 OS 错误信息
- **质量门禁**：沙箱配置必须与目标执行环境一致

### Step 4：超时控制与监控
- **操作**：设置执行超时，监控进程状态
- **参数**：超时时间（秒），轮询间隔
- **工具**：定时器，进程状态检查
- **质量门禁**：超时正确触发，进程状态可获取
- **超时清理要点**：捕获 TimeoutExpired 异常后必须调用 proc.kill() 或 proc.terminate()，再通过 proc.communicate() 回收输出；超时后不应再调用 proc.wait()，防止管道死锁

### Step 5：结果收集与清理
- **操作**：收集标准输出/错误，清理进程资源
- **参数**：输出缓冲区大小，编码设置
- **工具**：管道读取，进程等待
- **质量门禁**：输出完整捕获，资源正确释放

### Step 6：JSON 输出完整性校验
- **操作**：检查 CLI 输出是否为合法 JSON
- **校验步骤**：捕获 stdout 内容；尝试 JSON 解析（json.loads()）；解析失败时记录原始输出前 500 字符作为诊断信息；解析成功时进入 Schema 校验
- **质量门禁**：stdout 必须能被解析为 JSON 对象（非数组、非 null）

### Step 7：故障分类与诊断
- **操作**：分析退出码和错误信息，分类故障类型
- **参数**：退出码，错误消息，执行日志
- **工具**：退出码映射表，错误模式匹配
- **质量门禁**：故障分类准确，诊断信息完整

## 关键参数

### 通用判据（方法层）

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 进程创建方式 | fork/exec或CreateProcess | [D1] | 操作系统依赖的进程创建机制 |
| 标准流重定向 | PIPE, DEVNULL, STDOUT | [D1] | 控制输入输出流向 |
| 超时处理 | TimeoutExpired异常 | [D1] | 超时后的清理和重试机制 |
| 退出码范围 | 0-255 | [D2] | 标准退出码范围 |
| 信号处理 | SIGTERM, SIGKILL | [D1] | 进程终止信号 |

### 校准数值（体系专属值）

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 通用错误码 | 1 | [D2] | 通用错误，如除零、权限问题 |
| Shell误用码 | 2 | [D2] | shell内置命令使用错误 |
| 命令不可执行码 | 126 | [D2] | 权限问题或非可执行文件 |
| 命令未找到码 | 127 | [D2] | PATH问题或拼写错误 |
| 无效退出参数码 | 128 | [D2] | exit参数超出范围 |
| 信号终止码 | 128+n | [D2] | 被信号n终止，如137=128+9 |
| Ctrl+C终止码 | 130 | [D2] | 被Control-C终止 |
| 用户定义码范围 | 64-113 | [D2] | 建议的用户自定义退出码范围 |

## 边界与分流

**关键前提不成立时的改道方案**：

1. **命令路径无效**：
   - 转向：使用绝对路径或验证PATH环境变量
   - 方案族：路径查找工具（which/where），环境变量配置

2. **权限不足**：
   - 转向：权限提升或修改文件权限
   - 方案族：sudo/chmod，访问控制列表配置

3. **资源不足**：
   - 转向：资源监控和限制调整
   - 方案族：内存/磁盘检查，资源配额管理

4. **网络依赖失败**：
   - 转向：网络连接诊断和重试
   - 方案族：网络工具（ping/curl），超时重试机制

5. **超时频繁发生**：
   - 转向：性能优化或超时时间调整
   - 方案族：命令拆分，并行执行，超时阈值调整

## 质量检查

**验证点**：
- 命令执行前：路径验证、权限检查、参数格式验证
- 执行中：进程状态监控、资源使用监控、超时检测
- 执行后：退出码验证、输出完整性检查、资源清理确认

**阈值**：
- 退出码：0为成功，非0为失败
- 超时时间：根据命令复杂度设置合理值
- 输出大小：检查是否超出缓冲区限制

**失败处理**：
- 记录详细的错误日志
- 保存执行现场（标准输出/错误）
- 根据故障类型采取恢复策略

## 回退策略

**失败时的替代方案**：
1. **重试机制**：对于临时性错误（网络、资源），实现指数退避重试
2. **降级执行**：对于复杂命令，尝试简化版本或部分执行
3. **替代工具**：对于特定工具失败，使用功能相似的替代工具
4. **人工干预**：对于无法自动恢复的错误，触发人工介入流程

**具体故障案例分析**：

- **诊断步骤**：
  1. 检查CLI退出码（0=成功，非0=失败）
  2. 检查stdout/stderr内容
  3. 验证JSON输出是否可解析
  4. 执行Schema校验
  5. 分析字段缺失/额外字段/身份不匹配问题

**修复策略**：
1. **退出码检查**：确认退出码为0表示命令成功执行
2. **输出捕获**：确保stdout/stderr完整捕获
3. **JSON解析**：验证输出可被json.loads()解析
4. **Schema校验**：在输出前执行JSON Schema校验
5. **故障分类**：根据退出码和错误信息分类故障类型

**任务297特定问题**：

- **错误模式**：归因分析CLI退出码为1，输出不符合JSON Schema
