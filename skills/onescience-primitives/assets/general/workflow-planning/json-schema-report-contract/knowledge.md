# JSON Schema报告交付契约验证方法论

## 适用范围
本卡片提供基于JSON Schema的结构化报告交付契约验证的系统性方法论。适用于任何需要定义、验证和交付结构化报告的领域，包括但不限于：科研数据管理报告、API响应验证、配置文件验证、元数据管理、数据集成任务等。本方法论不依赖特定领域知识，可跨领域通用。

## 输入
- JSON Schema定义文件（规范版本如Draft 4/7/2019-09/2020-12）
- 待验证的JSON数据文档
- 参考Schema（可选，用于对比验证）
- 数据源信息（数据库、API、文件等）

## 输出
- Schema验证报告（通过/失败状态、错误详情）
- 数据质量评估指标（类型准确性、字段完整性、关系一致性等）
- Schema推断结果（从数据中自动推断Schema）
- 修复建议（针对验证失败的修复方案）

## 流程节点
1. **Schema加载与解析** → 加载JSON Schema并解析其结构
2. **数据验证** → 使用Schema验证JSON数据的合规性
3. **质量评估** → 评估Schema推断质量和数据一致性
4. **关系分析** → 分析数据实体间的关系和依赖
5. **时间演化检测** → 检测Schema随时间的变化模式
6. **报告生成** → 生成结构化验证报告
7. **修复建议** → 提供针对验证失败的修复方案

## 边界与分流
- **Schema版本不兼容**：降级到基础验证或提示升级Schema版本
- **数据格式异常**：记录异常模式但不阻塞验证流程
- **大规模数据验证**：使用编译优化或分片验证策略
- **自定义验证规则**：扩展标准Schema支持领域特定约束
- **多源数据集成**：使用统一中间Schema进行数据对齐

## 质量检查
- Schema验证覆盖率：检查所有必需字段是否被验证
- 类型推断准确性：比较推断类型与实际数据类型
- 关系完整性：验证实体间关系是否正确恢复
- 时间演化一致性：检测Schema变化是否合理
- 报告完整性：确保所有验证维度都被评估

## 回退策略
- Schema验证失败时：提供详细错误信息和修复建议
- 数据质量差时：标记数据问题但继续验证其他部分
- 性能瓶颈时：使用采样验证或异步验证策略
- 跨版本兼容性：提供版本转换建议或兼容性层

## 批次补充（2026-09-22）
### 补充内容：报告交付契约的任务身份匹配
本批次补充了JSON Schema报告交付契约中任务身份匹配的知识，包括：

1. **任务身份字段要求**：
   - task_id：任务唯一标识符
   - task：任务名称或描述
   - 版本信息：可选，用于跟踪报告版本

2. **身份匹配验证规则**：
   - 字段存在性检查：必填字段必须存在
   - 值一致性检查：task_id和task必须与预期匹配
   - 格式验证：字段格式符合Schema定义

3. **交付确认机制**：
   - 交付时间记录
   - 接收方确认
   - 状态跟踪和日志

4. **错误处理策略**：
   - 身份不匹配：终止交付并报告详细错误
   - 字段缺失：记录错误并请求补充
   - 格式错误：提供修复建议
