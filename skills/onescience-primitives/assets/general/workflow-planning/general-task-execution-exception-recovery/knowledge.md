# 任务执行异常恢复策略与离线执行方案

## 适用范围
**触发条件**：
- 任务因网络连接问题被阻塞（如 pip 安装失败）
- 依赖安装失败导致后续步骤无法执行
- 环境预检未通过，关键模块缺失
- 任务状态为 blocked，需要恢复执行
- **orchestrator 预检失败（BLOCKED 状态）需要自愈恢复**

**适用场景**：
- HPC集群无外网访问权限
- 网络不稳定导致依赖安装超时
- 任务执行中途失败需要恢复
- 需要离线部署科学计算环境
- **execution-manifest.json 缺失导致预检失败**
- **orchestrator 编排产物缺失需要自动生成**

**不适用场景**：
- 有稳定网络连接的环境
- 任务逻辑错误导致的失败
- 数据输入错误导致的失败

## 输入
**输入数据**：
- 任务执行日志（包含错误信息）
- 环境预检结果（如 preflight_result.yaml）
- 阻塞原因描述（如网络连接问题）
- 目标软件包列表（requirements.txt）

**预处理要求**：
- 分析错误日志确定阻塞原因
- 检查网络连接状态
- 识别缺失的依赖包

## 输出
**输出产物**：
- 异常恢复脚本（recover_task.sh 或 recover_task.py）
- 离线安装包目录
- 环境修复报告
- 任务恢复状态（从 blocked 到 running）

**验证标准**：
- 阻塞原因已解决
- 缺失依赖已安装
- 环境预检通过
- 任务状态恢复为 running

## 流程节点
### Step 1：阻塞原因分析
- **操作**：分析任务日志和错误信息
- **参数**：日志文件=execution.log, 错误关键词=timeout, connection refused
- **工具**：日志分析脚本
- **质量门禁**：准确定位阻塞原因，区分网络问题、依赖问题、环境问题

### Step 2：离线安装准备
- **操作**：在有网络环境中下载所需依赖包
- **参数**：下载目录=./offline_packages, 平台=目标平台
- **工具**：pip download, conda pack
- **质量门禁**：所有依赖包下载成功，版本兼容

### Step 3：环境修复
- **操作**：使用离线包安装依赖或配置本地源
- **参数**：安装命令=pip install --no-index --find-links=./offline_packages
- **工具**：pip, conda, 源码编译
- **质量门禁**：依赖安装成功，模块可导入

### Step 4：任务恢复
- **操作**：重新执行被阻塞的任务步骤
- **参数**：任务ID=原始任务ID, 恢复点=阻塞前步骤
- **工具**：任务调度器
- **质量门禁**：任务状态从 blocked 变为 running

### Step 5：验证与监控
- **操作**：验证任务恢复后的执行状态
- **参数**：监控间隔=5分钟, 最大重试次数=3
- **工具**：状态监控脚本
- **质量门禁**：任务正常执行，无再次阻塞

## 关键参数
| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 网络超时时间 | 30秒 | [1] | 默认连接超时 |
| 离线包下载目录 | ./offline_packages | [2] | 本地存储路径 |
| 最大重试次数 | 3 | [1] | 异常恢复重试上限 |
| 任务恢复点 | 阻塞前步骤 | [3] | 从失败点恢复 |
| 环境验证命令 | python -c "import module" | [4] | 模块导入测试 |

## 边界与分流
**异常处理**：
- 离线包下载失败：使用替代镜像源或手动下载
- 依赖冲突：使用虚拟环境隔离或版本约束
- 磁盘空间不足：清理缓存或选择性安装
- 任务恢复失败：回滚到初始状态，通知管理员

**orchestrator 编排层异常处理（CFD_S046 补充）**：
- **预检失败（execution-manifest.json 缺失）**：orchestrator 应检测到缺失后立即从 global_plan.json 映射生成该文件并重试预检，而非直接终止
- **超时异常**：应设置分阶段超时预算（s01-s02 预留 40%、s03 预留 30%、s04-s05 预留 30%），而非单一总超时
- **executor 调用失败**：记录失败原因，尝试降级到备用 executor 或通知用户

**OneScience任务超时与异常恢复机制（CFD_S087补充）**：
- **超时处理**：当执行步骤遇到不可恢复错误（如RuntimeError）时，应在该步骤标记BLOCKED并记录错误详情到execution-manifest.json，而非继续重试
- **manifest生成**：超时前必须确保execution-manifest.json已写入以保存中间状态
- **异常恢复**：编排器应在训练崩溃后有效恢复或标记BLOCKED状态，避免超时；execution-manifest未生成违反工作流契约

> **CFD_S046 失败模式**：blocked-run.log 仅记录超时和预检失败，未见任何重试或恢复尝试。orchestrator 在预检失败后未能启动异常恢复流程（如跳过预检继续执行或重新生成 execution-manifest.json），且时间预算分配不当导致超时。

**降级策略**：
- 核心功能优先：只安装必需依赖
- 使用容器：在有网络的环境中构建容器镜像
- 简化任务：跳过非关键步骤

## 质量检查
**验证点**：
- 阻塞原因分析准确性
- 离线包完整性
- 环境修复成功率
- 任务恢复成功率

**阈值**：
- 阻塞原因定位准确率：100%
- 离线包安装成功率：100%
- 任务恢复成功率：>90%

**失败处理**：
- 记录详细恢复日志
- 回滚到上一个已知良好状态
- 通知研究人员或管理员

## 回退策略
**失败时的替代方案**：
- 使用容器化部署（Docker/Singularity）
- 从源码编译安装
- 使用其他计算资源（如云GPU）
- 联系管理员配置网络代理
