# CLI执行失败诊断与故障分类

## 适用范围
面向命令行工具执行过程中的故障诊断与分类，提供系统化的错误分析框架，帮助开发者理解错误发生机制、分类根因并设计恢复策略。适用于CLI工具开发、测试、调试和运维场景，不适用于图形界面应用或网络服务故障诊断。

## 输入
- CLI工具执行日志（stdout、stderr、退出码）
- 错误消息和堆栈跟踪
- 执行环境信息（操作系统、依赖版本、权限状态）
- 任务规范和预期行为描述

## 输出
- 错误分类报告（错误类型、根因、影响阶段）
- 恢复策略建议（立即终止、修复尝试、验证确认）
- 预防措施推荐（输入验证、环境检查、错误处理改进）

## 流程节点
1. **错误收集** → 收集CLI执行过程中的所有错误信息
2. **错误分类** → 根据错误特征进行类型划分
3. **根因分析** → 识别错误发生的根本原因
4. **恢复评估** → 评估错误的可恢复性和影响范围
5. **策略制定** → 制定相应的处理和预防策略

每步含：操作、参数、工具、质量门禁

## 边界与分流
- **前提1：CLI工具具有明确的输入输出接口** → 不满足时转向交互式工具或GUI应用错误诊断
- **前提2：执行环境可重现** → 不满足时转向环境无关的静态代码分析
- **前提3：错误日志完整可获取** → 不满足时转向基于症状的启发式诊断

## 质量检查
- 错误分类是否覆盖所有已知错误类型
- 根因分析是否基于实际错误证据而非假设
- 恢复策略是否考虑时间窗口和资源约束
- 预防措施是否具体可操作

## 回退策略
- 当错误分类不确定时，采用保守分类策略，标记为"待进一步分析"
- 当根因分析证据不足时，记录已知信息并建议补充诊断步骤
- 当恢复策略不可行时，提供降级方案或终止建议
