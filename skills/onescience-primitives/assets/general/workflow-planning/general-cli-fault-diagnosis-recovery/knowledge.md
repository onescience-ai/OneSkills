# 命令行界面非交互执行故障诊断与恢复

## 适用范围

面向命令行界面在非交互执行环境（如自动化脚本、批处理作业、远程任务提交、持续集成流水线）中出现的各类运行时故障，提供系统化的诊断分类与恢复策略。适用于需要确保 CLI 工具在无人值守场景下可靠执行的研究与工程任务，包括科学计算作业提交、数据处理流水线、部署自动化等。不适用于交互式终端操作或图形界面应用。

## 输入

- **CLI 命令及参数**：待执行的完整命令行指令，包括可执行文件路径、参数、标志。
- **执行环境信息**：操作系统类型、shell 版本、环境变量、依赖软件版本。
- **历史执行日志**：过往执行记录，包括退出码、标准输出、标准错误、耗时。
- **超时阈值**：预期的最大执行时间（可选）。
- **沙箱配置**：隔离环境参数（如容器镜像、虚拟环境、权限限制）。

## 输出

- **故障类型报告**：结构化 JSON，包含故障类别（如认证失败、参数错误、资源不足、超时、沙箱限制）、严重等级、触发条件、相关日志片段。
- **恢复操作建议**：针对每类故障的推荐处理步骤，如重试策略、参数调整、环境修复、降级方案。
- **诊断证据链**：从退出码、错误信息到根因的映射关系。

## 流程节点

### Step 1：执行监控与日志捕获
- **操作**：启动 CLI 进程，实时捕获标准输出、标准错误、退出码、资源使用（CPU、内存、时间）。
- **参数**：日志级别=详细，监控间隔=100ms，超时设置=根据任务预期。
- **工具**：系统调用（subprocess）、日志库、性能监控工具。
- **质量门禁**：日志完整性 ≥ 95%，无关键信息丢失。

### Step 2：退出码分类
- **操作**：解析进程退出码，映射到标准故障类别。
- **参数**：退出码表 = 操作系统约定（0=成功，1=一般错误，2=误用命令，126=权限问题，127=命令未找到，128+信号=异常终止）。
- **工具**：退出码映射表、信号处理库。
- **质量门禁**：分类准确率 ≥ 98%，未知退出码标记为“待确认”。

### Step 3：标准错误流分析
- **操作**：提取错误关键词、堆栈跟踪、依赖缺失信息。
- **参数**：错误模式库（正则表达式），关键词权重。
- **工具**：正则表达式匹配、自然语言处理（可选）。
- **质量门禁**：关键词召回率 ≥ 90%，误报率 ≤ 5%。

### Step 4：超时检测与资源分析
- **操作**：检查执行时间是否超限，分析资源使用瓶颈。
- **参数**：超时阈值（默认300秒），资源限制（CPU、内存）。
- **工具**：计时器、资源监控。
- **质量门禁**：超时检测误差 ≤ 1秒，资源数据采样频率 ≥ 10Hz。

### Step 5：沙箱环境验证
- **操作**：检查隔离环境配置是否满足 CLI 要求（如依赖库、权限、网络）。
- **参数**：沙箱配置文件、依赖列表、权限掩码。
- **工具**：环境检查脚本、依赖解析器。
- **质量门禁**：配置验证覆盖率 = 100%。

### Step 6：恢复策略生成
- **操作**：根据故障类型生成具体恢复步骤，如重试、参数修正、环境修复。
- **参数**：恢复策略库、最大重试次数（默认3）、退避算法（指数退避）。
- **工具**：策略生成器、重试逻辑。
- **质量门禁**：恢复建议可执行性 ≥ 95%，无矛盾指令。

| 错误关键词库 | timeout, permission denied, not found, out of memory, connection refused | [1][2] | 常见 CLI 错误模式 |
| 超时阈值范围 | 1秒 - 86400秒 | [1] | 根据任务复杂度调整 |
| 资源监控指标 | CPU 使用率, 内存占用, I/O 吞吐 | [1] | 性能瓶颈诊断 |
| 沙箱验证点 | 依赖存在性, 权限设置, 网络可达性, 环境变量 | [2] | 隔离环境完整性检查 |

| 参数 | 值 | 来源 | 说明 |

## 边界与分流

- **退出码未知**：当退出码不在标准表中时，转为“自定义故障分析”流程，要求用户提供程序文档或源代码。
- **错误信息缺失**：当标准错误流为空时，转为“黑盒诊断”流程，基于资源使用和执行时间推断。
- **沙箱配置冲突**：当环境限制与 CLI 要求冲突时，建议调整配置或使用替代执行通道（如容器化）。
- **资源不足**：当资源使用持续超限时，建议升级硬件或优化任务负载。

## 质量检查

- **诊断准确性**：故障分类与根因匹配度 ≥ 90%（通过人工抽样验证）。
- **恢复有效性**：恢复建议执行后成功率 ≥ 80%（在测试环境中验证）。
- **日志完整性**：关键字段（退出码、错误信息、时间戳）缺失率 ≤ 1%。
- **性能开销**：监控与诊断逻辑对原任务执行时间增加 ≤ 5%。

## 回退策略

- **自动诊断失败**：转为“人工介入模式”，生成详细诊断报告供专家分析。
- **恢复策略无效**：建议回滚到上一个已知良好状态，或使用备用执行路径。
- **环境不可恢复**：建议重建环境或迁移至其他执行平台。

## 资源召回建议

当遇到以下情况时，应召回本卡片：
- 自动化脚本在无人值守时失败。
- 远程作业提交返回非零退出码。
- 批处理流水线出现超时或资源错误。
- 需要系统化排查 CLI 执行故障。

配套资源：`general-json-schema-report-validation`（用于验证故障报告格式）。
