# CLI非交互执行故障分类与诊断方法论

## 适用范围
本卡片提供面向命令行接口（CLI）程序的非交互执行故障分类与诊断的系统性方法论。适用于任何领域中CLI工具的故障诊断场景，包括但不限于：自动化脚本执行失败、批处理任务异常退出、CI/CD流水线中的命令行工具故障、科研计算工作流中的命令行程序错误等。本方法论不依赖特定领域知识，可跨领域通用。

## 输入
- 故障CLI程序的执行日志（标准输出、标准错误、退出码）
- 测试用例集（通过/失败案例）
- 程序源代码（可选，用于动态执行追踪）
- 执行环境信息（操作系统、依赖库版本等）

## 输出
- 故障分类报告（按退出码、错误类型、故障位置分类）
- 疑似故障语句/代码段排名列表
- 故障根因分析与修复建议

## 流程节点
1. **故障信息收集** → 收集CLI程序的退出码、标准错误输出、执行日志
2. **退出码分类** → 根据退出码数值和语义进行初步故障分类
3. **错误处理代码分析** → 识别程序中的错误处理逻辑和异常捕获点
4. **动态执行追踪** → 通过测试用例执行收集代码覆盖信息
5. **可疑度评估** → 使用评估指标计算代码段的可疑度值
6. **故障定位** → 按可疑度排序输出疑似故障位置
7. **根因分析** → 结合上下文分析故障根本原因

## 边界与分流
- **退出码为0但程序行为异常**：转向功能正确性分析，检查输出内容是否符合预期
- **退出码>125**：优先检查系统级故障（信号终止、资源限制等）
- **动态执行追踪不可用**：降级为静态分析方法，使用代码复杂度指标评估
- **测试用例不足**：补充测试用例或使用基于模型的诊断方法
- **多线程/并发程序**：考虑线程安全性和竞态条件分析

## 质量检查
- 退出码分类准确性：验证分类规则与实际故障类型的一致性
- 故障定位有效性：使用EXAM指标评估定位精度
- 可疑度评估一致性：比较不同评估指标的结果一致性
- 修复建议可行性：验证建议的修复方案是否可执行

## 回退策略
- 动态分析失败时：回退到静态代码分析和复杂度评估
- 故障定位不准确时：增加测试用例或使用机器学习辅助诊断
- 跨平台差异：针对不同操作系统调整退出码分类规则

## 批次补充（2026-09-22）
### 补充内容：非交互执行故障分类的通用实践
本批次补充了CLI非交互执行故障分类的通用实践知识，包括：

1. **退出码分类标准**：
   - 0：执行成功
   - 1-125：应用错误
   - 126：权限问题
   - 127：命令未找到
   - ≥128：信号终止

2. **恢复策略分类**：
   - 重试策略：参数调整、资源增加
   - 降级策略：简化输入、降低精度
   - 替代方案：使用其他工具或方法
   - 终止并报告

3. **质量检查点**：
   - 退出码分类准确率 ≥ 95%
   - 错误诊断信息完整率 ≥ 90%
   - 恢复策略成功率 ≥ 80%
   - 日志记录完整率 = 100%

4. **边界与分流条件**：
   - 退出码=0：执行成功，记录日志
   - 退出码1-125：应用错误，分析参数和输入
   - 退出码126：权限问题，检查文件权限
   - 退出码127：命令未找到，检查PATH
   - 退出码≥128：信号终止，检查资源和超时
