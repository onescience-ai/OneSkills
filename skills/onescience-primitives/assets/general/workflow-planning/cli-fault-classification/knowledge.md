# CLI非交互执行与故障分类知识

## 适用范围
本卡片服务的问题类：在命令行接口非交互执行场景下，如何对进程终止状态进行分类、解读退出码含义、处理错误码体系，并建立故障诊断流程。适用于自动化脚本、批处理作业、远程执行等需要程序化处理CLI执行结果的场景。

## 输入
- CLI命令执行结果（退出码、标准输出、标准错误）
- 进程终止状态信息
- 错误码（errno）值
- 父进程等待状态

## 输出
- 故障分类结果（成功/失败/异常类型）
- 退出码解读报告
- 错误处理建议
- 故障诊断流程图

## 流程节点
1. **进程终止状态捕获** → 捕获子进程退出码（status & 0xFF）[D1]
2. **退出码分类** → 区分EXIT_SUCCESS（0）、EXIT_FAILURE（非0）及自定义退出码 [D1]
3. **错误码解析** → 读取errno变量，映射到具体错误类型（如ENOENT、EACCES）[D2]
4. **故障类型判定** → 根据退出码和错误码组合判定故障类别
5. **错误处理执行** → 根据故障类型执行相应处理策略
6. **诊断报告生成** → 生成结构化故障诊断报告

## 关键参数

### 通用判据
| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| EXIT_SUCCESS | 0 | [D1] | 成功终止标准码 |
| EXIT_FAILURE | 非0 | [D1] | 失败终止标准码 |
| 退出码提取 | status & 0xFF | [D1] | 获取进程终止状态最低有效字节 |
| errno线程安全 | 线程本地 | [D2] | errno是线程局部变量 |

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| EPERM | 1 | [D2] | 操作不允许 |
| ENOENT | 2 | [D2] | 无此文件或目录 |
| EACCES | 13 | [D2] | 权限拒绝 |
| EIO | 5 | [D2] | 输入/输出错误 |

## 边界与分流
- **前提1：进程正常终止** → 若进程被信号终止，退出码为信号编号+128，需转信号处理流程
- **前提2：父进程正确等待** → 若父进程未设置SA_NOCLDWAIT，子进程可能成为僵尸进程
- **前提3：errno有效读取** → errno仅在系统调用失败后有效，成功调用后可能被修改

## 质量检查
- 验证退出码是否在0-255范围内（status & 0xFF）
- 检查errno是否在调用前被重置（对某些函数）
- 确认错误码映射表与目标系统一致
- 验证故障分类逻辑覆盖所有常见错误类型

## 回退策略
- 当errno信息不足时，检查标准错误输出（stderr）
- 当退出码为非标准值时，查阅具体程序的文档
- 当信号终止时，分析信号来源（如SIGKILL、SIGSEGV）

### 软件故障注入测试方法

基于论文[3]，补充CLI错误处理代码的测试方法：

#### 故障注入测试框架
- **目标**：测试错误处理代码的健壮性和覆盖率
- **方法**：通过软件故障注入模拟各种错误条件
- **技术**：错误覆盖率引导的模糊测试（Error-Coverage-Guided Fuzzing）
- **优势**：能够发现传统测试难以覆盖的错误处理路径

#### 错误覆盖率指标
| 指标 | 定义 | 来源 | 说明 |
|------|------|------|------|
| 错误处理代码覆盖率 | 被执行的错误处理代码行数/总错误处理代码行数 | [3] | 衡量错误处理代码的测试充分性 |
| 错误类型覆盖率 | 被触发的错误类型数/总错误类型数 | [3] | 衡量错误条件的覆盖广度 |
| 错误恢复成功率 | 成功恢复的错误场景数/总错误场景数 | [3] | 衡量错误处理的有效性 |

#### 故障注入策略
1. **系统调用失败注入**：模拟read/write/open等系统调用失败
2. **内存分配失败注入**：模拟malloc/calloc/realloc返回NULL
3. **资源耗尽注入**：模拟文件描述符耗尽、内存不足
4. **网络故障注入**：模拟连接超时、数据包丢失
5. **权限拒绝注入**：模拟EACCES、EPERM错误

### 集中式错误处理架构

基于论文[4]，补充大规模软件系统的错误处理架构：

#### 集中式错误处理框架
- **核心思想**：将分散的错误处理逻辑集中管理
- **技术栈**：机器学习技术辅助错误分类和处理
- **优势**：提高错误处理的一致性、可维护性和响应速度

#### 机器学习辅助错误处理
| 技术 | 应用场景 | 来源 | 说明 |
|------|---------|------|------|
| 异常检测 | 识别异常错误模式 | [4] | 使用无监督学习检测异常错误序列 |
| 错误分类 | 自动分类错误类型 | [4] | 使用监督学习对错误进行分类 |
| 根因分析 | 定位错误根本原因 | [4] | 使用关联规则挖掘错误因果关系 |
| 预测性维护 | 预测潜在故障 | [4] | 使用时间序列分析预测系统故障 |

#### 集中式错误处理流程
1. **错误捕获**：从各个组件收集错误信息
2. **错误标准化**：统一错误格式和编码
3. **错误分类**：使用ML模型自动分类错误
4. **错误路由**：根据错误类型路由到相应处理模块
5. **错误恢复**：执行预定义的恢复策略
6. **错误学习**：从错误处理结果中学习，优化处理策略

## 批次补充 2026-09-21（基于归因分析任务18案例：任务18案例补充）

### 案例描述

任务18（人类BRCA1调控变异多轨迹预测）的归因分析智能体未能交付有效的结构化报告，故障模式与之前案例高度相似：

- **故障现象**：CLI进程退出码为1，报告校验错误：缺少顶层字段 `['issues', 'summary', 'task', 'task_id']`；包含额外顶层字段 `['error', 'sessionID', 'timestamp', 'type']`；task_id与任务索引不一致；task与任务name不一致。
- **故障分类**：CLI非交互执行失败 + JSON Schema报告交付契约违反
- **根因分析**：
  1. CLI进程未正常退出（退出码1），可能由参数错误、认证失败、沙箱隔离或超时引起
  2. 输出报告不符合预定义Schema，缺少必填字段且包含未声明字段
- **修复方法**：
  1. 修正CLI启动配置，确保命令参数、认证、沙箱设置正确
  2. 在输出前使用JSON Schema校验报告，确保字段完整性和身份一致性
- **验证方式**：使用成功、非零退出和超时用例验证状态及日志；以report-schema.json校验最终输出并执行错配字段反例测试

### 校准数值（案例专属值，供量级校准）

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 缺失必填字段 | 4 | 任务18案例 | issues, summary, task, task_id |
| 额外字段数 | 4 | 任务18案例 | error, sessionID, timestamp, type |
| 身份校验失败项 | 2 | 任务18案例 | task_id不匹配、task不匹配 |
