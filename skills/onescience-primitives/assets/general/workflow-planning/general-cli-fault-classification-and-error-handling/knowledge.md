# CLI 非交互执行与故障分类

## 适用范围
当命令行工具在无人值守的自动化工作流（如 CI/CD 管道、批处理脚本、远程任务提交）中运行时，需要对其执行状态进行分类、对异常退出进行解读，并实施恢复策略。本卡片提供通用的故障分类框架、退出码语义、超时处理机制与错误诊断方法，适用于各类 CLI 工具在非交互环境下的稳定运行。

## 输入
- CLI 工具的可执行文件或脚本路径
- 执行参数与环境变量
- 预期的标准输出/标准错误流
- 可选：超时时间限制、重试策略配置

## 输出
- 执行状态分类（成功、可恢复错误、不可恢复错误、超时、信号终止）
- 结构化错误报告（退出码、错误消息、堆栈跟踪）
- 诊断证据（日志文件、环境快照、资源使用情况）
- 恢复建议（重试、降级、人工干预）

## 流程节点
1. **执行前检查** → 验证工具可用性、参数合法性、环境依赖
2. **执行监控** → 跟踪进程状态、资源使用、输出流
3. **退出码解析** → 根据退出码分类故障类型
4. **错误诊断** → 分析标准错误输出、日志文件、堆栈跟踪
5. **恢复决策** → 根据故障分类选择重试、降级或终止
6. **证据保留** → 保存执行日志、环境快照、错误上下文

## 关键参数

### 通用判据
| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 退出码 0 | 成功 | [D2] | 表示命令成功执行 |
| 退出码 1-125 | 可恢复/不可恢复错误 | [D2] | 具体语义依赖工具实现 |
| 退出码 126 | 权限问题或非可执行文件 | [D2] | 命令无法执行 |
| 退出码 127 | 命令未找到 | [D2] | 路径错误或工具未安装 |
| 退出码 128+n | 致命信号 n | [D2] | 进程被信号终止 |
| 退出码 130 | Ctrl+C 终止 | [D2] | 用户中断 |
| 退出码 255 | 退出状态超出范围 | [D2] | 无效退出码 |

### 校准数值
以下数值来自常见 Unix/Linux 环境，供量级校准；其他系统需以自身证据重新锚定。
| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 默认超时时间 | 300 秒 | [D1] | 可根据任务复杂度调整 |
| 重试间隔 | 指数退避（1s, 2s, 4s...） | [D1] | 避免雪崩效应 |
| 最大重试次数 | 3 次 | [D1] | 超过则转人工干预 |
| 日志保留期限 | 30 天 | [D1] | 用于事后分析 |

## 边界与分流
- **前提：CLI 工具支持非交互执行** → 若工具需要交互输入，则需通过 expect 脚本或管道提供输入，否则无法在自动化流程中运行。
- **前提：退出码语义明确** → 若工具未遵循标准退出码约定，则需查阅其文档或通过测试确定退出码含义。
- **前提：超时机制有效** → 若工具忽略 SIGTERM 信号，则需使用 SIGKILL 强制终止，但可能留下不一致状态。
- **前提：日志系统可用** → 若工具无日志输出，则需通过外部监控（如进程跟踪）获取诊断信息。

## 质量检查
- 验证退出码是否在预期范围内（0-255）
- 检查标准错误输出是否包含关键错误信息
- 确认超时设置是否合理（避免误报或漏报）
- 验证重试策略是否导致资源耗尽
- 检查日志文件是否包含足够诊断信息

## 回退策略
- 当退出码语义不明时：查阅工具官方文档或通过测试确定
- 当超时机制失效时：使用外部进程监控工具（如 timeout 命令）
- 当日志系统不可用时：启用详细输出模式（-v, --verbose）或使用 strace/ltrace 跟踪
- 当错误无法自动恢复时：发送警报并暂停工作流，等待人工干预
