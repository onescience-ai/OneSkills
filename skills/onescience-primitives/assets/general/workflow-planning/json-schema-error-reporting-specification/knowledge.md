# JSON Schema错误报告规范

## 适用范围
本卡片提供JSON Schema验证的错误报告规范，定义错误信息格式、错误分类、错误位置报告和用户友好错误消息生成。适用于任何需要生成结构化报告并交付给下游消费者的场景，确保验证错误可诊断、可修复。

## 输入
- JSON数据文档
- JSON Schema定义
- 验证上下文（如API端点、数据管道）
- 用户角色（开发者、终端用户、系统管理员）

## 输出
- 结构化错误报告（JSON格式）
- 错误分类统计
- 错误位置信息（路径、行号、列号）
- 用户友好错误消息
- 修复建议

## 流程节点
1. **验证执行** → 执行JSON Schema验证，收集所有错误
2. **错误分类** → 按错误类型分类（类型错误、缺失字段、格式错误等）
3. **位置解析** → 解析错误在文档中的精确位置（JSON路径、行号、列号）
4. **消息生成** → 生成用户友好的错误消息，避免技术术语
5. **修复建议** → 基于错误类型提供具体修复建议
6. **报告组装** → 组装结构化错误报告，包含所有必要信息

## 关键参数
### 通用判据（方法层）
| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 错误消息格式 | 分层结构：摘要→详情→位置→修复 | [D1] | 确保信息层次清晰 |
| 错误分类 | 类型错误、缺失字段、格式错误、枚举错误、约束错误 | [D1] | 覆盖常见错误类型 |
| 位置报告 | JSON路径 + 行号 + 列号 | [D1] | 精确定位错误位置 |
| 用户友好度 | 避免技术术语，提供上下文 | [D2] | 确保非技术人员也能理解 |
| 修复建议 | 具体、可操作、示例驱动 | [D1] | 帮助用户快速修复 |

### 校准数值（JSON Schema特定）
| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 错误消息最大长度 | 200字符 | [D1] | 避免过长消息影响可读性 |
| 位置信息精度 | 字符级 | [D1] | 精确定位错误位置 |
| 修复建议数量 | 每个错误1-3个建议 | [D2] | 避免信息过载 |
| 错误报告嵌套深度 | 最多3层 | [D1] | 保持报告结构清晰 |

## 边界与分流
- **验证器不支持精确位置**：降级到JSON路径定位，不报告行号列号
- **错误消息过长**：截断并添加省略号，提供详细日志链接
- **修复建议不适用**：标记为“需人工干预”，提供相关文档链接
- **多语言环境**：支持错误消息本地化，提供英文默认版本
- **性能敏感场景**：简化错误报告，只包含关键信息

## 质量检查
- 错误覆盖率：确保所有Schema错误都被捕获
- 位置准确性：验证错误位置信息是否准确
- 消息清晰度：测试用户是否能理解错误消息
- 修复建议有效性：验证修复建议是否能解决问题
- 报告性能：确保错误报告生成不会显著影响验证性能

## 回退策略
- 验证器功能不足：降级到基本验证，只报告关键错误
- 位置信息缺失：提供JSON路径作为替代
- 修复建议不准确：标记为“建议仅供参考”，提供通用修复指南
- 报告格式不兼容：提供多种格式（JSON、XML、纯文本）
