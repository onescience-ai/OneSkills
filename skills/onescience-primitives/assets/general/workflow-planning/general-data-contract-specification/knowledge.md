# 科学数据契约标准字段规范

## 适用范围

面向科学数据管理任务，定义数据契约(data_contract.json)的标准字段规范。适用于所有需要明确输入输出数据格式、物理量定义和单位映射的科学计算任务。不适用于非结构化数据或纯文本数据处理任务。

## 输入

- 任务目标：创建数据契约定义数据处理流程的输入输出
- 数据需求：物理量名称、符号、单位、维度、物理含义
- 格式要求：JSON格式，包含input_fields和target_fields

## 输出

- data_contract.json：数据契约文件，定义输入输出字段规范
- 字段完整性：所有物理量定义完整，单位映射准确
- 可追溯性：每个字段有明确的物理含义和来源

## 流程节点

1. **识别物理量** → 2. **定义字段结构** → 3. **映射单位** → 4. **验证一致性** → 5. **生成契约**

### 步骤1：识别物理量
- 操作：分析任务涉及的物理量
- 参数：物理量名称、符号、单位、维度
- 工具：任务文档、领域知识
- 质量门禁：物理量识别完整，无遗漏

### 步骤2：定义字段结构
- 操作：创建input_fields和target_fields结构
- 参数：字段名称、数据类型、物理含义
- 工具：JSON模板
- 质量门禁：字段结构清晰，层次分明

### 步骤3：映射单位
- 操作：为每个物理量定义SI单位映射
- 参数：单位符号、单位名称、转换因子
- 工具：单位转换表
- 质量门禁：单位映射准确，符合SI标准

### 步骤4：验证一致性
- 操作：检查字段定义和单位映射的一致性
- 参数：字段名称、单位符号、物理含义
- 工具：验证脚本
- 质量门禁：字段定义和单位映射一致

### 步骤5：生成契约
- 操作：创建data_contract.json文件
- 参数：完整的字段定义和单位映射
- 工具：JSON生成器
- 质量门禁：JSON格式正确，字段完整

## 边界与分流

### 前提1：任务涉及明确的物理量
- **不成立时转向**：使用通用数据契约模板，但需在metadata中声明"物理量定义可能不完整"

### 前提2：物理量有标准单位
- **不成立时转向**：使用非标准单位，但需在data_contract.json中明确定义转换因子

### 前提3：数据格式可被解析
- **不成立时转向**：编写自定义解析器，或转换为标准格式

## 质量检查

1. **字段完整性**：检查所有物理量是否定义完整
2. **单位准确性**：验证单位映射符合SI标准
3. **一致性检查**：检查字段定义和单位映射的一致性
4. **格式验证**：验证JSON格式正确
5. **可读性检查**：检查字段命名和描述是否清晰

## 回退策略

1. **物理量识别不全**：使用通用模板，补充遗漏的物理量
2. **单位映射错误**：修正单位映射，重新验证一致性
3. **格式错误**：修正JSON格式错误，重新生成契约
4. **字段命名不清晰**：重命名字段，改善可读性
