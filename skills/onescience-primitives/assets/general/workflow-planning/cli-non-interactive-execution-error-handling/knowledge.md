# CLI非交互执行与错误处理

## 适用范围
适用于命令行工具在非交互式环境（如自动化脚本、CI/CD流水线、批处理作业）中的执行，重点关注错误处理、退出码分类和故障诊断。适用于任何需要通过命令行接口进行自动化执行的场景，包括但不限于数据分析、构建工具、部署脚本等。

## 输入
- 命令行工具的可执行文件或脚本
- 必要的命令行参数和选项
- 执行环境（shell类型、操作系统、权限配置）
- 超时和资源限制配置

## 输出
- 执行状态码（退出码）
- 标准输出（stdout）和标准错误（stderr）流
- 执行日志和诊断信息
- 错误分类和恢复建议

## 流程节点
1. **命令构建** → 根据需求构建完整的命令行字符串，包括程序路径、参数、选项
2. **环境检查** → 验证执行环境（shell类型、PATH配置、权限）
3. **执行启动** → 通过subprocess或shell启动命令，设置超时和资源限制
4. **状态监控** → 监控进程状态，捕获输出流，处理超时和信号
5. **退出码分析** → 解析进程退出码，分类错误类型
6. **故障诊断** → 根据退出码和输出信息诊断故障原因
7. **恢复策略** → 根据错误类型执行重试、降级或报告策略

## 关键参数

### 通用判据
| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 退出码范围 | 0-255 | [D1] | 标准Unix退出码范围，超过255的值会被模256处理 |
| 成功状态 | 0 | [D1] | 退出码0表示命令成功执行 |
| 失败状态 | 非0 | [D1] | 任意非0退出码表示执行失败 |
| 信号终止 | 128+N | [D1] | 命令被信号N终止时，退出码为128+N |
| 命令未找到 | 127 | [D1] | shell找不到指定命令时返回127 |
| 权限拒绝 | 126 | [D1] | 命令存在但不可执行时返回126 |
| 参数错误 | 2 | [D2] | Python argparse解析错误时返回2 |

### 校准数值
以下数值来自Bash和Python环境，供量级校准；其他环境需以自身证据重新锚定：
- Bash内置命令失败：退出码2表示用法错误 [D1]
- Python argparse参数错误：默认退出码2，可通过exit_on_error参数控制 [D2]
- 信号编号范围：1-31（常见信号如SIGTERM=15, SIGKILL=9） [D1]

## 边界与分流
- **超时处理**：当命令执行时间超过预设超时，应强制终止进程并返回特定退出码（如124表示超时）
- **资源限制**：内存、CPU时间等资源超限时，系统可能发送SIGKILL信号，退出码为137（128+9）
- **权限问题**：当退出码为126或127时，应检查文件权限和PATH配置
- **参数错误**：当退出码为2时，应检查命令行参数格式和语法
- **信号处理**：对于信号终止的命令，应识别信号类型并采取相应恢复措施

## 质量检查
- 验证退出码是否在0-255范围内
- 检查stderr输出是否包含错误信息
- 验证命令是否在预期时间内完成
- 检查输出是否符合预期格式
- 对于关键命令，验证退出码与输出内容的一致性

## 回退策略
- 对于非确定性失败（如网络超时），可实施指数退避重试
- 对于权限问题，可尝试提升权限或修改文件权限
- 对于参数错误，可使用默认参数或交互式提示
- 对于不可恢复的错误，应记录详细日志并报警
