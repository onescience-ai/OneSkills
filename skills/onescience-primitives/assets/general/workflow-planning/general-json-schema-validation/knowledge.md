# JSON Schema验证与报告交付契约方法论

## 适用范围

**触发条件**：
- 需要验证JSON数据格式是否符合预定义Schema
- 需要确保报告交付物符合契约规范
- 需要标准化结构化数据的输出格式

**适用场景**：
- 科研计算任务的结构化报告生成
- 数据处理工作流的输出验证
- 自动化测试中的数据格式检查
- API接口的数据契约验证

**不适用场景**：
- 非JSON格式的数据验证
- 实时流数据的动态验证
- 复杂业务逻辑的语义验证

## 输入

**输入数据格式**：
- JSON Schema定义文件（JSON格式）
- 待验证的JSON数据
- 验证规则和约束条件

**来源**：
- 用户提供的Schema定义
- 标准化的数据格式规范
- 任务契约定义文件

**预处理要求**：
- Schema语法验证
- 数据类型预检查
- 必填字段完整性检查

## 输出

**输出产物**：
- 验证通过的JSON数据
- 结构化验证报告（JSON格式）
- 格式转换后的输出文件

**格式**：
```json
{
  "validation_status": "pass|fail",
  "schema_version": "1.0.0",
  "errors": [
    {
      "path": "/field/subfield",
      "message": "错误描述",
      "schema_path": "/properties/field/properties/subfield",
      "severity": "error|warning"
    }
  ],
  "warnings": [
    {
      "path": "/field",
      "message": "警告描述",
      "recommendation": "建议修复方案"
    }
  ],
  "metadata": {
    "validated_at": "2026-09-21T00:00:00Z",
    "validator_version": "1.0.0",
    "schema_url": "https://..."
  }
}
```

**验证标准**：
- Schema验证通过率：100%（对于error级别）
- 警告处理率：≥90%
- 格式转换准确率：100%

## 流程节点

### Step 1：Schema定义与加载
- **操作**：定义JSON Schema、加载Schema文件、验证Schema语法
- **参数**：Schema定义、版本信息、验证规则
- **工具**：Schema解析器、语法验证器、版本管理器
- **质量门禁**：Schema语法正确、版本兼容、规则完整

### Step 2：数据预处理与适配
- **操作**：数据类型转换、格式标准化、缺失值处理
- **参数**：输入数据、类型映射规则、默认值策略
- **工具**：类型转换器、格式标准化器、缺失值处理器
- **质量门禁**：数据类型正确、格式统一、缺失值处理合理

### Step 3：Schema验证执行
- **操作**：执行验证规则、检查必填字段、验证数据类型
- **参数**：验证规则、数据实例、约束条件
- **工具**：Schema验证器、规则引擎、约束检查器
- **质量门禁**：验证规则正确执行、错误准确识别、警告合理生成

### Step 4：错误处理与报告生成
- **操作**：分析验证错误、生成错误报告、提供修复建议
- **参数**：验证错误列表、错误严重性、修复策略
- **工具**：错误分析器、报告生成器、建议提供器
- **质量门禁**：错误分析准确、报告结构清晰、建议可行

### Step 5：格式转换与输出
- **操作**：数据格式转换、输出文件生成、验证元数据记录
- **参数**：目标格式、输出路径、元数据信息
- **工具**：格式转换器、文件生成器、元数据记录器
- **质量门禁**：格式转换正确、输出文件完整、元数据准确

## 边界与分流

**前提1：Schema定义正确**
- 不成立时：进行Schema语法修复或使用标准Schema

**前提2：数据格式兼容**
- 不成立时：执行数据格式转换或类型适配

**前提3：验证规则完整**
- 不成立时：补充验证规则或使用默认规则集

**前提4：错误处理策略明确**
- 不成立时：采用默认错误处理策略或人工介入

**前提5：输出格式确定**
- 不成立时：使用标准输出格式或协商确定格式

## 质量检查

**验证点**：
1. Schema语法验证：确保Schema定义符合JSON Schema规范
2. 数据类型检查：验证数据类型与Schema定义一致
3. 必填字段检查：确保所有必填字段都存在
4. 约束条件验证：验证数值范围、字符串格式等约束
5. 嵌套结构验证：验证嵌套对象和数组的结构

**阈值**：
- Schema语法验证通过率：100%
- 数据类型匹配率：≥95%
- 必填字段完整率：100%
- 约束条件满足率：≥98%

**失败处理**：
- Schema语法错误：修正Schema定义
- 数据类型不匹配：转换数据类型或修正Schema
- 必填字段缺失：补充字段或修正Schema
- 约束条件不满足：调整数据或放宽约束

## 回退策略

**策略1：Schema降级**
- 适用于：Schema版本不兼容
- 实施：使用兼容性更好的Schema版本
- 监控：记录版本降级影响

**策略2：数据清理**
- 适用于：数据格式不规范
- 实施：执行数据清理和标准化
- 监控：记录清理效果和数据损失

**策略3：部分验证**
- 适用于：完整验证失败
- 实施：验证核心字段，跳过可选字段
- 监控：记录验证覆盖率和遗漏风险

**策略4：人工审核**
- 适用于：自动化验证无法解决
- 实施：生成验证报告并提交人工审核
- 监控：记录审核过程和决策依据
