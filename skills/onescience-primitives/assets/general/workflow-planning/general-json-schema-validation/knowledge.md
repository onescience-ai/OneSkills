# JSON Schema报告交付契约验证

## 适用范围
本卡片适用于任何需要验证JSON格式报告是否符合预定义Schema契约的场景。覆盖Schema定义、验证执行、错误诊断和修复建议。不适用于非JSON数据格式或动态Schema生成。

## 输入
- JSON Schema文件（JSON格式）
- 待验证的JSON报告
- 验证选项（严格模式、格式检查等）
- 错误处理策略

## 输出
- 验证结果（通过/失败）
- 错误详情（路径、消息、违规类型）
- 修复建议（缺失字段、类型错误、约束违反）
- 验证报告（JSON格式，包含所有错误）

## 流程节点
1. **Schema加载** → 解析JSON Schema并验证其有效性
2. **报告加载** → 解析JSON报告并检查语法
3. **验证执行** → 逐字段验证是否符合Schema约束
4. **错误收集** → 收集所有验证错误并组织结构
5. **报告生成** → 生成验证报告并提供建议

每步含：操作、参数、工具、质量门禁

## 关键参数

### 通用判据
| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 必填字段检查 | 必须存在 | [D1] | Schema中定义的required字段 |
| 类型约束 | 必须匹配 | [D1] | string/number/array/object等 |
| 数值范围 | 必须在范围内 | [D1] | minimum/maximum/exclusiveMinimum |
| 字符串模式 | 必须匹配正则 | [D1] | pattern字段定义 |

### 校准数值
以下数值来自典型验证实践，供量级校准；其他场景需以自身证据重新锚定。
| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 最大错误数 | 100 | 实践 | 避免过长错误列表 |
| 嵌套深度 | 10层 | [D1] | JSON Schema支持的最大嵌套 |
| 字符串长度 | 10MB | 实践 | 防止内存溢出 |

## 边界与分流
- **Schema无效** → 先修复Schema再验证报告
- **JSON语法错误** → 修复JSON格式后再验证
- **类型不匹配** → 提供类型转换建议
- **缺少必填字段** → 提供字段默认值或示例
- **额外字段** → 决定是否忽略或严格拒绝

## 质量检查
- 验证必须覆盖所有required字段
- 错误消息必须包含具体路径和期望值
- 验证报告必须可被程序解析
- 敏感数据不得出现在错误消息中

## 回退策略
1. **部分验证**：继续验证其他字段，收集所有错误
2. **宽松模式**：忽略非关键约束，只检查必填字段
3. **降级处理**：使用默认值填充缺失字段
4. **人工审核**：对于复杂错误，提供人工审核入口

## 资源召回建议

- 自动化报告生成需要验证输出格式
- 数据交换管道中需要确保数据完整性
- API响应需要验证是否符合文档定义
- 配置文件需要验证是否符合Schema
