# CLI非交互执行与故障分类

## 适用范围

面向命令行界面(CLI)工具在自动化脚本、CI/CD流水线、批处理作业中的非交互执行场景，覆盖进程启动、参数传递、退出码判读、标准错误/stderr处理、超时控制与故障恢复策略。不适用于交互式会话（如REPL、交互式调试器）。

## 输入

- 命令行字符串或参数数组
- 执行环境变量（PATH、PYTHONPATH等）
- 超时阈值（可选，默认系统级）
- 重试策略配置（可选）

## 输出

- 进程退出码（exit code）
- 标准输出（stdout）内容
- 标准错误（stderr）内容
- 执行状态分类（成功/失败/超时/信号终止）

## 流程节点

### 1. 命令构建与参数验证
- 操作：解析用户输入，构建命令行字符串
- 参数：参数转义、特殊字符处理
- 工具：shell原生语法或编程语言subprocess API
- 质量门禁：参数合法性检查，防止注入攻击

### 2. 进程启动与监控
- 操作：fork/exec进程，设置超时计时器
- 参数：工作目录、环境变量继承、管道重定向
- 工具：subprocess.Popen (Python), Process (Go), std::process (Rust)
- 质量门禁：进程PID记录，资源限制设置

### 3. 退出码语义解析
- 操作：根据退出码分类执行结果
- 参数：退出码值（0-255）
- 工具：OS标准退出码规范
- 质量门禁：退出码范围有效性检查

### 4. stderr捕获与分类
- 操作：实时读取标准错误流，识别错误模式
- 参数：错误关键词列表、正则表达式模式
- 工具：流式读取、模式匹配
- 质量门禁：错误分类准确性验证

### 5. 故障恢复策略
- 操作：根据故障类型选择恢复路径
- 参数：重试次数、退避策略、降级选项
- 工具：指数退避、熔断器模式
- 质量门禁：恢复成功率统计

## 关键参数

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 退出码 0 | 成功 | [1] | 标准成功退出 |
| 退出码 1 | 通用错误 | [1] | 未分类错误 |
| 退出码 2 | 用法错误 | [1] | 命令行参数错误 |
| 退出码 126 | 权限错误 | [1] | 无法执行命令 |
| 退出码 127 | 命令不存在 | [1] | 找不到可执行文件 |
| 退出码 130 | 中断(SIGINT) | [1] | 用户中断 |
| 退出码 143 | 终止(SIGTERM) | [1] | 优雅终止 |
| stderr缓冲 | 行缓冲 | [1] | 实时错误输出 |
| 超时默认值 | 30s | [2] | 网络请求默认超时 |

## 边界与分流

- **超时触发**：进程超时未响应 → 发送SIGTERM（Windows: TerminateProcess），等待grace period后发送SIGKILL → 记录超时错误，返回超时退出码
- **信号处理**：收到SIGINT/SIGTERM → 转发给子进程，设置退出标志 → 子进程优雅退出后汇总结果
- **资源耗尽**：内存/CPU超限 → 操作系统强制终止 → 记录资源使用峰值，调整下次执行参数
- **依赖缺失**：子命令或工具不存在 → 退出码127 + stderr提示安装方法 → 建议依赖安装或替代工具

## 质量检查

- 退出码语义一致性：所有CLI工具遵循POSIX退出码规范
- stderr完整性：错误信息必须包含错误类型、原因和建议操作
- 幂等性：相同输入重复执行应产生相同结果（状态变更类命令除外）
- 资源释放：临时文件、锁、子进程在异常退出时必须清理

## 回退策略

- 退出码不可识别 → 按通用错误处理，记录原始退出码
- stderr捕获失败 → 仅依赖退出码分类，降低诊断精度
- 网络超时 → 增加重试次数或降低请求复杂度
- 权限不足 → 提示用户权限要求或使用sudo（需明确警告）

## 资源召回建议

- 当任务涉及CLI工具调用、自动化脚本编写、CI/CD流水线配置时召回
- 配套资源：`general-json-schema-report-delivery-contract`（报告生成类任务）
- 当遇到非交互执行故障时，先分类退出码，再分析stderr内容
