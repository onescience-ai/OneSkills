# CLI 非交互执行与故障分类

## 适用范围
面向命令行界面（CLI）程序的非交互执行场景，提供故障分类、退出码解读、信号终止诊断与恢复策略。适用于任何需要在自动化脚本、CI/CD 流水线或远程环境中稳定执行 CLI 程序并处理异常退出的情况。

## 输入
- CLI 程序的退出码（exit code）或终止信号
- 标准错误（stderr）输出内容
- 操作系统环境信息（Linux/macOS/Windows）
- 程序日志文件（如有）

## 输出
- 故障分类结果（错误类型、严重程度）
- 退出码解读（标准含义与自定义含义）
- 信号终止诊断（信号类型、来源）
- 恢复策略建议（重试、降级、告警）

## 流程节点
1. 退出码采集 → 获取 CLI 程序的 `$?` 或进程退出状态
2. 退出码分类 → 区分标准退出码（0-255）与自定义退出码
3. 信号终止检测 → 识别是否因信号导致终止（128 + 信号编号）
4. 标准错误分析 → 解析 stderr 输出中的错误信息
5. 故障归因 → 结合退出码、信号、错误信息确定故障原因
6. 恢复策略选择 → 根据故障类型选择重试、降级或告警

## 关键参数

### 通用判据
| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 退出码 0 | 成功 | [D1] | 程序正常执行完成 |
| 退出码 1 | 通用错误 | [D1] | 捕获一般性错误（如除零、权限问题） |
| 退出码 2 | Shell 内置命令误用 | [D1] | Bash 文档中定义的误用 |
| 退出码 126 | 无法执行 | [D1] | 权限问题或命令不可执行 |
| 退出码 127 | 命令未找到 | [D1] | PATH 问题或拼写错误 |
| 退出码 128+n | 致命信号 n | [D1] | 程序被信号 n 终止（如 137 = 128+9 = SIGKILL） |
| 退出码 130 | Ctrl+C 终止 | [D1] | 用户中断（信号 2 = SIGINT） |
| 退出码 255 | 退出状态超范围 | [D1] | exit 参数超出 0-255 范围 |

### 校准数值
| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 推荐用户定义退出码范围 | 64-113 | [D1] | C/C++ 标准建议，避免与标准退出码冲突 |
| exit 参数有效范围 | 0-255 | [D1] | 超出范围会取模 256 |

## 边界与分流
- **退出码为 0**：程序正常完成，无需处理
- **退出码为 1**：通用错误，需检查 stderr 获取具体原因
- **退出码 126-127**：环境问题（PATH、权限），需修复环境
- **退出码 128+n**：信号终止，需检查信号来源（系统、用户、程序崩溃）
- **退出码 255**：参数错误，需检查 exit 命令调用
- **自定义退出码**：需查阅程序文档了解具体含义

## 质量检查
- 验证退出码是否在有效范围内（0-255）
- 检查 stderr 输出是否包含有意义的错误信息
- 确认信号终止的信号类型是否可识别
- 评估恢复策略是否可行（重试次数、降级条件）

## 回退策略
- 退出码无法识别时：记录原始退出码和 stderr，报告人工诊断
- 信号终止无法恢复时：生成核心转储（如允许）并报告
- 环境问题无法修复时：切换到备用执行环境或容器化执行
