# orchestrator规划阶段效率优化策略

## 适用范围
本任务面向OneScience orchestrator规划阶段的效率优化，提供并行化执行器能力查询、提前生成execution-manifest.json、设置规划阶段时间预算等策略。适用于任务编排系统在规划阶段耗时过长、执行器能力查询不完整等场景。

不适用场景：任务执行阶段优化、数据处理优化、模型训练优化。

## 任务目标
1. 缩短orchestrator规划阶段耗时，确保任务在超时前进入实际执行
2. 实现执行器能力查询的完整性和并行化
3. 提前生成execution-manifest.json，避免预检失败
4. 设置规划阶段时间预算，自动切换到执行阶段

## 输入契约
**必需输入**：
- 任务描述：用户目标、约束条件、相关产物路径
- 执行器技能列表：所有可用executor技能的SKILL.md文件
- 资源检索结果：知识库匹配结果、在线文献检索结果

**可选输入**：
- 历史任务数据：以往任务的执行时间和成功率
- 系统资源信息：当前计算资源、网络状况

**数据格式要求**：
- 任务描述：JSON或YAML格式
- 执行器技能：SKILL.md文件路径列表
- 资源检索结果：JSON格式

## 输出契约
**必需输出**：
- 优化后的规划流程：包含时间预算、并行化策略
- execution-manifest.json：提前生成的任务清单
- 执行器能力视图：完整的executor能力台账

**输出格式**：
- 规划流程：JSON或YAML格式
- execution-manifest.json：标准JSON格式
- 能力视图：JSON格式

## 方法路线
### 阶段1：并行化执行器能力查询
1. **并行读取SKILL.md**：使用多线程/多进程同时读取所有executor技能
2. **能力提取**：从每个SKILL.md中提取输入要求、输出产物、负责事项、不负责事项、下游交接对象
3. **能力台账构建**：建立完整的executor能力视图
4. **完整性验证**：确保read_executor_skills包含所有all_executor_skills

### 阶段2：提前生成execution-manifest.json
1. **清单模板**：基于任务类型预定义清单模板
2. **字段填充**：根据任务描述和资源检索结果填充清单字段
3. **验证机制**：确保清单完整性和格式正确性
4. **错误处理**：清单生成失败时的降级策略

### 阶段3：设置规划阶段时间预算
1. **时间预算分配**：为每个规划步骤分配时间预算
   - 资源检索：30秒
   - 在线文献检索：60秒
   - 专家规划：30秒
   - 执行器能力查询：20秒
2. **监控机制**：实时监控各步骤耗时
3. **自动切换**：超过预算时自动切换到执行阶段
4. **降级策略**：规划不完整时使用简化方案

### 阶段4：优化验证
1. **性能指标**：规划阶段总耗时、各步骤耗时
2. **完整性指标**：执行器能力查询完整率
3. **成功率**：execution-manifest.json生成成功率
4. **任务成功率**：优化后任务执行成功率

## 操作序列
1. **需求分析**：解析任务描述，确定优化目标
2. **并行化设计**：设计执行器能力查询的并行化方案
3. **时间预算设置**：为各步骤分配时间预算
4. **清单模板创建**：创建execution-manifest.json模板
5. **实现并行查询**：实现多线程/多进程能力查询
6. **实现时间监控**：实现实时时间监控和自动切换
7. **测试验证**：测试优化效果
8. **部署应用**：将优化策略部署到生产环境

## 边界与分流
- **并行化失败**：回退到串行查询，但记录失败原因
- **时间预算超支**：自动切换到执行阶段，使用当前最佳规划
- **清单生成失败**：使用简化清单模板，确保基本功能
- **能力查询不完整**：使用默认能力台账，标记缺失技能
- **系统资源不足**：降低并行度，延长单步时间预算

## 质量检查
**验证点**：
1. 并行化效果：线程数与加速比的关系
2. 时间预算执行：各步骤是否在预算内完成
3. 清单完整性：execution-manifest.json字段是否齐全
4. 能力查询完整性：是否查询了所有executor技能
5. 任务执行效果：优化后任务是否成功执行

**阈值**：
- 规划阶段总耗时 ≤ 120秒
- 执行器能力查询完整率 = 100%
- execution-manifest.json生成成功率 ≥ 99%
- 任务执行成功率 ≥ 95%

**失败处理**：
- 并行化失败：记录日志，回退到串行
- 时间超支：自动切换，记录超支原因
- 清单生成失败：使用简化模板，记录错误
- 能力查询不完整：标记缺失技能，使用默认值

## 回退策略
- **并行化不可用**：使用串行查询，但优化查询顺序
- **时间预算不足**：动态调整预算，优先关键步骤
- **清单模板不适用**：使用通用模板，手动补充缺失字段
- **能力查询失败**：使用历史能力台账，标记过期信息
- **系统资源受限**：降低优化目标，确保基本功能
