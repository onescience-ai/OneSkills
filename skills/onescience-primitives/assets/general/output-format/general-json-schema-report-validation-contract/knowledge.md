# JSON Schema报告交付契约验证

## 适用范围

面向需要确保自动化科学计算流水线输出的JSON报告符合预定结构规范的场景，提供系统化的Schema验证与质量评估方法。适用于归因分析报告、实验结果报告、数据处理报告等任何需要结构化JSON输出并要求格式合规性的应用。

**不适用场景**：
- 纯文本日志或非结构化输出的验证
- 实时流式数据的Schema验证（需使用流式Schema处理器）
- XML/CSV等非JSON格式的验证

## 输入

- JSON报告数据（待验证的输出）
- JSON Schema定义（预期的结构规范）
- 可选的参考Schema（用于对比评估）
- 验证参数配置（阈值、权重）

## 输出

- Schema合规性评分（0-1）
- 六维度质量评估结果
- 不合规项列表与详细诊断
- Schema Quality Score（SQS）加权聚合值

## 流程节点

### Step 1：Schema定义与加载
- **操作**：定义或加载JSON Schema规范
- **参数**：Schema版本、必填字段列表、字段类型定义
- **工具**：jsonschema库、JSON Schema Draft-07/2020-12
- **质量门禁**：Schema语法正确，无循环引用

### Step 2：数据类型精度验证（DTA）
- **操作**：验证每个字段的数据类型是否符合Schema定义
- **参数**：Type Conformance = |obs ∩ inf| / |obs ∪ inf|
- **工具**：类型检查器、集合交并运算
- **质量门禁**：DTA ≥ 0.9（类型精度达标）

### Step 3：必填字段完整性验证（ROF）
- **操作**：验证必填字段存在性及字段间依赖关系
- **参数**：Presence Accuracy = 正确识别数 / 总字段数
- **工具**：频率统计、关联规则挖掘（support/confidence/lift）
- **质量门禁**：存在精度 ≥ 0.85，依赖置信度 ≥ 0.8

### Step 4：多类型支持验证（MTS）
- **操作**：验证字段是否正确支持多种数据类型（union types）
- **参数**：MTS = |T_obs ∩ T_inf| / |T_obs| - λ × penalty
- **工具**：类型集合比较、惩罚系数λ=0.5
- **质量门禁**：MTS ≥ 0.8（类型多样性覆盖）

### Step 5：集合结构一致性验证（CSC）
- **操作**：验证数组字段的嵌套深度和元素类型一致性
- **参数**：CSC = α×Homogeneity + (1-α)×DepthConformance
- **工具**：Shannon熵计算、深度比较，α=0.7
- **质量门禁**：CSC ≥ 0.8（数组结构规范）

### Step 6：实体关系恢复验证（ERR）
- **操作**：验证跨字段的实体关系和引用完整性
- **参数**：ERR = β×F1 + (1-β)×GED_norm，β=0.7
- **工具**：图对齐、精确率/召回率计算
- **质量门禁**：ERR ≥ 0.75（关系恢复完整）

### Step 7：时间演化检测验证（TED）
- **操作**：验证Schema是否能检测随时间的结构演化
- **参数**：TED = 0.5×(VDA + [1 - |CDR_inf - CDR_ref|])
- **工具**：版本检测、变化检测率比较
- **质量门禁**：TED ≥ 0.7（演化检测灵敏）

### Step 8：聚合评分与报告生成
- **操作**：计算Schema Quality Score（SQS）
- **参数**：SQS = Σ(w_i × S_i)，权重可配置
- **工具**：加权求和
- **质量门禁**：SQS ≥ 0.8（整体质量达标）

## 关键参数

### Schema验证维度权重（通用判据）

| 维度 | 符号 | 默认权重 | 说明 | 来源 |
|------|------|---------|------|------|
| 数据类型精度 | DTA | 0.20 | 原子类型正确性 | [1] |
| 必填/可选字段 | ROF | 0.15 | 字段存在性与依赖 | [1] |
| 多类型支持 | MTS | 0.15 | Union类型覆盖 | [1] |
| 集合结构一致性 | CSC | 0.15 | 数组嵌套与均匀性 | [1] |
| 实体关系恢复 | ERR | 0.20 | 跨实体引用完整性 | [1] |
| 时间演化检测 | TED | 0.15 | Schema版本追踪 | [1] |

### 验证阈值（校准数值）

| 参数 | 推荐值 | 说明 | 来源 |
|------|--------|------|------|
| 存在阈值 | 0.90 | 字段出现频率≥90%视为必填 | [1] |
| 依赖置信度 | 0.80 | 关联规则置信度阈值 | [1] |
| 依赖提升度 | 1.20 | 关联规则提升度阈值 | [1] |
| 惩罚系数λ | 0.50 | 多类型过度泛化惩罚 | [1] |
| 均匀性权重α | 0.70 | CSC中均匀性vs深度权重 | [1] |
| ERR平衡系数β | 0.70 | F1 vs GED归一化权重 | [1] |

以下数值来自SVEF框架实验评估，供量级校准；其他体系需以自身证据重新锚定。

## 边界与分流

### 前提不成立时的改道方案

| 前提 | 不成立时的改道 |
|------|---------------|
| Schema定义完整可用 | 改用运行时类型推断+人工审查 |
| JSON数据可完整加载 | 改用流式Schema验证或分块验证 |
| 有参考Schema可用 | 仅执行无参考的结构一致性检查 |
| 时间序列数据可用 | 跳过TED维度，仅评估静态Schema质量 |

### 降级策略

| 场景 | 降级方案 |
|------|---------|
| 六维度全部评估成本过高 | 仅评估DTA+ROF+ERR三个核心维度 |
| 实时性要求高 | 采样验证而非全量验证 |
| Schema频繁变更 | 增量验证而非全量重验证 |

## 质量检查

1. **Schema语法校验**：确保Schema本身符合JSON Schema规范
2. **类型覆盖检查**：验证所有实际出现的类型都在Schema中有定义
3. **必填字段完整性**：验证所有必填字段在每条记录中都存在
4. **依赖关系一致性**：验证字段间的条件依赖关系正确表达
5. **数组结构规范性**：验证数组嵌套深度和元素类型一致性
6. **跨记录一致性**：验证同一集合内不同记录的Schema一致性

## 回退策略

1. **Schema缺失**：从已有数据自动推断Schema，人工审查后使用
2. **验证失败**：记录详细错误信息，支持人工审查和Schema修正
3. **性能瓶颈**：对大数据集采用采样验证策略
4. **Schema演化**：支持多版本Schema并存，按时间戳选择验证版本
