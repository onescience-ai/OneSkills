# CLI非交互执行与故障分类知识

## 适用场景

当任务需要通过命令行接口（CLI）执行非交互式操作时，本知识提供故障诊断和分类框架。适用于：
- 自动化脚本执行
- 批处理任务
- CI/CD流水线中的命令执行
- 远程服务器执行
- 容器化环境中的命令执行

## 故障分类体系

### 1. 启动故障（Startup Failures）

**特征**：命令未能正常启动或立即失败

**常见原因**：
- 命令不存在或路径错误
- 权限不足（Permission denied）
- 依赖缺失（Library not found）
- 环境变量未设置
- 参数格式错误

**诊断方法**：
- 检查命令路径：`which command` 或 `where command`
- 检查权限：`ls -l /path/to/command`
- 检查依赖：`ldd command` (Linux) 或 `otool -L command` (macOS)
- 手动执行命令查看详细错误

### 2. 超时故障（Timeout Failures）

**特征**：命令在预定时间内未完成

**常见原因**：
- 任务过于复杂或数据量过大
- 死锁或无限循环
- 资源竞争（CPU、内存、I/O）
- 网络延迟（远程执行）
- 外部服务无响应

**诊断方法**：
- 检查进程状态：`ps aux | grep command`
- 监控资源使用：`top`, `htop`, `vmstat`
- 分析日志文件
- 设置合理的超时时间
- 实现进度监控和中间产物检查

### 3. 退出码故障（Exit Code Failures）

**特征**：命令执行完成但返回非零退出码

**退出码分类**：
- `0`：成功
- `1-125`：一般错误（具体含义由程序定义）
- `126`：命令不可执行（权限问题）
- `127`：命令未找到
- `128+N`：被信号N终止（如130=Ctrl+C）
- `130`：SIGINT（Ctrl+C）
- `137`：SIGKILL（被强制终止）
- `255`：退出码超出范围

**诊断方法**：
- 记录退出码：`echo $?`
- 查看程序文档了解退出码含义
- 检查标准错误输出
- 分析日志文件

### 4. 输出解析故障（Output Parsing Failures）

**特征**：命令输出不符合预期格式

**常见原因**：
- 输出格式变更
- 语言/区域设置影响
- 编码问题
- 输出被截断
- 多余的调试信息

**诊断方法**：
- 捕获原始输出：`command > output.txt 2>&1`
- 检查输出编码：`file output.txt`
- 设置统一的区域和语言环境
- 使用正则表达式而非固定位置解析

### 5. 资源故障（Resource Failures）

**特征**：系统资源不足导致执行失败

**常见原因**：
- 内存不足（Out of memory）
- 磁盘空间不足
- 文件描述符耗尽
- CPU时间限制
- 网络带宽限制

**诊断方法**：
- 监控系统资源：`free -h`, `df -h`, `ulimit -a`
- 检查资源限制配置
- 实现资源使用监控
- 设置资源使用告警

### 6. 环境故障（Environment Failures）

**特征**：执行环境配置问题

**常见原因**：
- Python/Node/R版本不兼容
- 依赖包版本冲突
- 虚拟环境未激活
- 环境变量缺失或错误
- 路径配置错误

**诊断方法**：
- 检查环境版本：`python --version`, `node --version`
- 检查依赖列表：`pip list`, `npm list`
- 验证环境变量：`env | grep VARIABLE`
- 创建最小化测试环境

## 故障诊断流程

### 1. 收集信息
- 记录完整的命令和参数
- 保存标准输出和标准错误
- 记录退出码
- 记录执行环境信息
- 记录时间戳和执行时长

### 2. 分类故障
根据退出码、错误信息和执行行为，将故障归类到上述6种类型之一。

### 3. 分析根因
- 查看详细错误信息
- 检查相关日志文件
- 分析资源使用情况
- 验证环境配置

### 4. 制定修复策略
- 启动故障：修复命令路径、权限或依赖
- 超时故障：优化算法、增加资源或调整超时设置
- 退出码故障：根据具体退出码采取相应措施
- 输出解析故障：修复解析逻辑或标准化输出格式
- 资源故障：释放资源、增加配额或优化资源使用
- 环境故障：修复环境配置或依赖版本

## CLI最佳实践

### 1. 统一接口设计
- 支持多种查询方式：单个查询、文件输入（--file）、标准输入（--file -）
- 确保所有子命令接受统一参数格式
- 支持Unix管道组合

### 2. 输出格式控制
- 提供多种输出格式：CSV、TSV、JSON（--outfmt）
- 支持输出重定向到文件（--out）
- 支持按查询拆分输出（--split）
- 使用stderr显示进度信息，保留stdout给下游工具

### 3. 分页与完整性
- 透明处理分页：自动获取所有结果页
- 确保大结果集完整返回，无截断
- 实现顺序分页，避免数据遗漏

### 4. 错误处理与重试
- 实现指数退避重试机制
- 区分临时性错误和永久性错误
- 提供有意义的错误信息
- 记录详细的错误日志

### 5. 性能优化
- 使用系统编程语言（如Rust）提升性能
- 减少进程调用开销
- 实现并行处理（在适用场景）
- 优化内存使用

## 最佳实践

### 命令执行
1. 使用绝对路径或验证PATH环境变量
2. 设置合理的超时时间
3. 实现重试机制（针对临时性故障）
4. 记录详细的执行日志

### 错误处理
1. 捕获并处理所有退出码
2. 区分可恢复和不可恢复错误
3. 实现优雅降级机制
4. 提供有意义的错误信息

### 监控和告警
1. 监控关键指标（执行时间、资源使用、错误率）
2. 设置阈值告警
3. 实现健康检查
4. 记录性能指标

## 边界说明

本知识专注于CLI执行层面的故障诊断，不涉及：
- 业务逻辑错误（如算法错误、数据校验失败）
- 领域特定错误（如生物信息学分析错误、CFD收敛失败）
- 业务结果验证（如模型精度不达标）

业务逻辑错误应由对应的领域专家技能处理。本知识仅提供CLI执行层面的故障分类和诊断框架。
