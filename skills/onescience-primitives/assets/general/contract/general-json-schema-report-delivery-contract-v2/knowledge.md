# JSON Schema 报告交付契约

## 适用范围

面向结构化报告交付场景，定义JSON Schema验证契约。适用于任何需要生成符合特定Schema的JSON报告的自动化工作流，包括但不限于科研任务报告、数据分析报告、模型评估报告等。本契约确保报告格式的一致性、可验证性和可解析性。

## 输入

- JSON Schema定义文件
- 原始数据或分析结果
- 任务元数据（任务ID、任务名称、执行时间等）
- 验证规则和约束

## 输出

- 符合Schema的JSON报告
- 验证结果（通过/失败，错误详情）
- 诊断信息（缺失字段、格式错误、类型不匹配）

## 流程节点

1. **Schema解析** → 2. **数据映射** → 3. **报告生成** → 4. **Schema验证** → 5. **错误处理**

### 步骤1：Schema解析
- **操作**：解析JSON Schema定义，提取必填字段、类型约束、格式要求
- **参数**：Schema版本、字段定义、验证规则
- **工具**：JSON Schema解析器
- **质量门禁**：正确解析Schema，识别所有约束条件

### 步骤2：数据映射
- **操作**：将原始数据映射到Schema定义的字段，处理缺失值和类型转换
- **参数**：数据源、字段映射规则、默认值
- **工具**：数据映射器、类型转换器
- **质量门禁**：确保数据完整性和类型一致性

### 步骤3：报告生成
- **操作**：按照Schema结构生成JSON报告，填充所有必填字段
- **参数**：报告模板、数据源、格式选项
- **工具**：JSON生成器、模板引擎
- **质量门禁**：生成符合Schema结构的JSON报告

### 步骤4：Schema验证
- **操作**：使用JSON Schema验证器检查生成的报告是否符合定义
- **参数**：Schema文件、验证选项、错误处理策略
- **工具**：JSON Schema验证器
- **质量门禁**：验证报告符合所有Schema约束

### 步骤5：错误处理
- **操作**：处理验证失败的情况，提供详细的错误信息和修复建议
- **参数**：错误类型、错误位置、修复策略
- **工具**：错误处理器、日志记录器
- **质量门禁**：提供清晰的错误信息，便于问题定位

## 关键参数

### 通用判据

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 必填字段 | 按Schema定义 | [1] | 所有必填字段必须存在 |
| 类型约束 | 按Schema定义 | [1] | 字段类型必须匹配 |
| 数组约束 | 按Schema定义 | [1] | 数组字段必须为数组类型 |
| 任务身份 | task_id + task | [2] | 必须包含任务ID和任务名称 |
| 字符串约束 | 非空字符串 | [2] | summary等字段必须为非空字符串 |

### 校准数值

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 验证通过率 | ≥99% | [1] | 正常工作流中验证通过的比例 |
| 错误检测延迟 | ≤1秒 | [1] | 从报告生成到验证完成的时间 |
| 错误信息完整性 | 100% | [2] | 所有错误必须包含位置和原因 |
| 重试成功率 | ≥90% | [1] | 自动修复后重新验证的通过率 |

## 边界与分流

- **前提1：Schema文件存在且有效** → 若Schema文件缺失或格式错误，转向Schema定义或修复
- **前提2：数据源可访问** → 若数据源不可访问或格式错误，转向数据预处理或验证
- **前提3：验证器可用** → 若JSON Schema验证器不可用，转向替代验证方案或人工验证
- **前提4：任务身份完整** → 若缺少task_id或task字段，转向任务元数据补全
- **前提5：输出格式正确** → 若生成的JSON格式错误，转向JSON格式修复

## 质量检查

- Schema验证通过率 ≥ 99%
- 必填字段缺失率 = 0%
- 类型错误率 ≤ 1%
- 错误信息完整率 = 100%

## 回退策略

- 验证失败时，提供详细的错误信息和修复建议
- 记录完整的验证日志，便于问题追踪
- 提供降级方案，确保核心信息可提取
