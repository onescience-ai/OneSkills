# JSON Schema报告交付契约

## 适用范围

面向需要定义结构化JSON输出格式的自动化任务，提供使用JSON Schema作为报告交付契约的规范。适用于任何需要确保输出数据格式一致性、可验证性和可解析性的场景，包括但不限于自动化报告生成、API响应格式化、数据管道输出、机器学习模型预测结果输出。

不适用于二进制格式输出、流式数据处理、实时交互式响应或需要复杂数据转换的场景。

## 输入

- **JSON Schema定义**：描述输出数据结构的JSON Schema文档
- **待验证数据**：需要验证格式的JSON数据
- **验证配置**：验证级别、严格模式、自定义规则

## 输出

- **验证结果**：成功/失败状态
- **错误详情**：具体的验证错误信息
- **错误路径**：JSON数据中出错的位置路径
- **结构化诊断**：便于程序解析的错误报告

## 流程节点

### 1. Schema加载与解析
- **操作**：加载JSON Schema文档，解析其结构
- **参数**：Schema文档路径、Schema版本、解析选项
- **工具**：JSON Schema解析器、Schema验证器
- **质量门禁**：Schema语法正确、版本兼容、无循环引用

### 2. 数据准备
- **操作**：准备待验证的JSON数据
- **参数**：数据来源、编码格式、预处理规则
- **工具**：JSON解析器、数据预处理器
- **质量门禁**：JSON语法正确、编码有效、数据完整

### 3. 验证执行
- **操作**：根据Schema验证数据结构
- **参数**：验证级别（strict/lenient）、错误处理策略
- **工具**：JSON Schema验证器、验证引擎
- **质量门禁**：验证算法正确、性能可接受、结果准确

### 4. 错误收集
- **操作**：收集所有验证错误
- **参数**：错误类型、严重级别、上下文信息
- **工具**：错误收集器、错误分类器
- **质量门禁**：错误完整收集、分类准确、信息丰富

### 5. 诊断生成
- **操作**：生成结构化的诊断报告
- **参数**：输出格式、详细级别、包含建议
- **工具**：诊断生成器、格式化器
- **质量门禁**：诊断信息完整、格式规范、便于程序解析

### 6. 结果返回
- **操作**：返回验证结果和诊断信息
- **参数**：返回格式、编码、压缩选项
- **工具**：结果包装器、序列化器
- **质量门禁**：结果完整、格式一致、可被调用方正确解析

## 关键参数

### 通用判据

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| Schema版本 | Draft 2020-12 | [1] | 当前推荐使用的JSON Schema版本 |
| 必填字段标记 | "required" | [1] | Schema中定义必填字段的关键字 |
| 类型约束 | "type" | [1] | Schema中定义数据类型的关键字 |
| 格式验证 | "format" | [1] | Schema中定义格式约束的关键字 |
| 枚举约束 | "enum" | [1] | Schema中定义枚举值的关键字 |
| 引用机制 | "$ref" | [1] | Schema中定义引用的关键字 |
| 验证严格级别 | strict | [2] | 严格模式下所有错误都必须报告 |
| 错误路径格式 | JSON Pointer | [1] | 错误位置的表示格式 |

### 校准数值

以下数值来自Web API和数据验证领域，供量级校准；其他领域需以自身证据重新锚定：

| 参数 | 值 | 来源 | 说明 |
|------|-----|------|------|
| 验证性能目标 | <10ms | [3] | 单个JSON对象验证时间目标 |
| 编译优化加速比 | 10x | [3] | 编译优化后验证速度提升倍数 |
| 错误信息最大长度 | 1000字符 | [D1] | 单个错误信息的最大长度 |
| 最大嵌套深度 | 10层 | [D1] | Schema允许的最大嵌套深度 |
| 最大属性数量 | 100个 | [D1] | 单个对象允许的最大属性数量 |

## 边界与分流

### 前提1：Schema有效
- **条件**：提供的JSON Schema文档语法正确且符合规范
- **不成立时转向**：返回Schema解析错误，提示修正Schema文档

### 前提2：数据可解析
- **条件**：待验证数据是有效的JSON格式
- **不成立时转向**：返回JSON解析错误，提示检查数据格式

### 前提3：版本兼容
- **条件**：Schema版本与验证器兼容
- **不成立时转向**：返回版本不兼容错误，建议使用兼容版本

### 前提4：性能可接受
- **条件**：验证时间在可接受范围内
- **不成立时转向**：考虑使用编译优化（如Blaze）或简化Schema

## 质量检查

| 检查点 | 阈值 | 失败处理 |
|--------|------|----------|
| Schema语法正确性 | 100% | 语法错误需修正Schema |
| JSON数据有效性 | 100% | 无效JSON需修正数据 |
| 必填字段完整性 | 所有required字段存在 | 缺失必填字段需补充数据 |
| 类型匹配性 | 所有字段类型正确 | 类型错误需修正数据或Schema |
| 格式合规性 | 所有format字段合规 | 格式错误需修正数据 |
| 验证性能 | <10ms（单个对象） | 性能不达标需优化Schema或验证器 |
| 错误信息可读性 | 100% | 不可读错误需改进错误消息 |

## 回退策略

1. **Schema降级**：使用更简单的Schema进行验证，只检查关键字段
2. **部分验证**：只验证最重要的字段，跳过非关键验证
3. **延迟验证**：将验证推迟到后续处理阶段执行
4. **人工验证**：在自动验证失败时，记录数据并等待人工处理
